# Hearth

Hearth는 Minecraft 기반 RPG 및 서버 엔지니어링 프로젝트입니다. 마법 없이 현실적인 중세 기술을 바탕으로 NPC, 퀘스트, 세계 진행과 경제 시스템을 설계합니다.

스토리 월드의 핵심 콘셉트는 현대인이 이 세계에 등장해 현대의 과학·기술 지식을 활용하는 것입니다. 경제 월드는 스토리 월드를 기반으로 경제 중심 멀티플레이 환경으로 확장합니다.

## 두 게임 월드

| 월드 | 목적 | 주요 설계 범위 |
| --- | --- | --- |
| 스토리 월드 | 싱글 플레이 또는 소규모 협동으로 이야기를 경험 | NPC, 퀘스트, 플레이어·공동체별 독립 월드와 진행, 필수 AI 스마트폰 어시스턴트 |
| 경제 월드 | 별도의 멀티플레이 환경에서 경제 활동을 경험 | 생산, 재고, 공급·수요, 시장가격, 거래·무역, 자원 순환, 선택형 AI 스마트폰 어시스턴트 |

두 월드의 월드 파일, 플레이어 상태, 진행도와 경제 데이터는 논리적으로 분리합니다. 월드 간 데이터 공유나 이전 규칙은 미정입니다.

공통 기반 기능은 재사용할 수 있습니다. 스토리 월드의 AI 스마트폰 어시스턴트는 퀘스트, NPC, 게임 내 정보를 바탕으로 플레이어의 질문에 답하도록 계획합니다. 경제 월드에서는 선택 기능이며 제거할 수 있도록 설계합니다.

스토리 월드는 **하나의 Minecraft 서버 프로세스에서 진행별 독립 월드를 운영하는 B안**을 채택했습니다. 싱글은 자신만의 진행을 갖고 코옵 공동체는 하나의 진행과 월드를 공유합니다. 퀘스트·NPC·월드 변화·플레이어 상태는 진행별로 격리하며, 유휴 월드는 저장 후 언로드하는 방향으로 설계합니다. 로컬 AI는 공통 서비스를 사용하되 진행별 정보 접근을 격리합니다. 논리 진행 ID와 물리 서버 배치를 분리해 향후 A안 확장 가능성을 유지합니다. [ADR-0001](docs/decisions/0001-story-world-multiworld.md)에 결정과 미검증 범위를 기록했습니다.

인벤토리·아이템 관리는 [ADR-0003](docs/decisions/0003-inventory-performance-and-recovery.md)에 따라 성능과 원활한 플레이를 우선합니다. 일반 상자·창고는 월드 파일, 개인 인벤토리는 PostgreSQL 중심으로 저장합니다. 정상 동작의 기본 안전성은 유지하되 고비용 자동 복구는 필수가 아니며, 예기치 못한 장애의 일부 아이템 유실·복사는 최소 로그·백업 기반 관리자 수동 조정을 허용합니다. 자동 무손실이나 모든 상황의 복사 방지를 보장하지 않습니다.

## 저장소 구조

```text
docs/                  설계 문서와 의사결정 기록
minecraft/
  story/               스토리 월드 설계 및 향후 설정
  economy/             경제 월드 설계 및 향후 설정
services/              Hearth 보조 서비스 설계 및 향후 소스
infrastructure/        Hearth 배포·모니터링 설계 및 향후 설정
scripts/               향후 개발·검증·운영 보조 스크립트
```

문서의 출발점은 [문서 안내](docs/README.md), 시스템 구성안은 [아키텍처](docs/architecture.md)입니다. 작업 규칙은 [AGENTS.md](AGENTS.md)를 따릅니다.

Git 저장소의 문서를 ChatGPT와 Codex가 공유하는 공식 프로젝트 기록으로 사용합니다. ChatGPT는 기획·아키텍처·결과 검토를, Codex는 구현·테스트·승인 범위의 인프라 작업을 담당합니다. 현재 사실은 [프로젝트 현황](docs/PROJECT_STATUS.md), 단계별 목표·완료 조건은 [로드맵](docs/ROADMAP.md), 주요 커밋 이력은 [변경 이력](docs/CHANGELOG.md)에서 확인합니다. 작업 인계 시 관련 문서와 커밋을 함께 전달합니다.

## 현재 단계

[S4-3](docs/s4-3-verification.md)는 인증된 플레이어의 수동 건축 시험 경로를 준비했습니다. 클라이언트 미확보로 실제 접속 행동과 수동 경로 런타임은 미실행이며 S4는 진행 중입니다.

후속 [S4-2 검증](docs/s4-2-verification.md)에서 새 JVM의 A/B 영속성·구역 API·자연 피스톤 보호를 확인했습니다. 접속 플레이어 설치/파괴는 미실행이며 전체 S4는 진행 중입니다.

기술 스택과 월드 운영 정책을 확정했고 Temurin JDK 25·Gradle 9.1.0·고정 Paper API로 최소 플러그인 컴파일·JAR 생성을 확인했습니다. 주요 API 참조 컴파일·위험·후속 기준 정리로 S2를 완료했고 C1 승인·12영역 감사에 따라 [S3 상세 설계](docs/story-world-detailed-design.md)를 설계 기준선으로 완료했습니다. S4 사전 [플러그인 검토](docs/plugin-suitability-review.md)를 기록했으며 S4-1 최소 플러그인·파일 시험을 구현했습니다. [S4-1 기록](docs/s4-1-verification.md)의 EULA 동의 후 Paper/Hearth/WG/WE 로딩, 합성 A/B 월드·블록 보존·WG 구역 API smoke는 통과했습니다. 실제 플레이어 이벤트·전체 기능/부하 시험은 남습니다. 전체 게임 구현·운영 검증은 미완료이며 [검증 기록](docs/stack-build-verification.md)에 범위를 구분했습니다. 초기 설계·검토와 B안 ADR 및 S3 필수 명세는 준비됐으며 명시적 보류 정책·구현·실행 검증은 남습니다. 저장소에는 최소 Java 플러그인·Gradle·파일 시험과 제한된 시험 실행 도구가 있으며 실제 월드/서버 JAR·AI 소스·운영 배포 설정은 없습니다. Git 보안 검사 Hook과 활성화 스크립트는 존재합니다. 호스트 전체 설치·가동 상태 조사나 운영 변경은 하지 않았으며, 이번 서버 실행은 시간·자원을 제한한 Hearth 전용 격리 시험뿐입니다. 확인 근거와 날짜는 프로젝트 현황에서 관리합니다.

확정 스택은 Paper 26.2, Java 25, Gradle, PostgreSQL, 단일 플러그인 JAR과 내부 기능별 모듈화, Docker Compose, 기존 Zabbix 활용입니다. 순정 Minecraft Java Edition을 대상으로 별도 모드 설치를 최소화하며 필요시 서버 리소스팩을 제공합니다. AI 구체 기술과 세부 배포 구성은 미정입니다.

스토리 월드는 버전별 사전 제작 템플릿을 복제하고 기존 월드·진행을 유지합니다. 공간 템플릿과 NPC·대화·퀘스트 콘텐츠 정의를 분리하며 진행 상태는 PostgreSQL에 월드별로 격리합니다. 비활성 월드는 저장·언로드 후 재접속 시 복원합니다. 스토리·경제의 인벤토리와 진행은 분리합니다.

스토리는 전체 보호·지정 구역 변경 허용, 경제는 도시·공용 시설 등 지정 구역 보호와 일반 지역 자유도 확대를 적용합니다. 양쪽 주요 자원 수급은 전용 채집 인던 중심이며 건축 지형 변경과 채집 정책을 구분합니다. 채집 리셋 정책은 ADR-0011로 확정했고 경제 배치·실행 기술·세부 콘텐츠는 미정입니다. 기존 지형/건축 업데이트는 충돌 검사/보존 우선이며 도구는 S4 대상입니다. 결정 원문은 [ADR-0002](docs/decisions/0002-stack-and-world-policies.md)를 따릅니다.

기존 Docker, Zabbix, Cloudflare 환경은 변경하지 않습니다. 향후 운영 변경은 기존 구성 확인, 변경 계획과 롤백 계획 수립, 필요한 명시적 승인을 거쳐 진행합니다. 비밀 정보와 실제 플레이어 데이터는 Git에 넣지 않습니다.

공동체·개인 퀘스트, 고정 분기와 장별 따라잡기/스킵의 확정 정책은 [ADR-0004](docs/decisions/0004-community-quests-and-chapter-skip.md)를 따릅니다. 중요 퀘스트는 당시 접속한 공동체 구성원 전원의 조건 충족이 필요하며 비접속자는 제외합니다. 개인 완료·보상은 구분하고, 따라잡기·스킵은 공유 분기·NPC·월드 상태를 변경하지 않습니다. 신규 접속 시 현재 단계는 중단하지 않고 다음 중요 단계에서 전원 조건을 재검사하며, 분기는 전체 대상의 50% 초과 투표로 선택합니다. 보상·단계 경합·과거 재현 세부는 보류/미정이며 투표는 ADR-0011의 채팅 정책을 따릅니다. 가입 기능은 없습니다.

2026-10-25 통합 정책과 설계 완료 근거는 [S3 최종 감사](docs/s3-completion-audit.md)를 따릅니다. 가입 없는 내부 진행 연결, 지도/메뉴/HUD(ADR-0010), 채팅 투표/정확한 보스 복귀/관전/채집 리셋(ADR-0011), 저장/월드/버전 보존(ADR-0012)을 반영했습니다. C1은 온라인 보스 시작 명단·온라인 사망자 자동 부활·기존 참가자 복귀 권리로 후속 확정했습니다(ADR-0013). 필수 12영역 명세를 재감사하여 S3 설계 완료이며 S4-1 최소 플러그인·파일 시험을 구현했습니다. [S4-1 기록](docs/s4-1-verification.md)의 EULA 동의 후 Paper/Hearth/WG/WE 로딩, 합성 A/B 월드·블록 보존·WG 구역 API smoke는 통과했습니다. 실제 플레이어 이벤트·전체 기능/부하 시험은 남습니다. 추천값·의도적 보류·구현/실행 미검증은 그대로 구분합니다.
