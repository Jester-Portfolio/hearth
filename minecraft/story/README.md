# 스토리 월드

현대인이 마법 없는 현실적인 중세 세계에 등장해 현대의 과학·기술 지식을 활용하는 것이 핵심 콘셉트입니다. 싱글 플레이 또는 소규모 협동으로 이야기를 경험하며 NPC, 퀘스트와 세계 진행을 설계합니다.

[ADR-0001](../../docs/decisions/0001-story-world-multiworld.md)에 따라 B안을 채택했습니다. 하나의 Paper 서버 프로세스에서 싱글 플레이어는 자신만의 독립 진행과 월드를 가지며, 코옵 파티는 하나의 진행과 월드를 공유합니다. 퀘스트·NPC·월드 변화·플레이어 상태는 진행별로 격리합니다.

버전별로 관리하고 지속 추가하는 사전 제작 공간 템플릿을 복제해 월드를 생성하며 기존 플레이어 월드·진행은 유지합니다. 비활성 월드는 저장 후 언로드하고 재접속 시 복원합니다. 논리 진행 ID와 물리 서버·월드 배치를 분리해 향후 진행별 서버 분리(A안) 가능성을 유지합니다. 파티 구성 변경 정책, 저장·언로드·재접속 처리와 격리의 구체 구현은 미정·미검증입니다.

게임 내 AI 스마트폰 어시스턴트는 필수 기능이며, 공통 로컬 AI 서비스를 사용하되 진행별 정보 접근을 격리합니다. 퀘스트, NPC, 게임 내 정보를 바탕으로 플레이어의 질문에 답하도록 계획합니다. AI 모델·런타임, 정보 제공·연동 방식과 접근 권한은 미정입니다.

진행도와 플레이어 상태는 경제 월드와 논리적으로 분리합니다. 공통 기반 기능은 재사용할 수 있지만 진행 데이터와 경제 데이터는 분리합니다. 시나리오, 협동 인원과 세부 진행 규칙은 미정입니다. 구현 기반은 Paper 26.2·Java 25·Gradle·PostgreSQL로 확정했습니다. 실제 월드 데이터나 서버 실행 파일은 포함하지 않습니다. [구조 비교](../../docs/story-world-architecture.md)와 [구현 가능성 검토](../../docs/story-world-feasibility.md)는 채택 근거와 남은 검증 항목을 정리합니다.

[ADR-0002](../../docs/decisions/0002-stack-and-world-policies.md)에 따라 지형·건축물 템플릿과 NPC 배치·대화·퀘스트 콘텐츠 정의를 분리합니다. 플레이어별 진행, 퀘스트·NPC 관계·스토리 분기 상태는 PostgreSQL에서 월드별로 격리합니다. 스토리·경제 인벤토리와 진행도 분리합니다. 기존 월드에 신규 지형·건축물을 적용하는 방식은 미정입니다.

전체 월드 보호가 기본이며 지정 구역에서만 건축·지형 변경을 허용합니다. 자원 수급은 별도 인던형 채집 구역 중심이고 건축 지형 변경과 채집 정책을 구분합니다. 인던 생성·초기화·재생성 방식은 미정입니다.
