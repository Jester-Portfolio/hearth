# 스토리 월드

현대인이 마법 없는 현실적인 중세 세계에 등장해 현대의 과학·기술 지식을 활용하는 것이 핵심 콘셉트입니다. 싱글 플레이 또는 소규모 협동으로 이야기를 경험하며 NPC, 퀘스트와 세계 진행을 설계합니다.

[ADR-0001](../../docs/decisions/0001-story-world-multiworld.md)에 따라 B안을 채택했습니다. 하나의 Paper 서버 프로세스에서 싱글 플레이어는 자신만의 독립 진행과 월드를 가지며, 코옵 공동체는 하나의 진행과 월드를 공유합니다. 퀘스트·NPC·월드 변화·플레이어 상태는 진행별로 격리합니다.

버전별로 관리하고 지속 추가하는 사전 제작 공간 템플릿을 복제해 월드를 생성하며 기존 플레이어 월드·진행은 유지합니다. 비활성 월드는 저장 후 언로드하고 재접속 시 복원합니다. 논리 진행 ID와 물리 서버·월드 배치를 분리해 향후 진행별 서버 분리(A안) 가능성을 유지합니다. 내부 플레이어–진행 식별 연결, 저장·언로드·재접속 처리와 격리의 구체 구현은 미정·미검증입니다.

게임 내 AI 스마트폰 어시스턴트는 필수 기능이며, 공통 로컬 AI 서비스를 사용하되 진행별 정보 접근을 격리합니다. 퀘스트, NPC, 게임 내 정보를 바탕으로 플레이어의 질문에 답하도록 계획합니다. AI 모델·런타임, 정보 제공·연동 방식과 접근 권한은 미정입니다.

진행도와 플레이어 상태는 경제 월드와 논리적으로 분리합니다. 공통 기반 기능은 재사용할 수 있지만 진행 데이터와 경제 데이터는 분리합니다. 시나리오, 협동 인원과 세부 진행 규칙은 미정입니다. 구현 기반은 Paper 26.2·Java 25·Gradle·PostgreSQL로 확정했습니다. 실제 월드 데이터나 서버 실행 파일은 포함하지 않습니다. [구조 비교](../../docs/story-world-architecture.md)와 [구현 가능성 검토](../../docs/story-world-feasibility.md)는 채택 근거와 남은 검증 항목을 정리합니다.

[ADR-0002](../../docs/decisions/0002-stack-and-world-policies.md)에 따라 지형·건축물 템플릿과 NPC 배치·대화·퀘스트 콘텐츠 정의를 분리합니다. 플레이어별 진행, 퀘스트·NPC 관계·스토리 분기 상태는 PostgreSQL에서 월드별로 격리합니다. 스토리·경제 인벤토리와 진행도 분리합니다. 기존 월드에 신규 지형·건축물을 적용하는 방식은 미정입니다.

전체 월드 보호가 기본이며 지정 구역에서만 건축·지형 변경을 허용합니다. 자원 수급은 별도 인던형 채집 구역 중심이고 건축 지형 변경과 채집 정책을 구분합니다. 채집 리셋은 정기 시각 또는 전원 퇴장 뒤 다음 입장(ADR-0011)이며 생성 기술/소유 단위는 미정입니다.

공동체·개인 퀘스트, 고정 분기와 장별 따라잡기/스킵의 확정 정책은 [ADR-0004](../../docs/decisions/0004-community-quests-and-chapter-skip.md)를 따릅니다. 중요 퀘스트는 당시 접속한 공동체 구성원 전원의 조건 충족이 필요하며 비접속자는 제외합니다. 개인 완료·보상은 구분하고, 따라잡기·스킵은 공유 분기·NPC·월드 상태를 변경하지 않습니다. 신규 접속 시 현재 단계는 중단하지 않고 다음 중요 단계에서 전원 조건을 재검사하며, 분기는 전체 대상의 50% 초과 투표로 선택합니다. 보상·단계 경합·과거 재현 세부는 보류/미정이며 투표는 ADR-0011의 채팅 정책을 따릅니다. 가입 기능은 없습니다.

2026-10-25 통합 정책과 미완료 조건은 [S3 감사](../../docs/s3-completion-audit.md)를 따릅니다. 가입 없는 내부 진행 연결, 지도/메뉴/HUD(ADR-0010), 채팅 투표/정확한 보스 복귀/관전/채집 리셋(ADR-0011), 저장/월드/버전 보존(ADR-0012)을 반영했습니다. 추천값·구현 기술은 사용자 확정 정책과 구분하며 S3는 진행 중입니다.
