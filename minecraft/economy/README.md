# 경제 월드

스토리 월드를 기반으로 확장하는 경제 중심 멀티플레이 환경입니다. 마법 없는 현실적인 중세 기술을 바탕으로 여러 플레이어가 활동하며, 생산, 재고, 공급·수요, 시장가격, 거래 및 무역과 자원 순환을 주요 요소로 설계합니다.

AI 스마트폰 어시스턴트는 선택 기능이며 제거할 수 있도록 설계합니다. 경제 월드의 핵심 기능은 AI 없이도 동작하도록 계획합니다.

공통 기반 기능은 재사용할 수 있지만 플레이어 상태, 진행 데이터와 경제 데이터는 스토리 월드와 논리적으로 분리합니다. 스토리 월드를 기반으로 확장한다는 방향이 실제 진행도나 경제 데이터의 공유를 뜻하지는 않으며, 월드 간 데이터 공유나 이전 규칙은 미정입니다. 화폐, 거래 방식, 가격 결정 방식과 세부 경제 시스템은 미정입니다. 기술 기반은 [ADR-0002](../../docs/decisions/0002-stack-and-world-policies.md)를 따르며 경제 서버 프로세스 분리 여부는 미정입니다. 실제 월드 데이터나 서버 실행 파일은 포함하지 않습니다.

스토리와 경제의 인벤토리·진행 상태는 분리합니다. 주요 도시·공용 시설 등 지정 구역만 보호하고 일반 지역의 건축·지형 변경 자유도를 높입니다. 주요 자원 수급은 스토리와 동일하게 전용 채집 인던 중심이며 건축 목적의 지형 변경과 자원 채집은 별개 정책입니다. 인던 생성·초기화·재생성 방식은 미정입니다.

## 격리 개발 프로토타입

[ADR-0015](../../docs/decisions/0015-economy-engine-and-transaction-boundaries.md)의 Java 내부 계산·경제 전용 SQL·Paper 적용 구조를 구현했다. 기존 문단의 미정 사항은 **운영 정책**을 의미하며 이번 개발 설정을 최종 정책으로 바꾸지 않는다.

철광석 생산 → 출발 재고 예약 → 3 모의 Tick 후 수도 도착 → 광석을 소모하는 제련 → 철괴 소비·상인 구매/판매가 연결된다. 생산 효율·수요·무역로 사건은 콘텐츠에서 정하며 AI 없이 동작한다. `src/main/resources/economy-demo.properties`의 가격·화폐·초기 자산·시간은 모두 개발 임시값이다.

`EconomyEngine`은 순수 계산, `EconomyStore`는 기존 제한 DB worker와 경제 스키마, `EconomyTrade`는 기존 최신 인벤토리 저장 장벽, `PaperEconomy`는 NPC·54슬롯 상점·기존 세션/월드 수명주기를 담당한다. NPC 상점은 선택한 지역의 상품 수량을 조절한 뒤 견적 확인 화면에서 구매·판매를 확정한다. 기본 공개 fixture는 철괴·철광석이며 `merchant-goods`와 상품 이름을 설정한다(기존 `merchant-good` 호환). 일반 36슬롯 안의 기본 아이템만 거래하며 방어구·보조 손·커스텀 메타데이터를 기본 상품으로 소모하지 않는다. 컨테이너·커서는 기존 격리 세션 제한을 유지한다.

자동 실행은 [기존 시험 도구](../../scripts/README.md)의 새 `--sessions --economy` 경로를 사용한다. 신규 사용자 소유 격리 루트/DB만 허용하며 두 JVM·600초·기존 CPU/RAM/포트 한도를 그대로 적용한다. 이번 자동 시험은 실제 플레이어 접속이 아니다. 결과·측정·미검증 범위는 [경제 검증 기록](../../docs/economy-verification.md) 한곳에 기록한다.

후속 수동 시험은 별도 사용자 요청 이후에만 진행한다. 실행 중인 **경제 전용 격리 환경**에서 콘솔 `hearthverify economy-fixture <프로필>`로 명시적으로 계정을 준비하거나 `economy-link-existing`으로 기존 계정만 연결한다. 인증된 UUID 확인 뒤 기존 세션 복원 경로를 사용한다. 자동 시험의 HOLD 계정과 실제 프로필을 공유하지 않는다. 이 명령은 일반 계정 생성 정책·운영 배포 수단이 아니다.

다품목 목록/상세·본인 거래 기록과 콘솔의 영수증 확인/오프라인 HOLD 정리를 추가했다. 기록은 소유 계정별 revision 순서로 조회하며, 복구는 거래 재실행이나 DB 덮어쓰기를 하지 않는다. 명령·정확한 전제·최신 검사 결과는 [상점/관리 검증](../../docs/economy-desk-verification.md)에 둔다. 최소 자동 검사는 기존 도구의 `--sessions --economy --economy-desk` 한 JVM 경로다.

## 공개 시장·운송·사건 정보

상점의 `시장 상황`에서 재고/목표·품목/시장 기준가·1개 구매/판매가·수요 설정, 지역 선택, 운송 중 물량/도착까지의 경제 Tick, 사건 적용 대기/적용 중 상태, 생산 상한/현재 재료 재고를 조회한다. 화면의 수량은 실제 저장 상태이며 생산 상한은 실제 생산 실적과 구분한다. 운송로 차단은 기존 엔진처럼 신규 출발에 적용하고 이미 출발한 물량은 도착 처리를 유지한다.

`report-regions`, `report-goods`, `report-routes`, `report-facilities`, `report-events`와 이름/사건 설명·공개 지역을 콘텐츠에 지정한다. 기본값은 상점 지역/상품이며 미등록 시설·운송로·사건은 공개하지 않는다. 기존 설정 파일을 자동 덮어쓰거나 hot reload하지 않는다.

`EconomyReport`는 계정/인벤토리/물리 월드 식별자가 없는 공개 DTO를 만든다. 상점의 탭·페이지는 같은 조회 결과를 재사용하고 새로고침에서만 DB를 읽는다. 다른 지역 화면은 참고 조회이며 실제 거래는 상점의 최신 견적을 다시 읽는다. 새로운 저장 스키마·가격 규칙·화폐/운송비 정책을 추가하지 않았다. [최신 검증](../../docs/economy-report-verification.md)과 `--sessions --economy --economy-report` 한 JVM 도구를 따른다.

## 복수 지역 상인

`merchants` 목록과 `merchant.<id>.name/region/goods/x/y/z`로 상인의 ID·지역·취급 상품·위치를 각각 정의한다. 기존 `merchant-*` 단일 설정은 `legacy_merchant`로 읽는다. 새 공개 fixture는 수도 상인과 광산 상인을 같은 격리 플랫폼의 서로 다른 위치에 배치한다. 이 배치는 실제 운영 지리나 이동 수단을 확정하지 않는다. 기존 콘텐츠 파일·실제 월드를 자동 덮어쓰지 않는다.

NPC 우클릭으로 고른 상인의 지역 재고/가격으로만 거래한다. 화면·비동기 조회는 상인 ID·엔티티 UUID·월드 세대·현재 선택에 연결하며 다른 상인으로 전환하면 이전 결과를 적용하지 않는다. 인벤토리/잔액은 기존 경제 realm 계정을 사용하고 지역별로 복제하지 않는다. 기록에는 실제 거래 지역을 보존한다.

월드 준비 시 정의당 NPC를 한 번 생성하고 언로드 전에 참조/화면을 정리한다. 상인이 있는 청크만 미리 인덱싱하며 관련 청크 로드 후 1틱 지연과 세대 확인을 거쳐 필요한 NPC만 확인한다. [검증과 미실행 범위](../../docs/economy-merchants-verification.md), 최소 도구 `--sessions --economy --economy-merchants`를 따른다.

## 거래 수량과 확인

상품에서 ±1/8/64개 조절 또는 최대 가능 수량을 선택하고 구매/판매 견적을 확인한다. 확인 화면은 수량·총액·예상 잔액을 표시하며 별도 확정 버튼에서만 기존 거래를 실행한다. 수량 변경은 DB에 저장하지 않는다. 시장/잔액/공간이 달라졌다면 확정 시 거부할 수 있고, 시세 변경 뒤에는 최신 견적을 다시 확인한다. 거래 완료 화면은 실제 영수증의 금액·잔액을 사용한다.

기존 1~4096 기술 한도와 36슬롯의 일반 아이템 거래 범위를 유지한다. 최종 운영 화폐/밸런스/거래 한도는 미정이다. [실제 검증·미검증](../../docs/economy-quote-verification.md), 최소 자동 도구 `--sessions --economy --economy-quote`를 따른다.

## 최근 경제 Tick 실적·제조 진단·사건 적용

시장 화면은 현재 재고/설정 수요와 **최근 완료 Tick**의 실제 생산·제조 투입·소비·미충족 수요·운송 도착/출발·전후 재고를 구분한다. 플레이어 거래 후 현재 재고는 최근 Tick 종료 재고와 다를 수 있다. 시설 화면의 상한/현재 재고 단독 계산은 참고값이며, 다음 Tick의 도착 물량·시설 실행 순서까지 예측한 실적이 아니다.

생산량/효율·레시피·지역 수요·운송량/지연과 사건 factor/duration은 기존 `economy-demo.properties`에서 정의한다. 기존 콘텐츠는 자동 덮어쓰지 않으며 시작할 때만 읽는다. 시뮬레이션 정의가 달라지면 기존 content hash 검사를 유지하며 운영 데이터를 자동 이관/초기화하지 않는다.

격리 경제 모드의 서버 콘솔만 `hearthverify economy-event <event_id> <request_uuid>`를 실행할 수 있다. 등록된 사건을 다음 경제 Tick부터 예약한다. 같은 ID의 동일 요청은 중복 예약하지 않으며 다른 사건으로 재사용하면 거부한다. DB 결과가 불명확하면 새로운 요청으로 반복하지 말고 기존 요청을 확인한다. 새로운 요청 ID는 별개 사건이므로 효과가 중첩될 수 있으며 자동 생성/재시도하지 않는다. 화폐·밸런스·운영 명령 승인을 대신하지 않는다.

E003은 E001/E002 파일·기존 계정/시장/영수증을 보존하고 최근 실적만 추가한다. 미등록 실적은 미등록으로 표시하며 기록 이후 일부/전체 누락·Tick 불일치는 오류로 거부한다. 시장·운송·실적·Tick은 기존 한 트랜잭션에서 저장한다. 누적 이력·새 아이템 원장·클릭별 저장은 만들지 않는다. [검증·미실행](../../docs/economy-flow-verification.md), 두 JVM 도구 `--sessions --economy --economy-flows`를 따른다.

## 상품 공급망과 공개 플레이 안내

상점의 `상품 공급망` 또는 상품 화면의 `이 상품 공급망`에서 공개 지역 시장·취급 상인과 위치·생산시설·재료 사용처·운송로를 함께 확인한다. 동일 운송로는 한 번만 표시한다. 등록된 공개 정보만 사용하며 미등록 생산시설/운송로/지역은 표시하지 않는다. 지역 참고 정보를 눌러도 현재 상인의 거래 지역을 바꾸지 않는다. 다른 지역 상인에게 거래하려면 직접 방문해야 한다.

`경제 플레이 안내`는 `guide-steps`와 `guide-step.<id>.kind/region/reference/title/text`의 순서대로 표시한다. kind는 `MARKET`, `PRODUCER`, `USE`, `ROUTE`이며 참조는 해당 상인의 공개 범위에 존재해야 한다. 제목/문구는 공개 합성 콘텐츠다. 기존 파일에 안내 정의가 없으면 미등록으로 표시하고 자동 추가하지 않는다. 안내 메타데이터는 시뮬레이션 content hash와 기존 계정/기록을 변경하지 않는다.

이 안내는 읽기 전용이다. 개인 퀘스트 완료·보상·자동 순간이동·개인 물품 운송·직접 제조를 실행하지 않는다. 현재 가격/재고와 자동 경제 Tick을 설명하며 수익을 보장하지 않는다. 기존 구매/판매는 별도 최신 견적 확인/확정 경로를 사용한다.

같은 상품의 공급망/안내/상품 선택/페이지는 현재 조회를 재사용하고 새로고침이나 다른 상품 선택 시에만 새 상태를 읽는다. 세션/상인/엔티티/거리/세대 검사를 유지한다. [검증·미실행](../../docs/economy-supply-verification.md), 최소 도구 `--sessions --economy --economy-supply`를 따른다. 신규 스키마·가격 규칙·운영 활성화는 없다.
