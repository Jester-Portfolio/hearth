# 정지 백업·복원과 수동 대응

도구: [`scripts/offline_backup.py`](../../scripts/offline_backup.py). 근거: [ADR-0003](../../docs/decisions/0003-inventory-performance-and-recovery.md). 서비스 중단·설정 변경·기존 데이터 복원은 별도 명시 승인이 필요하다. 이 문서는 운영 적용 명령을 자동 실행하지 않는다.

## 지원 범위

정상 종료한 **Paper 전체 디렉터리**와 **PostgreSQL 전용 클러스터 전체 디렉터리**를 한 백업으로 보존한다. 외부 템플릿/등록 설정이 있으면 `assets`로 함께 포함한다. Paper 트리에는 모든 스토리/경제 월드, 일반 상자, WorldGuard/WorldEdit 설정, Hearth 진행/물리 월드 매핑·콘텐츠/표식, 플러그인 JAR·서버 설정이 들어가야 한다. 다른 경로에 둔 데이터가 빠지지 않았는지는 적용 전 운영자가 확인한다.

공유 PG 클러스터의 일부 DB만 물리 복사하거나 실행 중 클러스터를 복사하는 용도가 아니다. 공유 DB 환경은 서비스 영향과 논리 백업 방식을 별도로 설계해야 한다. 외부 tablespace/symlink·다른 소유자/하드링크·특수 파일은 거부한다. PostgreSQL 주 버전·빌드/확장·아키텍처 호환성이 있는 복원 환경을 준비해야 한다. 이 도구는 `pg_upgrade`, PITR, 온라인 원자 체크포인트나 자동 무손실 복구를 제공하지 않는다.

## 적용 전에 준비할 것

운영 대상·담당자·점검 시간·롤백 위치를 확정하고 중단 승인을 받는다. 접속/다른 DB 작성자를 차단하고 정상 저장·종료와 오류/HOLD를 확인한 뒤 PG를 정상 종료한다. 프로세스가 강제 종료된 경우 정상 백업이라고 확인하지 않는다. 원본과 복원본을 동시에 플레이에 열지 않는다.

개인 정보·DB 역할/인증 자료·서버 설정이 포함되므로 백업/복원 부모 경로는 소유자 전용 0700을 사용한다. 별도 볼륨/외부 보관의 접근·암호화 정책과 실제 복구 시간/손실 허용치(RTO/RPO), 주기/보존/용량 알림은 운영 결정으로 남는다. 저장소에 실제 백업·원본 설정·비밀번호를 커밋하지 않는다.

## 생성·확인

명령은 실제 경로가 확정된 점검에서만 실행한다. `PAPER_DIR`, `PGDATA_DIR`, `BUNDLE_DIR`은 운영자가 정한 절대 경로이며 백업 출력은 존재하지 않는 새 경로여야 한다.

```bash
python3 scripts/offline_backup.py create \
  --paper "$PAPER_DIR" --postgres "$PGDATA_DIR" \
  --destination "$BUNDLE_DIR" --offline-confirmed
```

외부 자료가 있으면 `--assets "$ASSETS_DIR"`을 추가한다. 출력의 `manifest_sha256`을 백업 밖의 접근 제한 기록에 보관한다. 확인할 때는 그 기록의 해시를 사용한다.

```bash
python3 scripts/offline_backup.py verify \
  --bundle "$BUNDLE_DIR" --manifest-sha256 "$MANIFEST_SHA256"
```

`--offline-confirmed`는 정상 종료와 모든 작성자의 중단을 확인했다는 운영자 진술이다. 도구는 남은 `postmaster.pid`·획득할 수 없는 월드 `session.lock`, 파일 추가/삭제·복사 중 변경, symlink/하드링크·해시/구성 불일치를 추가로 거부한다. 이 검사만으로 원격 작성자나 임의 외부 프로세스의 부재를 증명하지 않는다.

기본 상한은 100,000개 항목·12GiB·각 작업 90초다. 공간/시간이 부족하면 실패 원본을 남기며 자동으로 확대·삭제·재시도하지 않는다. 실패 디렉터리를 다음 성공 출력으로 재사용하지 않는다. `manifest.json`은 생성 완료 표식이며 신뢰한 외부 해시로 전체 파일·크기·모드·누락/추가를 확인해야 한다. 해시 자체는 서명이나 출처 인증이 아니다.

## 새 경로의 복원·롤백 준비

```bash
python3 scripts/offline_backup.py restore \
  --bundle "$BUNDLE_DIR" --manifest-sha256 "$MANIFEST_SHA256" \
  --destination "$RESTORE_DIR"
```

기존 디렉터리는 빈 디렉터리도 덮어쓰지 않는다. 복원은 새 경로의 `paper/`, `postgres/`, 선택한 `assets/`를 만들며 원본 백업을 변경하거나 서비스를 기동하지 않는다. 실패 시 부분 출력은 남고 `restore-receipt.json`이 없으므로 적용하지 않는다. 완료 영수증과 전체 해시를 확인한 뒤에도 다음 점검이 필요하다.

1. 격리 네트워크/새 localhost 포트에서 복사 PG를 먼저 확인한다. 원본 PG·운영 연결로 착각하지 않도록 실제 `data_directory`를 확인하고 스키마 버전·진행/개인/경제/영수증 상태를 비교한다.
2. Paper/플러그인/Java·PG 버전과 템플릿/팩·보호 규칙을 확인한다. 절대 경로·DB 접속·포트·공개 접속 경로는 복원 위치에 맞춘 검토 대상이며 도구가 자동 재작성하지 않는다. 원본 인증·권한 경계는 유지한다.
3. 운영 전환 승인을 받기 전까지 복사본을 공개하지 않는다. 승인된 전환은 기존 원본 전체를 보존하고 서비스 경로를 바꾸는 방식으로 준비한다. 롤백도 Paper와 PG의 같은 백업 묶음을 사용한다. 한쪽만 되돌리지 않는다.
4. 실패/불명 결과는 HOLD로 보존한다. 새 JAR에 맞춰 DB가 마이그레이션된 뒤 옛 JAR만 되돌리는 롤백은 하지 않는다. DB까지 되돌려야 하는지 호환성과 손실 범위를 검토한다.

백업 이후 플레이를 재개하면 백업의 시점 이후 변경은 이 복원본에 없다. 장애 시 최근 인벤토리/상자의 차이는 자동으로 재구성할 수 없으며 수동 판단 대상이다.

## 장애 대응

- 저장 실패·commit 불명·stale/세대 오류: 해당 범위의 조작/전환을 보류하고 로그 시각·오류 코드·접속/진행 범위를 보존한다. 최신 revision과 DB/런타임 상태를 읽기 전용 진단으로 비교한다. 같은 거래/보상 재확정·HOLD 일괄 해제·빈 상태 초기화를 하지 않는다.
- 인벤토리/보상·경제 잔액 불일치: 본인/진행/경제 소유권과 저장 영수증을 확인한다. 일반 월드 상자의 저장 시점과 DB 시점 차이를 고려하고 지급/회수·데이터 보정은 근거와 별도 승인 후 수행한다.
- 활성 전투/이동 불명: 확정된 종료·복귀 대기는 기존 원장으로 복원하고 활성 전투는 HOLD한다. 전투를 임의 재소환하거나 원장을 지워 중복 보상을 만들지 않는다.
- 복구 실패: 원본·백업·부분 복사본·최초 오류를 보존하고 기존 공개 서비스를 다시 열지 않는다. 실패한 복사본을 원본으로 덮어쓰지 않는다.

검증 근거와 미실행 범위는 [오프라인 백업 검증](../../docs/offline-backup-verification.md)을 따른다. 운영 적용·정기 스케줄/삭제·외부 저장·기존 Zabbix 변경은 아직 수행하지 않았다.
