# 경제 직접 플레이어 거래

경제 전용 실행의 기존 인증 세션·PG 잔액·등록 상품·41슬롯 저장을 사용한다. 스토리↔경제 이전이나 운영 적용 절차가 아니다. 화폐 생성·세금·수수료·신용/대출·오프라인 거래·escrow는 추가하지 않는다.

## 플레이 흐름

같은 경제 월드에서 6블록 이내의 활성 참가자에게 `/hearthtrade request <이름>`으로 요청한다. 상대가 `/hearthtrade accept`를 실행해야 제안 화면을 연다. 한 사람은 한 요청/거래만 참여한다. 요청부터 3분 후 만료하며 이동·사망·연결 교체/종료는 제안을 취소한다. 아직 확정 요청을 제출하지 않았다면 아이템과 화폐가 이동하지 않는다.

화면의 왼쪽은 본인, 오른쪽은 상대 제안이다. 본인 상품은 좌/우클릭으로 수량을 1개, Shift 클릭으로 16개씩 변경한다. 화폐 버튼은 ±1/±10이며 `/hearthtrade item <품목 ID> <수량>`과 `money <금액>`으로 직접 지정할 수도 있다. 수량 0은 해당 상품 제안을 제거한다. 등록 상품은 페이지로 모두 조회한다. ESC로 화면을 닫아도 제안은 만료/명시적 취소 전까지 유지하며 `/hearthtrade show`로 다시 연다. 취소 버튼 또는 `/hearthtrade cancel`로 취소한다.

기존 등록 상품과 동일한 기본 아이템만 거래한다. 커스텀 이름/NBT가 다른 아이템은 같은 재료라도 대신 빼지 않는다. 보관 36슬롯에서 보내는 상품을 제거한 뒤 받는 상품을 합친다. 방어구/보조 손·개인 스마트폰 같은 별도 바인딩 아이템이나 임의 품목을 전송하는 기능이 아니다. 상품당 최대 4096개·최대 64종이며 실제 보관 공간/소지량은 최종 저장 시 재확인한다.

양쪽이 같은 최종 제안 revision을 확인해야 실행한다. 실제 제안이 바뀌면 양쪽 승인을 취소하고 새 화면을 생성한다. 이전 화면/다른 사람의 클릭·숫자키·드래그로 거래 아이템을 가져갈 수 없다. 빈 거래는 확정하지 않는다. 제안은 값이며 사전에 GUI 슬롯으로 아이템을 빼서 보관하지 않는다.

## 저장·실패 경계

양쪽의 최신 dirty 저장을 기존 세션 트랜잭션 순서로 정리하고 각 인벤토리를 동결한다. 기존 realm 잠금 아래 두 계정의 인벤토리 revision/payload·잔액과 양쪽 유효 세대를 재검사한다. 두 계정의 물품·화폐와 고유 영수증은 하나의 PostgreSQL 트랜잭션이다. 먼저 보내는 금액을 소지해야 하며 상대가 보낼 예정인 금액을 미리 빌려 쓰지 않는다. 잔액 정수 overflow도 거부한다. NPC 거래·일반 저장은 같은 account revision/CAS를 사용한다.

상품 부족/공간 부족/자금 부족처럼 확정 전 거부가 확인되면 제안을 종료하고 새로운 확인을 받는다. 제안 취소로 제출 전에 거부한 경우도 저장 성공으로 처리하지 않는다. SQL 실패·CAS·commit 불명·지연/부분 적용은 양쪽 HOLD와 원본/요청 정보를 보존한다. 같은 요청을 자동 제출하거나 재차감/재지급하지 않는다. 계정·영수증의 PG 확정과 실제 클라이언트 적용은 원자적이지 않으며 수동 검토 대상이다.

E004는 기존 E001~E003 파일/계정/시장/스토리 스키마를 보존하고 직접 거래 영수증과 조회 인덱스를 추가한다. 같은 요청 ID·제안의 재전달은 기존 결과를 읽으며, 같은 ID의 다른 제안/참가자는 거부한다. 오래된 요청을 새 거래로 다시 확정하지 않는다.

`/hearthtrade receipt <요청 UUID>`는 본인이 참가한 확정 영수증을 읽는다. HOLD로 행동이 막혔다면 콘솔 `heartheconomy peer-pending <player UUID>`와 `peer-receipt <player UUID> <request UUID>`로 요청/확정 영수증을 확인한다. 보류 시 서버 로그에도 요청/참가자 식별을 남긴다. 영수증 부재만으로 rollback을 확정하거나 HOLD를 풀지 않는다. 행 수정·임의 해제/재지급 명령은 없다.

저장 종료는 열린 제안을 취소하고 진행 중 확정을 기다린다. 불명/HOLD는 깨끗한 종료로 덮어쓰지 않는다. 실제 클릭·두 정품 계정·패킷/거리/연결 조합의 수용 시험과 운영 배포는 별도다. [자동 검증 기록](../../docs/economy-peer-trade-verification.md)을 따른다.
