# 경제 채집 연결

선택형 정상 경제 실행에서 기존 채집 인던·현장 시설·초기화 경계를 사용한다. 기존 월드·운영 설정에 콘텐츠를 자동 설치하지 않는다. 실제 좌표·자원 종류·주기·수급/가격 밸런스는 검토할 콘텐츠다.

## 정의

경제의 기존 `content-file` properties에 `gathering-file=<검토한 파일명>.yml`, `gathering-sha256=<해당 UTF-8 파일의 SHA-256>`을 함께 지정한다. 파일은 Hearth 데이터 폴더 바로 아래의 일반 파일이며 최대 1MiB다. 누락/해시 불일치·경로 이동·symlink를 거부한다. [형식 예시](gathering.example.yml)는 의도적으로 검토 값이 필요하며 그대로 실행할 수 없다.

YAML 최상위 `format: 1`, `gathering`, `facilities`를 사용한다. 두 하위 항목은 기존 `GatheringContent`·`GatheringFacilities` 형식이다. 현재 한 realm에 한 전용 구역이며 최대 4096블록·지원 재료/비컨테이너 제한·구역 밖 입구·구역 밖 현장 입퇴장 시설·시설 거리와 이동의 안전 검사를 유지한다. 기존 형식의 prototype 표식은 파서 버전 계약이고 실제 활성화는 정상 실행과 검토한 정의로 결정한다. 정상 서버 진입 위치를 초기화 영역 안에 두지 않는다.

파일을 지정하지 않으면 새 채집 콘텐츠를 만들지 않는다. PG에 저장된 채집이 있다면 같은 ID의 설정이 있어야 하며, 누락/이름 변경을 조용한 비활성화로 처리하지 않고 HOLD한다. 기존 구역/템플릿/보호나 미확인 블록을 새 설정으로 덮어쓰지 않는다.

## 동선·저장

첫 월드 준비에서 경제 소유 메타데이터를 읽고, 없는 행만 명시적으로 만든다. 개인/스토리 계정을 만들지 않는다. 현재/세대가 맞는 현장 시설에서 상태를 확인하고 입퇴장을 재확인한다. 필요하면 `/hearthgather info`, `enter`, `leave`의 기존 경계를 사용한다. 실제 시설 블록은 준비 월드에 있어야 하며 이 기능이 대신 설치하지 않는다.

첫 입장/재입장·주기 초기화는 기존 저장→퇴거→한정 영역 원본 기록→새 자원 적용/월드·WorldGuard 저장→세대 확정 경계를 사용한다. 빈 구역 최초 준비도 알 수 없는 기존 블록을 지우지 않는다. 초기화가 개인 인벤토리/잔액이나 소비품을 rollback하거나 자원을 직접 지급하지 않는다. 플레이어가 얻은 등록 상품은 기존 경제 인벤토리에 남고 NPC/직접 거래 흐름을 사용한다.

E005의 `hearth_economy.gathering_instance`는 `realm_id`에만 소유 FK를 둔다. 스토리 `hearth_progress.gathering_instance`와 같은 UUID/채집 ID도 분리된다. 일반 저장·초기화는 기존 제한 worker/풀과 CAS를 사용하며 아이템별 SQL을 추가하지 않는다. 초기화 증거는 `plugins/Hearth/economy-gathering/<realm>_<id>`에 보존하고 스토리 `gathering` 폴더와 섞지 않는다. 기존 symlink/파일·pending 표식은 채택하거나 삭제하지 않는다.

정상 실행의 타이머는 월드의 READY/ACTIVE/IDLE에서만 진행한다. 저장/언로드 장벽은 진행 중 초기화·입퇴장을 기다리고 바인딩/청크 참조를 해제한다. SQL·원본/매핑·초기화 실패는 HOLD/증거를 보존하며 자동 수리하지 않는다. 실제 플레이·자원 드롭·경제 밸런스·운영 적용은 [검증 범위](../../docs/economy-gathering-verification.md) 밖의 별도 수용이다.
