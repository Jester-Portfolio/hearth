# 스토리 확정 효과와 읽기 전용 복구

기본 비활성 정상 `story` 모드에 연결하며, 운영 서비스나 기존 설정을 적용하는 절차가 아니다. 실제 서사·레벨·보상 수치는 이 문서에서 정의하지 않는다.

## 검토 콘텐츠의 블록 변화

해시로 고정한 기존 통합 콘텐츠에 선택형 `world-effects`를 넣는다. 누락하면 세계 변화나 구역을 만들지 않는다. `format: 1`, `changes`의 각 항목에는 고유 `id`, 기존 공유 `stage`, 정수 `x/y/z`, `expected`, `target`, `regions` 목록을 지정한다. 최대 128개이며 동일 좌표의 여러 단계 치환은 거부한다. 현재 허용 재료는 `AIR`, `STONE`, `STONE_BRICKS`, `COBBLESTONE`, `OAK_PLANKS`, `OAK_LOG`, `GLASS`, `GOLD_BLOCK`, `DIAMOND_BLOCK`, `EMERALD_BLOCK`, `IRON_BLOCK`, `DIRT`, `GRASS_BLOCK`이다. 컨테이너·유체·중력 블록이나 범용 명령 실행은 지원하지 않는다.

각 `regions`는 같은 이름의 WorldGuard 영역과 기존 `shared.regions`의 `ENTRY`/`CONTENT` 제한 구역이어야 한다. 설정의 범위와 실제 보호 영역 모두에 효과 좌표가 포함되어야 한다. 구성된 실제 구역·안전 진입 위치는 준비 월드에 있어야 하며, 새 청크를 생성해 누락을 숨기지 않는다.

PG에 확정된 현재/완료 단계만 적용한다. 동일 run의 불변 연결·물리 UUID/차원 키/경로·로드 세대와 DB 스냅샷을 재확인한다. 예상 블록이면 목표로 치환하고, 이미 목표면 완료로 판단한다. 다른 블록이면 `EFFECT_CONFLICT`와 제한을 보존한다. DB 분기를 취소하거나 재확정·재보상하지 않는다. 지연된 결과·언로드·세대 변경은 쓰기를 차단하고, 비동기 청크 대기와 적용은 제한 시간 안에서만 진행한다.

정상 입장 전에 월드 준비와 효과 수렴을 확인한다. 진행 중 적용 충돌은 관련 스토리 구역을 제한하며 진단에 `WORLD_EFFECT_HOLD`를 표시한다. 저장·언로드 후에는 물리 상태를 다시 확인한다. 효과의 부분 적용은 저장된 분기 rollback으로 복구하지 않으며 관리자 수동 검토 대상이다.

## 콘솔 조회

`hearthrecovery list [page]`, `inspect <run UUID> <player UUID>`, `compare <report UUID>`를 사용한다. 실제 콘솔 전용이며 설정과 PG의 기존 불변 연결·회원이 모두 일치해야 한다. 설정에만 있는 미접속 계정의 개인 행을 만들지 않는다. 조회마다 등록 대상을 다시 확인하며, 회원 제거/연결 변경은 이전 보고서의 비교 권한도 무효화한다.

진단 전용 제한 풀은 스키마 생성/마이그레이션 없이 PostgreSQL 기본 트랜잭션도 읽기 전용으로 연다. 기존 행의 revision·payload 해시와 현재 월드/세션·공유 진행/효과·엔더·컷신·전투 HOLD/대기를 구분한다. 단일 개인 스냅샷의 행·바이트 한도와 10분/16개 보고서 보존은 기존 진단 계약을 따른다. 변경이 생긴 동안의 조회를 동일 상태로 단정하지 않는다.

기존 `story-runtime.active` 때문에 초기화가 HOLD여도 유효한 설정/콘텐츠/DB 연결이 있으면 동일 조회가 가능하다. 접속·월드 초기화·마이그레이션은 계속 차단하며 표식을 지우지 않는다. 설정/콘텐츠 해시 자체가 잘못되거나 DB 연결/스키마가 없으면 조회를 보류한다. 이 명령은 아이템 존재를 확정하거나 지급·행 수정·HOLD 해제·불명 commit 재시도를 하지 않는다.

구현·격리 검사 범위는 [검증 기록](../../docs/story-operations-verification.md)을 따른다. 실제 장애 수용·클라이언트 관측·운영 배포는 별도다.
