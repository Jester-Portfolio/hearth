# 전투 중 이동 제한·TPA

[구현·검증 기록](../../docs/combat-travel-verification.md)을 따른다. `survival` 경제 backend의 선택 기능이며 `survival-economy.enabled: true`와 PG가 필요하다. [설정 블록](combat-travel.yml)은 검토용이고 운영 적용/재시작 승인을 대신하지 않는다. 기본 비활성이다.

활성화 전 `combat-travel.include-pve`를 명시적인 true/false로 결정한다. false면 플레이어 간 유효 피해, true면 플레이어가 참여한 PvE 피해도 포함한다. 이 값의 운영 정책은 아직 미선정이다. 취소되거나 최종 피해가 0인 이벤트는 태그하지 않는다. 플레이어가 쏜 투사체·점화한 TNT·접속 중 소유자의 펫 공격자 귀속을 처리한다. 환경 추락/허기 자체는 공격 판정이 아니다. 실제 개별 엔티티/장비 조합의 행동 수용은 별도 시험이 필요하다.

유효 공격의 공격자/피격자는 마지막 공격 이후 **30초** 동안 일반 teleport·월드/개인 거주 이동·포탈·로비 전환을 사용할 수 없다. 추가 피해는 시간을 늘린다. 사망/로그아웃으로 태그를 지우지 않는다. 전투 중 즉시 공용 스폰 재접속을 이용하지 못하도록 남은 시간 동안 재접속을 보류한다. async 로그인 검사는 메모리만 읽는다. 정당한 리스폰과 권한 회수에 따른 내부 안전 복귀는 예외지만 태그는 남는다. 로그아웃 처벌/자동 사망/아이템 차감 정책을 추가한 것은 아니다.

서버 재시작은 아직 PG에 묶음 저장되지 않은 마지막 피해를 고려해 모듈 시작부터 30초의 이동/재접속 보호 대기를 적용한다. 정상 PG 저장·새 JVM 로드도 병행한다. 기존 native/거주 비정상 종료 HOLD는 유지하며 마커를 지워 우회하지 않는다. 활성 태그가 남은 realm에서 이 기능을 조용히 끄는 시작도 거부한다.

| 명령 | 기능 |
| --- | --- |
| `/tpa <플레이어>` | 같은 경제 Paper의 상대에게 이동 요청 |
| `/tpaccept` | 현재 받은 요청 수락 |
| `/tpdeny` | 현재 받은 요청 거절 |
| `/tpcancel` | 보낸 요청 취소 |

채팅의 수락/거절 버튼은 요청 UUID에 묶인다. 오래된 버튼이 새 요청을 처리하지 못한다. 요청 유효 시간은 기본 60초(설정 15~300초), 한 플레이어가 참여하는 요청은 하나로 제한한다. 떠나거나 사망한 연결의 요청은 취소한다. 이미 이동/결과 불명인 요청은 다시 수락하지 않는다.

요청·수락 시 양쪽 접속/생명/탑승/거래·전투 상태를 검사한다. 수락한 위치는 실제 안전 셀인지 확인하고, 요청자의 레벨/개인 거주 ACL을 적용한다. 이동 준비 뒤와 최종 teleport에서도 요청 ID·접속 세대·양쪽 전투 상태·상대의 다른 이동/탑승·최신 ACL을 재검사한다. 상대가 같은 월드의 수락 위치에서 2블록보다 멀리 이동하면 취소한다. 일반 이동과 같은 WorldTravel/HOLD/native future tombstone을 재사용한다.

TPA 요청은 메모리 상태이며 재시작 뒤 자동 실행하지 않는다. PG의 E009는 realm/플레이어별 전투 만료시각만 저장한다. 공격마다 트랜잭션을 만들지 않고 1초 주기·quit·종료 drain에서 묶는다. `GREATEST` upsert로 오래된 flush가 시간을 줄이지 못한다. DB 실패/commit 불명은 원본을 보존하고 HOLD로 닫으며 보상/인벤토리를 복사하거나 재지급하지 않는다.

다른 플러그인의 Home/TP 명령도 표준 teleport 이벤트를 사용하면 같은 전투/입장 검사를 받는다. 새 Home 명령, 다른 backend 간 분산 TPA, PvP 소유자 설정, 사망·부적·보상 페널티는 이번 기능이 아니다. 실제 클라이언트 조작·동접·운영 배포는 계속 보류한다.
