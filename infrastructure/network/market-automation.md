# 시장 자동 운영

[일반 생존 경제](native-economy.md)의 생산·소비·운송·가격 갱신에 수급 판단 에이전트를 연결한다. 사용자 선택에 따라 **LLM 없이 경제 에이전트만 사용하는 설정**을 기본으로 한다. `/경제`의 지역 재고/시세·생산/운송·사건/공급망 조회와 기존 상점/거래를 이용한다. 에이전트가 움직이는 재고는 경제 엔진의 상품 재고이며 실제 월드 상자에 아이템을 생성하는 기능은 아니다.

## 동작

| 모드 | 판단 | 운송 정책 기본값 |
| --- | --- | --- |
| BALANCED | 공급/목적지의 특별한 부족이 없음 | 출발지 목표의 25% 또는 현지 필요량을 비축, 소비/재료 2틱분 반영 |
| RESTOCK | 목적지 부족·가동 가능한 공급 경로 존재 | 비축 10%, 목적지 소비/재료 4틱분 반영 |
| CONSERVE | 공급지 재고/현지 소비·재료 부족 | 비축 50%, 소비/재료 1틱분 반영 |

공급지 부족을 우선한다. 목적지 부족은 목표 재고의 50% 미만을 기준으로 한다. 실제 출하는 도착·생산·소비 후 재고에서 계산하며, 도착 예정량·경로 최대량·차단 사건도 반영한다. 같은 공급지의 부족한 출하량은 요청 비율로 나누고 잔여 정수와 복수 공급지 우선순위는 틱마다 순환한다.

기본 12경제 틱마다 평가, 같은 후보 2회와 최소 유지 24틱 후 모드를 바꾼다. 실제 간격은 콘텐츠의 `tick-millis`를 곱한 값이다. 기존 생산·제련 재료·수급 가격/EMA·가격 변동 제한·매매 스프레드는 유지한다. 잔액/아이템 지급·강제 가격 지정·임의 사건 발생은 수행하지 않는다. 서버가 내려간 동안은 PAUSE다.

## 준비와 설정

1. 기존 `survival`·`survival-economy` 연결/realm/콘텐츠를 준비한다. [예제 절](market-automation.yml)을 새 검토 설정에 병합하고 세계 group/realm/개인 파일/기존 PG를 보존한다.
2. 새 컨트롤러를 생성할 때만 `enabled: true`, `allow-new-controller: true`로 지정한다. 최초 생성 후 `allow-new-controller: false`로 돌려 누락 시 재생성을 막는다. `ai-mode: none`이면 외부 모델·GPU·별도 AI 서버가 필요 없다.
3. `market-automation.properties`와 PG의 정책 해시가 맞아야 기동한다. 정책 매개변수를 바꾸어 기존 상태를 덮을 수 없다. 기존 정책 변경/컨트롤러 제거는 별도 이전 설계가 필요하며 파일/PG 행을 지워 해결하지 않는다. 초기화한 컨트롤러를 두고 `enabled: false`로 바꾸면 기동을 거부한다. LLM만 해제할 때는 `ai-mode: none`을 사용한다.

예약 틱·거래·컨트롤러는 같은 realm의 잠금/트랜잭션 경계를 따른다. DB/commit 불명과 원본 보존은 기존 경제 HOLD 정책을 사용한다. 모드·후보 연속 횟수·전환 이력은 정상 종료/재시작 후 이어지며 오프라인 틱을 보충하지 않는다.

## 콘솔

- `heartheconomy automation status`: 현재 모드/경제 틱, 선택 AI 상태·수용/거부 횟수·마지막 실패 코드.
- `heartheconomy automation history`: 최근 모드 전환 20개와 출처. `INITIAL`은 최초 상태, `RULE`은 경제 에이전트, `LLM`은 허용된 선택 조언이다.
- `hearthsurvivaladmin drain`: 기존 금융 작업/틱 정산을 포함해 저장 종료 준비. 완료 안내 후 정상 종료한다.

콘솔 명령으로 잔액/재고를 보정하거나 컨트롤러를 초기화하지 않는다. 실행 중인 운영 환경에는 이번 작업에서 설정을 적용하지 않았다.

## 별도 선택 연동

선택형 `ai-mode: ollama`는 기존 고정 Ollama/Qwen3 조합의 한정된 후보 선택 연동이다. 사용자는 경제 에이전트만 사용하기로 했으므로 기본 운영에는 활성화하지 않는다. 필요 시 검토한 설정으로 기동하고 별도 준비된 백엔드에 콘솔 `heartheconomy automation prepare`를 명시적으로 실행한다. Hearth가 모델 서버를 시작하거나 자동 준비하지 않는다.

집계 숫자·후보만 보내며 JSON 응답의 모드를 최신 PG 후보로 재검증한다. 준비 실패/제안 거부/6초 초과는 규칙 판단을 계속한다. 원시 응답을 저장하지 않으며 초기 준비 상태는 재기동 시 이어받지 않는다. LLM을 제거해도 경제 정책/컨트롤러는 보존된다. [설계](../../docs/decisions/0028-autonomous-market-agents.md)·[검증과 미검증](../../docs/market-automation-verification.md)을 따른다.
