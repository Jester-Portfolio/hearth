# 거주 월드 시스템 설정과 사용

일반 생존 경제에 기본 거주 구획, 구매형 개인 월드, 확장과 초대 공동 거주를 연결한다. 공용 스폰 한곳·공통 상점과 자원 오버월드/지옥은 유지한다. 가격·크기·정원·구획 배치는 [설정 예제](housing.properties)에 분리했으며 운영 밸런스/지형으로 확정한 값이 아니다.

## 플레이

`/월드`에서 기본 거주·자원 오버월드·자원 지옥을 선택하고, **개인 거주** 버튼에서 다음을 이용한다.

- 개인 월드 구매: 크기·결제액·잔액을 확인하고 최종 확정한다. 구매가 닫혀 있으면 안내만 표시한다.
- 나의 집: 집으로 이동, 차액 확장, 현재 안전한 위치를 집 입장점으로 지정, 초대/거주자 관리.
- 함께 사는 집: 수락한 거주자/방문자 권한으로 입장하거나 탈퇴한다. 소유자가 오프라인이어도 이용한다.
- 받은 초대: 거주자/방문자 권한을 확인하고 수락/거절한다. 초대는 서버에 등록된 계정 목록에서 선택하며 상대의 수락 전에는 권한이 없다.
- 기본 거주 구획: 계정당 하나를 배정받거나 자신의 구획으로 이동한다. 공용 시설과 구획 밖은 보호한다. 실제 안전한 구획 지형은 별도로 준비해야 한다.

거주자는 건축·시설/보관함을 공유하고, 방문자는 기본적으로 입장만 허용한다. 선택 [경제 RPG](economy-rpg.md)를 활성화하면 소유자가 특정 오브젝트의 상호작용만 따로 공개/지정할 수 있다. 소유자는 초대 취소/권한 해제를 할 수 있으며 거주자는 스스로 탈퇴할 수 있다. 역할 변경은 기존 권한을 해제하고 새 역할로 다시 초대한다. 권한을 해제하면 기존 화면/뒤늦은 요청과 보관함 조작을 차단하고 공용 스폰으로 복귀시킨다. 거래/이동 중이라 안전한 복귀가 불가능하면 연결을 종료해 재접속 시 공용 스폰에서 시작한다. 가방/잔액을 압수하거나 공용 상자를 자동 분배하지 않는다.

개인 월드는 전용 FLAT 월드로 생성한다. 같은 UUID/seed/중심을 유지하며 경계를 넓히고 기존 건축물을 보존한다. 확장 금액은 구매 당시 가격표의 새 등급 총액에서 현재 등급 총액을 뺀 차액이다. 유지비/미접속 회수·축소·환불/양도·삭제 기능은 두지 않는다. `/상점`과 잔액·인벤토리/엔더는 기존 경제 서버의 공통 데이터를 사용한다.

개인 월드는 필요할 때 로드하며, 마지막 이용자와 작업이 사라진 뒤 설정한 시간이 지나면 저장/언로드한다. 로드 중에는 입장 청크를 유지한다. 새 접속의 위치가 공통 3월드 밖이면 공용 스폰에서 시작하고 개인 거주 메뉴로 다시 입장한다. 네더 포탈은 공통 자원 지옥/오버월드로 연결하며, 미등록 차원 진입은 닫는다. 선택 [경제 RPG](economy-rpg.md)가 별도 등록한 자원 End는 공통 입장/사망 정책을 확인해 허용한다. 침대/리스폰·다른 이동도 개인 접근권한과 경계를 확인한다.

## 새 설정 준비

기존 `survival`·`survival-economy`가 준비된 설정에 다음 절을 검토해 병합하고 예제 properties를 Hearth 데이터 폴더에 복사한다. 기본 배포 설정의 두 기능 스위치는 모두 꺼져 있다.

```yaml
housing:
  enabled: false
  content-file: housing.properties
```

1. 가격/크기·정원/로드 한도·기본 구획을 검토한 새 설정에서 거주 시스템을 활성화한다. `purchases-enabled=false`이면 보호/기존 거주는 유지하면서 신규 구매·확장을 닫는다.
2. 최초 정책/가격표 생성 때만 `allow-new-policy=true`를 지정하고 생성 후 false로 유지한다. 기존 group/경제 realm/공통 월드 registry를 바꾸지 않는다.
3. 가격/크기를 바꿀 때는 새 `price-version`을 사용한다. 기존 버전의 내용 변경은 거부하며 기존 주택의 가격표는 PG에 남아 확장에 사용된다. 같은 버전의 해시를 바꾸거나 기존 표를 지워 오류를 덮지 않는다.
4. 기본 구획의 위치/크기와 자원 입장점 보호 반경은 보호 형상 해시에 묶인다. 운영 시작 후 변경은 기존 구획/건축물을 보존하는 별도 이전이 필요하다. 정원/로드 수·유휴 시간은 범위 안에서 설정할 수 있다.

기본 구획의 X/Z는 공용 스폰에 대한 상대 오프셋이다. 시작 높이는 공용 입장점의 Y이며 지정 높이 위/아래와 구획 밖은 변경할 수 없다. 개인 입장점/구획 이동은 기존 안전 지형만 이용하며 바닥을 자동 건축/수정하지 않는다. 테스트 전용 표식이 있는 격리 복사본의 시험 바닥 준비를 운영 기능으로 사용하지 않는다.

## 저장과 관리

E008은 가격표·소유권/월드 식별자·결제 요청/영수증·초대/역할·공용 구획을 추가한다. 구매는 닫힌 월드 준비/저장 후 같은 PG 거래에서 잔액과 소유 상태를 확정하고, WorldGuard/경계 저장 후 입장을 연다. 확장은 기존 월드에서 같은 절차를 사용한다. SQL 실패/commit 불명·늦은 요청은 원본/영수증과 닫힌 상태를 보존한다. 자동 재차감·환불·재생성하지 않는다.

- `heartheconomy housing status`: 소유/로드 수·준비/보류 상태.
- `heartheconomy housing inspect <주민 UUID> <요청 UUID>`: 결제 요청을 읽기 전용으로 확인한다. 경제 저장소가 준비돼 있으면 거주 런타임 초기화 실패 때도 이 조회를 사용할 수 있다. 경제 런타임 자체가 준비되지 않은 경우는 기존 오프라인 진단 절차를 따른다.
- `hearthsurvivaladmin drain`: 진행 작업을 확인한 뒤 개인 월드 저장/언로드·거주 표식 정리·기존 경제 종료를 이어 수행한다. 완료 안내 후 서버를 정상 종료한다.

`housing.active`는 정상 종료 확인, `housing-worlds/<ID>.properties`는 group/realm/주택·월드 UUID/seed/입장점, 같은 디렉터리의 `.pending`은 미완료 생성 보존 표식이다. 존재하는 표식을 지워 자동 재생성하거나 정책/소유권을 임의 재확정하지 않는다. 초기화한 정책이 있으면 거주 시스템 전체를 비활성화한 기동도 거부한다. 구매만 닫을 때는 properties의 구매 스위치를 사용한다.

기존 오프라인 백업의 Paper 전체 루트/PG 전체 루트 범위에 개인 월드·WorldGuard·이 메타데이터도 포함된다. 일부 폴더/PG 행만 골라 다른 세대와 섞지 않는다. [설계](../../docs/decisions/0030-residential-and-resource-worlds.md)·[검증/한계](../../docs/housing-system-verification.md)를 따른다. 실제 스폰/상품/가격·플레이/부하·운영 배포와 자원 월드 초기화는 이번에 적용하지 않았다.

## 파일 작업·언로드 실패

입장점 설정/ID 메타파일은 순서 보장 worker로 읽고 저장하며 월드/청크 API는 owner 스레드에서 적용한다. idle 언로드 실패는 해당 집만5초/10초 대기 후 재시도하고 세 번 실패하면 보류한다. 콘솔 `/heartheconomy housing unload-status`, `/heartheconomy housing retry-unload <집 UUID>`로 확인/재시도한다. 월드/원본 파일은 삭제하지 않는다. [보완 검증](../../docs/economy-followup-verification.md)을 따른다.
