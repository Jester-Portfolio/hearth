# 계산 근거 읽기·값 변경·과학 답변의 원래 자료

확인일: 2026-11-17. 기준 `41af14f` 이후. [ADR-0021](decisions/0021-science-reading-and-reference-questions.md)의 선택형 계산 설명을 구현했으나 **실제 모델 품질 수용은 실패하여 제품의 실제 백엔드 전송을 차단했다.** 정확 계산의 근거 조회·값 변경, 과거 과학 답변의 자료 조회와 Mock 연결의 필수 내부 검사는 통과했다. [아티팩트·실패 원본·최종 차단 근거](../verification/s5-calculation-help-result.json)를 함께 보존한다.

## 구현 범위

계산기의 본인 구조화된 기록에서 ‘계산 근거’를 열어 당시 입력값·식·정확값/단위·별도 근삿값·가정과 같은 원리의 공개 노트를 본다. ‘값 바꿔 다시 계산’은 원래 수치를 채운 입력 화면을 열며 직접 계산하기 전까지 새 기록을 만들지 않는다. 일반 수식/이전값 계산·다른 계산기/접속·삭제/밀려난 기록은 선택할 수 없다. 불변 계획으로 정확값을 다시 계산하고 다른 기록·게임/인벤토리·측정값·제작 해금 여부를 읽지 않는다.

계산 설명용 `SCIENCE_CALCULATION`은 노트 `[자료 1]`과 선택한 계산 `[자료 2]`만 허용한다. 입력 전체/식/값/가정을 사용자 확인 후 전송하고 이력·캐시는 해당 불변 스냅샷 전체/목적으로 분리한다. 100N/200N처럼 값이 다르면 서로의 이전 대화를 넣지 않는다. 원본/선택이 사라지면 전송·늦은 답변/캐시 반영을 거부한다. 실제 모델 품질 실패 후 이 경로는 **기본 거부**로 바꿨다. 현재 설정 가능한 백엔드 중 명시적 Mock만 전송 버튼을 제공한다. `local`/`ollama`와 기본 구현은 버튼을 숨기며 직접 Chat API를 호출해도 생성·캐시 확인 전에 `QUALITY_UNVERIFIED`로 초안을 보존한다. 모델을 준비해도 이 품질 보류를 해제하지 않는다. 새 설정/환경변수로 우회하는 스위치를 만들지 않았다.

대화 검토의 ‘이 답변의 과학 근거’는 그 답변에 실제 보낸 당시 노트/계산 자료를 읽는다. 현재 다른 값을 선택해도 과거 근거가 바뀌지 않으며, 전송 완료 후 계산 원본을 지워도 대화 수명 안의 당시 근거만 읽을 수 있다. 삭제된 계산을 재발급/재전송하지 않는다. 다른 Chat·오래된 기록 선택과 일반/게임 context는 이 조회 경로로 열지 않는다. 기존 과학 노트 답변에도 적용되므로 실제 백엔드의 계산 설명이 보류여도 원래 노트 근거 조회는 사용할 수 있다.

## 최종 내부 검사

- 스마트폰 관련 **210개 PASS**, 실패/오류/skip 0. 정확 분수·세 원리·불변 입력, 소유/현재 기록·한도 삭제, 타입/context 위조 거부, 번호/수식 검사, 범위별 이력/캐시·미리보기 일치, 늦은 답변 거부, 답변별 당시 근거와 게임 정보 비노출, 실제 백엔드 전송 차단/초안 보존을 확인했다.
- JAR 빌드·통합 fixture 컴파일 PASS. 최종 JAR는 `Hearth-calculation-help-gated.jar`이고, 두 실제 추론에서 사용한 이전 JAR와 별도 보존한다. 최종 차단 코드를 실제 GPU로 다시 실행하지 않았다.
- Python 시험 제어 **13개 PASS**. 같은 시계의 품질 재확인은 명시된 품질 실패와 PASS 행만 허용한다. HTTP/시간/모델·준비/품질 보류·알 수 없는 오류가 섞이면 재개하지 않는다.

순수 계산·DTO·접속 메모리/GUI와 전송 허용 경계의 변경이며 DB/DDL·세션 저장·게임 권한·월드 이벤트 계약을 바꾸지 않았다. Paper/PG를 다시 실행하지 않았고 실제 클릭/화면 성공으로 보지 않는다.

## 실제 모델 관측과 한도

고정 Ollama 0.40.16/Qwen3 4B Instruct Q4, 새 소유 경로 `/home/server/hearth-tmp/hearth-s5-trial.7e4brrzx`에서 한 번 시작하고 품질 실패에 한하여 **동일 최초 표식의 시계 안에서 한 번** 보완 확인했다. 최종 531.130초에 종료·정리 오류 0이며 새 시계/모델/예산으로 재시도하지 않았다. CPU 2·RSS 4GiB·GPU 5GiB, 총 600초/작업 550초·개별 90초·질의 6초, 4096/128토큰을 유지했다. 자료/캐시·원본 삭제 차단은 두 관측 모두 통과했다. 이는 전체 응답 품질 PASS가 아니다.

실패 답변을 대신 생성하거나 자료 표시를 서버가 덧붙여 통과시키지 않았다. 확인 가능한 자료 번호/일부 수식 검사와 자연어 정확성/질문 충실도는 구분한다. 최종 제품은 실패한 모델 기능의 통과를 필수 내부 검사로 대체하지 않고 그 전송 기능을 보류했다. 격리 probe의 명시적 opt-in은 향후 별도 승인된 품질 측정에만 사용하며 일반 플레이 기능의 허용이 아니다. 세 번째 실제 시도는 하지 않았다.

일반 과학 정답률·실제 계산 설명 수용은 HOLD, 실제 Minecraft 조작·장기 성능/목표 사용량·상시 예산·운영 배포/전체 S5 수용도 미완료다. 후속은 모델/상한 변경 없이 해결 가능한 응답 충실도 보완 검토이며, 새 실제 추론에는 소진된 시험 한도를 다시 시작할 명시적 승인 경계가 남는다.
