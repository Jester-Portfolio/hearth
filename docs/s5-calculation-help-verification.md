# 계산 근거 읽기·값 변경·과학 답변의 원래 자료

확인일: 2026-11-17. 기준 `41af14f` 이후. [ADR-0021](decisions/0021-science-reading-and-reference-questions.md)의 선택형 계산 설명을 구현했으나 **실제 모델 품질 수용은 실패하여 제품의 실제 백엔드 전송을 차단했다.** 정확 계산의 근거 조회·값 변경, 과거 과학 답변의 자료 조회와 Mock 연결의 필수 내부 검사는 통과했다. [아티팩트·실패 원본·최종 차단 근거](../verification/s5-calculation-help-result.json)를 함께 보존한다.

## 구현 범위

계산기의 본인 구조화된 기록에서 ‘계산 근거’를 열어 당시 입력값·식·정확값/단위·별도 근삿값·가정과 같은 원리의 공개 노트를 본다. ‘값 바꿔 다시 계산’은 원래 수치를 채운 입력 화면을 열며 직접 계산하기 전까지 새 기록을 만들지 않는다. 일반 수식/이전값 계산·다른 계산기/접속·삭제/밀려난 기록은 선택할 수 없다. 불변 계획으로 정확값을 다시 계산하고 다른 기록·게임/인벤토리·측정값·제작 해금 여부를 읽지 않는다.

계산 설명용 `SCIENCE_CALCULATION`은 노트 `[자료 1]`과 선택한 계산 `[자료 2]`만 허용한다. 입력 전체/식/값/가정을 사용자 확인 후 전송하고 이력·캐시는 해당 불변 스냅샷 전체/목적으로 분리한다. 100N/200N처럼 값이 다르면 서로의 이전 대화를 넣지 않는다. 원본/선택이 사라지면 전송·늦은 답변/캐시 반영을 거부한다. 실제 모델 품질 실패 후 이 경로는 **기본 거부**로 바꿨다. 현재 설정 가능한 백엔드 중 명시적 Mock만 전송 버튼을 제공한다. `local`/`ollama`와 기본 구현은 버튼을 숨기며 직접 Chat API를 호출해도 생성·캐시 확인 전에 `QUALITY_UNVERIFIED`로 초안을 보존한다. 모델을 준비해도 이 품질 보류를 해제하지 않는다. 새 설정/환경변수로 우회하는 스위치를 만들지 않았다.

대화 검토의 ‘이 답변의 과학 근거’는 그 답변에 실제 보낸 당시 노트/계산 자료를 읽는다. 현재 다른 값을 선택해도 과거 근거가 바뀌지 않으며, 전송 완료 후 계산 원본을 지워도 대화 수명 안의 당시 근거만 읽을 수 있다. 삭제된 계산을 재발급/재전송하지 않는다. 다른 Chat·오래된 기록 선택과 일반/게임 context는 이 조회 경로로 열지 않는다. 기존 과학 노트 답변에도 적용되므로 실제 백엔드의 계산 설명이 보류여도 원래 노트 근거 조회는 사용할 수 있다.

## 정형 응답·현재 질문 보완 — 실제 추론 미실행

`e44802f` 이후에는 질문과 관계없이 정확값을 반복하라는 지시를 제거했다. 값/단위를 물을 때만 그 값을 인용하고, 관계/원리·가정 질문에는 해당 내용을 답하도록 한다. 서버의 정확값 표시는 별도로 유지한다. 이는 지시 개선이며 모델이 실제로 따랐다는 판정이 아니다.

Ollama의 계산 설명 요청에만 `format` JSON schema를 붙인다. 답변은 `answer` 문자열 하나인 객체이며 비어 있지 않은 최대 160 Unicode codepoint로 제한한다. 일반/과학 노트·게임/문자열 질의와 준비 요청에는 적용하지 않는다. [공식 구조화 출력 문서](https://docs.ollama.com/capabilities/structured-outputs)와 고정 [v0.40.16 API의 format 필드](https://github.com/ollama/ollama/blob/v0.40.16/api/types.go#L85), [raw generate의 format 전달](https://github.com/ollama/ollama/blob/v0.40.16/server/routes.go#L693)을 확인했다. 새 라이브러리/모델·토큰/HTTP/준비 한도를 추가하거나 늘리지 않았다.

수신 시 기존 바깥 응답의 모델·완료/중단 이유·토큰·본문·Unicode 검사를 먼저 통과해야 한다. 이후 내부 객체의 중복/추가 키·타입·잘린 JSON/코드 블록/후행 데이터·깨진 Unicode·160자 초과를 엄격히 거부한다. 모델이 **답변 문자열 안에 직접 출력한** 자료 2 표시와 기존 제한된 수식 검사를 적용한 뒤 표시/이력/캐시에 넘긴다. 서버가 누락된 인용을 붙이거나 잘못된 JSON을 보정/평문으로 대체하거나 자동 재시도하지 않는다. 일반 요청의 JSON처럼 생긴 텍스트는 이 경로로 풀어 읽지 않는다.

기존 스마트폰 회귀 **210개 PASS**, 신규 응답 계약 **8개 최종 PASS**, JAR·통합 fixture 컴파일 PASS다. 최초 218개 실행 중 신규 HTTP fixture 하나가 ‘모순 1+1=3’처럼 한국어 접두사를 넣어 실패했다. 기존 검사는 독립 수식 줄만 다루므로 지원 계약에 맞는 `1+1=3`으로 fixture를 수정하고 영향받은 신규 8개만 재실행했다. 운영 차단 경로의 생성뿐 아니라 version/tags/ps HTTP도 시작하지 않음을 함께 확인했다. 첫 실패 XML/로그와 최종 8개 결과를 [별도 증거](../verification/s5-calculation-reply-result.json)에 보존한다. 이 fixture 수정으로 자연어 전체 수식 검사까지 지원한다고 주장하지 않는다.

정형 파서의 합성 HTTP 검사이며 **실제 모델/GPU 추론·Minecraft·Paper/PG를 실행하지 않았다.** 같은 과학 범위의 자료/캐시·준비/기존 목적의 회귀를 확인했으며 영속 저장/게임 권한/월드 이벤트 계약은 바꾸지 않았다. 구조화된 외형이 의미 정확성·질문 충실도·128토큰 내 완료를 보증하지 않는다. 이전 실제 품질 실패는 그대로이며 실제 `local`/`ollama` 계산 설명의 전송 차단과 S5 품질 HOLD를 유지한다.
