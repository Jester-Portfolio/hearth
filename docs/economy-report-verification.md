# 공개 시장·운송·사건·생산시설 정보 연결

확인일: 2026-11-07. 기준: `f89c2c3`. [이전 상점/관리 검증](economy-desk-verification.md)은 보존하고 이번 결과는 [별도 JSON](../verification/economy-report-result.json)에 기록한다.

## 구현

상점·상품 화면에서 시장 상황으로 이동해 다음 정보를 조회한다.

- 재고/목표·부족/과잉 상태, 품목/시장 기준가, 1개 구매/판매가와 현재 수요 설정.
- 공개 지역 선택과 지역별 참고 시세. 상점 지역의 취급 상품을 선택하면 최신 견적을 다시 조회한다. 다른 지역의 화면은 거래나 이동을 실행하지 않는다.
- 운송로의 출발/도착 지역·상품·기본 운송량/지연, 신규 출발 차단 여부, 운송 중 수량/건수·가장 가까운 도착까지의 경제 Tick. 운송 중 물량은 시장 재고와 분리한다.
- 공개된 경제 사건의 적용 대기/적용 중 상태, 시작/종료까지의 경제 Tick.
- 공개된 생산시설의 현재 효율을 반영한 생산 상한과 재료 소모량/재고. 실제 생산 실적으로 표시하지 않는다.

`EconomyReport`가 콘텐츠 공개 범위를 적용해 화면과 분리된 DTO를 만든다. 계정·잔액·인벤토리·물리 월드 UUID·운송 요청 UUID는 포함하지 않는다. `report-*` 설정이 없으면 상점 지역/상품만 조회하고 시설·운송로·사건은 공개하지 않는다. 알 수 없는 ID·중복·숨겨진 운송 끝점/재료 연결은 활성화 전에 거부한다. 공개 목록 변경은 개발 콘텐츠 설정이며 운영 공개 정책의 확정을 뜻하지 않는다.

조회는 기존 제한 DB worker와 realm 잠금에서 같은 Tick의 상태를 읽는다. 화면의 탭/페이지는 불변 조회 결과를 재사용하고 새로고침에서 DB를 다시 읽는다. 클릭 뒤 캐시 화면 전환도 **명시적 1틱 지연** 후 현재 화면·세션·세대·거리 조건을 재검사한다. [공식 InventoryClickEvent 계약](https://jd.papermc.io/paper/26.2/org/bukkit/event/inventory/InventoryClickEvent.html)의 이벤트 내 화면 변경 제한을 따른다.

가격·생산·수요·운송 알고리즘과 저장 형식은 유지했다. 기존 계산을 표시와 공유하는 작은 메서드로 추출했으며 새 밸런스·화폐·운송비·DB 마이그레이션을 추가하지 않았다.

## 실행·수정 이력과 자원

자동 통합은 승인 한도 내 **3묶음**이며 각각 Paper 한 JVM·격리 PG 하나를 순차 실행했다. 세 경로의 원본 증거는 보존했다.

1. `/tmp/hearth-s4-11.CxPUEUSy`: 데이터/화면 객체 검사 PASS(36.355초). 검토에서 클릭 이벤트 뒤 화면 전환 예약을 보완했다.
2. `/tmp/hearth-s4-11.1xL3v3Ys`: 기본 예약의 다음 틱 검사가 FAIL(32.492초). 정상 drain 확인 표식도 누락되어 원본 정리 판정은 FAIL로 유지한다. Hikari 종료 완료 로그와 부모 프로세스·localhost 포트·postmaster PID 파일의 종료를 추가 확인했다. 명시적 1틱 지연으로 수정했다.
3. `/tmp/hearth-s4-11.ltgZdJbf`: 최종본 PASS, **35.148초**. `original_tick=146`, 확인 시 `current_tick=148`, 적용 횟수 1로 지연과 무효 표시 거부를 확인했다. 이후 소스 변경·추가 시험은 하지 않았다.

최종 Paper 시작 15.884초·종료 3.754초, 관측 RSS 최고 **1,189,376KiB**, CPU 누적 **59.91초**. DB 시험 부모 RSS 최고 220,136KiB·CPU 2.32초이며 PG 전체 자식 합계로 해석하지 않는다. 호스트 가용 RAM 최저 약 **11.74GiB**였다.

localhost·Xmx1,536MiB·CPU2/nice+10·RSS2.5GiB 중단·가용6GiB·디스크4GiB·600초 한도를 유지했다. TPS/MSPT·장기 메모리 누수·대형 생산망 성능은 측정하지 않았다. 기존 운영 서비스·월드/DB·이전 증거를 변경하지 않았다.

## 미검증·후속

- E1/E2·전체 S4는 진행 중이고 일반 서버 기본 비활성을 유지한다. 운영 적용과 실제 클라이언트 시험은 별도 범위다.
