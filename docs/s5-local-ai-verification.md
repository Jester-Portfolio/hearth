# S5 선택형 Ollama 연결·첫 실제 모델 검증

확인일: 2026-11-10. 기준 `9604fce` 이후 코드. 사용자가 [ADR-0018](decisions/0018-local-ai-runtime-and-trial-budget.md)의 모델/런타임·격리 예산을 승인했다. 선택형 연결 구현과 내부 검사는 통과했고 실제 모델의 아래 제한 흐름을 확인했다. **전체 S5 수용·Minecraft 실제 시험·운영 배포 완료는 아니다.** 상세 명령·해시·수치·실패 원본은 [검증 JSON](../verification/s5-local-ai-result.json)을 따른다.

## 구현

- `phone-ai-mode: ollama`, 명시적인 `http://127.0.0.1:11435/api/generate`를 지원한다. 기본은 여전히 Mock이며 기존 local text/plain도 유지한다. 공유 HTTP 계층의 worker 2개/queue 8개·4개 요청·연결 2초·전체 요청 6초·본문 8,192바이트·UTF-8·취소/종료 경계를 두 프로토콜이 사용한다. JSON 프로토콜의 버전/모델 조회부터 생성까지 합쳐 6초다. 대화 8초/공개 DTO·후속 권한 재검증은 그대로다.
- 매 요청의 `/api/version`과 `/api/tags`로 Ollama 0.40.16/고정 모델 manifest digest를 확인한다. 원격/인증정보/쿼리/잘못된 경로와 리다이렉트는 허용하지 않는다. 불일치·혼잡·잘못된 JSON·중복 키·잘못된 타입/UTF-8·미완료·과도한 깊이/크기·입출력 한도는 명시적으로 거부한다. 오류 본문/내부 주소를 화면에 노출하거나 Mock으로 대체하지 않는다.
- 고정 Qwen3 Instruct의 기본 ChatML 형식을 `raw:true`로 구성한다. `stream:false`, `truncate:false`, `shift:false`, context 4096·출력 128·스레드 2·keep-alive 60초를 명시한다. 모델이 반환한 context/도구/임의 URL을 다음 요청에 넘기지 않는다. 실제 입력/출력 토큰·완료 사유를 검증하며 길이 때문에 자료를 몰래 잘라 보내거나 미완료 답변을 성공 기록으로 삼지 않는다. 근거는 [고정 Ollama 소스](https://github.com/ollama/ollama/blob/v0.40.16/server/routes.go)와 [제작자 채팅 템플릿](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507/blob/main/tokenizer_config.json)이다.
- Gson 2.14.0은 고정 Paper의 기존 라이브러리를 사용하며 단위/독립 probe에도 같은 버전을 제공한다. 비공개 콘텐츠/DB 도구·모델 설치 기능·새 영속 저장/응답 캐시는 플러그인에 추가하지 않는다.
- 새 시험 도구는 이미 있는 libzstd로 고정 해시 아카이브를 제한적으로 해제한다. 경로 탈출/링크/특수 파일/덮어쓰기를 거부한다. 공식 모델 manifest와 모든 blob을 검증하며 새 격리 프로필·모델 경로·클라우드 비활성·CPU/RSS/GPU/디스크/시간 감시를 사용한다. 부모 환경/기존 프로필은 유지한다. 검토 후 재개도 **최초 실행의 남은 시간만** 사용하고 원래 결과/로그/프로필·모델 파일을 덮어쓰지 않는다.

## 실행한 내부 검사

- 관련 스마트폰 단위/회귀 **64개 고유 검사·실패 0개**다. 첫 실행 64개 중 응답 타입 시험 fixture 오류 1개를 수정해 해당 Ollama 8개를 통과했고, 실제 HTTP 400 표시 보완 후 같은 관련 8개도 통과했다. 중복 실행은 합산하지 않는다.
- Python **11개 고유 검사 PASS**. 새 도구의 5개는 마지막 변경 기준으로 재검사했다. 기존 libzstd 스트림/해제, 경로/링크 차단, 호스트/시간 한도와 해시 실패 시 원본/partial 보존을 확인했다.
- 최종 main/JAR/test/integration fixture 컴파일 PASS. 격리 **Paper 1 JVM/PG 1개, 98회 assertion PASS·42.819초**다. 플러그인 안의 Gson 로딩·Ollama 입력 한도 거부와 기존 Dialog/퀘스트·개인/진행 격리·PG 조회 실패/지연·원본 일지/인벤토리/revision 보존을 검사했다. 실제 모델 호출은 해당 Paper 검사에 포함하지 않는다.
- 마지막 HTTP 400 변경은 실패 사유 분류만 수정했다. 관련 단위에서 실제 서버가 남긴 한도 초과 문구를 재현했다. 전송/영속 계약은 같으므로 이미 통과한 Paper/PG 검사는 반복하지 않았다. 실제 최종 안내 문구는 모델 서버에 다시 요청해 확인하지 않았다.

## 실제 모델 관측과 보존한 실패

공식 Ollama 아카이브·모델/config/template/license/params의 실제 파일 해시를 확인했다. 다운로드는 **4,043,062,302바이트**이며 시스템 설치·서비스 등록·드라이버 변경 없이 `/tmp/hearth-s5-trial.9iqwd8ex`에서 실행했다. 모델 가중치/manifest는 사전 고정값과 일치했다.

첫 실행은 빈 프롬프트로 로딩만 준비했다. 이후 초기 질의 6개가 6초를 넘었고, 후반의 짧은 동시 질의 4개는 응답했다. 첫 자동 판정 `ACTUAL_MODEL_ACCEPTANCE_FAILED`와 로그를 보존했다. 준비 동작의 옵션/실제 프롬프트를 질의와 통일하는 보완을 했다.

재확인은 다운로드 없이 원래 파일 해시를 다시 대조하고, 별도 모델 복사본·프로필·로그를 사용했다. 실제 질의 형식의 준비는 **66.295초**로 준비 동작 90초 이내였다. 사용자 질의의 6초 제한은 늘리지 않았다.

| 재확인한 흐름 | 실제 응답/결과 | 시간 |
| --- | --- | --- |
| 짧은 한국어 | `준비 완료` | 221ms |
| 진행 A 공개 기록 | `느티상점` | 477ms |
| 다른 진행 B 공개 기록 | `바람상점`·A 이름 혼입 없음 | 206ms |
| 자료에 없는 정보 | 제공된 자료에 암호가 없어 알려줄 수 없다는 응답 | 766ms |
| 요청 취소→다음 요청 | 취소 결과 확정/이력 없음, 다음 `준비 완료` | 다음 192ms |
| 긴 입력 | **6568토큰 > 4096**으로 서버 거부, 로그 `truncated=0` | 23ms |
| 짧은 요청 4개 동시 | 4개 모두 응답. 실제 혼잡 거부는 관측하지 못함 | 개별 지연/부하 기준 판정 아님 |

긴 입력은 Ollama가 HTTP 400으로 거부했으나 기존 분류가 `INVALID_RESPONSE`여서 두 번째 원시 자동 판정도 `ACTUAL_MODEL_ACCEPTANCE_FAILED`다. 이를 성공으로 덮어쓰지 않았다. **입력을 자르지 않고 거부하는 경계는 실제로 확인**했고, 해당 오류 문구를 `CONTEXT_LIMIT`로 분류하도록 고쳐 단위로 확인했다. 이후 실제 재요청은 하지 않았다. 최종 제품 JAR과 이 실제 관측 JAR은 해당 실패 분류 수정 때문에 해시가 다르며 JSON에 각각 기록한다.

최초 시작부터 재확인 종료까지 **430.624초**로 같은 600초 예산 이내였다. 예산을 새로 시작하거나 모델/상한을 바꾸지 않았다. 두 실행의 DB/운영 데이터 접근은 없고 소유 프로세스·포트·GPU 반환은 모두 확인했다. 최대 표본 RSS는 **3,413,804KiB**, GPU **3128MiB**, 시험 경로 파일 크기 **9,207,487,335바이트**로 승인 상한 이내였다. 샘플 감시이며 순간 피크/커널 하드 제한의 증거는 아니다. 다운로드·실패·각 재확인 원본은 모두 보존했다.

## 남는 범위

실제 모델의 일반적인 정답률·과학 지식·출처 충실도·긴 자료/대화 품질, 모델 응답 캐시와 캐시 격리, 실제 혼잡 거부·목표 동시 사용·장기 메모리/성능·전체 장애 수용은 남는다. HTTP 취소/다음 요청 성공을 모든 모델 추론의 즉시 중단 보장으로 해석하지 않는다. 예열 전 6초 응답과 예열 후 짧은 5개 응답의 성능을 구분한다. Minecraft 입력/클릭/화면·코옵·운영 상시 배포는 실행하지 않았다.

필수 내부 검사의 실패는 관련 수정/검사로 해소했으며 실제 원시 판정과 미재실행 범위는 위와 같이 남긴다. 현재 기본 설정을 자동 활성화하지 않는다. 다음 S5 배치는 승인된 모델을 바탕으로 공개 자료·응답 품질/캐시와 실제 사용량 기준을 함께 다루고, 운영 예산/배포는 별도 결정한다.
