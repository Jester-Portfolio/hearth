# 스마트폰 Dialog·AI 프로토타입

2026-10-30 · Paper 26.2 build 134 / Java 25 · 일반 서버 비활성 · S4 진행 중.

## 구현과 실행 방법

- 기존 격리 세션·퀘스트 모드에서만 `phone-dialog-enabled: true`로 활성화한다. 준비된 ACTIVE 세션의 `/hearthphone`은 상자 인벤토리가 아닌 Dialog를 연다. `/hearthphone legacy`는 기존 6메뉴 인벤토리 GUI를 보존한다.
- 새 홈은 HEARTH OS, AI 어시스턴트·퀘스트·연구·지도·기록·설정이다. 퀘스트/지도/기록은 기존 공개 정보 DTO의 첫 페이지를 읽고, 설정은 기존 개인 HUD 저장을 재사용한다. 연구는 미구현 안내다. 기존 공동체·알림 기능을 삭제한 것이 아니며 기존 GUI에서 계속 제공한다.
- AI는 텍스트 입력(최대 256자), 전송, 최근 대화 네 쌍, 응답 확인, 홈 이동을 지원한다. UUID의 현재 검증된 세션별로 메모리를 분리하고 세션 교체/종료 시 이전 요청·기록을 정리한다. 기록은 DB에 영속화하지 않는다.
- 중복 전송을 막고, 응답은 1,200자로 제한하며 오류/빈 응답/8초 제한을 정상 답변으로 표시하지 않는다. Bukkit 호출은 owner/다음 틱으로 전달한다. HTTP 어댑터는 비동기·유한 큐/동시 요청·응답 8KiB·6초 제한을 적용한다.
- 기본 `phone-ai-mode: mock`은 명시된 Mock 답변이다. `local`은 `phone-ai-endpoint`의 루프백 HTTP 주소만 허용하며 `POST text/plain; charset=utf-8` 질문을 전송하고 HTTP 200의 UTF-8 답변을 읽는다. OpenAI/Ollama 전용 JSON API를 자동 지원하는 어댑터는 아니다. 실제 모델·서버 설치/실행은 하지 않았다.
- AI에는 질문만 전달하며 게임 원본 콘텐츠·DB·타인 정보·미발견 비밀을 조회하는 도구 권한은 제공하지 않는다. 정식 S5의 승인된 정보 검색·모델 선택·운영 예산은 별도 작업이다.
- `/hearthphone device`는 준비된 세션과 `hearth.verify` 권한이 있는 개발자만 빈 슬롯에 시험 아이템을 명시적으로 지급한다. PDC와 `hearth:phone` 아이템 모델을 사용하며 우클릭/버리기 차단을 연결했다. 자동 지급·고정 슬롯·운영 복구/양도 정책은 추가하지 않는다. 기본 인벤토리/E키는 유지한다.

## 리소스팩

`resourcepack/`에 원본 PNG·Bitmap Font·아이템 모델을 둔다. `python3 scripts/build-phone-pack.py`로 참조/JSON/PNG를 검사하고 `build/hearth-phone-pack.zip`을 만든다. 생성 ZIP은 Git에 넣지 않는다. 디자인은 `assets/hearth/textures/gui/`의 PNG와 `font/phone.json`을 교체한다.

26.2의 리소스팩 형식은 [Mojang 발표](https://www.minecraft.net/it-it/article/minecraft-java-edition-26-2)에 따라 88.0으로 제한했다. 시험 시 ZIP을 클라이언트 리소스팩으로 적용하거나 승인된 별도 배포 URL을 통해 제공해야 한다. 이번에 웹 서버·공개 포트·서버 리소스팩 URL·운영 설정은 생성/변경하지 않았다. 모드는 필요하지 않다.

## API 제약과 미검증

[Paper Dialog API](https://docs.papermc.io/paper/dev/dialogs/)는 본문/입력/액션의 정해진 흐름 배치다. Glyph 텍스트에 서버 콜백 클릭 이벤트를 연결하고, 클릭 호환성 문제가 있을 때를 위해 같은 앱의 기본 액션 버튼도 둔다. 투명 버튼·임의 좌표 히트박스·전체 화면 스킨 교체를 구현했다고 주장하지 않는다. 배경 PNG는 현재 헤더 장식이며 모든 입력/앱을 하나의 배경 이미지 위에 자유 배치한 것은 아니다. 기본 버튼 배경은 남는다.

ESC 종료 이후 AI 응답이 화면을 다시 열지 않게 자동 재표시를 하지 않는다. 전송 후 대기 화면의 **응답 확인** 또는 AI 앱 재진입으로 완료 답변을 조회한다. 실시간 부분 갱신/메신저 애니메이션은 없다.

실제 클라이언트의 Glyph 클릭 지원·이미지 정렬·화면 크기·스크롤/줄바꿈·핫바 미표시·ESC·책/기존 GUI 전환·아이템 우클릭/드롭은 미검증이다. Dialog는 플레이어 인벤토리를 GUI 슬롯으로 사용하지 않지만 실제 화면과 인벤토리 보존을 모두 검증 완료로 취급하지 않는다. 실제 클라이언트 시험은 보류한다.

## 자동 검증

관련 단위·회귀 **21개 PASS**, 최종 JAR의 Paper 한 JVM/격리 PostgreSQL 한 개 **PASS** (37.269초). 실제 Dialog 입력/버튼 객체 생성과 기존 퀘스트 저장·개인/진행 격리·41슬롯 인벤토리 불변, 정상 종료·프로세스/포트 반환을 확인했다. 실행 JAR과 최종 빌드 해시는 일치한다. 저장 형식은 불변이므로 두 번째 JVM을 반복하지 않았다.

관련 결과는 [검증 JSON](../verification/phone-dialog-result.json)에 기록한다. 단위 시험은 Mock 순서·개인 분리·길이/중복·늦은 응답·종료·시간 초과와 격리 localhost HTTP의 정상 응답/초과 크기·주소 거부를 검사한다. 실제 모델 답변·실제 플레이어 입력/클릭 성공을 뜻하지 않는다.

다음 작업은 사용자 요청 후 실제 리소스팩/클라이언트 화면과 입력을 확인하고, 선택한 로컬 AI 서비스의 실제 프로토콜 어댑터·권한 있는 게임 정보 검색을 연결하는 것이다. S4/S5 전체 완료나 운영 활성화로 기록하지 않는다.
