# 격리 플레이어 슬롯 조작·시설 이용 연결

2026-10-28 · S4 진행 중. 기존 세션·41슬롯·dirty 저장을 재사용하며 신규 DB 스키마나 저장 정책은 추가하지 않았다.

## 구현

- 활성 세션의 본인 기본 인벤토리 화면에서 커서가 비었을 때 숫자키 핫바 교환, Shift 슬롯/장비 이동, 보조 손 교환, Q/Ctrl-Q 슬롯 버리기를 허용한다. 클릭 종류뿐 아니라 실제 InventoryAction·클릭한 인벤토리·슬롯 0~40·핫바 인덱스를 검사한다.
- 기본 클릭으로 커서에 집기·드래그·제작/결과 슬롯·컨테이너·개발 GUI 아이템 이동·크리에이티브 조작은 계속 거부한다. 스마트폰 버튼의 기존 처리는 유지한다. E키 기본 화면과 저장 슬롯 범위는 바꾸지 않는다.
- 허용된 실제 변경은 기존 다음 틱 캡처→dirty→30초 비동기 저장에 연결한다. 클릭마다 DB 쓰기를 하지 않는다. 다른 플러그인의 취소를 해제하지 않는다.
- 문·다락문·울타리 문·버튼·레버는 비컨테이너 시설로 허용한다. WorldGuard의 기존 이벤트 보호를 유지하며 상자·제작대·화로·독서대 등은 계속 제한한다.
- `/hearthplay help`에서 지원 조작·제한·퀘스트/공유 안내/스마트폰 명령을 확인한다. 복원 후 도움말 위치를 안내하고 거부된 슬롯 조작의 안내는 플레이어별 5초 간격으로 제한한다.

## 검사 결과

- 관련 단위·회귀 **25개 PASS**, 컴파일/JAR·스크립트 구문 PASS. 커서·외부 인벤토리·미준비/HOLD에 해당하는 비활성 상태·범위 밖 슬롯·위조된 클릭/액션 조합 거부, 세션·기존 저장/전환 실패 경로를 검사했다.
- 기존 도구의 `--sessions --player-interactions` 모드로 새 격리 Paper 한 JVM/PG 한 개에서 **PASS**. 내부 제어 인벤토리의 핫바/보조 손 슬롯 교환→기존 dirty/flush→DB revision1·메타데이터 일치, A의 다른 개인 및 B 데이터 보존, 같은 JVM의 새 세션 복원을 확인했다. 이 시험은 실제 키 입력이나 합성 Player 이벤트 시험이 아니다.
- 최초 시도는 B의 초기 수량을 시험 코드가 잘못 가정해 FAIL. 실제 작업 전/후 저장 스냅샷 비교로 바꾸고 새 경로에서 재검증했다. 첫 시도의 풀 종료 확인 누락은 FAIL 증거에 남기며 정상 저장 성공으로 취급하지 않는다.
- [결과 JSON](../verification/player-interactions-result.json)에 두 시도 경로·자원·검사를 기록했다. 최종 프로세스/포트 정리 및 실행 JAR·빌드 SHA-256 일치를 확인했다. 변경 없는 성공 단위 검사는 반복하지 않았다.

## 미검증·후속

실제 인증 클라이언트의 숫자키/Shift 자동 장착·아이템 버리기·취소 경합·시설 조작 및 시설별 WorldGuard 실제 이벤트는 미검증이다. 내부 슬롯 교환·DB 저장 성공을 실제 사용자 행동 성공으로 보지 않는다. 저장/복원 계약이 불변이므로 두 번째 JVM은 생략했다. DB 실패·HOLD는 관련 기존 단위 시험으로 검사했으며 이번 통합에서 장애를 주입하지 않았다. 커서·제작·상자 등의 지원은 별도 범위/저장 경계 검토가 필요하고 일반 서버 자동 활성화·전투·운영 배포는 수행하지 않는다.
