# 제작 준비 순서·복수 목표의 재료 계산·조달 장소 안내

> 최신 결과: 이 배치의 필수 통합은 [누적 배치 최종 통합](pending-batch-review.md)에서 같은 최종 JAR로 통과했다. 아래는 환경 차단 당시의 최초 구현·검사 기록이며 현재 미완료 목록이 아니다.

확인일: 2026-11-09. 기준 `7dd0750` 이후의 미커밋 작업 트리이며, 앞선 [일괄 제작 배치](crafting-batch-verification.md)를 보존하고 확장했다. 현재 **구현·직접 컴파일·관련 단위 검사는 통과했으나 Paper/격리 DB 통합은 미실행**이다. 상세 수치와 원시 로그 경로는 [검증 JSON](../verification/crafting-preparation-result.json)에 기록한다.

## 연결한 기능

- 작업대 상세의 **전체 준비 순서**에서 현재 보관 재료·중간 제작법·추가 원재료·남는 재료를 확인한다. 순서의 항목을 누르면 해당 제작법으로 이동하며, 목표 제작법/횟수로 돌아가기와 현재 재료 기준 새로고침을 제공한다. 준비 화면에는 제작 확정 요청을 만들지 않는다.
- 스마트폰·책의 기존 준비 안내는 설정된 도구들을 **함께** 계산한다. 원목→판자→막대기→도구의 순정 결과 개수와 올림을 반영하고 같은 보유분을 두 번 배정하지 않는다. 중간 제작 후 남은 판자·막대기는 다음 목표에 사용할 수 있으나 목표로 요청한 완성품은 보존한다. 두 도구는 원목 2개와 조약돌 3개를 준비하면 중간 재료를 공유할 수 있다.
- 현장 작업대에서 기존 시설·재료·던전 준비 책으로 이동해 조달 장소를 읽는다. [공개 콘텐츠](../src/main/resources/play-preparation-demo.yml)의 원목·조약돌 출처는 기존 공개 채집 장소를 참조한다. 이름·위치·설명은 본인의 필터된 장소 DTO가 있을 때만 표시한다. 숨겨진/접근 불가 장소의 정의·좌표·내부 ID를 직접 표시하지 않는다.
- 제작법은 같은 시설의 등록 순서에서 선택한다. 순정 기본 아이템과 동일한 보관 슬롯 0~35만 수량에 포함하며 이름/메타데이터가 다른 재료·방어구·보조 손은 제외한다. 순정 잔여물도 계산한다. 비기본 결과/잔여물은 추정하지 않고 안내 계산을 거부한다.
- 순환/과도한 경로는 부분 성공으로 표시하지 않고 준비 안내 불가로 처리한다. 깊이 16·방문 128·표시 단계 32의 계산 한도를 적용한다. 이는 읽기 계산의 한도이며 제작 밸런스가 아니다. 등록 순서의 예시이고 최소 비용·재료 보유 예약·제작 공간을 보장하지 않는다. 실제 제작 시 기존 재검사가 실행된다.
- `material-sources`는 선택 항목이다. 이전 콘텐츠에 확장된 이름표가 없으면 기존 직접 재료 안내를 유지한다. 기존 파일·월드의 시설 블록을 자동 이전하거나 덮어쓰지 않는다. 새 플러그인·DB 스키마·저장/보상 정책은 추가하지 않았다.

## 남은 검증

기존 자동 도구의 새 사용자 소유 `/tmp/hearth-s4-11.*`·자원·EULA·시도 한도를 그대로 사용한다. 앞선 배치의 `--sessions --crafting` 및 `--sessions --quests --story-batch --crafting-quests`에 더해, 준비 안내는 기존 `--sessions --quests --story-batch --combat-players --dungeon-play --play-preparation`으로 실행한다. 새 검사 코드에는 순정 그래프 변환·실제 Inventory 준비 화면·기본 재료만 집계·조회 불변·두 도구의 공동 원재료 계산이 들어 있다. **이 신규 Paper/PG 검사들은 이번에 실행하지 않았으므로 PASS를 주장하지 않는다.**

저장/복원 계약은 불변이어서 별도 두 번째 JVM/DB 재시작은 추가하지 않는다. 실제 인증 플레이어의 화면 전환·단계 선택·책/스마트폰·이벤트/권한·가독성, 장기 성능·운영 배포는 미검증이다. 필수 통합 통과 후 원격 기준을 확인하고 관련 파일만 Git에 반영한다. 실제 클라이언트는 사용자 요청 전 보류한다.
