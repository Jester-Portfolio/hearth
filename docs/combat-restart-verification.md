# 보스만 재도전: 저장·복귀·새 도전 연결

2026-10-29 · 격리 개발 모드 · S4 진행 중.

## 구현한 흐름

[기존 재도전 투표](combat-retry-verification.md)의 확정 식별자를 이어받아 다음을 연결했다.

1. 초기 로딩한 콘텐츠에 `retry.scope: BOSS_ONLY`·진입 위치/방향·회복 비율·효과가 명시된 경우에만 준비한다. 기존 콘텐츠에 이 항목이 없으면 자동 실행하지 않는다. 공개 합성 `combat-demo.yml`에만 시험값을 추가했으며 기존 서버 파일은 덮어쓰지 않는다. 길목부터 재도전 설정은 현재 지원하지 않고 활성화 전에 거부한다.
2. 동일 진행의 검증된 온라인 세션을 준비 명단으로 잡고 조작·아이템 변경을 제한한다. 기존 `PlayerSessions`·`InventorySaveSession` 경로로 모든 관련 활성 세션의 in-flight/최신 dirty와 퇴장 저장을 기다린다. 퀘스트·일지·공유 진행 저장 장벽도 확인한다. 이 경계는 일반 아이템마다 DB 쓰기를 추가하는 정책이 아니다.
3. 기존 Player 적용 경로로 안전성이 확인된 제작자 지정 위치에 복귀하고 설정된 회복값/효과를 적용한다. 새 참가자의 실제 적용 성공·현재 세션·월드 세대·명단을 다시 확인한다. 이전 참가자의 늦은 적용 가드는 다음 참가자 처리·완료·실패·종료에서 닫는다.
4. 모든 준비가 성공한 뒤 기존 보스를 교체한다. 새 도전 UUID·시작 명단·해당 인원의 난이도·보스전 전용 부활 횟수 0회 사용 상태를 확정한다. 온라인 사망자도 준비 적용 후 새 명단에 들어가며 이전 도전/길목의 사용량은 새 한도를 차감하지 않는다. 시작 뒤 명단은 다시 고정한다.
5. 새 도전의 전투·관전·채팅 투표·HUD를 기존 적용기에 연결한다. 같은 요청/식별자의 중복 처리로 새 보스를 다시 만들지 않는다. 시작 안내는 새 도전 연결 확인 후에만 출력한다.

[ADR-0007](decisions/0007-dungeon-and-boss-operations.md)·[ADR-0013](decisions/0013-vote-boss-and-gathering-state-boundaries.md)의 인던별 선택 정책 중 보스만 재도전하는 범위다. 위치·회복값은 콘텐츠 제작값이며 운영 밸런스나 공통 기본 정책을 확정하지 않는다. 기존 Paper/API와 저장·세션 모듈을 재사용했고 새 플러그인·DDL·범용 복구 체계는 추가하지 않았다. V001~V007과 41슬롯/30초 비동기 저장을 유지한다.

## 실패와 보존

저장 실패·안전하지 않은 진입점·이동 실패·참가자/세션/세대 변경·종료·새 보스 생성/연결 실패는 HOLD로 남긴다. 자동 반복 실행하지 않고 해당 진행만 제한한다. 다른 진행을 함께 정지하지 않는다. 후보 보스 생성이 실패하면 기존 보스를 유지하고, 교체 후 연결 실패는 새 도전도 보류한다. 새 도전 성공으로 바꿔 기록하지 않는다.

인벤토리·퀘스트·보상·공동체 진행·월드 파일을 이전 스냅샷으로 되돌리거나 소비품을 복원하지 않는다. 여러 사람 중 일부의 이동/회복 이후 실패할 수 있으며 DB와 실제 Player 상태의 완전 원자성·자동 원상 복구는 보장하지 않는다. 기존 요청 식별자·오류 로그·DB 저장값을 보존하여 관리자 확인 대상으로 남긴다.

실제 Paper에서는 관리 몹과 DB·세션 저장을 검사했지만 참가자의 이동/회복은 기존 내부 제어 포트다. 실제 인증 플레이어의 채팅 수신·teleportAsync·GameMode/체력/아이템 동작·HUD 성공은 미검증이며 별도 요청 전 보류한다. 장기 부하·운영 배포도 미실행이다.

## 남은 범위

길목/체크포인트 초기화, 승리·전원 오프라인 뒤 일반 복귀와 새 도전 진입, 정식 인던 수명주기, 보스 상태의 프로세스 재시작 복구는 남아 있다. 과거 컷신/개인 퀘스트를 자동 초기화하지 않으며 전체 S4도 진행 중이다.
