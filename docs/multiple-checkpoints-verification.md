# 복수 체크포인트·지정 지점 재시작

2026-11-05. S4 진행 중. [기존 회복 구현](checkpoint-recovery-verification.md)을 확장했다. [검사 JSON](../verification/multiple-checkpoints-result.json).

## 변경

- 외부 `path.checkpoints`에 여러 지점을 정의하고 `restart-checkpoint`로 재시작 지점을 명시한다. 기존 단일 `path.checkpoint`도 그대로 읽는다. 중복 ID·없는 재시작 ID·두 형식 혼용은 활성화 전에 거부한다. 최대 16개는 이번 구현의 입력 상한이며 게임 밸런스 값이 아니다.
- 지점별 도달·회복·완료 기록을 독립 처리한다. 한 지점 완료가 다른 지점 처리를 막지 않으며 이미 완료한 지점은 반복 회복하지 않는다. 자동으로 마지막 지점을 선택하거나 순차 통과를 강제하는 새 규칙은 추가하지 않았다.
- 체크포인트 재시작 직전에 기존 도전 참가자의 신뢰하는 온라인 세션과 대상 개인 퀘스트를 비동기로 다시 조회한다. ACTIVE/REPORT_READY만 포함하며 완료자·미수락자·다른 진행은 제외한다. 기존 도달 당시 명단을 권한 근거로 사용하지 않는다.
- 조회 중 세션/온라인 명단·월드 세대가 바뀌거나 조회가 실패하면 재시작을 보류한다. 준비 작업도 기존 저장 장벽에 포함한다. 이후 기존 활성 기록 확인→저장→이동→구역 정리→새 도전 흐름을 사용한다.
- 무료 부활·생존자 포함 전원 최대 체력·기존 부활 사용 횟수 보존은 유지한다. 일반 서버 비활성 및 실제 클라이언트 시험 보류도 유지한다.
- V008의 기존 진행/던전/퀘스트/체크포인트 복합 키를 재사용한다. V001~V008과 기존 기록을 수정하거나 새 마이그레이션을 추가하지 않았다. 공개 합성 콘텐츠에만 두 번째 지점을 추가했다.

## 남은 범위

실제 인증 플레이어의 복수 지점 도달·체력·이동·화면은 미검증이다. 전체 전투 도전의 새 JVM 복원, 복수 길목 진행, 운영 배포·장기 부하는 이번 범위 밖이다. 복수 지점의 자동 진행 순서나 최신 지점 선택 정책을 확정한 것으로 해석하지 않는다. 운영 서비스·실제 월드·기존 시험 증거는 변경하지 않았다.
