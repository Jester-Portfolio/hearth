# 보스 재도전 채팅 투표·기존 도전 종료

2026-10-29 · 격리 개발 모드 · S4 진행 중.

## 구현한 연결

- 기존 전투·세션 조정자와 스토리 채팅 투표의 처리 방식을 재사용해 도전별 보스 운영 투표를 연결했다. 스토리 분기 투표의 저장·대상·결과는 변경하지 않았다. 새 투표 GUI·개인/공동체 알림·DB 테이블은 없다.
- `/hearthcombat retry`로 투표 요청, `/hearthcombat vote`로 상태 조회, 채팅의 찬성/반대/기권 링크로 투표한다. 기존 도움말·상태/관전 링크와 보스 HUD에도 요청 경로를 연결했다. 명령은 본인의 검증된 세션과 현재 보스 도전만 사용한다.
- 대상은 시작 명단 중 현재 온라인인 참가자다. 사망 관전자·복귀 중인 기존 참가자도 포함하고 오프라인·타 진행·신규 비참가자는 제외한다. 초기 30초, 전체 대상의 50% 초과 찬성, 중복 투표 차단, 기권/미투표 비찬성 정책을 적용한다. 미달/동률은 만료 시 미확정이며 다시 요청할 수 있다. 한 명도 명시적으로 찬성해야 한다.
- OPEN 중 대상 UUID 또는 세션 식별자가 바뀌면 기존 표를 폐기하고 새 투표 ID·대상·제한시간으로 재투표한다. 이는 보스 시작 명단·난이도 변경이나 도중 신규 참가 허용이 아니다. 오래된 ID·타 진행·중복 입력은 거부한다.
- 과반수 달성 시 INPUT_CLOSED로 먼저 입력을 마감한다. 이후 접속 변화로 득표를 재계산하지 않고 기존 부활 적용 장벽을 기다린 뒤, 아직 유효한 도전만 RETRY로 단일 종료한다. 먼저 확정된 승리/전원 접속 종료는 덮어쓰지 않는다. 세대 변경·적용 실패·종료/owner 전달 실패는 취소 또는 HOLD로 보존하며 성공으로 안내하지 않는다.
- 확정된 `(story_run_id, attempt_id, request_id)` 준비 요청 식별자를 보관한다. 같은 요청을 다시 읽어도 도전 종료를 반복 적용하지 않는다. 표 전체나 이 식별자를 DB에 영속화하지 않으며 프로세스 재시작에서 투표를 자동 복구하지 않는다. 기존 `combat-trials.started` 보호도 유지한다.

근거는 [ADR-0007](decisions/0007-dungeon-and-boss-operations.md)·[ADR-0011](decisions/0011-votes-boss-return-and-gathering-reset.md)·[ADR-0013](decisions/0013-vote-boss-and-gathering-state-boundaries.md)다. 외부 투표 플랫폼을 추가하지 않고 기존 Paper 채팅/API를 재사용했다. 일반 서버에서는 기존 격리 모드 게이트 밖으로 활성화하지 않는다.

## 아직 연결하지 않은 부분

**투표 통과는 기존 도전 종료와 다음 준비 요청까지다. 새 도전을 시작하지 않는다.** 다음 도전의 이동·집결·부활 횟수 초기화·길목 초기화·새 보스 생성 실행기는 미구현이다. 인던별 보스만/길목부터 재도전 정책을 임의 선택하지 않았고, 새 도전이 두 번 생성되지 않는다는 실제 실행 보장도 아직 시험하지 않았다. 채팅/도움말은 이 대기 범위를 명시한다. 기존 도전의 사망 상태나 소비 아이템을 초기화하지 않는다.
