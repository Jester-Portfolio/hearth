## 결정/추천/검증의 구분

사용자 확정은 ADR-0010~0012의 ‘사용자 확정’ 절입니다. 추천값은 복귀 보호3초·IDLE5분, 추천 모델은 작업ID/generation·지도층/DTO·백업 manifest입니다. 이들은 승인된 게임 규칙이나 구현 완료가 아닙니다. 물리 SQL·실제 Paper·부하·원형HUD 가능 범위는 S4 이관입니다. 단지 런타임을 실행하지 않았다는 이유로 위 충족 영역을 미충족으로 낮추지 않았습니다.

## 누락과 잠재 충돌 — 추측으로 해결하지 않은 항목

- **G1:** 대상 변경은 미확정 투표를 취소하지만 분기는 DB 영속 성공 뒤 확정해야 합니다. 투표 통과 직후 DB 요청 중 대상 변경/시간 만료가 오면 이미 commit한 분기를 어떻게 구분할지 경계가 미정입니다. 원자적일 수 없는 메모리/DB 사이 상태·취소 가능 시점·성공 안내 순서를 설계해야 합니다. 현재 문서가 어떤 경우에도 취소/rollback한다고 가정하지 않습니다.
- **G2:** ‘생존자가 남으면 지속’과 ‘정상 복귀까지 보호/개입 금지’ 사이에서 온라인 생존자가 보호자뿐일 때 일시정지/지속은 직접 지정되지 않았습니다. 기존 ‘전투 가능0이면 실패’로 해결하지 않습니다. 특수 퀘스트의 사망/시간 실패와 보스 전멸 대기/투표의 선후, 집결 당시 오프라인 생존자 처리도 검토가 필요합니다. 카메라/정확좌표 기술 문제와 구분한 게임 상태 설계 누락입니다.
- **G3:** 리셋 계기는 확정이지만 어느 플레이어/진행 범위를 ‘전원 퇴장’으로 판단할지 인던 소유 단위가 남았습니다. 피난 이동·개인 저장 일부 실패·초기화중 종료·다음입장 경합 시 실패/재시도/보류 전이를 단순 후보로 작성했으며 승인/정합 검토는 미완료입니다. 생성/배치 도구 자체는 S4 이관입니다.
- **G4:** S3 기존 완료 조건은 보호 이벤트 목록·콘텐츠 참조·검증 입력/결과 형식을 요구합니다. 결과 형식은 §12에 추가했으나 현 §8은 대표 이벤트 예시입니다. 모든 허용/차단 행위와 간접영향·외부/내부 변경 경로, 중첩 규칙과 정확한 동시 fixture를 완성/검토해야 합니다. 실제 이벤트 컴파일/실행은 S4입니다.

## 정합성 변경과 보존

가입 미정/관리자 관리 후보는 게임 기능에서 제외하고 player_uuid–story_run_id만 내부 식별로 둡니다. 보스 위험 좌표 보정은 정확좌표/방향 복귀로 대체하되 조건부 부활 안전성은 유지합니다. 채집 리셋·지도 공개·HUD 배치·채팅 투표/30초·개인 알림 제한은 확정, 구현 미정과 섞지 않습니다. 과거 비교/CHANGELOG·결정일은 보존하고 후속 배너로 대체 관계를 표시했습니다.

공개 문서는 실제 비공개 서사 없이 일반 시스템만 담습니다. 문서/보안 검사 성공은 위 미완료 설계의 통과나 S4 실행 승인이 아닙니다. 다음 작업은 G1~G4 추천 전이/행렬·fixture를 작성해 사용자 검토를 받는 것이며 이번에는 S4를 시작하지 않습니다.
