# 정식 스토리 초기화·고정 연결·저장 종료 검증

확인일: 2026-11-17. `b7836b3` 이후 승인된 시스템 개발의 연관 배치다. [ADR-0010](decisions/0010-coop-information-and-hud.md)·[ADR-0012](decisions/0012-progress-storage-world-lifecycle-and-content.md)의 내부 계정 연결/원본 보존을 따르며, [결과·원시 경로·횟수](../verification/story-runtime-result.json)와 [정식 실행 준비](../infrastructure/story/README.md)를 연결한다.

## 구현 범위

기본 비활성 `runtime-mode: story`를 추가했다. verification과 함께 켜지 않으며 정품/whitelist와 설정에 등록한 계정 UUID만 받는다. 서버가 정한 진행·물리 차원/UUID·원래 템플릿 버전/해시·콘텐츠 해시를 PG에 고정한다. 같은 진행의 다른 연결, 두 진행의 같은 물리 차원, 같은 계정의 다른 진행 경합을 거부한다. 가입/초대/파티 역할·클라이언트의 진행 선택 기능은 추가하지 않았다.

기존 PG 값·revision·슬롯은 갱신하지 않는다. 최초 빈 인벤토리/커서만 빈 저장을 생성할 수 있고 기존 개인 진행에 인벤토리만 없으면 HOLD한다. 미확인 아이템·다른 진행 소유 표식·늦은 접속 결과를 거부하며, PG 저장/조회 후 원래 세션/슬롯/소유 표식을 다시 확인한다. 새로운 연결 스키마만 별도 버전/체크섬으로 만들고 기존 스토리/경제 자료는 초기화하지 않는다.

이미 준비한 차원/진입 지역/소유 표식만 로드한다. 기존 WorldPersistence로 WorldGuard 로드·안전한 진입·개인 저장 장벽·구역/월드 저장·언로드를 연결했다. 서로 다른 경제/스토리 소유 표식은 양쪽 실행에서 거부한다. 새 빈 월드나 템플릿으로 누락/실패를 대체하지 않는다.

검토한 단일 콘텐츠 묶음으로 퀘스트/NPC·공유 진행·탐험/일지·보상/장 스킵·스마트폰·지도/장면/개인 엔더를 초기화한다. 스토리는 Ollama/스마트폰 구성을 필수로 요구하며 Mock으로 대신하지 않는다. 콘솔의 명시적 모델 준비는 유지하고 기동/접속이 추론을 시작하지 않는다. 콘솔 상태/비동기 drain과 배타적 실행 표식을 연결했다. 모든 저장/언로드·DB 종료 뒤에만 본인 표식을 제거하며 비정상/불명 상태는 원본과 HOLD를 유지한다.

## 검증과 영향 재검사

관련 단위 **19개 PASS**(신규 13개)다. 설정/미확인 인벤토리·외부 진행·저장 실패·늦은 응답을 검사했다. 새 JVM의 저장 계약을 포함하므로 같은 JAR의 두 Paper/한 격리 PG를 사용했다. CPU 2/nice 10·Paper heap 1536MiB/RSS 2560MiB·호스트 가용 6GiB·총 600초/작업 550초와 기존 localhost 경계를 유지했다.

1. 첫 실행은 시험 조정자의 물리 월드 없는 제어용 연결까지 준비하려다 **FAIL·33.248초**였다. 실패 원본을 보존하고 실제 차원 둘만 준비하도록 고쳤다.
2. 다음 실행에서 실제 PG 연결 경합·불변 콘텐츠/세계 소유권·기존 슬롯/공유 진행 보존·누락 인벤토리 HOLD·INSERT 실패의 전체 rollback을 통과했다. 둘째 JVM의 정상 모드 초기화·소유권/기존 저장 복원도 통과했다. 실제 접속자가 없는 상태에서 NPC 청크를 유지하지 않은 마지막 준비 가정은 **FAIL·101.565초**였다. 해당 결과와 미종료 HOLD/종료 확인 오류도 보존한다.
3. 마지막 실행은 성공한 SQL/접속 거부 시나리오를 다시 돌리지 않고 새 복원 입력만 준비했다. 명시적 격리 probe에만 NPC 청크 티켓을 걸고 판정 뒤 본인이 추가한 티켓을 제거했다. 정상 게임의 청크 유지 정책은 바꾸지 않았다. **51.162초·8개 assertion**에서 새 JVM의 정식 기동, 양쪽 소유권 거부/원래 표식 보존, 개인 슬롯 복원·활성 세계/세션·WorldGuard/NPC와 `PROBE PASS`, `DRAINED PASS`, `DISABLE_CLOSE PASS`를 실제 로그로 확인했다.

마지막 실행의 **원시 제어 결과는 FAIL**이다. 공통 제어기가 정상 스토리 전용 종료 로그 대신 격리 모드 로그를 요구한 오류 때문이다. 이후 종료 분류를 수정하고 **Python 5개 PASS**로 정상/다른 모드/누락/HOLD/비정상 종료를 확인했다. 같은 수정된 `Monitor.stop`을 마지막 원본 로그·종료 코드에 재적용한 별도 검사와 소유 PID 부재·기록된 포트 해제·실행 표식 제거를 통과했다. 원시 JSON은 고치지 않았고 별도 결과는 `PASS_AFTER_CONTROLLER_LOG_REPLAY`다. 종료 판정만을 위해 Paper/DB를 다시 기동하지 않았다.

성공한 PG/접속 검사의 JAR와 마지막 JAR에서 정상 스토리·저장/세션·기능/월드 경계의 본체/중첩 **28개 class가 동일**함을 확인했다. 테스트 유틸리티의 NPC 유지·최소 입력 준비 변경과 제어기 종료 분류를 구분한다. 단위/실제 DB 성공 검사를 이유 없이 반복하지 않았다.

## 남은 범위

실제 Minecraft Player·접속/소유 표식·이동·NPC 클릭·UI는 실행하지 않았다. 이동 성공 값을 반환하는 제어 Port와 실제 PG/WorldGuard/엔티티의 검사이며 실제 teleport 성공이 아니다. 이 배치의 새 AI 추론은 없고 기존 [합동 관측](s5-joint-observation-verification.md)을 반복하지 않았다. 실제 모델 준비/품질·전체 S4/S5 수용·운영 배포 완료를 뜻하지 않는다.

정상 콘텐츠 묶음의 제작/채집/호위/던전/전투·거점 이동·세계 효과 연결, 새 진행 템플릿 준비 자동화와 저장 콘텐츠의 호환 이관은 후속이다. 해당 기능의 기존 개발 모드 구현/검증과 구분한다. 콘텐츠/밸런스·실제 플레이·운영 적용/상시 예산은 별도이며 기존 운영 서비스와 원본 `/tmp` 증거를 변경하지 않았다.
