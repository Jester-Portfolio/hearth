# 스마트폰 지도·일지·관련 NPC 연결

## 구현

기존 스마트폰 Dialog의 장소·지역·일지 상세에 **관련 정보**를 연결했다.

- 발견 장소에서 공개 지역과 본인에게 실제 저장된 발견 일지를 연다. 지역에서는 현재 공개된 장소만 나열한다. 미발견 장소의 물음표는 기존 공개 범위만 사용하며 숨겨진 이름·원본 좌표·일지 연결을 공개하지 않는다.
- 개인/공유 일지에서 동일 소유 범위의 최초 연대기 기록을 열고, 과거 기록에서 현재 일지로 돌아간다. 새 사실로 현재 기록이 갱신되어도 과거 제목·상세는 덮어쓰지 않는다.
- 본인 일지에 이미 기록했고 현재 질문 공개 조건을 충족한 NPC만 대화 대상으로 표시한다. 기존 `NpcContacts`와 NPC 거리·월드·엔티티·지역/WorldGuard 검사를 재사용하며 멀리 있는 NPC로 이동시키거나 권한을 우회하지 않는다.

연결 목록은 6개씩 표시하고 페이지·원래 정보·이전 정보 이동을 제공한다. 정렬 위치 대신 내부의 소유 구분/기록 ID/버전으로 대상을 다시 찾는다. 클릭 후 최신 개인 조회를 비동기로 수행해 세션·화면·HOLD·기록 내용·현재 연결 권한을 재검사한다. 기록 갱신·삭제·공개 조건 변경 후 옛 요청은 거부하며 조회 오류를 빈 기록/성공으로 처리하지 않는다.

`PhoneReaderLinks`는 승인된 조회 스냅샷만 사용한다. 내부 연결 키는 본문이나 AI 문맥에 넣지 않으며 기존 `PhoneLibrary.Entry`/공개 게임 정보 형식은 유지한다. 지역 이름이 중복되어 연결을 구분할 수 없으면 추측하지 않는다. `QuestJournal.placeFacts`는 발견했고 본인의 개인 기록이 실제 존재하는 장소의 연결만 반환하며 대기/실패 HOLD/종료 상태에서는 거부한다.

신규 스키마·아이템/보상·퀘스트 완료·공유 분기·거점 해금·빠른 이동·AI 호출을 추가하지 않았다. 관련 정보를 읽는 것만으로 발견이나 알림을 생성하지 않는다. 일반 서버는 기존 비활성 상태를 유지한다.

## 검증

- 관련 단위·회귀 **55개 PASS**, 컴파일/JAR PASS. 개인/공유 동일 ID 구분, 최초/현재 기록 왕복, 변경된 정렬 위치의 올바른 대상 복원, 갱신/삭제 후 stale 요청, 위조 NPC/다른 플레이어 정보 차단, 물음표/비공개 정보, 40개 NPC 연결의 고유 키·페이지 분리, 대기/HOLD/종료 및 기존 조회 경합을 검사했다.
- **Paper 한 JVM·격리 PostgreSQL 한 개 PASS**, 한 묶음 **47.616초**. 기존 `--sessions --quests --story-batch --npc-topics --npc-pages --phone-dialog`를 재사용했다. 실제 발견·일지/연대기 저장값에서 지도↔일지↔최초/현재 기록과 기존 NPC 검증 경계를 연결하고 Dialog 객체를 생성했다. 조회 전후 장소/일지/연대기·revision·알림/추적/표시 설정·41슬롯 스냅샷 불변, P2/다른 진행의 개인 정보 비노출을 확인했다.
- 같은 묶음의 기존 중요 답변 저장 충돌 시험에서 HOLD·원본 기록 보존·다른 진행 불변을 확인했다. 도구·저장 경계를 재사용했으며 별도 시험 프레임워크나 새 저장 경로를 만들지 않았다.
- 최종 빌드/설치 JAR 해시 일치, 정상 종료와 소유 프로세스/포트 반환 PASS. 자원·원시 실행 경로·세부 판정은 [결과 JSON](../verification/phone-reader-links-result.json)에 기록했다. 저장/복원 계약이 같아 두 번째 JVM은 반복하지 않았다.

## 미검증·다음

실제 인증 클라이언트의 Dialog 클릭·페이지 배치·NPC 재대화·이동/권한 변경은 미실행이다. 서버 객체·내부 컨텍스트 성공을 실제 사용자 행동 성공으로 보지 않는다. 실제 시험은 별도 요청 전 보류한다. S4는 진행 중이며 다음 기능 배치에서도 기존 게임플레이 연결과 승인된 정보 경계를 재사용한다.
