# 코스의 장소·일지·연대기·공유 정보 연결

> 최신 결과: 이 배치의 필수 통합은 [누적 배치 최종 통합](pending-batch-review.md)에서 같은 최종 JAR로 통과했다. 아래는 환경 차단 당시의 최초 구현·검사 기록이며 현재 미완료 목록이 아니다.

확인일: 2026-11-09. 기준 `7dd0750` 이후의 미커밋 작업 트리. [공개 코스 진행판](playthrough-overview-verification.md)과 기존 [장소·일지 연결](phone-reader-links-verification.md)의 조회·공개 경계를 재사용했다. **구현·직접 컴파일·관련 단위 검사는 통과했으나 필수 Paper 통합은 환경 제한으로 미실행**이다. 수치·원시 로그 경로는 [검증 JSON](../verification/course-records-result.json)에 기록한다.

## 연결한 플레이 흐름

- 진행판의 장소 항목에서 공개된 장소 정보를 읽고, 개인 발견 일지→최초 연대기→현재 기록으로 이동한다. 같은 지역의 공개 장소도 조회할 수 있다. 책과 스마트폰은 같은 화면 모델과 기존 `PhoneReaderLinks`·`PhoneLibrary`를 사용한다.
- 공유 단계 항목은 **현재 공동체 상태**로 연결한다. 현재 공유 목표·접속자 조건·확정된 분기를 읽는다. 과거 단계의 당시 상태를 재현하거나 미래 단계의 조건을 추정하지 않는다. 선택 자체로 투표·진행·보상·이동은 실행하지 않는다.
- 본문과 관련 링크를 함께 쪽 나누기하며 한 쪽의 관련 링크는 최대 6개다. 이전 정보·새로고침·진행판 복귀를 제공한다. 같은 정보로 돌아가는 순환은 경로를 접고, 경로 길이는 최대 8개로 제한한다. 공개 항목의 위치가 달라졌다면 새로고침 후 선택한 항목의 현재 진행판 쪽으로 복귀한다.
- 처음 선택할 때 진행판·행·쪽을 검사한다. 이후 쪽 이동과 관련 링크 선택도 최신 진행판, 현재 기록의 본문/버전·연결 목록, 현재 쪽의 선택 가능 링크를 확인한다. 새로고침/뒤로 가기도 시작 항목과 경로의 모든 연결을 현재 공개 DTO로 다시 확인한다. 사라진 연결을 빈 기록이나 성공으로 대체하지 않는다.
- 미발견 장소는 기존 공개 DTO의 위치/이름만 표시하고 발견 일지를 연결하지 않는다. 개인·공유 기록은 `P:`/`S:` 경계를 그대로 사용한다. 원본 장소 경계·비공개 제목/설명·다른 사람의 기록을 읽지 않는다. 공개된 식별자도 본문/버튼에는 이름으로 표시하며 식별자는 내부 연결에만 사용한다.
- 책은 기존 플레이어·세션·화면 표식·NPC 유효 조건을, Dialog는 기존 플레이어·세션·화면 세대를 유지한다. 조회 실패/공개 범위 변경 시 재조회·진행판 복귀 경로를 제공한다. 새 DB·저장/이동 정책·플러그인·설정·런타임 활성화는 추가하지 않았다.

## 남은 필수 통합과 Git 반영

기존 `courseRecordScreens`를 진행판 객체 검증에 연결했다. 해당 조회에 공개 장소/현재 단계가 있을 때 최신 DTO 기반 기록 화면·책/실제 Dialog 객체·새로고침·41슬롯 보존을 검사한다. 준비 안내의 신규 fixture는 기존 `journal.enterPlaces`로 개인 발견 기록을 먼저 저장한 뒤 조회 불변 검사의 기준을 잡는다. 그 실제 DB 조회의 `journal.placeFacts`에서 장소→개인 일지→최초 연대기→이전 정보 경로도 검사하도록 추가했다. 이 준비는 서버 내부 데이터 API 호출이며 Player 이동·채집을 증명하지 않는다. **이 Paper/PG 검사 코드는 이번에 실행하지 않았으므로 PASS를 주장하지 않는다.**

현재 미검증 배치는 기존 `--sessions --crafting`, `--sessions --quests --story-batch --crafting-quests`, `--sessions --quests --story-batch --combat-players --dungeon-play --play-preparation` 경로에서 최종 코드로 함께 검사한다. 이번 객체 검사도 마지막 준비 안내 경로에서 실행되므로 별도 Paper 기동을 추가하지 않는다. 독립 확인은 기존 `--sessions --quests --story-batch --quest-navigation --phone-dialog` 경로를 사용할 수 있다. 기존 stage/필수 인자·새 사용자 소유 `/tmp/hearth-s4-11.*`·EULA·자원/시도 한도를 유지한다.

저장/복원 계약은 불변이어서 두 번째 JVM/DB 재시작을 추가하지 않는다. 필수 통합 통과 후 원격 기준을 확인하고 승인 파일만 Git에 반영한다. 실제 인증 사용자의 장소/기록 클릭·경로 왕복·권한 변화·읽기 화면 가독성과 운영 배포는 미검증이며 클라이언트는 사용자 요청 전 보류한다.
