# 임시 제작칸·월드 보관함·개인 저장 통합

확인일: 2026-11-09. 기준 `f51432d` 이후 코드. 기존 세션/41슬롯·비동기 dirty 저장과 [ADR-0003](decisions/0003-inventory-performance-and-recovery.md), WorldGuard 보호를 재사용한다. S4는 진행 중이며 일반 서버/운영 환경을 자동 활성화하지 않는다. 상세 명령·실패·수치·원시 증거는 [검증 JSON](../verification/inventory-workspaces-result.json)에 기록한다.

## 연결한 기능

- 개인 순정 2×2 제작 입력칸과 허용된 일반 작업대 3×3 입력칸, 월드의 상자·이중 상자·덫 상자·통에서 클릭/드래그·Shift·숫자키·보조 손 교환·슬롯 버리기를 기존 행동 제한 안에서 처리한다. 결과 슬롯은 한 번씩 좌/우 클릭해 받으며 Shift/숫자키 제작과 더블클릭 수집·바깥 클릭·크리에이티브 이동은 허용하지 않는다. 등록 작업대의 기존 제작 메뉴·일괄 제작·개인 의뢰 연결은 보존한다. 순정 제작으로 의뢰 목표를 임의 확정하지 않는다.
- 제작 입력과 커서를 별도 영속 슬롯으로 늘리지 않고 기존 보관 36칸에 합친 **41슬롯 사본**을 저장한다. 결과 미리보기와 세계 보관함 전체 내용은 개인 snapshot에 포함하지 않는다. 같은 메타데이터/최대 수량 안에서만 합치며 보관 스택이 나뉘어 반환 공간이 부족할 때만 같은 스택을 압축한다. 장비/보조 손으로 넘치게 넣지 않는다. 일반 캡처는 실제 슬롯을 변경하지 않는다.
- 닫기·명령/개발 화면 전환·보상/이동의 저장 장벽·퇴장에 같은 반환 함수를 사용한다. 먼저 전체 반환 사본을 계산하고 나서 적용·제작 입력/미리보기·커서를 정리한다. 정상 동작의 반환 공간은 클릭/드래그·획득과 결과 수령 전에 확인하며, 계산 실패는 실제 이동 전에 거부한다. 정리 실패는 기존 lease/HOLD와 오류 표식을 유지하고 빈 값으로 저장하지 않는다.
- Paper 제작 계산 API의 3×3 배열에 개인 2×2 좌표를 명시적으로 매핑한다. 실제 제작 결과·남은 입력·우유 양동이/꿀병 같은 반환 용기와 추가 부산물의 보관 공간을 검사한다. 추가 부산물은 실제 보관 슬롯에 들어갈 공간이 있을 때만 결과 수령을 허용하며, 계산만으로 아이템을 지급하지 않는다. 실제 이동·소비·제작은 Minecraft 처리 경로다.
- 보관함은 현재 열림을 승인받은 세션·인벤토리·진행 월드/세대와 실제 현재 블록 인벤토리를 결합한다. 매 동작에 현재 화면·유효 세션·거리·진행 접근·WorldGuard `CHEST_ACCESS`/`INTERACT`를 재검사하고 이중 상자의 양쪽을 확인한다. 일반 작업대는 `USE`/`INTERACT`를 확인한다. 다른 플러그인의 취소를 해제하지 않으며, 권한 변경 직후에도 WorldGuard의 현재 적용 영역으로 판단한다. GUI·분리된 snapshot·다른 진행·기존 세대 화면은 보관함으로 인정하지 않는다.

일반 보관함 내용은 월드 파일에, 개인 인벤토리는 기존 PostgreSQL에 저장한다. 클릭별 SQL·동기 flush·새 스키마·월드/DB 원자화·아이템 이동 원장은 추가하지 않았다. 기존 30초 dirty 저장·단일 in-flight·CAS와 source 저장 뒤 이동/보상 순서를 유지한다. [기존 적합성 검토](plugin-suitability-review.md)의 WorldGuard와 Paper 순정 인벤토리/제작 API를 연동하며 새 플러그인을 도입하지 않았다.

- main/test 컴파일·Gradle JAR·신규 격리 runtime stage PASS. 초기 통합 fixture 컴파일의 누락 import를 수정했다.
- 신규 `--sessions --inventory-workspaces`의 **56회 세션 assertion PASS**, **47.699초**다. - 같은 최종 JAR의 기존 공개 코스 `--s4-gameplay`도 **375회 assertion PASS**, **119.89초**다. 기존 조사·채집/두 도구 제작·호위/실패 재개·투표·던전·탐험·결과·최종 월드 재연결 보존을 통과했다. 별도 새 PG/Paper 1 JVM을 순차 실행했고 설치 해시·DB 풀/프로세스·포트 정리를 확인했다.

## 미검증·남은 범위

실제 인증 클라이언트의 열기·좌/우/Shift/숫자키·드래그·결과 수령·동시 보관함 이동·닫기/접속 종료·다른 플러그인의 이벤트 경합은 사용자 별도 요청 전 보류다. 제어 세션·순정 ItemStack/제작 계산·실제 블록/WorldGuard/DB 검사는 실제 Player 이벤트/클릭 성공이 아니다. 가짜 Player나 인증 우회는 사용하지 않는다.

엔더 상자·이동식 보관함·화로/호퍼 등 가공/자동화 시설은 계속 제한하며 전부 허용하지 않는다. DB 저장 포맷은 기존 41슬롯 그대로다. 월드 파일과 개인 DB의 비정상 종료 시점 차이는 ADR-0003의 수동 대응 범위를 유지하고 자동 무손실/모든 장애에서 중복 0건을 보장하지 않는다. 운영 배포·실제 데이터 보정은 하지 않았다.
