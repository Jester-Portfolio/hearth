# Hearth 개발 로드맵

마지막 정리: 2026-10-28. [현재 구현·검증 상태](PROJECT_STATUS.md), [설계 정본 ADR](decisions/README.md), [작업·검증 정책](DEVELOPMENT_WORKFLOW.md)을 함께 사용한다. [이전 로드맵](ROADMAP-archive-2026-10-27.md)은 이력으로 보존한다. 아래 계획은 새 기능 구현·실행·운영 변경의 일괄 승인이 아니며 일정·밸런스·미정 기술을 확정하지 않는다.

## 개발 목표와 상태 기준

Hearth의 목표는 현대 과학·기술 지식을 활용하는 싱글·소규모 코옵 스토리 RPG와 별도 경제 월드다. 테스트는 이 게임을 완성하기 위한 검증 수단이다. 다음 작업은 실제 기능이나 플레이 흐름을 완성하는 중형~대형 배치로 선정한다. 토큰 절약을 위해 승인 범위를 줄이거나 기술 시험만 반복하지 않는다.

- **완료**: 해당 단계의 명시한 완료 조건을 충족. 설계 완료는 구현·실행 검증 완료와 다르다.
- **진행 중**: 구현 또는 검증을 시작했으며 완료 조건이 남음.
- **예정**: 후속 계획이며 착수·완료를 뜻하지 않음.
- **보류**: 재개 조건·사용자 결정을 기다림.

## S4 후속 기능 배치의 선정 방향

아래는 **다음 작업 추천·범위 협의 기준**이며 모두의 즉시 구현을 확정하지 않는다. 기존 구현은 재사용하고 각 배치의 승인 범위·완료 조건을 정한 뒤 연속 개발한다.

| 배치 방향 | 기능적으로 의미 있는 결과물 | 재사용 기반·주요 선행 조건 | 완료 판단 |
| --- | --- | --- | --- |
| 1. 공개 테스트 게임플레이 통합 — 우선 추천 | NPC 대화·개인 다단계 퀘스트·공유 중요 단계/분기·탐험 개방·스마트폰 안내가 이어지는 공개 합성 플레이 흐름 | 기존 NPC/퀘스트/공유 진행/탐험/GUI·저장 기반. 현재 연결 공백과 상호작용 범위를 먼저 특정; 비공개 서사 사용 금지 | 선정 흐름의 시작~완료, 개인/공유 구분, 재접속 보존, 정보 공개 경계가 함께 동작. 자동 검증과 후속 실제 행동 검증을 구분 |
| 2. 핵심 플레이어 상호작용·승인 게임 기능 보완 | 기존 흐름에서 빠진 NPC/퀘스트 동작·플레이 피드백을 연결하고 해당 기능의 실패·상태 보존을 완성 | 승인 ADR 및 현재 미구현 목록. 컷신·실패/재시작·전투/관전/부활 등은 필요한 범위를 별도로 선정; 미정 정책은 구현 전 결정 | 선정한 기능의 정상·예외 흐름과 기존 인벤토리/보호/세션 경계 유지. 무관한 다음 시스템까지 자동 확장하지 않음 |
| 3. AI 연동용 게임 정보 조회 통합 | 실제 퀘스트·NPC·탐험·일지·공유 진행의 권한 있는 조회를 일관되게 제공 | 기존 공개 DTO·개인/공유 소유권. NPC 정보의 미해결 은폐 범위 확인 | 다른 진행·개인의 비밀과 미발견/미공개 데이터 비노출, 늦은 응답·HOLD 처리. S5 AI 실행을 완료로 보지 않음 |

Issue #1·#2의 격리 단일 블록 효과는 완료한 기술 기반이다. A/B 효과 추가나 시험 시나리오 확장을 미완성 게임 기능보다 우선하는 다음 배치로 삼지 않는다. Issue #3은 `not_planned` 종료 상태이며 재착수 대상으로 삼지 않는다.

실제 인증 클라이언트의 NPC·채팅·이동·GUI·나머지 보호/권한 검증은 별도 요청 전 보류한다. 보류 중에도 독립적인 구현·자동 검증을 계속하며 실제 행동 미검증은 남긴다. 지형 지도·원형 미니맵·고정 HUD 목표는 기술·사용성 검증이 필요하고, 개발 표시나 GUI 객체 생성만으로 완성 판정하지 않는다.

## 공통 완료 경계

- 설계·구현·자동 검증·실제 플레이·운영 배포를 구분한다. 게임 정의와 미정 정책은 [ADR](decisions/README.md), S3 설계 완료 근거는 [감사](s3-completion-audit.md)를 따른다.
- [ADR-0003](decisions/0003-inventory-performance-and-recovery.md)의 성능 우선·30초 dirty 비동기 저장, 거래 즉시 저장·보상 중복 방지·전환 전 source 저장 원칙을 유지한다. 거래/보상 전체 구현은 아직 없다. 고비용 체크포인트·완전 자동 무손실 복구를 완료 조건에 추가하지 않는다.
- 기존 진행·월드·인벤토리·콘텐츠를 보존하고 필요한 오류 기록·로그/백업 기반 관리자 수동 대응을 마련한다. 승인된 기능 범위에서 기성 플러그인 검토와 위험별 필수 검증을 수행하며 같은 성공 검사를 반복하지 않는다.
