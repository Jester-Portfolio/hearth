# 상품 공급망·공개 경제 플레이 안내

확인일: 2026-11-08. 기준: `0be39ec`. [결과 JSON](../verification/economy-supply-result.json)에 실제 실행·실패 이력·자원·소스/JAR 식별자를 기록한다. 기존 [실적/제조/사건](economy-flow-verification.md)과 [수량/확정](economy-quote-verification.md)을 재사용한다.

## 구현

- `EconomySupply`가 공개 지역별 시장·취급 상인/위치·상품 생산시설·재료 사용처·중복 없는 운송로를 읽기 전용 DTO로 만든다. 기존 `EconomyReport.Definition`의 공개 필터를 먼저 적용하며 계정/인벤토리/물리 식별자는 담지 않는다.
- `guide-steps`와 단계별 kind/region/reference/title/text로 공개 합성 안내를 정의했다. 광산 철광석 시장 → 자동 운송 → 수도 제련 → 수도 철괴 거래를 현재 공개 데이터에 연결한다. 없는 연결·중복 ID·미공개 참조는 로드 전에 거부하고, 기존 안내 미등록 파일은 그대로 유지한다.
- 안내는 퀘스트 상태나 보상을 만들지 않는다. 시장 자동 운송과 개인 가방을 구분하고 직접 제작/자동 이동/무역 수익 보장을 안내하지 않는다. 다른 지역/취급하지 않는 상품의 노드는 참고 조회로만 연결한다. 실제 거래는 직접 방문한 상인의 최신 견적 확인/확정 경로를 사용한다.
- 기존 상점/상품 화면에서 공급망·상품 선택·안내·지역 시장/시설/운송·본인 기록으로 연결한다. 같은 상품의 화면/페이지는 한 조회 결과를 재사용하며 새로고침·다른 상품 선택에서만 다시 조회한다. 기존 실적 Lore는 여러 줄로 나눴다.
- 기존 세션·상인 선택·엔티티·거리·세대·nonce·busy·다음 틱 전환 및 41슬롯 보호를 유지한다. 늦은 결과를 다른 세션/상인에 표시하지 않는다. DB는 기존 제한 worker와 realm 잠금 안에서 일관된 snapshot/실적을 조회한다.
- 새 SQL/의존성/경제 규칙·운영 활성화는 없다. E001~E003과 계정/시장/거래 저장 규약은 변경하지 않았다. 안내 메타데이터를 추가해도 기존 시뮬레이션 content hash는 바뀌지 않는다.

첫 묶음 `/tmp/hearth-s4-11.P24l6LKE`는 잘못된 상품 ID의 인자 예외를 저장 오류 코드로 기대해 실패했다. 기능은 요청을 거부했고, 검증기의 기대 예외 타입만 수정했다. 원시 FAIL/풀 종료 확인 누락은 보존하며 후속 검사로 PID/DB PID 파일/25585·37977 포트 반환을 별도 확인했다. 변경 없는 단위 검사는 반복하지 않고 JAR만 다시 빌드한 뒤 새 경로에서 재시험했다. 총 2묶음을 사용했다.

새 조회는 같은 realm의 기존 snapshot/실적을 한 DB 작업으로 읽고 공개 DTO를 생성한다. 같은 화면의 페이지 전환에는 추가 DB 작업을 만들지 않는다. 큰 콘텐츠의 투영 비용이나 TPS 개선율은 측정하지 않았다. 경제 계산/저장·복원 계약은 바뀌지 않아 기존 90일/두 JVM 전체 시험은 반복하지 않았다.

## 미검증

실제 클라이언트의 NPC/GUI 클릭·가독성·인벤토리 조작·이동은 보류다. 이번 PASS는 GUI 객체·내부 세션·실DB 관측이며 실제 플레이어 성공이 아니다. 운영 규모 부하/TPS/MSPT·장기 누수·DB 프로세스 재시작·운영 배포는 미실행이다. S4와 경제 E1~E3는 완료하지 않았다.
