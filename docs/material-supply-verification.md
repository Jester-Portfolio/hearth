# 채집 자원·제작 재료·개인 의뢰 연결

확인일: 2026-11-08. 기준 `99d2270`. [채집 인던](gathering-dungeon-verification.md)과 [제작 의뢰](workshop-quest-verification.md)의 저장/세션 경계를 재사용했다. 상세 수치와 두 실패 기록은 [JSON](../verification/material-supply-result.json)을 따른다. S4는 진행 중이며 일반 서버에서는 비활성이다.

## 연결한 기능

- 공개 채집 구역의 원목 → 작업대 판자·막대기·나무 곡괭이 → 채집 구역의 돌/조약돌 → 돌 곡괭이 → NPC 보고를 연결했다. 입퇴장은 기존 `/hearthgather enter`, `/hearthgather leave`를 사용한다.
- 새 개인 의뢰 `gathering_workshop_route`는 구역 방문 → 나무 곡괭이 실제 제작 → 재방문 → 돌 곡괭이 실제 제작 → 보고를 기록한다. **방문 목표는 채굴/획득 횟수를 세지 않는다.** 이미 가진 재료도 순정 제작에 사용할 수 있으며 아이템 제출·별도 보상은 없다.
- 제작 상세의 재료 아이템에 필요·보유·부족 수량을 표시하고 `재료 다시 확인`을 추가했다. 본인 보관 슬롯 0~35의 실제 제작 가능 재료만 집계하며 이름/메타데이터가 다른 아이템·방어구·보조 손은 제외한다. 조회와 갱신은 인벤토리를 변경하거나 DB를 조회하지 않는다. 확인 시 기존 재료/공간/세션 검사를 다시 수행한다.
- `/hearthgather info`는 같은 진행의 등록 구역 상태·본인 입장 등록·이용 인원·초기화 대기를 읽기 전용으로 안내한다. RESETTING/HOLD를 이용 가능으로 표시하지 않는다. 다른 사람의 개인 진행이나 인벤토리를 표시하지 않는다.
- 기존 지도·개인 일지·추적·책/스마트폰 공용 상세와 다음 플레이 안내에 새 코스를 연결했다. 일반 아이템 획득 알림은 추가하지 않았다.

원목/돌은 [새 채집 정의](../src/main/resources/gathering-workshop-demo.yml), 의뢰/장소/일지/돌 곡괭이 레시피는 [새 코스 정의](../src/main/resources/gathering-workshop-course.yml)에 둔다. 기존 광석 템플릿과 퀘스트 ID를 보존한다. 신규 레시피는 명시한 기존 시설에만 추가하며 ID 덮어쓰기·없는 시설·잘못된 연결은 거부한다. 일반 컨테이너 허용이나 전용 획득/자동 지급 엔진은 만들지 않았으며 기존 순정 드롭·Paper 레시피·WorldGuard로 충분해 외부 플러그인은 추가하지 않았다.

## 저장·초기화 경계

개인 소유권은 계속 `story_run_id + player_uuid`다. V001~V009와 41슬롯 형식을 바꾸지 않았다. 일반 획득은 기존 dirty/30초 저장에 연결하고 입퇴장·제작 목표 반영은 기존 저장 장벽을 사용한다. 제작 목표와 일치할 때 source 저장 성공 후 퀘스트 CAS를 수행한다. 아이템마다 DB 트랜잭션을 만들거나 원장/완전 자동 장애 복구를 추가하지 않는다.

채집 초기화는 기존 세대·원본 보존·전원 퇴장 후 다음 입장 규칙을 따른다. 시험 코스의 바닥 준비에서 등록 채집 영역을 제외해 최초 템플릿의 소유권 검사가 기존 블록을 덮어쓰지 않게 했다. 새 콘텐츠는 신규 격리 경로에서만 준비했으며 기존 채집 월드의 자동 이전을 구현하지 않았다. 60초 설정은 공개 시험 데이터이며 운영 주기 확정이 아니다.

| 실행물/정리 | 최종 소스 빌드 JAR과 설치/실행 JAR 해시 일치. 임시 청크 티켓 해제, 정상 종료·모든 프로세스/포트 반환 PASS |

첫 실행은 아이템 엔티티 조회 단계에서 실패했다. 두 번째에는 취소되지 않은 실제 ItemSpawnEvent를 관측했지만 플레이어 없는 청크가 `BORDER`여서 엔티티 유효성 확인이 실패했다. 마지막 실행은 시험 코드에서만 소유 청크 티켓을 잡고 `ENTITY_TICKING`을 다음 틱으로 나눠 기다린 뒤 파괴/드롭을 관측했다. [Paper의 청크 처리 구분](https://jd.papermc.io/paper/26.2/org/bukkit/Chunk.LoadLevel.html)과 [블록 드롭 API](https://jd.papermc.io/paper/26.2/org/bukkit/block/Block.html)를 참고했으며 실제 실행 대상은 기존 build 134다. 티켓은 성공/실패 뒤 본인이 추가한 것만 해제한다. 앞선 두 실행의 자동 DB 풀 종료 확인 누락과 별도 PID·포트 반환 확인도 JSON에 남겼다.

최종 실행은 49.309초, Paper 최대 표본 RSS 1200.1MiB·CPU 84.08초였다. 묶음당 Paper 1회·PG 1개, 600초·힙 1536MiB·RSS 2.5GiB·가용 RAM 6GiB·CPU 2/nice +10 제한을 유지했다. 총 세 묶음에서 실패 증거를 보존했고 통과한 단위 시험은 시험 환경 관측 수정 때문에 반복하지 않았다. TPS/MSPT·장기 부하는 측정하지 않았다.

## 실행 및 미검증

새 사용자 소유 `/tmp/hearth-s4-11.*` 경로를 기존 stageLifecycleRuntime으로 준비한 뒤 `verify-lifecycle.py`의 필수 인자와 `--sessions --quests --story-batch --gathering-crafting --accept-eula`를 사용한다. 기존 도구를 확장했으며 설정 `gathering-workshop-verification-enabled`는 기본 꺼짐이다.

**실제 플레이어의 채굴·줍기·도구 내구도·입퇴장 이동·NPC/GUI 조작은 미검증**이다. 시험용 인벤토리 투영은 실제 PlayerInventory/EntityPickupItemEvent 검증이 아니다. 실제 클라이언트 시험은 사용자 요청 전 보류한다. 저장/복원 계약은 그대로여서 두 번째 JVM·DB 프로세스 재시작과 이전 전체 회귀 반복은 생략했다. 운영 서비스/DB/월드·기존 증거·비공개 스토리는 변경하지 않았다.
