확인일: 2026-10-27. main·작업 트리/스테이징이 깨끗했고 fetch 후 기준 `4220232ba5f67d6d37e6a7d30718d4305a3dcb7b`와 origin/main이 일치했습니다. 격리 개발 모드만 구현·검증했으며 **전체 S4는 진행 중**입니다.

## 구현과 사용 경로

| 범위 | 구현 |
| --- | --- |
| 공유 단계 | `story-demo.yml`의 첫 단계·다음 단계/분기·공개 목표·진입/완료 조건. `SharedStory`가 run별 owner 순서화·revision CAS·완료 단계 기록을 관리. 미등록 단계/조건·순환/누락 참조·중복 정의는 진행하지 않음 |
| 조건 | 같은 run의 검증된 실제 온라인 연결만 대상으로 개인 퀘스트 COMPLETED를 확인. 한 명이라도 미충족이면 차단, 오프라인 제외·단독 대상 허용. 검사 전후의 명단/세션 토큰·generation/revision과 쓰기 직전 atomic fence 확인. 개인 조건 ID/제목은 타인에게 공개하지 않음 |
| 투표 | 기본 채팅 개발 명령 `/hearthstory vote` 및 현재 선택지의 채팅 클릭 링크. 30초·전체 대상50% 초과·중복 차단·기권/미투표 비찬성·동률/미달 미확정. OPEN 명단 변경은 취소/조건 재확인 후 새 vote ID로 재투표. 입력 마감 후에는 명단/시간 변화로 결과를 바꾸지 않음 |
| 영속 분기 | 입력 마감→DB 대기→같은 run revision/조건·필드 길이를 포함한 fingerprint·고유 요청 ID 검증→분기/단계/주요 일지 트랜잭션→DB 성공 확인→공유 캐시·안내. 같은 요청은 fingerprint 확인 후 멱등 조회, 다른 경쟁 요청은 CAS 거부. 확정 분기는 불변 |
| 불명·실패 | 확실한 저장 실패는 HOLD와 이전 캐시/DB를 보존. commit 불명/연결 계열 오류는 RESULT_UNKNOWN으로 보류하고 같은 요청 receipt만 조회. 없다는 이유로 새 분기를 확정하지 않음. 긍정 receipt와 fingerprint 확인 후 상태 복원. 다른 run은 계속 동작 |
| 탐험 개방 | 제작자 지정 `opens-exploration` 단계 진입과 같은 트랜잭션에서 공유 개방을 저장. 공유 캐시/지도/공동체 조회와 연결. 개인 퀘스트·방문·거점 해금·보상을 완료시키지 않음 |
| 지역 접근 | 외부 지역 bounds와 OPEN/ENTRY/CONTENT·필요 공유 단계 정의. 실제 세션의 PlayerMoveEvent와 기존 허용된 teleport 경계에서 ENTRY 검사. CONTENT는 NPC 대화/퀘스트 목록·상세/목표/추적 HUD/발견/지도 공개를 제한. WorldGuard 건축 권한을 변경하지 않음 |
| 스마트폰·일지 | 현재 단계/다음 공개 목표·온라인별 조건 충족 여부·지도 접근 상태. 확정 분기는 퀘스트 메뉴에서 조회하며 공유 사건·선택된 분기만 일지/연대기에 기록. 중복 기록/개인 알림 생성 없음 |

`/hearthstory next`는 등록된 다음 단계 조건을 확인하고 전이를 요청합니다. 현재 분기가 필요하면 투표를 요구합니다. `/hearthstory vote VOTE_UUID CHOICE_ID`는 현재 연결의 본인 표만 받으며 run/player 인수를 받지 않습니다. `/hearthstory resolve`는 불명 요청만 같은 ID로 확인하고 `/hearthstory refresh`는 불명 이외 HOLD의 DB 재조회 경계입니다. 조회·투표 안내를 개인 알림 DB에 저장하지 않습니다. 온라인 조건에는 접속 중이지만 준비가 끝나지 않은 검증 연결도 포함될 수 있으며 실제 준비/이동/개인 조작 허용은 기존 세션이 따로 검사합니다.

## 저장·스레드·접근 불변식

V001~V005는 바이트 그대로 보존하고 V006에 run+request_id의 receipt/fingerprint, run+stage의 완료/불변 분기를 추가했습니다. 기존 V005 community_story를 CAS로 갱신합니다. 요청·공유 단계·완료·분기·공유 일지 fact/event를 같은 트랜잭션에 기록하고 개인 퀘스트/인벤토리는 변경하지 않습니다. 진행 소유권은 story_run_id이며 월드 UUID/클라이언트 run 입력은 사용하지 않습니다. 기존 saveStory 경로는 엔진 receipt가 있는 진행의 우회 변경을 거부합니다.

기존 bounded worker/owner·세션·월드 저장 장벽을 재사용했습니다. DB/조건 조회는 비동기, Bukkit/안내·이벤트 순서는 메인 owner에서 처리합니다. move마다 DB를 읽지 않으며 확인된 공유 캐시만 사용합니다. 조건/저장/선택 요청과 effect future를 종료·언로드 장벽에 포함합니다. 늦은 UI 응답은 세션/현재 공유 revision·HOLD·명단을 다시 검사합니다. 실패/불명 공유 상태에서 제한 지역을 열지 않고 무관한 run까지 잠그지 않습니다.

명단 변경은 메인 owner에서 token/version을 갱신하고 DB worker는 atomic fence만 읽습니다. 최종 fence 검사 뒤 시작한 commit을 접속 이벤트와 분산 원자적으로 묶는 구조는 아닙니다. 최종 검사 뒤의 새 접속으로 이미 승인한 현재 단계를 중단하지 않으며 다음 단계에서 다시 검사합니다. 투표는 입력 마감 시점의 명단/선택/요청을 고정합니다. 파일·DB의 완전 원자성이나 모든 장애의 무손실을 보장하지 않습니다.

세계 변화 `Effects`는 DB 확인 후에만 호출되는 안전한 비동기 인터페이스입니다. 기본 구현은 `NOT_IMPLEMENTED`이고 실제 콘텐츠 변경은 수행하지 않습니다. 효과 실패를 DB 분기 취소/개인 보상 재지급으로 바꾸지 않습니다. 진행·접근 캐시/화면 반영 성공을 물리 세계 효과 실행 성공으로 기록하지 않습니다.

기존 exploration/session/quest 게이트에 `story-verification-enabled: true`와 `-Dhearth.verification.sharedStory=true`를 추가 요구합니다. 기본값 false. 기존 콘텐츠 파일을 덮어쓰거나 운영 서버에 활성화하지 않습니다. 기성 플랫폼 비교는 [기존 검토](plugin-suitability-review.md)의 Citizens/BetonQuest 근거를 재사용했습니다. 정본/진행 격리를 중복 관리할 외부 엔진을 채택하지 않고 기존 Hearth PostgreSQL/CAS를 확장했으며 신규 라이브러리·플러그인 설치는 없습니다.

## 남은 범위

현재 조건은 온라인 전원의 개인 퀘스트 COMPLETED 목록입니다. 조건을 생략한 단계는 미등록으로 차단합니다. 프로토타입 분기의 대상 단계는 동일한 진입 조건을 요구하며 불일치는 정의 오류로 거부합니다. 실제 서사의 장/사건/개방 시점을 정하지 않았고 공개 합성 콘텐츠만 사용했습니다.

실제 인증 플레이어의 채팅 입력/수신·이동/텔레포트·NPC/GUI/인벤토리 행동은 **미실행·별도 요청 전 보류**입니다. 엔티티 외형을 숨기는 시스템이나 모든 외부 플러그인/차량 이동 우회 검증을 완료했다고 하지 않습니다. 물리 세계 효과 실행기·보스/전투/재도전 투표·장 스킵·보상·빠른 이동·폰 아이템·렌더러/미니맵·AI·경제·운영 활성화는 미구현입니다. 불명 receipt가 없으면 자동으로 새 요청을 실행하지 않으며 관리자 확인을 기다리는 보류를 유지합니다. PG 재시작·실제 네트워크 장애/강제 종료 복구·장기 TPS/MSPT/부하/누수도 미실행입니다.

기존 운영 서비스·데이터·과거 증거는 변경하지 않았고 비공개 스토리 저장소에 접근하지 않았습니다. 후속은 새로운 조건/콘텐츠 범위·세계 효과의 안전한 적용 또는 별도 승인된 실제 클라이언트 시험이며 전체 S4 완료 선언은 하지 않습니다.
