# 복수 지역 상인·지역별 거래 통합

확인일: 2026-11-08. 기준: `ee4cb0b`. [이전 시장 정보](economy-report-verification.md)는 보존하며 이번 결과는 [JSON](../verification/economy-merchants-result.json)에 기록한다.

## 구현

- 콘텐츠에 `merchants`와 `merchant.<id>.name/region/goods/x/y/z`를 추가했다. 수도 상인은 철괴/철광석, 광산 상인은 철광석을 취급한다. 기존 단일 `merchant-*` 설정은 `legacy_merchant`로 유지한다.
- NPC ID·엔티티 UUID·선택 객체·월드 세대를 화면/조회에 연결했다. 다른 NPC 선택, 같은 NPC의 새 선택, 엔티티 교체·세대 변경 뒤 이전 결과를 적용하지 않는다. 기존 세션/거리/화면 검사를 유지한다.
- 상점 목록/상품/시장 정보는 선택한 상인의 지역·상품을 사용한다. 다른 지역의 견적이나 상품을 섞으면 화면 생성/거래 전에 거부한다. 지역 참고 조회를 원격 거래로 바꾸지 않는다.
- 인벤토리·잔액은 기존 `realm_id + player_uuid` 계정을 공유하고 지역별로 복제하지 않는다. 거래 기록에는 실제 시장 지역을 남긴다. 기존 E001/E002·스토리 스키마·가격/제조 규칙은 변경하지 않았다.
- 월드 준비 시 상인마다 하나를 생성하고 quiesce/종료 시 참조·선택·화면을 정리한다. 청크별 정의를 인덱싱해 관련 청크만 다음 틱에 확인하며 세대/로드 상태를 재검사한다. 일반 상인의 청크를 강제로 상시 유지하지 않는다.

공개 fixture의 두 상인은 새 격리 플랫폼의 서로 다른 지점에 있다. 실제 운영 지리, 상인 배치, 교통/빠른 이동·운송비 정책의 확정을 뜻하지 않는다. 기존 콘텐츠 파일·실제 월드를 자동 덮어쓰거나 hot reload하지 않는다.

## 실패 수정·자원

1. `/tmp/hearth-s4-11.ywYFbksz`: NPC 유효 상태 확인 FAIL. 접속자가 없는 시험에서 청크 유지와 유효 시점 전제가 빠졌다. 기존 NPC 시험처럼 **자동 격리 시험에만** 소유 청크 티켓·짧은 대기를 적용하고 quiesce/종료에서 티켓을 해제했다. 일반 플레이의 상시 청크 유지 정책으로 확대하지 않았다.
2. `/tmp/hearth-s4-11.UqOHjXiX`: 수정 최종본 PASS. 자동 통합 총 2묶음이며 실패 원본과 정상 drain 표식 누락은 FAIL로 보존했다. 실패 시험의 부모 프로세스·localhost 포트·postmaster PID 파일 종료는 추가 확인했다.
