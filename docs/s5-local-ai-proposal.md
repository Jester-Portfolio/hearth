# S5 로컬 AI 연동·격리 실행 제안

확인일: 2026-11-10. 제안 기준 `ce06f70`. **후속 승인:** 사용자가 이 조합과 예산의 격리 구현·실행을 승인했으며 [ADR-0018](decisions/0018-local-ai-runtime-and-trial-budget.md)이 현재 결정이다. 아래 비교·측정값은 승인 전 검토 자료로 보존한다. [준비 확인 JSON](../verification/s5-ai-readiness.json)의 미채택/미다운로드 표시는 조회 당시의 사실이다. 운영 상시 배포 승인은 포함하지 않는다.

## 확인한 환경

현재 호스트는 i7-9750H(6코어/12스레드), RAM 15,442MiB, GTX 1660 Ti VRAM 6,144MiB다. 조회 당시 가용 RAM은 13,134MiB, GPU 여유는 5,762MiB였다. 드라이버는 615.71.09, CUDA compute capability는 7.5다. 가용량은 순간값이며 AI에 배정된 예산이나 Paper와의 동시 사용 검증 결과가 아니다.

PATH에서 `ollama`/`llama-server`를 찾지 못했고 11434/11435에 TCP 리스너가 없었다. 시스템 전체 미설치를 증명한 것은 아니다. 8080의 기존 리스너는 보존하며 요청을 보내거나 변경하지 않았다. Python 3.9.25, tar, taskset, nice와 `libzstd.so.1`은 확인했으나 zstd 실행 파일/파이썬 모듈은 없었다. 압축 해제 경로도 사전 검증 대상이며 시스템 패키지를 임의 설치하지 않는다.

## 비교와 권장 후보

| 선택 | 연결 방식·장점 | 추가 확인 |
| --- | --- | --- |
| **권장: Ollama + Qwen3 4B Instruct 2507 Q4_K_M** | 공식 Linux 배포와 모델 태그/manifest가 있으며 로컬 JSON 생성 API·동시 실행/대기 제어를 제공 | 사용자 소유 격리 경로의 바이너리/라이브러리 로딩, 실제 GPU/메모리·한국어 품질·6초 응답 가능 여부 |
| llama.cpp + 별도 고정 GGUF | 서버의 completion/chat JSON API와 직접 실행 옵션을 사용 가능 | 별도 바이너리/모델 조합·채팅 템플릿·라이브러리 호환성을 고정해야 함 |
| 기존 text/plain 서비스 지정 | 기존 어댑터를 유지할 수 있음 | 현재 접근 가능한 서비스가 확인되지 않았으며 실행 장비/모델/예산 정보가 필요 |

Ollama 공식 문서의 NVIDIA 요구 조건과 측정 드라이버/compute capability는 부합한다. 이는 실제 구동 성공 판정이 아니다. [GPU 지원](https://docs.ollama.com/gpu), [llama.cpp 서버](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)를 비교 근거로 사용했다.

권장 모델은 4B 비사고형 Instruct다. 공식 모델 설명의 non-thinking 특성과 배포 크기를 기준으로 짧은 보조 응답 시험에 선정한 **후보**다. 한국어 게임 도움의 정확성·과학/기술 지식·출처 충실도는 별도 평가한다. [제작자 모델 카드](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507), [Ollama Q4_K_M 배포](https://ollama.com/library/qwen3:4b-instruct-2507-q4_K_M).

메타데이터 기준 고정 후보는 Ollama **v0.40.16**과 `qwen3:4b-instruct-2507-q4_K_M`이다. Linux amd64 아카이브는 약 1.55GB, 모델 가중치 레이어는 약 2.50GB다. 아카이브 SHA-256/모델 manifest·레이어 digest는 준비 JSON에 기록했으며 **실제 파일을 다운로드해 검증한 해시가 아니다.** 실행 시 파일 해시·manifest를 대조하고 불일치는 중단한다. 태그가 바뀌어도 자동 갱신하지 않는다. [공식 릴리스](https://github.com/ollama/ollama/releases/tag/v0.40.16), [모델 manifest](https://registry.ollama.ai/v2/library/qwen3/manifests/4b-instruct-2507-q4_K_M).

## 채택 시 구현할 연동 배치

1. 기존 Mock/text/plain을 보존하면서 선택형 Ollama JSON 어댑터를 연결한다. 기본 비활성/Mock은 유지한다. 현재 공개 정보·제한된 대화만 전송하고 응답 전후 권한/세션을 재검증한다. 다른 개인/진행의 데이터·원본 스토리·DB/명령/웹 도구 권한은 제공하지 않는다.
2. `POST /api/generate`, `stream:false`, 고정 모델, 기존 `AssistantRequest`의 제한된 프롬프트를 사용한다. 서버가 반환한 `context`를 다음 개인/요청에 넘기지 않는다. HTTP 429/503·잘못된 JSON·미완료/빈 응답·취소·종료를 기존 실패 안내에 연결하고 자동 재시도/Mock 대체를 하지 않는다. [공식 생성 API](https://docs.ollama.com/api/generate).
3. 제안 초기값은 context 4,096토큰·출력 128토큰·CPU 스레드 2·모델 1개·병렬 추론 1개·대기 1개·keep-alive 60초다. Ollama의 `OLLAMA_MAX_LOADED_MODELS`/`OLLAMA_NUM_PARALLEL`/`OLLAMA_MAX_QUEUE`와 요청 options를 명시한다. 기존 플러그인의 동시 HTTP 4개·6초/대화 8초는 확대하지 않는다. [공식 동시 실행·메모리 설명](https://docs.ollama.com/faq#how-does-ollama-handle-concurrent-requests).
4. 기존 문자 수 예산을 토큰 수와 같다고 가정하지 않는다. 한국어·긴 자료의 입력 토큰과 출력 여유를 확인하고, 한도 초과를 몰래 자르거나 참고자료를 임의 제거해 전송하지 않는다. 토큰 검증 수단과 오류 처리를 어댑터/실제 모델 조합에서 확인한다. 콜드 로딩은 별도 준비 단계로 측정하고, 준비된 질의가 기존 제한을 넘으면 실패로 기록한다.
5. 합성 자료로 한국어 도움/모르는 정보, 개인·진행별 비노출, 최신 정보 변경 중 지연/취소, 혼잡과 실제 GPU/RAM/지연을 검사한다. 출력은 텍스트 데이터이며 게임 상태를 변경하지 않는다. 기존 PG 원본·인벤토리 불변과 요청 종료/포트 반환을 함께 검증한다. 실제 Minecraft 접속은 이번 범위에 포함하지 않는다.

## 제안 실행 예산과 종료 기준

아래는 **새 AI 프로세스에 대한 승인 요청값**이다. 기존 Paper/자동 검사 한도를 변경하거나 이미 승인된 것으로 취급하지 않는다.

| 항목 | 제안 |
| --- | --- |
| 설치·데이터 | 새 사용자 소유 `/tmp` 하위만 사용. 시스템 설치/서비스 등록·기존 Docker/운영 설정 변경 없음 |
| 다운로드·디스크 | 공식 고정 바이너리/모델·필요한 사용자 소유 도구만, 전송 합계 최대 6GiB·새 시험 경로 최대 12GiB·시작 전 여유 16GiB 이상 |
| AI CPU/RAM/GPU | CPU 2개/nice 10, 소유 프로세스 트리 합산 RSS 4,096MiB·GPU 사용 5,120MiB 초과 시 중단. 샘플 감시 임계값이며 커널 하드 제한을 보장하지 않음 |
| 호스트·네트워크 | 가용 RAM 6GiB 미만이면 중단. 최초 포트 확인 후 `127.0.0.1:11435`만 사용·외부 노출/포워딩 없음 |
| 시간·횟수 | 다운로드 포함 실행 총 600초, 작업 550초·정리 50초, 준비 동작 최대 90초. 첫 실행 1묶음 후 결과 검토, 모델/시간/상한 자동 확대 없음 |
| 기존 검사 | 필요 시 Paper 최대 2 JVM 순차·힙 1536MiB/RSS 중단 2560MiB 등 기존 한도 유지. 불필요한 게임 JVM 실행 없음 |
| 로컬 처리 | 격리 프로세스에서 `OLLAMA_NO_CLOUD=1`, 독립 모델 저장 경로/사용자 설정 사용. 기존 홈·공유 캐시·클라우드 모델·웹 검색은 사용하지 않음 |

클라우드 비활성화와 독립 모델 경로는 [Ollama FAQ](https://docs.ollama.com/faq)를 근거로 한다. 설치 스크립트·systemd/드라이버 변경은 이 제안의 실행 방식이 아니다. 기존 libzstd를 통한 안전한 압축 해제 등 사전 조건이 충족되지 않으면 임의 시스템 설치 대신 중단한다. 시간/공간 내 다운로드가 끝나지 않으면 실패/미완료를 보존한다.

롤백은 이 묶음에서 만든 소유 PID/프로세스 그룹만 종료하고 포트·GPU 사용 반환을 확인하는 것이다. 기존 서비스·모델·월드/DB를 종료/삭제하지 않는다. 새 다운로드/로그/실패 증거도 임의 삭제하지 않고 경로와 상태를 보고한다.

## 이번 결과와 남은 결정

이번에는 읽기 전용 장비/도구/포트 확인, 공식 문서·릴리스/manifest 메타데이터 조회, 제안서/JSON·링크 확인만 수행했다. Java 빌드·DB/Paper·AI 실행·모델/런타임 다운로드·패키지 설치는 하지 않았다.

제안 당시 [로드맵 S5](ROADMAP.md)의 선행 조건은 기술/모델/자원 예산 결정과 실행 승인이었다. 후속 사용자 승인으로 첫 격리 조합/예산을 확정했다. 어댑터 구현·회귀·격리 실제 모델 확인은 같은 배치로 수행하며, 운영 상시 배포와 전체 S5 품질/부하 완료는 별도로 남는다. 최초 실행 결과와 실제 미완료 범위는 현재 현황/검증 기록을 따른다.
