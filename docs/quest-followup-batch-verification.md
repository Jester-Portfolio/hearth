# 공개 코스의 실패·보상·결과·복귀 흐름 통합

확인일: 2026-11-09. 기준 `8e74638` 이후 코드. [현장 제작 의뢰](crafting-orders-verification.md)와 [채집·던전 목표 안내](facility-objectives-verification.md), 기존 재시작·보상·책/스마트폰을 재사용해 아래 네 작업을 한 배치로 구현·검증했다. 상세 명령·수치·해시·원시 로그는 [검증 JSON](../verification/quest-followup-batch-result.json)에 모았다. 운영 활성화/배포는 수행하지 않았다.

## 함께 연결한 기능

1. **실패·보상 대기 의뢰 유지**: 작업대와 채집/던전 시설 목록에 본인의 실패·재시작 대기와 실제 완료 후 청구 가능한 보상 대기 기록을 표시한다. 실패/보상 행에서 재제작이나 재입장을 목표로 만들지 않는다. 미수락·차단·장 스킵·이미 지급/미등록 보상은 제외하며 기존 명시적 시설/코스 연결을 유지한다. 지급 epoch를 목록 표식에 포함해 지급 후 이전 선택을 거부한다.
2. **책의 확인·취소·결과**: 의뢰 상세 책에서 기존 정책의 재시작/보상 수령을 확인한다. 취소하면 최신 의뢰를 읽으며 저장을 요청하지 않는다. 확인 시 현재 세션·원래 시설/대화 조건·화면 표식과 DB revision/지급 epoch를 재검사한다. 처리 중/완료/보류·실패를 구분하고 의뢰 상세와 원래 작업대·시설·진행판으로 돌아간다. 작업대 복귀도 현장 접근 조건과 현재 의뢰 목록을 다시 확인한다.
3. **스마트폰의 원래 안내 복귀**: 재시작/보상 확인을 취소하거나 결과를 확인한 뒤 원래 의뢰 상세·코스 진행판 쪽·실패/보상 목록·다음 플레이 안내로 이어진다. 장 스킵도 확인을 열었던 장 상세로 다시 조회한다. 복귀 시 배열 인덱스나 오래된 본문을 재사용하지 않고 의뢰 ID와 최신 공개 정보로 재조회한다. 더 이상 공개되지 않는 항목은 현재 목록/진행판에서 다시 확인한다.
4. **책·스마트폰 공통 요청 표식**: 같은 접속 세션은 한 후속 작업만 처리한다. 결과는 요청 객체에 묶여 이전 요청·다른 개인/세션·로그아웃 뒤 콜백이 현재 요청을 완료로 바꾸지 못한다. 저장 future 성공 전에는 완료를 표시하지 않으며, 실패/commit 불명/HOLD를 성공으로 재해석하거나 자동 재요청하지 않는다. 확인 메시지도 기존 동작 정책을 공통으로 사용한다.

공통 요청 표식은 세션 내 UI 상태다. DB 작업·보상 원장·재시작 위치·장 스킵/보상 정책을 새로 만들거나 초기화하지 않는다. 실제 처리는 책과 스마트폰 모두 기존 어댑터의 최신 상태 확인 및 재시작/인벤토리 보상 경로를 사용한다. 소유권·source 저장·CAS·중복 지급 방지·HOLD/원본 보존·기본 비활성 설정은 유지했다.

## 실행한 검사

- Gradle main/test 컴파일·JAR·격리 runtime stage PASS. 퀘스트/스마트폰/제작과 관련 저장/세션의 고유 **421개 단위·회귀 PASS**. 최초 관련 420개 통과 후 보상 목록 소멸 회귀 한 건을 보강해 해당 후속 모델 8개만 재실행했다. 변경 영향이 없는 성공 검사를 반복하지 않았다.
- 신규 15개 검사는 실패/지급 대기 공개 조건·미등록/스킵/이미 지급/차단 제외·시설 연결/재료 미배정·지급 epoch와 이전 확인 거부, 공통 요청의 중복·실패·교체·개인/세션 identity·로그아웃/늦은 응답을 확인했다.
- 기존 `verify-lifecycle.py`의 완료 콘텐츠를 재사용하는 `--completion-navigation`을 추가했다. 자동 `--sessions --quests --story-batch --quest-completion --phone-dialog`가 필수이며 한 JVM만 실행한다. 필수 옵션 누락 2건·다른 모드 혼합 1건은 workspace/서버 변경 전에 거부됨을 확인했다. 기존 두 JVM 완료/분기 복원 모드는 변경하지 않았다.

## 미검증과 다음 경계

실제 인증 클라이언트의 책/스마트폰 간 중복 클릭, 확인/취소/결과·시설/코스/장 상세 왕복과 가독성은 별도 요청 전 보류다. 통합의 공통 요청은 같은 모델을 쓰는 제어 호출이며 실제 두 화면 클릭 성공이 아니다. 실제 저장·거부·Book/Dialog/Inventory 객체와 인증 Player 행동을 구분한다. 저장/복원 계약은 불변이므로 새 JVM/DB 재시작 및 과거 장 스킵/분기 전체 복원은 반복하지 않았다. 장기 성능·운영 활성화/배포와 전체 S4/S5 완성도 미검증/미완료다.
