# NPC 대화 조회 경합과 종료 정리 보완

2026-10-30 · 격리 개발 모드 · S4 진행 중. 실제 클라이언트 시험은 사용자 요청 전까지 보류한다.

## 변경

- NPC 대화 조회는 같은 진행·개인의 기존 목록 읽기와 퀘스트 저장이 정리된 뒤 한 번 읽는다. 대화 준비 중 중복 클릭을 제한하고 배경 HUD/표식 갱신을 잠시 미룬다. 이미 도착한 배경 응답도 대화 준비 중에는 적용하지 않는다.
- 대화 결과 표시 전에 세션·대화·월드·거리·권한과 저장 상태를 다시 검사한다. 실패/HOLD를 정상 선택지나 빈 목록으로 바꾸지 않는다. 거부 원인은 비밀값을 제외한 예외 종류와 제한된 오류 코드로 남긴다.
- 플러그인 비활성화 후에는 NPC 숨김 API를 호출하지 않는다. 개인 표식과 참조 정리는 유지한다. 한 모듈의 종료 예외가 다른 모듈 정리와 DB 비동기 종료 요청을 건너뛰지 않도록 했다. 메인 스레드 DB 대기는 추가하지 않았다.
- DB 스키마·콘텐츠·저장 정책·일반 서버 활성화는 변경하지 않았다.

## 이전 실제 시험 관측과 남은 문제

수동 시험 자료는 `/tmp/hearth-s4-11.t4djvd0w`와 `/tmp/hearth-s4-11.camzocbw`에 보존했다. 첫 실행에서는 PC 전달 포트 연결이 실패했고, 두 번째 실행에서 인증된 P1의 접속·일반 권한·기존 인벤토리 복원을 관측했다. 수락 전 방문 후 `survey_marker`는 미수락을 유지했고 별도 `entry_marker`는 `ACTIVE/revision0`으로 시작했다. 사용자도 퀘스트 목록의 해당 항목을 확인했다.

NPC 우클릭에서는 일반 오류 안내가 반복됐고, 이후 선택지가 보였다는 사용자 응답만으로 수락·보고 성공을 판정하지 않았다. 당시 로그에 구체적인 거부 원인이 없어 실제 오류 전체의 원인은 아직 확정하지 않았다. 이번에는 코드에서 확인한 배경 조회 경합을 보완했으며 실제 NPC 클릭 해결 여부는 후속 클라이언트 시험 대상이다.

두 번째 실행은 작업 시간 상한에 도달해 종료됐다. Watchdog 종료가 아니며, 온라인 플레이어 표시 정리 중 `Plugin (Hearth) cannot be disabled` 예외가 발생해 DB 풀 정상 종료 확인이 누락됐다. 수동 실행 전체 결과는 `FAIL`로 보존한다. 소유 JVM/DB 프로세스는 종료됐고 해당 리스너도 반환됐다. 정상 종료 확인 누락을 성공으로 바꾸지 않는다.

## 자동 검증

- 관련 단위·회귀 **31개 PASS**. 기존 조회와의 경합, 조회 도중 세션 무효화, 쓰기 성공/실패·HOLD, 다른 개인/진행 격리, 종료 중 대기 요청 거부와 모듈 종료 실패 전파/후속 정리를 검사했다. 중복 실행한 시험은 개수에 합산하지 않았다.
- 최종 JAR의 `--sessions --quests --story-batch --npc-views` 자동 검증 **PASS**: Paper 한 JVM·새 PostgreSQL 한 개에서 내부 확인 71건, 기존 조회 대기·NPC 표시 데이터/엔티티·인벤토리 불변·공유 진행 저장·월드 언로드/재로드 회귀를 확인했다. 정상 DB 풀/월드 작업 종료와 프로세스·포트 반환도 통과했다.
- 실행 44.585초, Paper 최대 관측 RSS 1,016,672KiB, CPU 71.12초, 최소 가용 RAM 11,984,700KiB. 기존 자원 한도 준수, 실행 JAR과 최종 빌드 SHA-256 일치. 저장 형식은 불변이므로 두 번째 JVM을 반복하지 않았다.
- 최초 준비 명령에서는 소유권 표식 누락으로 서버 실행 전에 거부됐다. 표식을 준비한 뒤 실제 통합 실행은 한 묶음만 수행했다. Gradle 시작 제한은 환경 권한 처리 후 해결했으며 기능 시험 실패로 집계하지 않는다.

최종 결과는 [검증 JSON](../verification/npc-session-stability-result.json)에 기록한다. 제어 경계와 서버 내부 검사를 실제 인증 플레이어 행동으로 취급하지 않는다.

## 미검증·다음 작업

- 실제 NPC 우클릭·선택·수락·보고, 주민 거래창 차단과 클라이언트 표시, 온라인 플레이어가 남은 상태의 종료를 다시 확인해야 한다. 사용자의 준비·접속·TTY 조작은 이번에 요청하지 않는다.
- 실제 퀘스트 전체 흐름·GUI·전투 조작과 나머지 S4 수용 조건은 여전히 남아 있다. 자동 검증 통과로 S4 전체 완료나 운영 배포를 승인하지 않는다.
