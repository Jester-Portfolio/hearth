# 퀘스트 목록·보고·추적·알림 동선 통합

2026-10-29 · 격리 개발 모드 · S4 진행 중.

## 구현

- 스마트폰 퀘스트에 전체·보고 가능·추적 중·완료 목록을 연결했다. 보고 가능 항목과 추적 항목을 우선 표시하며 페이지 이동 시 선택한 목록을 유지한다. 미수락·지역 제한 퀘스트와 완료된 추적 항목은 해당 목록에서 제외한다.
- 상세 화면에서 추적 설정·추적 목록·알림·공유 채팅 안내로 이동한다. 보고 대기 항목에만 가까운 NPC의 보고 대화를 여는 버튼을 제공한다.
- 보고 버튼은 원격 완료가 아니다. 기존 NPC 대화 경로를 재사용하며 활성 세션·NPC 거리/엔티티·지역 조건·WorldGuard 상호작용 권한과 bypass를 확인한다. 새로 발급한 대화 토큰을 사용하고 실제 보고 시 현재 개인 상태·세션·CAS를 다시 확인한다.
- 수락/보고 뒤 퀘스트 목록·스마트폰 링크를 제공하며 안내 NPC에서 완료하면 공유 진행 안내도 제공한다. GUI에서 투표를 직접 실행하거나 새 보상/저장 정책을 만들지 않았다.

## 검사

- 구현 완료 후 관련 단위·회귀 **25개 PASS**, JAR 빌드·스크립트 구문 PASS. 필터·표시 순서·잠금 비노출·보고 전용 대화 링크·중복 슬롯 방지·페이지 유지·기존 대화/개인 상태 경계를 함께 검사했다.
- `--sessions --quests --story-batch --quest-navigation` 축소 모드에서 새 Paper 한 JVM/PG 한 개 **PASS**. 실제 DB에서 수락→목표 도달→REPORT_READY/revision1→완료/revision2, 추적 정리·목록 갱신·다른 개인/진행의 미수락 보존을 확인했다.
- 실제 54슬롯 GUI 객체·버튼의 고유 슬롯·보고 대화 링크·41슬롯 인벤토리 불변을 검사했다. GUI 생성/조회 자체가 퀘스트 revision을 변경하지 않는 것도 확인했다.
- 최초 실행 35.92초에 통과했다. 기존 자원 한도·프로세스/포트 반환 및 실행 JAR과 최종 빌드 일치를 확인했다. 저장 계약이 불변이므로 두 번째 JVM은 생략했다. 이전 공유 투표 전체 시험은 이번 축소 경로에서 반복하지 않았다.
- [결과 JSON](../verification/quest-navigation-result.json)에 실행 경로·검사·자원·해시를 보존한다.

## 미검증

실제 인증 플레이어의 GUI 클릭→NPC 대화·거리/권한 변경·보고·알림/추적 화면은 미검증이다. 내부 DB/GUI 객체 검사를 실제 플레이 성공으로 보지 않는다. WorldGuard 실제 플레이어 권한 질의와 임의 외부 플러그인 충돌도 후속 실제 행동 검증 대상이다. 실제 클라이언트 시험은 별도 요청 전 보류한다.
