# 채집·던전 시설의 개인 목표·다음 행동 통합

> 후속 변경: 실패·보상 대기 기록과 확인/결과·원래 화면 복귀의 현재 동작은 [실패·보상·결과·복귀 통합](quest-followup-batch-verification.md)을 따른다. 아래 검증은 명시한 기준 커밋의 기록이다.

확인일: 2026-11-09. 기준 `5803f42` 이후 코드. 기존 현장 채집 입퇴장·공개 던전 의뢰·개인 퀘스트·책/스마트폰을 재사용해 **시설 안내→본인의 현재 목표→의뢰 상세/보고 안내→현장/이전 안내 복귀**를 한 배치로 연결했다. [검증 JSON](../verification/facility-objectives-result.json)이 명령·해시·검사 표식·자원·원시 로그의 정본이다. 일반 서버 활성화나 운영 적용은 포함하지 않는다.

## 연결한 플레이 흐름

- 채집 입구/출구의 **내 목표·다음 행동**에서 등록 코스와 연결된 개인 의뢰를 읽는다. 관련 의뢰 ID는 기존 공개 `gathering-workshop-course.yml`에서 가져오며, 같은 구역을 방문한다는 이유로 무관한 의뢰를 섞지 않는다. 현재 방문 목표와 채집 후 제작 등 다음 목표, 담당 NPC 보고 대기를 구분한다. 방문을 채굴 횟수/아이템 획득으로 표시하지 않는다.
- 등록 던전 NPC에는 기존 입장 버튼과 별도로 **던전 목표·다음 행동**을 표시한다. 미수락 때는 개인 의뢰 제목/미래 목표 없이 일반 안내만 읽고 입장 버튼도 추가하지 않는다. 수락 후 현재 던전 목표·승리 저장 뒤 보고 대기·완료 후 진행 중 목표 없음이 본인 저장 상태에 맞게 바뀐다.
- 스마트폰의 기존 **던전 진행 안내**도 같은 책 화면으로 연결한다. 이 경로는 읽기 전용이며 원격 던전 입장/채집 입퇴장/의뢰 수락/보고를 제공하지 않는다. 입장은 기존 현장 NPC·시설 확인에서만 수행한다.
- 본인의 의뢰를 6개씩 표시하고 선택한 의뢰 상세에서 시설 목표 안내로 돌아온다. 등록돼 있을 때 기존 시설·재료 준비 및 다음 플레이 안내와도 왕복한다. 현장 채집 버튼이나 NPC에서 열었다면 거리·세션·월드 세대/대화·지역 권한의 현재 조건을 유지하며 복귀 시 현장 상태를 다시 조회한다.
- 페이지/상세 선택 전에 비동기 조회와 현재 공개 DTO를 다시 확인한다. 목표·revision·공유 공개 범위가 바뀌면 이전 선택을 거부한다. 초 단위 초기화 안내 갱신만으로 같은 목표의 선택을 막지는 않는다. 새로고침/복귀는 현재 페이지 수에 맞춘다. 오류·늦은 응답·무효화된 출처를 빈 성공이나 완료로 바꾸지 않는다.
- 안내 조회는 새 입장 조건이 아니다. 채집 메뉴에서 조회를 시작해도 기존 입퇴장 버튼을 정보 조회 성공에 의존시키지 않으며 기존 일회용 확인·최신 저장·CAS/세대·HOLD를 재사용한다. 던전의 고정 명단·저장 후 시작·온라인 승리 반영·개인 보고 정책과 DB 형식/기본 비활성 설정도 보존했다. 새 플러그인이나 운영 정책은 없다.

## 실행한 검사

- Gradle 컴파일·JAR·기존 stageLifecycleRuntime PASS. 관련 단위/회귀 **108개 PASS**: 채집, 던전 연결, 신규 시설 목표 모델 10개, 목록/책/GUI, 인벤토리 저장·세션 경계. 첫 실행에서 모두 통과했다.
- 신규 모델은 방문/던전/다음 목표/보고 구분, 미수락/차단/미래 목표 비노출, 명시적 코스 연결과 개인 상태 분리, 이전 선택/위조 행 거부, 상태 문구 갱신·쪽 나누기·한글/이모지 책 예산과 불변을 확인했다.

각 모드는 새 사용자 소유 `/tmp/hearth-s4-11.*`의 PostgreSQL 1개·Paper 1 JVM으로 순차 실행했다. 두 실행 모두 같은 최종 Gradle JAR을 사용했다.

- 채집: 기본/확인 Inventory의 새 목표 안내 아이콘, 실제 개인 저장의 미수락→수락/방문→다음 목표, 책 객체/복귀 표시·이전 선택 거부·41슬롯/revision 불변·P2/B 비노출·재접속 목표 보존. 기존 입퇴장 저장 지연/중복·실제 CAS 실패·원본/다른 진행 보존도 함께 PASS.
- 던전: 미수락 입장 차단·현재 목표/보고 대기/완료 상태의 책 객체·이전 선택 거부·41슬롯/revision 불변, 서로 다른 개인 보고 상태·다른 진행의 독립 목표·재접속 완료 기록. 기존 실제 관리 몹 사망→개인 목표 저장, 중복 승리 처리와 실제 DB 충돌 보존도 함께 PASS.
- 두 모드 모두 소유 프로세스/포트 정상 정리·오류 없음. 기존 localhost·EULA·600초/작업 550초·힙 1536MiB/RSS 중단 2560MiB·가용 RAM 6144MiB·CPU 2/nice +10을 유지했다. 운영 서비스/DB/월드와 과거 시험 증거를 변경하지 않았다.

## 미검증과 다음 경계

실제 인증 클라이언트의 시설/NPC/스마트폰 클릭·목표/상세/준비 왕복·쪽 이동·거리/권한 변경·가독성은 별도 요청 전 보류다. 서버 내부 방문/이동 제어와 Inventory/Book 생성은 실제 Player 행동 성공이 아니다. 저장/복원 계약이 불변이라 두 번째 JVM/DB 재시작을 추가하지 않았다. 장기 부하와 운영 활성화/배포도 실행하지 않았다. 전체 S4·S5 로컬 AI 완료를 뜻하지 않으며, 후속 범위는 남은 공개 플레이 상호작용과 실제 클라이언트 미검증을 구분해 선정한다.
