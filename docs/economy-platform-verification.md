# 경제 공통 플랫폼 일괄 구현·검증

2026-11-20. 사용자가 승인한 8개 작업을 기존 경제/RPG/인챈트에 한 배치로 연결했다. [운영·설정 가이드](../infrastructure/network/platform.md), [ADR-0033](decisions/0033-economy-platform-lifecycle.md), [구조화 증거](../verification/economy-platform-result.json)를 정본으로 사용한다. 밸런싱·획득처·상세 콘텐츠/레벨 디자인·실제 클라이언트 시험·운영 배포는 이번에 진행하지 않았다.

## 데이터·권한·실패 보존

E012는 개인 판매 설정의 revision CAS, 자원 세대/요청 상태, 설정 변경 영수증만 추가한다. 강화 아이템 PDC는 기존 `hearth:upgrade`와 버전1을 사용하고 E011에 UPGRADE를 추가했다. SHOP/PEER/ENCHANT 기존 저널 계약을 유지하며 UPGRADE는 단일 actor다. replay는 아이템 payload를 돌려주지 않는다. 비용/원본 revision/결과는 같은 PG 트랜잭션이며 DB 콜백에서 인벤토리를 조작하지 않는다.

자동 판매는 제출된 드랍 수량으로 화폐를 생성하지 않는다. 최종 수집/픽업은 알림이며 현재 소지품을 다시 판정해 기존 상점 판매 경로로 소비한다. 같은 아이템의 재정산은 native 최신 payload/CAS와 거래 중 freeze/세션 장벽으로 막는다. 메타데이터 물품은 plain 상품과 구별하고 모든 판매에 기존 가격/재고 revision을 적용한다.

자원 교체는 원래 3월드/extra 바인딩을 재작성하지 않고 별도 활성 세대를 투영한다. 원래 월드 파일은 다음 기동에서도 신원을 검증하므로 임의 삭제하면 안 된다. 현재 ACTIVE와 후속 pending이 함께 있으면 기동 후에도 역할을 닫는다. 최초 준비 청크는 PG 확정 동안 plugin ticket으로 유지하며 활성화 후 기존 월드 관리자로 소유를 넘긴다. deadline 이후 늦은 결과는 자동 입장 재개로 처리하지 않는다. UNKNOWN commit은 같은 요청의 PG 조회·명시적 재개가 필요하다. 정전 시 월드 파일과 PG 전체를 무손실 원자 복구한다고 보장하지 않는다.

인챈트 제한은 실제 세대 key 외에 원래 논리 key와 `role:<role>`를 인식한다. 기존 설정을 세대마다 변경하거나 다른 역할까지 열지 않는다. 이전 UUID의 Home/포탈/TPA는 최신 공통 입장/ACL/전투 검사를 통과해야 하며 좌표를 새 세대로 자동 치환하지 않는다. 실제 대피 플레이는 별도 시험이다.

라이브 설정 이전은 허용된 파일만 수정한다. schema/ID/world identity를 지키고 RPG registry는 제거 없이 추가한다. RPG 정책/registry 변경은 온라인 0명·유지보수/재시작이 필요하다. 경제/시장 불변 해시는 정지 전용 도구가 source/binding/PG를 같은 계획으로 교체한다. DB 확정 후 파일 공개가 끊긴 상황도 pending 표식과 전후 해시로 재개한다. 가격/효율 같은 검토 수치 외의 토폴로지/ID/초기 자산 변경은 전용 어댑터 없이는 거부한다. 파일과 PG의 분산 원자성을 주장하지 않는다.

## 발견·수정한 문제

- 최초 컴파일에서 Capacity accessor/비동기 반환 타입·검증 helper의 문자열 인자를 수정했다. 관련 최종 컴파일/검사를 통과했다.
- 최초 Paper에서 후보 spawn 청크가 PG 확정 전 언로드될 수 있어 안전 등록이 거부됐다. 검사를 완화하지 않고 candidate ticket 유지/이관·종료/중단 정리를 추가한 뒤 실제 교체와 두 JVM을 통과했다. 원본 월드/실패 증거를 보존했다.
- 정지 정책 CLI fixture가 신규 native 계정을 nonempty로 생성하려 해 기존 `ECON_INITIAL_NOT_EMPTY`에 거부됐다. 빈 계정 생성 후 정상 shadow CAS 저장으로 바꿨다. 해당 실패 실행의 제어기 `NORMAL_STOP_TIMEOUT_database`도 원시 FAIL에 남겼다. 후속 최종 실행은 모든 프로세스/포트 정리·원본 보존을 통과했다.
- 검토 중 ACTIVE 복원 뒤 후속 pending의 역할 차단이 풀리는 경로와 세대 key 변경에 따른 인챈트 제한 불일치를 보완했다. 복원본 두 JVM에서 같은 역할 차단과 논리 key/role alias 보존을 확인했다. timeout 뒤 늦은 완료는 guard로 계속 보류한다.

## 자원 측정·실용적 한계

주 통합 두 JVM+PG는 **55.524초**, Paper 최대 표본 RSS **1,437,844KiB**(약1.37GiB), 합산 최대 **1635.8MiB**였다. Paper CPU는 기동 포함 40.32/38.53 CPU초였다. 전체 백업·검증·복원은 **32.241초**였다. 백업 복원본의 최종 두 JVM은 **53.298초**, 합산 최대 **1526.2MiB**였다. 마지막 접근 경계 JAR의 별도 좁은 수치는 JSON을 따른다.

기존 CPU2/nice10·Paper heap1536MiB/RSS2560MiB·합산6144MiB·호스트 가용6144MiB·600초/작업550초·시험당 최대 두 Paper/한 PG를 유지했다. 백업 도구의 기존 CPU2/90초/12GiB 한도도 유지했다. GPU/실제 AI 시험은 필요하지 않아 실행하지 않았다.

접속 0명의 API/기동/세계 교체·계획 모델 측정이며 **실제 유저당 비용·지속 TPS/MSPT·채굴/전투/판매 동접 용량·장기 누수**를 합격 판정하지 않는다. Paper status가 수집하는 TPS/MSPT/heap과 개별 시간 집계는 이후 운영 기준을 정할 관측 기반이다. 원본 세대 보존에 따른 디스크 증가도 운영 보존 정책에서 다룬다.

## 남은 범위

이번 8개 플랫폼 배치의 구현·필요 자동 검증·문서/Git 반영을 수행했다. 획득처·가격/확률/효과/레벨/개수·상품/콘텐츠·레벨 디자인은 사용자 지시대로 보류한다. 자원 초기화 엔진/API와 실제 자동 실행 주기·과거 세대 보존/정리 운영은 구별한다. registry/세계 ID/재질/경제 토폴로지의 임의 변환은 구현된 안전 이전 범위를 넘는다.

실제 Player GUI/강화·판매 입력/다인 경합·전투/사망·대피·전원 차단 복구 수용, 목표 동접/장기 부하와 운영 배포는 미검증이다. 사용자 재개 요청 없이 인증 우회/가짜 Player 시험을 하지 않았다. 운영 서비스/DB/세계·Docker/Zabbix/SSH/방화벽·시스템 패키지를 변경하지 않았다. 배포는 별도 승인 후 정상 drain·일관 백업·격리 복원과 롤백 계획으로 진행한다.
