# 경제 직접 상품 거래 구현·검증

2026-11-17. 기존 경제 전용 실행·상품·PG 화폐·세션 저장에 양쪽 확인 거래를 한 배치로 연결했다. [플레이/명령과 저장·보존 경계](../infrastructure/economy/PEER_TRADES.md)를 따른다. 실제 인증 플레이·운영 적용 완료는 아니다.

## 구현

`PeerTrade`는 초대→상대 수락→제안/양쪽 최종 확인→확정→완료/취소/HOLD를 분리한다. 제안 변경은 승인을 지우며 같은 revision의 양쪽 확인만 제출한다. `PaperPeerTrades`는 같은 경제 월드의 활성 세션·거리·화면/세대·타임아웃을 검사한다. 기존 등록 상품을 수량/화폐 버튼과 전체 품목 페이지로 조회하고, 명령으로도 지정한다. 다른 이름/NBT의 아이템을 기본 상품 대신 소비하지 않으며 36슬롯 밖 장비/보조 손은 보존한다. escrow나 플레이어 입력 가격의 NPC 재고 조작은 없다.

`PeerExchange`는 양쪽 최신 저장과 기존 인벤토리 트랜잭션을 순서화한다. `EconomyStore.peer`는 같은 realm 잠금·각 payload/revision CAS·잔액/overflow·유효 fence를 확인하고 두 계정과 E004 영수증을 하나의 PG 트랜잭션으로 확정한다. 일반 저장/NPC 거래와 같은 계정 revision을 사용한다. 중복 요청은 기존 영수증을 읽고 다른 제안은 거부한다. 제출 전 취소/명백한 자금·상품·공간 거부와 SQL/CAS/commit 불명·부분 적용 HOLD를 구분한다. 후자는 양쪽 임대·원본·요청 정보를 보존하며 자동 재제출/차감/지급하지 않는다.

정상 실행에서도 요청/수락·확인 GUI·본인 영수증·콘솔 보류/영수증 조회를 연결했다. 종료는 새 요청을 막고 열린 제안을 취소한 뒤 진행 중 저장을 기다리며 HOLD는 깨끗한 종료로 처리하지 않는다. E001~E003 파일·기존 계정/시장·스토리 스키마는 보존한다. 새 계정 잔액 0·오프라인 PAUSE·운영 비활성은 변경하지 않았다.
