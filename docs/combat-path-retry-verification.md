# 길목 재도전·체크포인트 복귀·관리 구역 초기화

2026-11-05. S4 진행 중. 기존 [집결/보스 입장](combat-gathering-verification.md), [종료 복귀/구역 초기화](combat-return-verification.md), 저장·세션·채팅 투표를 한 배치로 연결했다. [결과 JSON](../verification/combat-path-retry-result.json)에 최초 실패와 최종 결과를 함께 보존한다.

## 연결한 사용자 흐름

- 길목 전멸이 필수 실패로 확정된 뒤 현재 참가자가 `/hearthcombat retry`를 요청하면 등록된 길목 재도전을 준비한다. 진행 중·승리·HOLD를 실패 재도전으로 우회하지 않으며 중복 요청은 기존 작업 상태를 안내한다. 별도의 길목 투표 정책은 추가하지 않았다.
- 보스전은 기존 채팅 과반수·30초·온라인 대상/사망 관전자·중복 차단 정책을 유지한다. 투표 확정 후 콘텐츠의 `BOSS_ONLY` 또는 `FROM_PATH` 범위를 적용한다.
- 기존 활성/퇴장 세션의 최신 인벤토리와 퀘스트·일지·공유 진행 저장 장벽을 확인한다. 온라인 대상의 복귀 이동·위치 확인이 모두 끝난 뒤에만 관리 구역을 초기화하고 새 길목 또는 보스 전투를 생성한다.
- 길목 재도전은 콘텐츠의 시작 위치 또는 고정 지정 체크포인트 위치·방향·회복값을 사용한다. `ALL`/`PRESERVE`/`AFTER_CHECKPOINT` 설정으로 기존 관리 구역 초기화 경계를 재사용한다. 초기화 뒤 실제 재진입 시 기존 스폰/인원 산정 경로를 사용한다.
- 다시 길목을 진행하고 기존 집결 명령으로 온라인 사망자를 포함한 보스 입장에 연결한다. 새 단계의 명단·난이도·전용 부활 횟수를 초기화하고, 원래 도전의 확정 결과와 사용 기록을 바꾸지 않는다. 소비품·인벤토리·보상·개인 퀘스트/컷신은 되돌리지 않는다.

## 콘텐츠와 안전 경계

보스 `retry`와 `path.retry`는 분리된다. `FROM_PATH`는 길목 정의와 명시적 `reset` 설정이 있어야 하며 초기화 대상 구역 ID를 활성화 전에 검사한다. `BOSS_ONLY`는 기존 설정과 호환되며 구역 초기화를 강제하지 않는다.

`combat-demo.yml`은 기존 보스만 재도전을 유지하고 길목 실패용 설정을 추가했다. 별도 공개 합성 `combat-path-demo.yml`은 보스 투표 후 길목 복귀도 검사한다. 격리 설정 `combat-content-file`은 이 두 시험 파일만 선택한다. 새 파일에만 기본 콘텐츠를 제공하며 기존 콘텐츠를 자동 덮어쓰지 않는다. 중첩 YAML은 같은 재귀 변환기로 읽는다.

현재 체크포인트는 **제작자가 고정 지정한 복귀 지점**이다. 도달에 따른 자동 해금·공동체 체크포인트 갱신 규칙을 새로 확정하지 않는다. 새 재도전 참가자는 현재 검증된 온라인 진행 연결에서 결정하고, 이후 보스 명단 고정/기존 참가자 재접속 정책을 유지한다.

저장 실패는 이동/초기화 전에 차단한다. 이동 실패는 초기화 전에 차단하고, 초기화 실패는 새 전투 생성 전에 HOLD로 남긴다. 이미 이동하거나 일부 관리 몹을 제거한 뒤의 실패를 완전 롤백했다고 기록하지 않는다. 원본 참조·오류 상태를 남겨 관리자 확인 대상으로 삼는다. 요청 ID 재전달·이전 세대 완료로 두 개의 도전을 생성하거나 새로 소환된 구역을 다시 지우지 않는다. 월드 전체·지형·상자·경제 데이터를 초기화하지 않는다.

## 실제 검사

- 고유 단위/회귀 **125개 최종 PASS**. 최초에는 이전 도움말 문구를 기대하던 1건이 실패했고, 기대값 수정 후 해당 클래스만 재검사했다. 성공한 나머지 검사는 반복하지 않았다. 저장→모든 이동→초기화→생성 순서, 양쪽 재도전 진입점·중복·잘못된 요청·초기화 실패·세대/종료·기존 보스만 재도전 회귀를 포함한다.
- 최초 Paper 실행은 중첩 `reset` 매핑 변환 누락으로 준비 단계 FAIL이었다. 정상 풀 종료 표식 누락과 원시 실패를 보존했고 Paper/DB 프로세스 종료 코드는 0이었다. 재귀 로더 수정 후 새 경로에서 최종 JAR 재검증을 통과했다.
- 기존 도구의 `--sessions --quests --story-batch --combat-players --combat-paths` 한 묶음, Paper 한 JVM·독립 PostgreSQL 한 개 **PASS** (39.356초). 실제 DB 최신 dirty 저장/revision 1→2·다른 개인/진행 보존, 실제 관리 몹 교체·체크포인트 이전 구역 보존·이후 구역 제거/재진입 소환, 재집결 후 보스 생성·전용 부활 횟수 초기화를 확인했다.
- 실제 DB CAS 실패 시 이동·초기화·생성을 차단하고 원본/dirty를 보존했다. 초기화 실패는 제어 경계에서 주입했으며 새 전투를 만들지 않고 기존 실제 몹·참조를 유지했다. 인증 플레이어 이동/회복은 내부 제어 포트 검사다.
- Paper 최대 RSS 1,151,256KiB, 관측 CPU 65.9초, 준비 17.3초. 최소 관측 가용 RAM 11,596,232KiB. 기존 힙/CPU/nice/시간/메모리 한도, 최종 실행 JAR 일치·정상 종료·프로세스/포트 반환을 확인했다.

## 미검증·남은 범위

실제 클라이언트 retry·투표·이동·회복은 보류한다. 동적 체크포인트 도달/해금, 복수 길목 단계 진행, 전원 오프라인 종료 뒤 복귀와 전투/길목의 새 JVM 복구, 보스 패턴·전체 인던·장기 부하는 남아 있다. DB 저장/복원 형식은 유지하여 두 번째 JVM은 생략했다. 전체 S4와 운영 배포는 완료하지 않았다.

## 후속 사용자 확정: 체크포인트 활성화·무료 부활

해당 던전 및 퀘스트를 함께 진행하는 참가자 중 현재 접속한 생존자 전원이 지정 체크포인트에 도착하면 활성화한다. 서버 전체 접속자나 같은 공동체라는 이유만으로 대상에 포함하지 않는다. 대상은 서버가 검증한 해당 던전 도전·퀘스트 공동 진행의 참가 범위로 판정하며, 가입·탈퇴·파티 관리 기능을 추가하지 않는다. 이 공동 진행 도중에 사망한 참가자의 체크포인트 무료 부활은 집결 대상인 생존 참가자 전원이 해당 체크포인트에 도달했을 때 또는 해당 체크포인트에서 재시작할 때만 활성화한다. 체크포인트가 활성화됐다는 이유만으로 이후 사망 시 즉시 또는 상시 부활시키지 않는다. 이 경계에서 부활하는 참가자의 체력은 최대 체력까지 전부 회복한다. 부활 조건부 행동·아이템·개인/공동 부활 횟수·데스카운트를 소모하지 않는다. 사망자는 생존자 집결 대상에 포함하지 않는다. 위 두 시점에는 생존자를 포함한 해당 던전·퀘스트 공동 진행의 대상 참가자 모두를 최대 체력까지 회복한다. 사망자는 무료 부활과 전량 회복을 함께 적용하고 생존자도 전량 회복한다. 이 경계 밖의 상시 회복이나 해당 공동 진행에 참여하지 않는 유저의 회복을 뜻하지 않는다.

이는 앞 절의 동적 체크포인트 활성화 미정 상태를 대체하는 사용자 결정이다. 접속 종료는 기존 온라인 대상 정책을 따르며 보스 시작 명단·중도 참가·재접속 정책을 변경하지 않는다. 위의 기존 자동 검사 결과는 이 후속 기능의 구현·검증 완료를 의미하지 않는다. 무료 부활의 명령/UI와 적용 시점은 구현 시 실제 동작과 구분하여 기록한다.
