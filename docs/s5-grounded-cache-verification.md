# S5 공개 자료·답변 표시·접속 캐시 통합

확인일: 2026-11-11. 기준 `1e561ab` 이후 코드. 승인된 다음 배치로 [ADR-0019](decisions/0019-session-ai-cache-and-reference-contract.md)의 접속별 캐시와 자료 표시 계약을 기존 도움/참고자료/PG 검증 흐름에 연결했다. 상세 명령·최종 JAR·원시 증거는 [검증 JSON](../verification/s5-grounded-cache-result.json)을 따른다.

## 구현

- 접속마다 별도 캐시를 만들고 4개 LRU·60초·UTF-8 프롬프트+답변 128KiB로 제한한다. 질문·본문·자료 계약과 실제로 전송할 최근 대화가 완전히 같을 때만 찾는다. 캐시를 위해 대화를 빼거나 다른 개인/진행과 공유하지 않는다. 자료의 전체 공개 DTO/식별/버전/목표가 바뀌면 발췌문이 같아도 이전 응답을 폐기한다. 정리/종료도 캐시를 지운다.
- 캐시에서 찾았어도 Ollama 버전/모델 digest와 최신 PG 공개 자료·현재 세션을 다시 확인한다. 확인 중에는 busy/질문 초안을 유지한다. 실패/불명·취소·stale는 원래 대화/진행/인벤토리를 성공한 것처럼 바꾸지 않는다. 성공한 답변만 저장하며 캐시 조회로 생성 시각/만료 시간을 갱신하지 않는다. Mock은 고정 Mock의 확인 경로, 기존 local text/plain은 캐시 미지원이다.
- `AssistantRequest`에 서버가 선택한 자료 수 0~4를 추가하고 기존 3인자 생성자는 보존한다. 실제 도움의 `PhoneGrounding.Scope`에서 자료 수를 얻으며 원본 키/소유권은 요청에 넣지 않는다. 단일 자료도 `[자료 1]`, 복수 자료는 선택 후 전송 순서대로 번호를 매긴다. UI의 최근 참고자료 목록/상세에 같은 번호를 표시하고 기존 최신 상태 조회를 유지한다.
- 모델에 해당 자료 번호와 자료에 없는 사실을 추측하지 않는 기준을 제공한다. 답변의 잘못된/없는 번호, 형식 오류·과도한 숫자, 표시 길이에 의해 유일한 근거가 잘린 응답을 거부한다. 자료 0개 요청은 가짜 번호도 거부한다. 거부한 응답은 대화/캐시에 저장하지 않고 질문을 유지한다. **이 검사는 번호/표시 정합성이며 내용의 정답·실제 인용 충실도 보장이 아니다.**
- 요청/대화의 기존 6초/8초·HTTP 4개/8,192바이트·고정 모델/context/출력 한도는 유지한다. 새 DB 스키마/영속 캐시·보상·명령·운영 활성화는 추가하지 않는다.

## 실행한 내부 검사

- 관련 스마트폰/자료 단위·회귀 **102개 고유 검사 PASS**. 세션 분리, 전체 요청/이력/자료 계약 키, 자료/버전 변경, 만료/LRU/바이트 한도·시간 역행, 캐시 적중 중 백엔드/PG 확인·지연/실패/취소·현재 권한 변경, 대화 정리/종료, 번호 0/음수/범위 초과/과대 값·유일한 근거 잘림과 공개 제목/선택 순서를 검사했다. 중복 실행은 합산하지 않는다.
- Python **14개 PASS**. 기존 시험 자원/수동 경계와 안전한 해제/해시 실패 보존에 더해, 원본 모델 파일의 검증 복사·전송 0바이트·원본 byte/mtime 보존·잘못된 해시 차단을 확인했다. 모델을 재다운로드하지 않아도 **최초 디스크 여유 16GiB를 우회하지 않는 것**도 검사했다.
- 최종 main/test/JAR/integration fixture 컴파일 PASS. 기존 `--sessions --quests --story-batch --quest-navigation --phone-dialog`를 새 사용자 소유 경로의 **Paper 1 JVM/PG 1개**에서 실행해 **119회 assertion PASS·51.145초**다. 캐시 적중도 백엔드 확인과 실제 PG 재조회가 필요함을 확인했다. 같은 본문에서 private fact 버전만 바꾸는 fixture로 이전 응답 거부와 새 생성, 다른 개인 데이터·일지/인벤토리/revision 보존을 확인했다. 잘못된 자료 번호는 PG 후속 조회/캐시/이력 적용 전에 거부했다.
- 실행 JAR/최종 제품 JAR 해시 일치, DB 풀·소유 프로세스·포트 종료 PASS. 저장/복원 계약은 그대로여서 두 번째 Paper JVM은 생략했다. 무관한 전체 회귀·리소스팩 검사는 반복하지 않았다.

## 실제 모델 시험의 전제와 현재 미실행

이번 실제 AI 재시험은 아직 실행하지 않았다. 시작 시 `/tmp` 여유가 15,815MiB로 기존 16GiB 조건에 부족해 사용자에게 알렸고, 사용자가 **직접 공간 확보 후 알림**을 선택했다. 내부 검사 후 조회값은 15,425MiB였다. 이전 증거를 삭제하거나 디스크 전제를 낮추지 않았으며 공간 확보 확인을 기다린다.

기존 고정 해시 아카이브/blob을 새 경로에 복사하는 `--artifact-source`와 자료/캐시 전용 `--grounded` probe를 준비하고 컴파일했다. 기존 프로필/모델 실행 상태는 재사용하지 않고 원본을 덮어쓰지 않는다. 준비 동작은 자료 번호 계약이 있는 대표 프롬프트를 사용하며, 단일/다른 진행/자료 없음·같은 본문의 다른 세션·실제 캐시 적중/신원 확인·stale 거부와 지난 HTTP 400 한도 분류 재확인을 묶는다. **실행 전의 구성·컴파일·HTTP fixture를 실제 모델 성공으로 기록하지 않는다.**

[이전 실제 모델 시험](s5-local-ai-verification.md)의 예열/짧은 응답 결과는 당시 코드의 관측으로 보존한다. 새 자료 번호 지시 준수·모델 캐시 실제 절약/응답 품질·실제 400 안내 재확인, 과학 지식/출처 충실도·목표 동시 사용/장기 성능과 Minecraft 입력/화면·코옵·운영 배포는 남는다. 공간 확보 후에도 [ADR-0018](decisions/0018-local-ai-runtime-and-trial-budget.md)의 자원/600초 한도를 유지한다.
