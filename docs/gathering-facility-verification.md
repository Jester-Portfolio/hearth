# 현장 채집 입퇴장·저장·재입장 연결

확인일: 2026-11-09. 기준 `9688b38`. 기존 [채집 인던](gathering-dungeon-verification.md)·[재료 공급 실습](material-supply-verification.md)·[준비 안내](play-preparation-verification.md)를 재사용했다. 상세 실행 표식·수치·JAR 해시는 [검증 JSON](../verification/gathering-facility-result.json)에 둔다. S4는 진행 중이며 일반 서버에서는 비활성이다.

## 구현한 플레이 흐름

- 공개 합성 [시설 정의](../src/main/resources/gathering-facility-demo.yml)의 현장 버튼을 우클릭하면 채집 상태·입장/퇴장·새로고침·다음 플레이 안내를 표시한다. 입퇴장은 별도 확인 화면에서 확정하며 스마트폰/지도에 원격 이동을 추가하지 않았다.
- 시설별 ENTER/LEAVE를 분리한다. 초기화 영역 바깥에 두므로 자원 초기화가 시설 블록을 덮어쓰지 않는다. 중복 ID/좌표·잘못된 채집 ID·지원하지 않는 블록·초기화 영역 내부·출구에서 도착 지점까지의 잘못된 거리는 활성화 전에 거부한다.
- 같은 플레이어의 기존 명령과 현장 메뉴가 `GatheringVisit`을 공유한다. 중복 입퇴장은 거부하고, 퇴장 시 조작 제한 → 최신 인벤토리 저장 완료 → 이동 → 기존 채집 참가 정리 순서로 처리한다. 새 저장기·이벤트 원장·DB 스키마는 만들지 않았다.
- 시설 확인 시 동일 세션/진행/월드·월드 세대·채집 세대/revision·참가 상태·대기 작업을 다시 확인한다. 현장 거리·블록·생존·커서·진행 접근·WorldGuard 권한도 재검사한다. 화면을 열어 둔 채 상태가 달라졌으면 이전 선택을 거부한다.
- 조회·새로고침은 입퇴장이나 인벤토리 저장을 실행하지 않는다. 상단 시설 GUI만 별도로 허용하며 클릭/드래그/Shift/숫자키로 41슬롯이나 GUI 아이템을 옮길 수 없도록 기존 세션 보호를 유지한다.
- 진행별 입퇴장 대기 작업도 저장/언로드 장벽에 포함한다. 저장·이동 실패는 성공으로 표시하지 않고 HOLD를 보존한다. 종료는 일치하는 미완료 요청만 취소하고, 이미 실패한 HOLD를 자동 해제하지 않는다. 이동 후 채집 퇴장 기록 저장 중 종료해도 기존 저장 작업은 채집 장벽에서 정리한다.
- 시설 전용 WorldGuard INTERACT 구역을 생성·검사하고 월드 재로드 때 다시 연결한다. 서로 다른 진행은 각 월드 RegionManager를 사용한다. 기존 건축 보호·자료 소유권·템플릿·30초 일반 저장 정책은 변경하지 않았다.

기성 UI·Bukkit 이벤트·WorldGuard·기존 채집 조정자로 충분해 외부 플러그인은 추가하지 않았다. 비용/교통 수단/운영 배치·주기를 확정하지 않았으며 기존 템플릿·월드 파일을 자동 이전하거나 덮어쓰지 않는다.

## 실행 및 미검증

새 사용자 소유 `/tmp/hearth-s4-11.*`를 기존 `stageLifecycleRuntime`으로 준비하고 `verify-lifecycle.py` 필수 인자와 `--sessions --quests --story-batch --gathering-crafting --gathering-facilities --accept-eula`를 사용한다. `gathering-facility-verification-enabled`와 JVM `hearth.verification.gatheringFacilities`를 함께 켜야 한다. 이번 자동 시험은 신규 fixture에서만 버튼을 명시적으로 배치했다. 콘텐츠 파일만 추가하면 기존 월드의 시설 블록까지 자동 배치되는 구조가 아니다. 실제 시험 재개 시 별도 신규 fixture의 시설·채집 등록 준비가 필요하다.

**실제 인증 플레이어의 우클릭·GUI/확인 조작·PlayerInventory·teleportAsync·종료 이벤트는 미검증**이다. 자동 시험의 이동과 HOLD는 서버 내부 제어 포트이며 실제 플레이어 성공이 아니다. 기존 자원/시도 한도를 지켰고 실제 클라이언트는 요청하지 않았다. 저장 형식/복원 계약은 불변이므로 두 번째 JVM·DB 재시작·이전 전체 기능 시험은 반복하지 않았다. 장기 부하/누수·TPS/MSPT·운영 배포도 미실행이다. 운영 서비스/DB/월드·과거 증거·비공개 스토리는 변경하지 않았다.
