# 정지 백업·새 경로 복원과 관리자 대응 검증

확인일: 2026-11-17. 기준 `891018a` 이후 운영 준비 배치다. [도구·적용 전제·대응/롤백 절차](../infrastructure/backup/README.md), [실행 횟수·원시 증거](../verification/offline-backup-result.json)를 따른다.

정상 종료한 Paper 전체 트리·PG 전체 전용 클러스터와 선택형 외부 자료를 함께 보존하는 도구를 구현했다. 새 0700 경로에만 복사하고 각 파일의 크기·모드·SHA-256과 전체 구성/빈 디렉터리를 manifest에 담는다. 별도 보관한 manifest 해시로 검증한 뒤 새 경로에만 복원한다. 기존 원본/백업·이미 존재하는 복원 경로를 덮어쓰지 않는다. 서비스 제어·설정 자동 변경·아이템/DB 보정·자동 삭제는 없다.

정상 종료 확인이 없는 요청, PG 실행 표식·잠긴 월드, 복사 중 변경·추가/삭제, 잘못된 해시/경로·누락/추가 파일, symlink/하드링크·특수 파일, 자원/시간 상한 초과를 거부한다. 오류 원문/원본 설정을 콘솔에 출력하지 않는다. 실패의 부분 출력은 보존하며 완료 영수증 없이 적용하지 않는다. 상한은 100,000개 항목·12GiB·각 작업 90초이며 격리 통합에서는 기존 최초 600초/작업 550초 시계를 함께 지킨다.

## 실행 결과

- 관련 Python **12개 PASS**, 첫 실행·실패 0. 실제 별도 프로세스의 POSIX 월드 잠금, 기존 파일/복원 대상 보존, 변조·경로 탈출·누락/추가·링크·시간/용량·복사/복원 실패와 불완전 증거를 확인했다.
- 통합 fixture 컴파일/staging PASS. 게임 메인 코드/JAR은 바꾸지 않아 기존 단위/실제 AI 검사를 반복하지 않았다.
- 새 격리 Paper **1회·원본 PG 1회**, 정상 저장/종료 후 테이블별 행 수/해시를 읽기 전용으로 남기고 PG를 정상 종료했다. Paper 전체와 PG를 묶어 검증·새 경로로 복원한 뒤 **복사 PG 1회**를 새 localhost 포트에서 기동했다. 실제 `data_directory`와 모든 사용자 테이블의 내용 해시가 원본과 같음을 확인했다.
- 통합 **66.12초 PASS**, 백업 2326개 항목·245,011,490바이트. 소유 프로세스/포트 닫힘·정리 오류 0. 복사 PG 종료 뒤 원본 파일과 보관 백업의 해시가 그대로임을 확인했다. 같은 성공 검사를 다시 실행하지 않았다.

## 범위와 남은 결정

이는 정지 상태의 격리 저장 데이터 복원 근거다. 다른 PG 버전/빌드·확장/외부 tablespace, 실행 중 또는 공유 클러스터의 부분 백업, 복원 Paper의 실제 행동·운영 경로 전환·장기 보관은 미검증/미지원이다. 운영자 정상 종료 진술과 파일 잠금 검사만으로 원격 작성자의 부재를 자동 증명하지 않는다. 전체 S7/E3나 운영 배포 완료를 뜻하지 않는다.

운영 서비스·Docker/Zabbix/SSH/방화벽·기존 데이터는 변경하지 않았다. 운영 자원/배치, 백업 주기·보존/외부 저장·암호화·RPO/RTO와 실제 복구/롤백 적용은 별도 결정·승인이 남는다. 장애 시 자동 무손실/아이템 이력 재구성 대신 기존 HOLD·원본 보존·읽기 전용 진단·수동 대응 정책을 유지한다.
