# 공개 시험 코스·연속 플레이 안내 통합

2026-10-29 · 격리 개발 모드 · S4 진행 중.

## 완성한 흐름

새 `playthrough-demo.yml`은 다음 안내 순서를 정의한다. 기존 퀘스트·스토리·장소 ID와 저장 기록을 유지하며 별도 안내 진행 테이블을 만들지 않는다.

1. NPC 개인 방문 조사 수락→목표 방문→보고.
2. 접속 중 전원 조건을 확인하고 공동 조사 준비·경로 선택 단계로 진입.
3. 개인 경로 조사 자동 완료→기존 채팅 투표→확정 공유 분기·자유 탐험 개방.
4. 개인 다단계 경로 조사→NPC 보고→선행 조건이 있는 후속 자동 시작·자동 완료.
5. 본인 장소 발견·일지·알림 확인→공동 조사 마무리.

`/hearthjourney`는 본인의 기존 퀘스트·공유 진행·발견 기록에서 **현재 해야 할 안내 하나**를 계산한다. 퀘스트 시작/보고, 상세, 스마트폰, 공유 채팅 안내에 연결하며 미래 잠금 퀘스트·비밀 장소 좌표를 공개하지 않는다. 대화 명령은 현재 안내 대상과 일치해야 하고 기존 NPC 거리·지역·WorldGuard·대화 토큰 검사를 거친다. 안내 조회 자체는 수락·완료·보상·세계 변화를 발생시키지 않는다.

공동체가 먼저 진행했어도 개인 단계를 자동 완료하지 않는다. 이 안내는 선택적인 공개 시험 동선이며 자유 탐험의 새 필수 학습 관문이나 정식 스토리 완료 정책이 아니다. 기본 6메뉴를 유지하고 기존 퀘스트 화면·안내 NPC·조작 도움말에서 접근한다.

## 걸을 수 있는 격리 코스

기존 합성 월드는 대부분 빈 공간이어서 시작 발판 밖 목표에 도보로 도달하기 어려웠다. 새 모드를 명시적으로 켠 진행 A/B 복제 월드에만 0~40 좌표의 바닥과 시험용 월드 경계를 준비한다. 원본 템플릿과 기존 시험 경로는 변경하지 않는다.

`hearth-public-course.properties`의 버전·진행 ID·물리 UUID를 확인한다. 최초 준비는 바닥이 공기/돌인 경우만 허용하고 기존 다른 블록과 충돌하면 원본을 보존하며 거부한다. 재접속·새 JVM에서는 이미 기록된 코스를 다시 만들지 않아 이후 바닥 변경을 보존한다. 크기·경계는 공개 시험 전용이며 일반 스토리 월드의 운영값을 확정하지 않는다.

기본 `playthrough-verification-enabled: false`와 별도 JVM 게이트를 유지한다. 새 파일만 복사하고 기존 사용자 콘텐츠를 자동 갱신하지 않는다. 계획에 존재하지 않는 참조·중복 단계가 있으면 활성화 전에 실패한다.

## 최종 일괄 검사

- 관련 단위·회귀 **29개 PASS**, JAR 빌드·스크립트 구문 PASS. 개인 상태별 안내·잠금/장소 비노출·공유/개인 완료 분리·미완료/HOLD/불명 응답·오래된 revision·콘텐츠 참조를 검사했다.
- 새 사용자 소유 경로에서 **Paper 순차 두 JVM/PG 한 개 PASS**. 사전 완료 행을 심는 대신 실제 개인 퀘스트 수락·목표·보고 코드와 공유 전이·투표를 연결했다. 접속 중 두 번째 시험 문맥 미완료로 공유 전이가 차단되고, 조건 충족 후 과반수/DB 확인으로만 탐험을 개방했다.
- 3단계 보고형·선행 조건/지역 자동 시작·2단계 자동 완료, 개인 일지·알림·장소 발견, 다른 개인/진행의 독립성을 같은 실행에서 확인했다. 이들은 서버 내부 시험 문맥이며 실제 로그인·클릭·이동 성공이 아니다.
- 새 JVM에서 안내 완료·개인 미완료의 차이·발견·일지·다단계 revision을 기존 행에서 복원했다. 시험 코드로 수정한 A 바닥의 벽돌과 B의 돌, 코스 경계가 보존됐으며 빈 월드 재생성이나 코스 덮어쓰기를 하지 않았다.
- [결과 JSON](../verification/public-playthrough-result.json)에 실제 실행 시간·CPU/RSS·검사·해시를 기록했다. 최초 실행 통과, 기존 600초/두 JVM/단일 DB·메모리 한도와 정상 종료/포트 정리·최종 실행 JAR 일치를 확인했다.

## 사용·미검증

기존 도구의 `--sessions --quests --story-batch --playthrough`로 새 격리 환경에서 자동 실행한다. 실행 파일 준비·EULA·자원 사전 검사는 기존 [시험 도구 안내](../scripts/README.md)를 따른다. 실제 사용자 모드는 여기에 기존 `--manual-player --operator-ready --profile`을 조합할 수 있도록 준비했지만 이번에는 실행하지 않았다. 사용자 별도 요청·클라이언트/전달 경로 준비 확인 없이 제한시간 서버를 먼저 기동하지 않는다.

실제 클라이언트 도보 이동·NPC 대화·투표 채팅·GUI, 새 수동 경로 및 표현/사용성은 미검증이다. 공개 코스를 준비한 것이 정식 스토리 콘텐츠·보상·전투·AI·전체 S4나 운영 배포 완료를 뜻하지 않는다.
