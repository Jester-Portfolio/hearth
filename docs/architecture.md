# Hearth 시스템 아키텍처

상태: 스토리 월드 B안 채택. [ADR-0001](decisions/0001-story-world-multiworld.md)에 사용자가 확정한 아키텍처 결정을 기록합니다. [ADR-0002](decisions/0002-stack-and-world-policies.md)로 기술 스택과 월드 정책을 추가 확정했습니다. 구현·성능·격리·복구 검증은 미완료이며 이 문서는 설치나 운영 변경을 수행하는 실행 지침이 아닙니다.

## 요구사항과 확인 범위

- 스토리 월드와 경제 월드는 서로 다른 목적을 가지며 데이터를 논리적으로 분리합니다.
- 세계관은 마법 없는 현실적인 중세 기술을 지향합니다. 스토리 월드는 현대인이 이 세계에 등장해 현대의 과학·기술 지식을 활용하는 것이 핵심 콘셉트입니다.
- 스토리 월드는 싱글 플레이와 소규모 코옵을 지원하는 방향이며, 싱글 플레이어는 자신만의 독립 진행과 월드를 가지며 코옵 공동체는 하나의 진행과 월드를 공유합니다.
- 스토리 월드의 게임 내 AI 스마트폰 어시스턴트는 필수 기능이며 로컬 AI를 활용하는 방향입니다. 퀘스트, NPC, 게임 내 정보를 바탕으로 플레이어의 질문에 답하도록 계획합니다.
- 경제 월드는 스토리 월드를 기반으로 확장하는 경제 중심 멀티플레이 환경입니다. 생산, 재고, 공급·수요, 시장가격, 거래 및 무역과 자원 순환을 주요 요소로 합니다.
- 경제 월드의 AI 스마트폰 어시스턴트는 선택 기능이며 제거할 수 있어야 합니다.
- 두 월드는 공통 기반 기능을 재사용할 수 있지만 진행 데이터와 경제 데이터는 분리합니다.
- Docker 기반 배포와 Zabbix 모니터링을 계획합니다.
- 초기 문서 작성 당시 기존 추적 파일은 `AGENTS.md`뿐이었습니다. 이후 설계 문서와 ADR을 추가했습니다.
- Rocky Linux 9.8, 호스트 `rocky-laptop`, 기존 Docker·Zabbix·Cloudflare Tunnel은 제공된 환경 정보입니다. 실제 서비스 상태와 구성은 이번 작업에서 조사하지 않았습니다.

## 확정된 스토리 월드 운영 구조

1. 하나의 Paper 26.2 서버 프로세스에서 플레이어·공동체별 독립 월드를 운영합니다(B안).
2. 퀘스트·NPC·월드 변화·플레이어 상태를 진행별로 격리합니다. 같은 코옵 진행에서도 개인 상태는 플레이어별로 구분합니다.
3. 비활성 월드는 저장 후 언로드하고 재접속 시 복원합니다. 비활성 판단·대기 시간과 복구의 상세 절차는 미정이며 데이터 삭제를 뜻하지 않습니다.
4. 필수 로컬 AI 스마트폰 어시스턴트는 공통 AI 서비스를 사용하되 검색·대화·캐시를 포함한 진행별 정보 접근을 격리합니다.
5. 논리 진행 ID(`story_run_id`)와 물리 서버·월드 배치를 분리하여 필요 시 A안으로 확장할 가능성을 유지합니다. 이전 도구·무중단 이전은 검증하거나 확정하지 않았습니다.

## 확정 기술·템플릿·보호 정책

[ADR-0002](decisions/0002-stack-and-world-policies.md)에 따라 플러그인은 Java 25·Gradle 기반 단일 JAR로 배포하며 내부 기능별로 모듈화합니다. DB는 PostgreSQL, 배포는 Docker Compose, 모니터링은 기존 Zabbix를 활용합니다. 순정 Java Edition 클라이언트를 대상으로 별도 모드를 최소화하고 필요시 서버 리소스팩을 제공합니다. AI 구체 기술은 미정입니다.

월드는 사전 제작한 공간 템플릿을 복제합니다. 지형·건축물 템플릿은 버전별로 관리하고 지속 추가하며, 기존 플레이어 월드·진행은 보존합니다. NPC 배치·대화·퀘스트 정의는 별도 콘텐츠 데이터로 관리하고 플레이어 진행은 PostgreSQL에 저장합니다. 콘텐츠 형식/연결 도구는 미정이며 기존 지형/건축 반영은 충돌 검사·기존 상태 보존 우선(ADR-0012)입니다.

스토리는 전체 보호를 기본으로 지정 구역에서만 건축·지형 변경을 허용합니다. 경제는 주요 도시·공용 시설 등 지정 구역만 보호하며 일반 지역 자유도를 높입니다. 양쪽 주요 자원 수급은 전용 인던형 채집 구역 중심입니다. 건축용 지형 변경과 자원 채집은 별개 정책이며 채집 리셋은 정기 시각 또는 전원 퇴장 뒤 다음 입장(ADR-0011)이며 생성 기술/소유 단위는 미정입니다.

보호 엔진은 양쪽 월드 모두 **WorldGuard**로 채택했습니다([ADR-0014](decisions/0014-worldguard-protection-engine.md)). 일반 건축/간접 변경·구역 중첩/플래그는 WorldGuard에 위임하고 Hearth는 NPC/퀘스트 변경 권한·run 접근·채집 리셋·전용 예외만 담당합니다. 자체 범용 보호 엔진은 제외합니다. WorldEdit는 구역 제작/관리 도구이며 WG 7.0.19가 요구하는 WorldEdit와 선택 WE 7.4.4의 최소 로딩은 S4-1에서 확인했고, 전체 동작/부하는 후속 검증입니다. 설치/운영 변경 승인은 아닙니다.

## 논리적 구성

```text
싱글 / 코옵 공동체
       ↓
스토리 Paper 26.2 서버 프로세스 하나 (B안)
  ├─ 진행 ID 1 → 독립 월드 → 진행 1 전용 상태
  └─ 진행 ID 2 → 독립 월드 → 진행 2 전용 상태
       ↕ 진행별 접근 격리
공통 로컬 AI 서비스 (필수·미구현)

플레이어 → 경제 월드 영역   → 경제 전용 데이터
                    ↕
             AI 스마트폰 어시스턴트 (선택·제거 가능·계획)

Hearth 운영 영역: Docker Compose 배포 및 기존 Zabbix 활용 (미구현)
```

화살표는 논리적 관계를 나타내며 네트워크 경로나 프로토콜을 확정하지 않습니다. 스토리 진행은 같은 서버 프로세스 안의 독립 월드로 배치합니다. 경제 월드와의 프로세스 경계, 컨테이너 구성 및 외부 접속 방식은 미정입니다. 기존 Cloudflare Tunnel 사용 여부도 미정입니다.

공통 기반 기능의 재사용은 가능하지만 월드별 데이터 경계는 유지합니다. 경제 월드는 AI를 제거해도 핵심 경제 기능이 동작하도록 설계합니다. 스토리 AI의 진행별 정보 접근 격리는 확정 요구사항이며, 세부 정보 제공·연동 방식, 권한 모델과 장애 시 동작은 미정입니다.

## 인벤토리·아이템 운영 원칙

[ADR-0003](decisions/0003-inventory-performance-and-recovery.md)에 따라 서버 성능과 원활한 플레이를 복잡한 자동 장애 복구보다 우선합니다. 일반 상자·창고는 월드 파일, 플레이어 인벤토리는 PostgreSQL 중심으로 관리합니다. 정상 플레이의 중복·유실은 기본 동시성·저장 순서로 예방하되 아이템 이동마다 DB 트랜잭션·동기 디스크 저장을 요구하지 않습니다.

일반 dirty 인벤토리는 초기 30초 간격으로 비동기 배치 저장하며 성능 측정 후 주기를 조정할 수 있습니다. NPC 상점 구매·판매와 플레이어 경제 거래는 거래별 즉시 DB 반영, 퀘스트 보상은 중복 방지·지급 상태 즉시 저장 방향으로 설계합니다. 스토리·경제 전환 시 이전 인벤토리 저장 완료를 확인합니다. 즉시는 30초 주기를 기다리지 않는다는 뜻이며 메인 스레드 DB 대기는 금지합니다. 거래의 최신 미저장 상태·인벤토리/화폐/기록 일관성·순서·중복 방지의 구체 후보는 S3에서 다룹니다.

복잡한 거래 전용 보관 시스템·고비용 체크포인트·완전 자동 복구는 필수가 아닙니다. 추가 안전장치는 단순하고 성능 영향이 작을 때만 검토하며 부하·지연이 크면 생략합니다. 예기치 못한 장애의 일부 아이템 유실·복사는 관리자 로그·백업 기반 수동 조정을 허용합니다. 최소 오류 기록·조치 절차는 유지하며 자동 무손실·모든 상황의 복사 방지를 보장하지 않습니다. 구현·성능·복구 검증은 미실행입니다.

## 데이터 경계

| 영역 | 분리 대상 | 원칙 |
| --- | --- | --- |
| 스토리 | 월드 파일, 플레이어 상태, 퀘스트와 진행도, AI 관련 상태 | 스토리 전용 범위 안에서 진행 ID별 격리; 개인 상태는 진행 ID와 플레이어 ID로 구분 |
| 경제 | 월드 파일, 플레이어 상태, 진행도, 생산·재고·공급·수요·가격·거래·무역·자산 등 경제 상태, 선택형 AI 관련 상태 | 경제 전용 범위에서 관리 |
| 운영 | 설정, 로그, 백업, 비밀 정보 | 월드별 구분과 접근 범위를 별도 설계 |

진행 상태 저장소는 PostgreSQL로 확정했습니다. 퀘스트·NPC 관계·스토리 분기와 플레이어별 진행 상태는 월드별로 논리적으로 격리합니다. 스토리와 경제의 인벤토리·진행도 분리합니다. 실제 저장 경로, 스키마와 백업 매체는 미정입니다. 공통 플레이어 식별, 데이터 이전 및 월드 간 교환도 미정이며, DB 인스턴스·스키마 분리 방식은 확정하지 않습니다. 백업과 복구는 월드별 복구 범위를 구분하도록 설계합니다.

스토리 진행 단위는 싱글 또는 코옵 공동체로 확정했습니다. 코옵 가입·탈퇴·추방·파티장 UI는 없고 내부 플레이어–진행 연결과 저장·격리 구현만 구분합니다. 경제 월드가 스토리 월드를 기반으로 확장된다는 방향이 진행 데이터나 경제 데이터의 공유를 뜻하지는 않습니다.

Git에는 설계 문서, 소스 코드와 비밀 정보가 없는 설정 예시만 저장합니다. 실제 월드·플레이어 데이터, 백업, 로그, 인증 정보는 실행 구성을 도입하기 전에 저장 경로와 제외 규칙을 정합니다.

## 구성 요소별 책임

- `minecraft/story/`: 현대 지식 활용, NPC, 퀘스트, 협동 플레이와 플레이어·공동체별 독립 진행 규칙을 설계합니다.
- `minecraft/economy/`: 생산, 재고, 공급·수요, 시장가격, 거래·무역과 자원 순환 등 경제 규칙을 설계합니다.
- `services/`: 로컬 AI 등 보조 기능을 설계합니다. AI 스마트폰 어시스턴트는 스토리 월드에서 필수, 경제 월드에서 선택·제거 가능한 기능입니다. AI 연동 인터페이스, 권한과 장애 시 동작은 미정입니다.
- `infrastructure/`: Hearth 배포와 모니터링 연동, 영속 저장소 및 복구 방식을 설계합니다.
- `scripts/`: 향후 필요한 검증과 운영 보조 자동화를 둡니다.

| AI 모델·런타임·연동 방식 | 미정 | 로컬 자원, 응답 품질과 접근 권한 |

| 외부 접속·Cloudflare 활용 | 미정 | 접속 요구사항, 지원 방식과 기존 구성 |

S3 설계 완료 기준선은 [상세 설계](story-world-detailed-design.md)와 [최종 감사](s3-completion-audit.md)를 참고합니다. 승인 정책과 상태명/물리 스키마/API 등 구현 후보·보류를 구분하며 실행은 미검증입니다. 실제 기능 구현 전에는 [기성 플러그인 검토](plugin-suitability-review.md)를 갱신하여 재사용/API 확장/자체 개발을 비교합니다.

## 이후 구현 절차

1. 게임 요구사항과 월드별 데이터 소유권을 구체화합니다.
2. 확정 스택의 호환성·검증 수용 조건과 상세 설계를 정리하고 후속 확정 변경은 `docs/decisions/`에 기록합니다.
3. 운영 변경을 제안하기 전에 관련 기존 구성을 읽기 전용으로 확인합니다.
4. 중요한 운영 변경에는 대상, 영향, 검증 방법과 롤백 계획을 준비하고 적용 승인을 받습니다.
5. 승인된 범위에서 구현하고 결과를 확인합니다.

향후 롤백 계획에는 변경 전 설정 보존, 월드별 데이터 백업, 복원 절차와 복구 확인 방법을 포함해야 합니다. 이번 작업은 문서 생성에 한정하며 서비스 설치·실행·재시작, 시스템 패키지 설치, 방화벽·SSH·Cloudflare 및 기존 Docker·Zabbix 구성 변경을 포함하지 않습니다.

공동체·개인 퀘스트, 고정 분기와 장별 따라잡기/스킵의 확정 정책은 [ADR-0004](decisions/0004-community-quests-and-chapter-skip.md)를 따릅니다. 중요 퀘스트는 당시 접속한 공동체 구성원 전원의 조건 충족이 필요하며 비접속자는 제외합니다. 개인 완료·보상은 구분하고, 따라잡기·스킵은 공유 분기·NPC·월드 상태를 변경하지 않습니다. 신규 접속 시 현재 단계는 중단하지 않고 다음 중요 단계에서 전원 조건을 재검사하며, 분기는 전체 대상의 50% 초과 투표로 선택합니다. 보상·단계 경합·과거 재현 세부는 보류/미정이며 투표는 ADR-0011의 채팅 정책을 따릅니다. 가입 기능은 없습니다.

2026-10-25 통합 정책과 설계 완료 근거는 [S3 최종 감사](s3-completion-audit.md)를 따릅니다. 가입 없는 내부 진행 연결, 지도/메뉴/HUD(ADR-0010), 채팅 투표/정확한 보스 복귀/관전/채집 리셋(ADR-0011), 저장/월드/버전 보존(ADR-0012)을 반영했습니다. C1은 온라인 보스 시작 명단·온라인 사망자 자동 부활·기존 참가자 복귀 권리로 후속 확정했습니다(ADR-0013). 필수 12영역 명세를 재감사하여 S3 설계 완료이며 S4는 진행 중입니다. [S4-1 기록](s4-1-verification.md)에 최소 플러그인과 격리 서버의 A/B 블록/식별자·WG 구역 API smoke 결과를 구분했습니다. 전체 게임/부하 검증 완료는 아닙니다. 추천값·의도적 보류·구현/실행 미검증은 그대로 구분합니다.
