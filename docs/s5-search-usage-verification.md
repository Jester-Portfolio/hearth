# S5 한국어 공개 검색·AI 사용 집계

확인일: 2026-11-11. 기준 `1235ec9` 이후 코드. 사용자의 연속 진행 요청에 따라 기존 S5 공개 검색과 사용량 진단을 연결했다. [이전 캐시·참고자료 계약](s5-grounded-cache-verification.md)과 [ADR-0018](decisions/0018-local-ai-runtime-and-trial-budget.md)의 정보/실행 한도를 유지한다. 최종 JAR·원시 로그는 [검증 JSON](../verification/s5-search-usage-result.json)을 따른다.

## 검색과 관리 조회

기존 스마트폰 도움 검색에 NFKC/대소문자 정규화와 유한한 한국어 조사 보조를 추가했다. `석재는`, `목재를`, `창고에는`, `기록을`처럼 공개 제목/본문과 조사가 붙은 질문도 찾는다. 원문 일치 점수를 우선하고 보조 일치는 낮은 점수를 쓴다. 일반적인 질문 표현은 제외하며 중복 검색어로 점수를 늘리지 않는다. 영문·숫자·식별자는 단어 경계를 확인해 `iron`이 `irony`를, `64`가 `640`을, `node_12`가 `node_123`을 찾지 않게 했다.

질문 256자·검색어 최대 16개/각 2~32자·자료 최대 4개와 제목/발췌/문맥 한도는 유지한다. 긴 단어를 32자 조각으로 잘라 새로운 검색어로 만들지 않는다. 정규화는 비교에만 쓰며 선택한 공개 DTO의 원문·스냅샷 인덱스·자료 키/버전·PG 최신성 검증은 그대로다. 새 사전/외부 검색/임베딩·비공개 콘텐츠는 추가하지 않았다. 이 보조 규칙은 한국어 형태소 분석 전체를 구현하거나 검색 정답률을 보장하지 않는다.

스마트폰이 생성한 서비스에 `MeasuredAssistant`를 연결했다. 서버가 켜진 동안 생성 요청과 캐시 신원 확인을 구분해 시작/성공/실패/취소/진행 중 개수와 완료 지연 합계/최댓값·고정 6구간을 집계한다. 구간 상한은 100/500/1000/3000/6000ms/그 이상이다. 실패 유형은 기존 enum에 한정한다. 질문·응답·문맥·사용자/진행 식별자·주소/실패 원문을 집계에 저장하지 않으며 개별 요청 기록/영속 저장/외부 전송은 없다. 정상 생성/캐시/취소·6초/8초·HTTP 4개 제한을 바꾸지 않는다.

`hearthai status`는 서버 콘솔 전용 읽기 전용 조회다(`hearth.ai.inspect`, 기본 op). 플레이어는 op여도 처리기에서 거부한다. 모듈 비활성이면 미준비를 안내한다. 조회는 HTTP·모델 로딩·추론·집계 초기화·PG/게임 상태 변경을 하지 않는다. 평균은 완료된 요청의 정수 ms 평균이고 진행 중 요청은 완료 지연에 포함하지 않는다. **백엔드 성공은 자료 번호·PG/권한 검사·화면 표시 성공을 뜻하지 않는다.** 캐시 확인 성공도 실제 답변 재사용 확정/토큰 절약량과 구분한다. 현재 연결 가능/모델 준비 상태나 목표 동시 사용량 합격을 판정하지 않는다.

완료와 취소는 같은 동기화 경계에서 처리하고 집계를 먼저 확정한 뒤 응답을 전달한다. 취소/종료는 원래 백엔드 작업으로 전파하며 늦은 완료를 다시 세지 않는다. 공유 서비스 종료도 한 번만 수행한다. `--grounded` 실제 모델 probe도 같은 계측기로 연결해 다음 실행 때 집계를 수집하도록 준비했다.

## 실행한 검사

- 관련 스마트폰·공개 자료 단위/회귀 **137개 고유 검사 PASS**. 중복 실행은 합산하지 않았다. 이 중 합성 공개 자료 검색 품질 사례 22개는 조사/정규화·영문/숫자/식별자·일치 없음·도움 범위 분리를 확인했다.
- 계측 검사에서 구조화된 요청/캐시 기능·응답 보존, 지연 구간/실패 유형, 원문 비보유·불변 스냅샷, 취소/종료·동시 완료 120개, 같은 요청의 완료/취소 경합 200회와 후속 콜백의 확정 집계를 확인했다. 실제 localhost HTTP fixture에서 생성 1회·캐시 확인·모델 불일치·취소도 구분했다. 콘솔 조건/잘못된 인자는 집계조차 읽지 않고, 정상 조회는 백엔드를 호출하지 않는다.
- 최종 main/test/JAR/integration fixture 컴파일 PASS. **격리 Paper 1 JVM/PG 1개·123회 assertion PASS·52.433초**. 본인 PG 공개 기록의 조사 검색, 기존 검색/캐시의 최신성·조회 실패·다른 개인 및 일지/인벤토리/revision 보존을 확인했다. 자료/PG가 거부한 응답도 백엔드 성공 집계와 구분하고, 실제 등록된 서버 콘솔 명령을 실행했다. 실제 클라이언트 접속/플레이어 명령 실행은 포함하지 않는다.
- 실행 JAR/설치 JAR/최종 빌드 SHA 일치, 소유 프로세스/포트 종료·정리 오류 없음. 최초 실행은 작업 경로 표식 누락으로 프로세스 시작 전에 거부됐으며 로그를 보존했다. 표식 준비 후 첫 Paper 검사도 통과했으나 완료/취소 계측 순서 보완으로 영향을 받은 단위와 Paper를 다시 확인했다. 이전 경로/로그/JAR은 덮어쓰지 않았다. 영속 저장/복원 계약은 같아 두 JVM 복원 시험은 생략했다.

## 다음 실행과 미검증

배치 시작 시 `/tmp` 여유는 15,424MiB로 실제 AI 시험의 기존 16GiB 시작 전제에 미달했다. 사용자는 직접 공간을 확보한 뒤 알리기로 했고 아직 알림을 받지 않았다. 원본 증거 삭제·디스크 전제 완화·모델 다운로드/실제 AI 실행은 하지 않았다. 공간 확보 후 고정 해시 파일을 새 경로로 검증 복사하고, 준비된 자료/캐시/계측 probe를 기존 자원/600초 한도에서 이어간다.

새 모델 응답 품질·캐시 실제 절약량·동시 사용량/장기 성능·과학 지식/인용 충실도와 Minecraft 화면/클릭·코옵·운영 배포는 미검증이다. 합성 검색 사례/HTTP fixture/콘솔·PG 성공을 실제 모델 또는 전체 S5 완료로 기록하지 않는다.
