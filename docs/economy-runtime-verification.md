# 경제 전용 실행·정상 계정·저장 종료 검증

확인일: 2026-11-17. 기준 `b3cd7a8` 이후 [ADR-0024](decisions/0024-dedicated-economy-admission-and-currency.md)의 연관 구현 배치다. [실행 횟수·최초 실패·최종 JAR/원시 결과](../verification/economy-runtime-result.json), [설정과 운영 전제](../infrastructure/economy/README.md)를 따른다.

## 구현

기본 비활성 `runtime-mode: economy`를 추가했다. 정품/whitelist와 명시한 기존 경제 차원·UUID·진입 위치·WorldGuard 구역을 확인하고 기존 PaperEconomy/세션/41슬롯/거래를 연결한다. 시험/스토리 모듈·AI를 초기화하지 않는다. 정상 모드의 DB 풀은 같은 제한 worker/연결 수를 쓰되 스토리 스키마 준비/DDL을 허용하지 않는다. 새 빈 월드/바닥/보호 구역이나 fixture 자산을 만들지 않는다.

새 계정은 PG 잔액 0·빈 41슬롯으로 한 번만 생성한다. 동시 생성과 재접속은 기존 행을 읽고 기존 realm의 재고/가격·계정/영수증을 초기화하지 않는다. 비어 있지 않은 미확인 인벤토리, 다른 경제 소유 표식, 기존 아이템이 있는데 계정이 없는 상태는 보류한다. 최신 본인 세션/원래 인벤토리를 다시 확인한 뒤에만 정상 저장·이동을 시작한다. 실패/늦은 결과를 빈 인벤토리로 대체하지 않는다.

콘텐츠는 PAUSE/fixture 잔액 0을 요구하며 실제 신규 잔액은 SQL에서 0으로 고정한다. 배포 비밀번호는 환경 변수에서만 읽는다. 일반 블록 조작도 같은 경제 월드/준비 세션과 WorldGuard에 묶는다. 콘솔 상태/영수증 조회·오프라인 HOLD 대응과 비동기 drain을 연결했다. 저장/이동·월드/구역·PG 종료 확인 뒤에만 본인 실행 표식을 제거한다. 기존/변조·다른 파일로 교체한 표식은 보존하고 다음 기동에서 접속 HOLD한다.

## 검사와 실패 보완

- 경제/세션·DB 경계 **121개 PASS**, 신규 13개. Python 제어 **6개 PASS**. 처음 fixture 콜백 구문의 컴파일 오류는 테스트 실행 전에 고쳤고 원본 로그를 남겼다. 실제 검사 묶음은 한 번이다.
- 최초 두 JVM에서는 PG 새 계정 0/빈 슬롯, realm/계정 생성 경합·기존 값 보존·실제 INSERT 실패의 rollback·잘못된 초기 자산/외부 문맥 거부를 확인했다. 둘째 JVM의 정상 모드 기동·기존 계정/스토리 PG·시장/운송/PAUSE도 통과했으나 마지막 상인 준비 가정에서 실패했다. 실행 전체는 **FAIL·59.788초**이며 종료 확인 오류도 보존한다.
- 원인은 실제 플레이어가 없는 제어 시험에서 NPC 청크를 유지하지 않은 전제였다. 명시적 격리 probe에만 기존 시험 청크 티켓을 연결했다. 부수적으로 드러난 비활성 플러그인 종료 중 예약 오류는 예약 차단과 finally의 PG 정리로 보완했다. 일반 모드가 없는 청크를 상시 강제 유지하도록 바꾸지 않았다.
- 실행 표식의 새 파일·변조/교체·symlink·중복 기동과 본인 정리/이후 표식 보존 **5개 PASS**를 추가했다. 기존 성공 121개는 반복하지 않았다. 계정/설정·DB worker/세션 적용의 본체/중첩 class 바이트가 최초 검사 JAR와 최종 JAR에서 같음을 확인했다. Paper 종료/시험 준비 변경은 새 JAR의 영향 통합으로 검사했다.

## 최종 영향 재검사

새 소유 경로에서 **전체 기존 거래 시나리오를 반복하지 않고** 최소 PG/계정/월드 복원 입력만 준비했다. 같은 최종 JAR의 두 JVM에서 둘째 JVM은 verification/lifecycle/economy-verification을 모두 끈 정상 경제 모드로 기동했다. **20개 assertion·51.747초 PASS**, PG 1개·Paper 2회, 정리 오류 0·소유 프로세스/포트 닫힘이다.

기존 계정 8개와 새로 저장해 둔 인벤토리/revision을 복원했고 스토리 원본 PG·시장·운송·Tick을 보존했다. 미확인/다른 경제 인벤토리를 거부하고 정상 신규 계정을 잔액 0으로 만들었다. 기존 경제 차원/WorldGuard·상인 준비와 본인 PG 인벤토리의 제어 포트 적용을 확인했다. 명시적 drain은 월드 저장/언로드·PG 풀 종료와 실행 표식 정리·정상 disable까지 통과했다. 기존 CPU 2/nice 10·Paper heap 1536MiB/RSS 2560MiB·호스트 가용 6GiB·총 600초/작업 550초를 유지했다.

제어 포트이며 실제 Player를 만들거나 인증을 우회하지 않았다. Port의 이동 확인 값을 사용했으며 실제 teleport 성공을 판정한 것은 아니다. 실제 정품 접속의 인벤토리 소유 표식·상인 클릭/이동·동시 사용자, 실제 강제 장애/hot reload·장기 부하·운영 자원/배포는 미검증이다. 기존 데이터/운영 서비스는 변경하지 않았다. 전체 E1~E3 완료나 운영 배포 승인으로 보지 않는다.
