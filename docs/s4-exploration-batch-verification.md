# S4 탐험·지도·일지·공동체 통합 배치

확인일: 2026-10-27. 기준 `6139e686d7d25474ce95c766b6f85bda0adbe0cc`의 깨끗한 main·스테이징에서 시작했고 fetch 후 origin/main과 일치했습니다. 격리 개발 모드의 구현·자동 시험이며 전체 S4는 **진행 중**입니다. 실제 클라이언트 시험은 요청하거나 실행하지 않았습니다.

## 구현 범위

| 영역 | 구현과 경계 |

공유 일지 작성·공유 진행 변경은 신뢰하는 서버 내부 인터페이스만 제공합니다. 일반 공유 사건 엔진이 없어 게임 플레이 중 임의 사건·챕터를 생성하지 않습니다. 통합 시험의 공유 사건/단계는 명시적 합성 fixture입니다. 조건 provider가 없으면 공유 단계만 등록돼도 조건은 미등록입니다. 타인의 개인 퀘스트 제목·조사·인벤토리·알림은 공동체 화면에 포함하지 않습니다. 공유 기록 열람은 개인 퀘스트나 보상을 바꾸지 않습니다.

## 저장·실패·성능

V001~V004 원본은 수정하지 않고 V005로 장소/발견 알림, 개인·공유 일지 fact/event, 공유 진행 및 기존 설정의 5개 마커 열을 추가했습니다. 기존 V004 퀘스트 알림 테이블/FK는 그대로 두고 발견 알림을 읽기 단계에서 합칩니다. 개인 키는 `story_run_id + player_uuid`, 공유 키는 `story_run_id`이며 물리 UUID는 소유권 키가 아닙니다. 존재하는 플레이어 연결·복합 FK·PK와 설정/공유 단계 CAS를 사용합니다. 단순 사실 버전 이력은 일지 요구를 위한 것이며 전체 아이템 원장/복구 체크포인트가 아닙니다.

`QuestJournal`·기존 bounded DB worker/owner·세션·월드 저장 장벽을 재사용했습니다. 같은 장소의 진행 중 관측은 합치고 UI 조회/퀘스트 저장 정리 후 처리합니다. 퀘스트 저장 성공 콜백 처리 전에는 settled로 판정하지 않도록 보완했습니다. 서버 메인 스레드에서 DB future를 기다리지 않습니다. 블록 변화/구역 진입에만 관측하고 UI는 진입/변경 때 조회하며 매 틱 DB 조회·지도 렌더링을 하지 않습니다.

발견/일지 SQL 실패는 트랜잭션 전체를 롤백하고 해당 UI 범위 HOLD와 저장 장벽 실패를 보존합니다. 조회 실패를 빈 지도·일지 성공으로 바꾸지 않습니다. 세션/퀘스트/HOLD·현재 구성원/조건을 비동기 응답 후 재검증합니다. 미니맵·지형 렌더러/빠른 이동/스마트폰 아이템/가입 관리/AI/보상/경제는 추가하지 않았습니다. 폰 아이템이나 가입 정책을 임의 확정하지 않았습니다.

새 `exploration-verification-enabled: true`와 `-Dhearth.verification.exploration=true`는 기존 격리 세션/퀘스트 게이트까지 요구합니다. 기본값은 false이고 기존 콘텐츠 파일을 덮어쓰지 않습니다. 장소 정의는 기존 NPC 참조를 사용하며 새 지형·실제 월드·NPC를 자동 배치하지 않습니다. 새 콘텐츠는 초기 로딩 전용이고 hot reload/기존 콘텐츠 자동 이관을 구현하지 않았습니다. 렌더러 후보 근거는 [기성 플러그인 검토](plugin-suitability-review.md#탐험일지공동체-통합-배치--2026-10-27)를 따릅니다.
