# 공통 예약 작업·관리자 작업센터

2026-11-20. 플랫폼 우선 후속 배치로 기존 자원 세대 엔진에 예약·작업 이력·중단 복구를 연결했다. [설정/운영](../infrastructure/network/platform-jobs.md), [ADR-0034](decisions/0034-persistent-platform-jobs.md), [구조화 증거](../verification/platform-jobs-result.json)를 따른다. 운영 서버·실제 초기화 주기·콘텐츠/밸런스·실제 클라이언트는 변경/진행하지 않았다.

## 구현

- E013은 역할별 예약 간격/다음 논리 tick/revision과 안정 요청 ID·version1·종류/대상·고정 입력·시작 tick·상태·판정 이력을 저장한다. 예약/수동 실행은 같은 작업 엔진을 사용하고 실제 효과 전에 PG 의도를 확정한다.
- 자원 교체 handler는 job ID를 기존 ResourceGenerations 요청 ID로 전달한다. 시드는 예약 선점 전에 한 번 정해 저장하며 같은 ID 재요청은 입력 변경/재굴림을 거부한다. PG replay가 새 실행을 허가하지 않는다.
- 경제 논리 시계를 사용하므로 기존 offline PAUSE를 유지한다. 완료/명시적 취소 후 현재 tick+주기에서 다음 작업을 잡으며, 밀린 예약을 한꺼번에 재생하지 않는다. 플랫폼/RPG/생존/경제 준비·설정 변경/종료·기존 작업/세계 교체 상태를 공통 검사한다.
- realm당 RUNNING/HOLD 작업 하나만 허용한다. 재시작 RUNNING은 HOLD로 바꾸며 자동 재실행하지 않는다. 관리자 결과 확인은 기록된 효과만 조회한다. 효과가 ACTIVE/RETIRED여도 로컬 세계 제어 상태가 불명하면 먼저 자원 복구가 필요하다. 미시작/명시적으로 중단된 효과만 작업 취소를 허용한다. 전역/native HOLD를 해제하거나 보상을 재지급하지 않는다.
- 기존 `/플랫폼 reset`도 작업 이력을 남긴다. 관리자 작업센터는 예약·진행/보류·최근 이력·개별 입력/결과를 보여 주고 같은 API로 결과 확인/취소한다. 관리자 조회는 일반 강화/판매의 busy 제한과 분리하지만 현재 접속/화면·설정 세대·권한 검사는 유지한다. 콘솔 경로도 제공한다.
- 신뢰하는 Java 모듈은 JobHandler/JobExtension으로 prepare/execute/inspect를 등록한다. 임의 명령/스크립트·LLM 실행기는 없다. 새 handler 등록은 초기화 전에만 허용한다. 초기 적용은 resource_reset 한 종류이고 자동 예약 대상은 거주를 제외한 네 자원 역할이다.

기존 인벤토리·시장·접근·사망/전투·원본 세계를 재구현하지 않았다. jobs.enabled 기본 false, 네 역할 주기 기본0이며 기존 platform.properties에 키가 없어도 비활성으로 읽는다. 새 운영 주기를 선택하지 않았다.

## 안전·비용 경계

JobStore는 기존 realm 잠금·발급 context와 비동기 DB worker를 사용한다. 선점/동일 ID·고정 입력·작업 상태 revision/identity CAS를 적용한다. 성공/취소와 다음 예약 갱신은 같은 PG 트랜잭션이다. SQL 실패·효과 실패/불명은 기록을 보존하고 HOLD/명시적 확인으로 처리한다. 재확정 시 아이템/화폐·세계 효과를 다시 실행하지 않는다.

활성 예약/미확정 작업이 있으면 플랫폼을 끄는 기동을 거부한다. 예약 구성 변경은 미확정 작업이 있으면 거부하며, 원본/후보/이전 이력을 보존하는 기존 config-stage/apply 경로를 사용한다. 설정 공개 중에는 신규 작업/일반 플랫폼 작업을 열지 않는다. 일반 reload로 예약 정책을 암묵적으로 바꾸지 않는다.

예약은 경제 tick 변화 때 캐시를 확인하며 due가 없으면 DB를 호출하지 않는다. handler 최대32개·자동 예약4개·동시 작업1개·최근 조회128개·전체 이력4096개의 기술 상한을 둔다. 전체 ID 조회는 개별 inspect로 제공한다. 자동 삭제/원본 세대 정리는 추가하지 않았다. status는 요약만 출력하고 상세 입력은 관리자 개별 화면에 둔다. DB/세계 효과가 불명인 상태의 무손실 자동 장애 복구를 약속하지 않는다.

초기 PG16개는 통과했지만 Paper 검사 helper가 기존 격리 경제 tick(60초)을 30초만 기다려 timeout이었다. 서버 clock/정책이나 자원 한도를 늘리지 않고 기존 advanceTick 경로를 한 번 호출해 조건을 만들었다. 실패 원본은 보존했다. 재시험에서는 E013·JobStore/EconomyStore/JobPolicy·fixture hash가 같은 경우만 그 PG 결과를 재사용했다. 새 준비 guard는 이후 추가한 별도 순수 정책 검사를 따른다.

실제 자원 교체는 비플레이어 Paper 세계 수명주기 검증이다. Player 인증/조작을 합성하지 않았으며 GUI 클릭·실제 대피/전투 중 예약·다인 행동의 수용 완료를 뜻하지 않는다.

## 자원·미검증

성공한 주 배치 두 JVM+PG는 56.385초, Paper 최대 표본 RSS 1,321,960KiB, 합산 최대1517.8MiB였다. 기동 포함 Paper CPU는42.51/39.40 CPU초였다. 최종 좁은 JAR 수치는 JSON에 별도 기록한다. 기존 CPU2/nice10·heap1536MiB/Paper RSS2560MiB·합산6144MiB·호스트 가용6144MiB·600초/작업550초·시험당 최대 두 Paper/한 PG·localhost/EULA/소유 임시 경계를 유지했다.

기동/0명/두 차례 격리 세계 교체 측정이므로 실제 동접·지속 TPS/MSPT·장기 이력/디스크·운영 수용은 미판정이다. 기존 전체 Paper/PG 백업 형식은 변경하지 않았으며 이번에 전체 백업 행렬을 반복하지 않았다. 새 작업 데이터는 PG에, 실제 세계는 기존 Paper 루트에 저장된다.

후속은 새로 승인된 플랫폼 기능/확인된 연동 공백을 대상으로 한다. 운영 주기·보존/아카이브·콘텐츠/획득처·밸런스는 별도다. 운영 서비스/DB/세계·SSH/방화벽·패키지는 변경하지 않았으며 실제 운영 적용은 별도 승인이 필요하다.
