# 전투 표시·안내 기능 통합

2026-10-29 · 격리 개발 모드 · S4 진행 중.

## 함께 구현한 기능

1. 보스 이름·실제 체력 비율을 전용 빨간 BossBar로 표시한다. 일반 퀘스트 BossBar와 별도 객체이며 체력/제목/표시 여부가 달라질 때 갱신한다.
2. 본인의 개인 또는 공동 부활 남은 횟수, 예약 중인 횟수 차감, 부활 불가 상태를 기존 전투 정본에서 읽어 표시한다. 다른 참가자의 개인 사용량·UUID·체력은 DTO에 포함하지 않는다.
3. ActionBar의 전투 출력은 한 경로로 모아 HOLD·전멸·복귀/부활 적용 대기·일시정지·관전 안내를 부활 횟수보다 먼저 구성한다. 상태 변화는 즉시 반영하고 같은 내용의 유지 출력은 초기 구현값 20틱 간격이다. 같은 상태의 채팅 안내를 매 틱 반복하지 않는다. 일반 발견/퀘스트 메시지는 기존 채팅을 유지하며 프로젝트 밖 플러그인의 출력까지 제어한다고 보지 않는다.
4. `/hearthcombat`·`/hearthcombat help`와 본인 상태/관전 전환 채팅 링크를 추가했다. 기존 status/watch를 재사용하고 전투 종료 사유를 승리·필수 조건 실패·전원 접속 종료·재도전 결정·시험 종료로 구분한다. 새 재도전 투표나 부활 명령은 제공하지 않는다.
5. 사망·복귀 중에도 연결과 진행이 검증된 세션은 퀘스트 HUD를 읽기 전용으로 갱신한다. 사망 실패 저장 장벽을 기다린 뒤 실패 상태를 표시하며 GUI/대화/수락/보고/보상·진행 복원은 호출하지 않는다. 세션 교체/종료/HOLD의 늦은 결과를 거부하며 부활 후에는 기존 정상 화면 갱신으로 돌아간다.

기존 [전투 세션](combat-player-verification.md)·[사망 퀘스트 연결](quest-death-verification.md)·[ADR-0010](decisions/0010-coop-information-and-hud.md)의 범위 안이다. 기존 Paper 표시 API를 재사용했고 외부 플러그인·DB 스키마·저장 형식·운영 활성화를 추가하지 않았다. 표시 오류는 경고/화면 정리로 처리하며 전투 참가자의 생존·사망 상태를 바꾸지 않는다. 기존 세션·월드 세대·도전 식별자를 검사하고 퇴장·정리 시 해당 세션의 화면만 제거한다.

## 미검증과 남은 기능

실제 Player에게 BossBar/ActionBar를 보여 주거나 채팅 링크를 누르는 시험은 하지 않았다. 자동 결과는 표시 DTO·실제 BossBar 객체·내부 세션 경계이며 실제 화면/클릭/관전 성공을 뜻하지 않는다. 고정 위치 HUD·원형 미니맵·클라이언트 가독성·다른 플러그인의 채널 충돌·장기 부하는 미검증이다. 실제 인증 클라이언트 시험은 별도 사용자 요청 전 보류한다.

보스 재도전 투표·정식 종료/복귀·패턴·전체 인던은 후속 기능이다. 이번에는 승인된 표시·안내 기능을 묶어 구현했으며 전체 S4 완료로 처리하지 않는다.
