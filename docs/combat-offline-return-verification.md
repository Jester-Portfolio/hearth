# 종료 중 오프라인 참가자 복귀·도전 정리

2026-11-06. S4 진행 중. [기존 종료 복귀](combat-return-verification.md), 세션·저장 장벽·월드 수명주기를 재사용했다. [실행 결과 JSON](../verification/combat-offline-return-result.json).

## 구현

- 승리·필수 실패·전원 오프라인으로 종료된 도전에서 원래 참가자의 복귀 권한을 보존한다. 기존 콘텐츠에 `exit`가 있을 때만 적용하며 복귀 위치·체력·효과는 기존 설정을 따른다. 진행 중인 전투 재접속의 정확한 위치/방향·관전/부활 정책은 변경하지 않는다.
- 같은 Paper 프로세스에서 재접속하면 기존 진행/인벤토리 복원 후 저장 장벽→안전한 복귀 위치 이동→회복/모드·카메라 정리→복귀 완료 순으로 처리한다. 종료된 전투를 재개하거나 새 참가자로 추가하지 않는다. 복귀가 끝나기 전에는 해당 플레이어의 일반 조작을 허용하지 않는다.
- 권한은 원래 도전·story_run_id·player_uuid에 연결한다. 다른 플레이어/진행·중복 세션은 사용할 수 없다. 완료된 권한은 소비하며 종료 도전 정리 대기 중 다시 생성하지 않는다. 이전 세션·세대의 늦은 적용, 저장·이동·정리 실패는 HOLD와 미완료 정보를 보존한다.
- 복귀 중 작업도 기존 진행별 저장 장벽에 포함한다. 기존 미완료/실패 작업을 버린 채 종료 도전을 정리하지 않는다. 미접속 대기 기록에는 UUID·콘텐츠 복귀 설정·원래 게임 모드만 남기고 Player·실제 월드·전투 객체를 붙잡지 않는다. 활성 작업은 완료/실패 확인까지 기존 적용 경계에 남는다.
- 같은 JVM에서 기존 월드를 언로드·재로드한 경우 물리 매핑을 확인하고 현재 세대의 새 적용기로 복귀한다. 다른 월드나 누락 데이터를 대신 생성하지 않는다. 복귀 대기는 온라인 준비가 끝난 다른 참가자의 새 도전을 막지 않으며 도전별 기록을 분리한다. 복귀 중인 플레이어는 새 시작 명단에 넣지 않는다.
- 기존 온라인 참가자의 `/hearthcombat leave`도 같은 권한·저장·이동 경계를 사용한다. 일반 서버 자동 활성화는 없으며 격리 개발 모드 게이트를 유지한다. 신규 DB 테이블·마이그레이션·인벤토리 저장 체계는 추가하지 않았다. V001~V008과 과거 증거는 보존했다.

- 전투·세션 기존 회귀 131개와 신규 복귀 검사 최종 9개 **PASS**. 초기 관련 검사 138개 통과 후 변경된 복귀 검사만 재실행했다. 개인/진행 격리, 중복/종료 권한, DB 실패·이동 실패·세션/세대 변경·종료·owner 거부, 기존 실패 장벽, 다른 도전 기록 공존을 확인했다.

## 남은 범위

복귀 기록은 같은 Paper 프로세스의 메모리 범위다. 프로세스 재시작을 넘는 복귀 대기·전투 상태 복구는 **미구현**이며 두 번째 JVM 시험을 수행하지 않았다. 기존 전투 시작 마커의 관리자 검토 경계도 유지한다.

실제 인증 클라이언트의 종료/재접속 이벤트·teleportAsync·화면·회복/모드, 다인 실제 행동·장기 부하는 미검증이다. 사용자 접속·클릭·TTY 조작은 요청하지 않았다. 운영 서비스·실제 데이터·기존 시험 증거는 변경하지 않았고 전체 S4 완료를 뜻하지 않는다.
