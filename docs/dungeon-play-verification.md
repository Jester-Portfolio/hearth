# 공개 던전 의뢰·NPC 입장·개인 보고 연결

확인일: 2026-11-08. 기준 `bdc6e2d`. [복수 길목](combat-route-verification.md)·기존 NPC/퀘스트·세션/저장 경계를 재사용한다. 상세 수치와 산출물 식별은 [JSON](../verification/dungeon-play-result.json)에 기록한다. 전체 S4는 진행 중이다.

## 연결한 플레이 흐름

1. 공개 던전 의뢰를 기존 NPC 아이템창/책에서 수락한다. 수락 전에는 던전 입장 버튼이 없고, 목표 좌표 방문이나 NPC 일반 대화로 승리 목표를 달성할 수 없다.
2. 등록 NPC의 입장 버튼은 현재 대화의 nonce·NPC 엔티티·거리·구역/스토리 권한·세션을 확인한다. 같은 진행의 입구 근처 서버 세션 중 해당 의뢰의 현재 목표가 ACTIVE인 대상만 비동기로 선별한다. 다른 진행과 미수락자는 제외하며 새 가입/파티 기능을 만들지 않는다.
3. 선별한 대상의 변경을 제한하고 기존 진행별 인벤토리/퀘스트 저장 장벽을 기다린다. 준비·대화·세대·대상 명단과 최신 목표를 다시 확인한 뒤 명시적 명단으로 길목을 시작한다. 입장 대기만 중복 요청을 합치며 완료/HOLD 뒤 다시 입장 성공이라고 답하지 않는다.
4. 두 길목과 체크포인트의 전원 회복·무료 부활·보스 집결은 기존 전투 경로를 사용한다. 도전 교체는 같은 진행/월드/세대의 이전 도전 ID·종료 결과·기존 참가 범위를 확인한다.
5. 등록한 최종 보스 도전이 실제 VICTORY일 때만 개인 목표를 저장한다. 온라인 현재 세션의 개인 기록을 기존 CAS로 갱신하며 DB 성공 후 REPORT_READY로 안내한다. 중복 승리나 늦은 다른 도전 결과로 목표를 중복 적용하지 않는다.
6. 기존 NPC 보고로 개인 COMPLETED를 저장한다. 스마트폰 목록·상세·알림과 책은 기존 저장값을 표시한다. 보고는 개인별이어서 한 명의 보고가 다른 참가자를 완료시키지 않는다. 보상/경제 기능을 추가하지 않았다.

`dungeon-play.yml`은 등록 NPC·의뢰·입구 범위를, `dungeon-quest-demo.yml`은 새 공개 합성 의뢰를, `dungeon-play-combat.yml`은 해당 의뢰에 연결한 기존 두 길목/체크포인트 전투 정의를 담는다. 기존 파일을 덮지 않고 명시적 격리 모드에서만 의뢰를 합친다. 기존 ID·저장 기록·V001~V009는 변경하지 않았다. `dungeon:<id>` 목표는 등록 연결이 없거나 중복/다른 연결이면 활성화 전에 거부한다.

## 안전·지원 범위

- `DungeonPlay`는 `PersonalQuest`·`QuestJournal`·기존 전투 도전과 bounded worker를 사용한다. 별도 풀·저장 구조·일반 세션/진행 선택 UI를 만들지 않는다. 클라이언트가 진행 ID나 입장 명단을 전달하지 않는다.
- 실제 Player 연결기는 기존 `freezeTravel`·`prepared` 세션·명시적 전투 명단 API를 사용한다. 기존 개발 콘솔 시작은 별도 fixture이며 정식 게임 입장 정책으로 확정하지 않는다. 전용 스마트폰 아이템이나 운영 서버 자동 활성화도 추가하지 않는다.
- NPC 아이템창에 조건부 입장 버튼을, 수락한 의뢰의 책/스마트폰 상세에 전투 상태·던전 진행 안내를 연결한다. 6메뉴·E키·41슬롯·커서/드래그 보호는 그대로다. 입장은 NPC에서만 요청하며 스마트폰으로 원격 입장하지 않는다.
- 조회 오류/쓰기/HOLD, 종료·세션 교체·명단/세대 변경, 저장 실패를 빈 상태나 입장/완료 성공으로 처리하지 않는다. 입장·승리 작업은 개발용 30초 한도다. 미완료 작업도 저장 장벽에서 기다린다.
- 승리의 개인 기록은 각자 저장하므로 전체 참가자 DB 원자성을 약속하지 않는다. 한 명의 쓰기가 실패하면 기존 기록을 보존하고 HOLD하며, 이미 성공한 다른 개인 기록을 되돌리거나 중복 실행하지 않는다.
- 완료된 전투와 저장이 정리된 월드만 던전 참가 참조를 해제한다. 대기·HOLD를 버리지 않으며 이전 세대의 참조로 새 세션을 바꾸지 않는다. 기존 월드 재로드 후 개인 완료 기록은 기존 DB에서 읽는다.

**현재 세션 전용 개발 프로토타입이다.** 콘텐츠의 `isolated-current-session-credit: true`는 현재 유효한 온라인 참가자만 목표 반영하는 시험 범위를 명시한다. 오프라인 참가자의 의뢰는 성공으로 표시하거나 자동 지급하지 않고 미지원으로 보류한다. 이를 운영 공적/완료 정책으로 확정하지 않는다. 정식 반복 입장·오프라인 완료/재접속 반영과 전체 전투의 프로세스 재시작 복구는 후속 범위다.

기본 `dungeon-play-verification-enabled`는 false이고 JVM의 `hearth.verification.dungeonPlay`도 필요하다. 실제 클라이언트 시험은 사용자 요청 전 보류한다. 추후 수동 시험도 기존 명시적 operator-ready·인증 프로필·격리 경로 조건을 따라야 하며 이번에 실행하지 않았다.
