# 본인 공개 게임 정보 조회 통합

2026-10-29 · 격리 개발 모드 · 전체 S4 진행 중, S5 AI는 미구현이다.

## 구현

- `/hearthinfo`는 요약, `/hearthinfo quests|map|diary|story [페이지]`는 수락한 퀘스트·공개 지도 장소·조회 가능한 일지 항목·현재 공유 목표/확정 분기/진행 조건을 채팅에 표시한다. 다른 플레이어·진행 ID를 인수로 받지 않는다.
- 페이지당 최대 8개·표시 줄 길이 제한과 다음 페이지 안내를 제공한다. `/hearthplay help`에서 명령을 안내하며 처리 중 중복 조회는 거부한다.
- `GameInformation`은 GUI와 분리된 불변 공개 데이터다. 미수락/접근 제한 퀘스트, 원본 콘텐츠·진행/플레이어/물리 월드 UUID를 포함하지 않는다. 미발견 장소는 기존 공개 필터가 만든 물음표·허용 위치 정보만 사용한다. 내부 표식 키·서버 발견 경계도 제외한다.
- 외부 모듈용 `QuestJournal.information`은 검증된 본인 문맥에서 기존 비동기 조회를 수행한다. 임의 화면 데이터를 받는 공개 API를 만들지 않았다. 현재 세션·HOLD/진행 중 저장·조회 버전을 재검사하고 늦은 결과를 거부한다. 명령은 기존 UI 요청 순서/종료 경계를 재사용한다.
- 조회는 DB 행·revision·보상·개인/공유 진행을 변경하지 않는다. AI 서비스·모델 호출·별도 캐시·새 스키마는 추가하지 않았다.

## 검사

- 관련 단위·회귀 **24개 PASS**, 최종 JAR·스크립트 구문 PASS. 미수락/지역 제한 퀘스트·비밀 장소/좌표·내부 키 비노출, 개인 상태별 projection, 조회 인수 제한·불변 목록·잘못된 페이지, stale/HOLD/미완료 조회/DB 읽기 오류를 검사했다.
- 기존 도구의 `--sessions --quests --story-batch --game-information`에서 새 Paper 한 JVM/격리 PG 한 개 **PASS**. 공유 단계 변경 전후 및 같은 JVM의 월드 재로드 뒤 5개 조회 구분이 동작하고, 소유권 UUID 비노출·공유 revision·알림/설정/추적의 DB 값 불변을 확인했다. 기존 진행 격리·조건·분기·GUI/인벤토리 보존도 같은 실행에서 확인했다.
- [결과 JSON](../verification/game-information-result.json)에 실행 경로·자원·검사·해시를 기록했다. 최초 실행 통과, 기존 자원 한도·정상 종료/포트 반환 및 최종 실행 JAR 일치를 확인했다. 저장 계약이 불변이어서 새 JVM 재시험은 생략했다.

## 남은 범위

실제 인증 클라이언트의 명령 입력·채팅 출력·중복 입력/종료 타이밍은 미검증이다. 연대기 전용 조회·전체 NPC 관계 정보·AI 질의/검색/캐시/지연 응답 경계는 이번 범위가 아니다. 공개 데이터 생성 기반을 AI 통합 완료로 보지 않는다. 실제 클라이언트 시험과 운영 배포는 별도 요청 전 보류한다.
