# 단계별 퀘스트 목표 위치 공개

2026-10-29 · 격리 개발 모드 · S4 진행 중.

## 콘텐츠와 표시

단일 `objective` 또는 각 `objectives` 항목에 선택적인 `location`을 둔다.

- `kind: EXACT`와 `x/y/z`: 실제 목표 구역 안에 명시한 지점만 표시한다.
- `kind: AREA`와 `min-x/max-x/min-y/max-y/min-z/max-z`: 실제 목표를 포함하도록 제작자가 정한 공개 탐색 범위만 표시한다. 내부 목표의 정확한 위치를 자동 계산해 공개하지 않는다.
- `kind: HIDDEN`: 위치 비공개 문구만 표시하며 좌표 필드를 함께 지정하면 거부한다.

알 수 없는 형식·비정상 수치·잘못된 좌표/범위는 콘텐츠 활성화 전에 거부한다. 메타데이터가 없는 기존 콘텐츠의 안내와 기존 저장 행/목표 순서/revision은 유지한다. 공개 시험 콘텐츠의 연속 목표에 정확→구역→비공개 사례를 추가했고 기존 서버 파일은 자동 덮어쓰지 않는다.

현재 활성 단계의 상세 조회·스마트폰·공개 게임 정보·플레이 안내에 같은 정형 위치 표시를 사용한다. 다른 단계의 위치를 합쳐 내보내지 않으며 보고 대기/완료에서는 이전 목표 위치를 추가 표시하지 않는다. HUD·일반 진행 메시지는 기존의 짧은 목표 문구를 유지한다.

이 정책은 **정형 위치 데이터의 공개 경계**다. 제작자가 공개 대사·목표 설명에 직접 입력한 좌표를 자동 검열하지 않는다. 비공개/탐색형 콘텐츠의 설명에도 민감한 좌표를 쓰지 않아야 하며 실제 서사 콘텐츠는 이번에 사용하지 않았다.

## 검사

- 관련 단위·회귀 **22개 PASS**, JAR 빌드·스크립트 구문 PASS. 세 공개 방식, 잘못된 좌표 거부, 현재/다음 단계 분리, 기존 정의 호환과 기존 목록·공개 정보·퀘스트 진행을 검사했다.
- 기존 도구의 `--sessions --quests --story-batch --quest-locations`로 새 Paper 한 JVM/PG 한 개 **PASS**. 실제 로딩된 콘텐츠의 3가지 위치 메타데이터, 스마트폰 상세 객체·공개 정보 조회의 정확 위치 표시, 조회 후 ACTIVE/revision0 유지, 목표 달성 후 보고 대기에서 이전 위치 미표시를 확인했다.
- [결과 JSON](../verification/quest-locations-result.json)에 실행 경로·자원·검사·해시를 보존한다. 최초 실행 통과·기존 자원 한도·프로세스/포트 반환 및 최종 실행 JAR 일치를 확인했다. 저장 계약 불변으로 두 번째 JVM은 생략했다.

## 미검증

실제 인증 클라이언트의 화면/채팅·이동 및 미니맵/목표 마커 렌더링은 미검증 또는 미구현이다. 서버 내부 표시 데이터 검사를 실제 사용자 화면 성공으로 취급하지 않는다. DB 스키마·보상·진행 조건·운영 활성화는 변경하지 않았다.
