# AI 공개 자료 선택·최신 조회·참고자료 복귀 통합

확인일: 2026-11-09. 기준 `25b1fff` 이후 코드. 기존 공개 게임 정보·키워드 검색·[단일 항목 도움](phone-selected-help-verification.md)·스마트폰 대화를 재사용했다. 상세 명령·결과·해시·원시 증거는 [검증 JSON](../verification/phone-grounding-result.json)에 모은다. 실제 AI 서버/모델이나 운영 서비스를 실행·변경하지 않았다.

## 함께 구현한 흐름

- 퀘스트·지도·기록·공유 정보 검색에서 최대 4개 일치 자료를 확인하고 포함/제외할 수 있다. **전체 자료**에서 원래 공개 본문의 모든 쪽을 읽고 자료 선택으로 돌아간다. AI에 전달하는 발췌는 전송 확인 화면에서 확인한다. 모든 자료를 제외하면 전송하지 않으며, 실제 검색 결과 없음은 별도 상태로 유지한다. 기존 단일 항목 도움은 한 자료만 전달한다. 일반 질문의 게임 정보 미전달 기본값도 유지한다.
- 네 범위 검색과 단일 항목 요청 모두 **전송 직전과 응답 뒤 비동기 최신 DB 조회**를 거친다. 선택한 항목의 내부 식별 키·전체 공개 본문·퀘스트 revision/현재 목표·기록 버전·공유 revision을 확인한다. 이름이나 목록 인덱스로 대상을 추측하지 않으며, 본문의 400자 발췌 뒤쪽이 바뀌어도 이전 요청을 거부한다. 선택하지 않은 자료는 전송·응답 검증 대상에서 제외한다.
- 같은 항목이 정렬되어 위치만 바뀌면 내부 키로 다시 찾아 원래 자료를 연다. 내용/버전 변경·삭제·공개 제한·HOLD·조회 실패를 빈 정보나 준비된 응답으로 처리하지 않는다. 결과 없음 요청도 새 일치 자료가 생기면 재선택한다. 응답 확인과 화면 반영 사이의 기존 개인 정보 세대 검사, 취소·세션 교체·시간 초과·질문 초안 보존을 유지한다.
- 최근 요청 참고자료는 최신 DB를 읽어 목록→전체 본문→원래 퀘스트/장소/기록 정보로 연결하고, 원래 상세에서 AI 참고자료로 돌아온다. 공유 자료는 공동체 정보와 최근 AI 참고자료로 연결한다. 자료 상세에서 한 항목 도움으로 이어갈 수도 있다. 변경된 자료는 갱신 안내로 전환한다.
- 참고자료는 세션의 **요청 객체**에 묶인다. 이전 요청의 늦은 조회가 취소 뒤 새 요청의 자료를 덮어쓰거나 삭제하지 못한다. 전송한 최대 4개 자료만 보관하며 전체 개인 조회 스냅샷은 보관하지 않는다. 대화 이력도 전체 자료의 식별/버전으로 구분해 발췌문이 같아도 서로 다른 자료·변경 버전의 답변을 다음 요청에 섞지 않는다. 내부 키·버전·진행/개인 UUID는 프롬프트나 화면 본문에 포함하지 않는다.

DB 스키마·아이템 저장·퀘스트/보상 정책·AI 도구 실행 권한은 추가하지 않았다. 요청/응답/자료/대화 길이 상한과 세션 메모리 한도를 유지하며 새 외부 검색·임베딩·지속 대화 저장은 만들지 않았다.

## 실행한 검사

- main/test 컴파일·JAR·runtime stage PASS. 관련 퀘스트/스마트폰/제작/채집/던전/인벤토리·세션의 **512개 단위·회귀 PASS**. 신규 18개는 4개 범위·포함/제외·단일 항목·결과 없음 구분, 전체 본문/동일 상태 버전 변경, 재정렬·개인/공유 같은 ID·접근/삭제 거부, 제외한 자료 변경 허용, 요청 객체/세션 identity·취소 후 늦은 조회, 동일 발췌의 대화 이력 격리와 초안 보존을 검사했다.
- 신규 `/tmp/hearth-s4-11.QBQkiRqh`의 PostgreSQL 1개·Paper 1 JVM에서 **293회 세션 assertion PASS**(고유 표식 194개), **102.509초**. 이 중 신규 자료 경계 42회는 실제 개인 목표 갱신 중 지연 응답의 최신 DB 재검사/거부, 네 검색 범위·단일 자료·결과 없음의 Mock 응답 후 DB 확인, 실제 PG 미존재 행 읽기 실패/초안 보존, 프롬프트 식별 키/UUID 비노출·Dialog 객체·조회 원본 불변을 검사했다. 기존 인물 공개 경계·공유 투표·채집/제작·던전 보고/CAS 실패 보존·최종 월드 재연결과 제작 도구/개인 기록 보존도 PASS다. 최초 빌드·통합 모두 통과했고 최종/설치 JAR 해시 일치, Paper 최대 표본 RSS 약 1293MiB로 기존 상한을 유지했다. DB 풀·소유 프로세스/포트 정리도 PASS다.

기존 `--sessions --quests --story-batch --public-course`의 한 Paper JVM·PG 한 개를 사용한다. 실제 순정 제작/몹·WorldGuard·DB 저장은 기존 공개 코스 경계를, AI는 기존 Mock과 제어 future를 사용한다. 가짜 Player나 인증 우회로 화면/실제 행동을 대체하지 않았다.

## 남은 범위

실제 인증 클라이언트의 자료 선택/포함/제외·입력 초안·Dialog 왕복·NPC/코옵 행동은 별도 요청 전 보류다. 실제 AI 모델/HTTP 서버의 품질·은폐·지연·동시 부하와 S5는 미완료이며 운영 배포는 하지 않았다. 이번 DB 실패는 미존재 행의 실제 읽기 실패 경계이며 네트워크 장애/연결 단절 시험으로 확대 해석하지 않는다. 저장/복원 계약이 불변이라 두 번째 JVM 복원을 반복하지 않았으며, 공개 코스의 같은 JVM 월드 언로드/재로드·개인 기록/인벤토리 보존과 구분한다.
