# 플랫폼 설정 작업대·중단 복구 검증

2026-11-20. [ADR-0033](decisions/0033-economy-platform-lifecycle.md)의 설정 수명주기를 보완했다. [관리 가이드](../infrastructure/network/platform.md#설정-후보리로드복구)와 [구조화 증거](../verification/platform-configuration-result.json)를 따른다. 밸런스/획득처·스토리 콘텐츠·운영 설정은 변경하지 않았다.

## 변경과 판단

기존 파일 공개 후 롤백이 ROLLED_BACK으로 표시돼 PG 확정 전 재시작에서 pending을 놓칠 수 있었다. PG 기록을 생성만 하고 다시 PREPARED로 만들지 않는 기존 롤백은 확정 사이의 중단을 설명하기 어려웠다. 오류 뒤 maintenance가 영구 유지되는 경우도 있었다.

로컬 의도 → PG PREPARED → 원자 파일 교체 → live/예약 구성 → PG 최종 상태 → 로컬 최종 상태로 순서를 통일했다. 기존 E012 스키마와 manifest version1/원본·후보를 유지하고 PREPARING/ROLLBACK_PREPARING/ROLLBACK_APPLIED 상태를 추가했다. 구버전 기록도 PG와 대조하므로 ROLLED_BACK만 보고 완료로 판단하지 않는다. realm 잠금 아래 다른 PREPARED 후보를 배제하고 요청 ID/파일/양쪽 해시가 같을 때만 준비를 재개한다. SQL 실패는 원래 상태를 보존한다.

작업대 GUI/명령으로 후보·로컬/PG 상태·현재 파일 해시·변경 요약을 조회하고 같은 API로 적용/롤백한다. 정상 live 복구는 설정 유지보수만 해제한다. 재시작 필요 변경은 같은 JVM의 recover로 풀리지 않는다. 다른 모듈의 HOLD는 변경하지 않는다. 원본/후보·충돌 임시 파일·부분 생성 증거를 삭제해 성공으로 만들지 않는다.

시작 시 bounded 전체 조회를 수행하고 관리 요청 외에는 DB/파일을 반복 읽지 않는다. 후보 최대4096개·파일128KiB·GUI36개/페이지·비교13줄/줄180자 상한을 둔다. 후보별 점검은 전체 과거 파일을 현재 파일로 강제 복원하지 않으므로 후속 정상 변경을 막지 않는다. 임의 운영 파일 편집 자체를 막는 보안 기능이나 완전한 전원 장애 복구 보장은 아니다.

## 미검증·후속

실제 관리자 인벤토리 클릭·접속자 포함 live 설정 전환·장기 부하·운영 배포/재시작·물리 전원 장애는 미검증이다. Player를 합성하지 않았고 콘솔/API PASS를 실제 클릭 성공으로 세지 않는다. 기존 전체 백업 계약/DDL은 바꾸지 않아 이전 전체 백업 시험을 반복하지 않았다. 증거 유실/외부 충돌은 수동 원본 확인 대상으로 보존하며 자동 삭제/강제 확정은 추가하지 않았다.
