# 공개 코스 이어 하기·재접속 안내 통합

확인일: 2026-11-09. 기준 `3ce99f0` 이후 코드. 기존 공개 코스·개인 의뢰/추적·실패/보상 확인·공유 조건·세션 저장을 재사용한다. 상세 명령·수치·해시·원시 증거는 [검증 JSON](../verification/course-resume-result.json)에 기록한다.

## 구현한 흐름

- `/hearthresume` 책과 스마트폰 홈·다음 플레이 안내·현재 코스 동선에서 **이어 하기**를 연다. 현재 코스의 개인 목표를 먼저 보여주고, 본인의 보고 대기·재시작 확인·수령 가능한 지급 대기 보상·나머지 수락 의뢰를 모은다. 개인 완료/장 스킵, 이미 지급·미등록·정책 미정·정의 불일치 보상과 미수락 미래 의뢰를 새 재개 동작으로 만들지 않는다.
- 저장된 목표·담당 NPC·추적 여부와 현재 코스/공동체 조건을 함께 읽는다. 조건이 충족된 코스 안내와 개인 보고/보상을 구분하며, 수락 의뢰가 없으면 현재 공개 수락/탐험 안내로 이어진다. 공유 상태가 불명/HOLD이거나 조회가 실패하면 정상 재개·완료·빈 목록으로 표시하지 않는다.
- 의뢰 선택은 기존 상세와 재시작/보상 확인·취소·결과로 이어지고 **이어 하기로** 돌아온다. 다른 쪽의 의뢰 선택을 실행하지 않도록 현재 쪽·원래 행·개인 revision/목표·추적·공유/보상 epoch를 다시 확인한다. 책은 현재 세션·화면 표식·원래 접근 조건을, Dialog는 기존 nonce를 유지한다. 다음 행동/NPC·현재 시설 동선·해당 진행판 쪽으로도 연결한다.
- 정상 상호작용이 가능한 현재 세션의 첫 승인된 조회 뒤 채팅으로 `[이어 하기]`를 한 번 안내한다. 새 접속은 새 표식을 사용하며 같은 접속의 재조회/변경은 중복 안내하지 않는다. 대기·오류·HOLD·이전 세션 콜백은 안내를 소비하지 않는다. 실제 Player 객체별 소유 토큰을 보관하고 종료 때 정확한 토큰만 정리해 이전 종료가 새 접속의 표식을 지우지 못하게 했다.

안내는 DB/일지/인벤토리·추적을 변경하지 않는다. 재접속 시 자동 수락·추적·재시작·지급·입장/이동을 하지 않는다. 기존 저장 장벽·개인/진행 격리·CAS·HOLD와 기본 비활성 게이트를 유지하며 DB 스키마·복원 계약·전투 재생성 정책은 바꾸지 않았다.
