# 필드 전투·고정 명단·사망/복귀 통합

확인일: 2026-11-17. 기준 `cdc6d19` 이후 [사용자 선택 ADR-0023](decisions/0023-field-combat-dungeon-rules.md)에 따른 연관 구현 배치다. [실행 횟수·JAR/소스·원시 결과](../verification/field-combat-result.json)를 따른다.

## 연결한 동작

실제 인증된 준비 세션이 필드 구역에 들어오면 기존 소환 시점 난이도와 참가 가능한 인원을 고정하고 `CombatAttempt`·`CombatPlayers`를 연결한다. 이미 인던/길목 도전이 있으면 그 도전의 고정 참가자만 필드 관리 몹에 개입한다. 다른 진행/월드·세대, 늦게 들어온 개인과 사망/복귀 보호 중 참가자의 개입을 거부한다. 전투 적용기가 없는 기존 개발 모드는 플레이어 피해 제한을 유지한다.

관리 필드 몹의 근접 피해만 기존 전투 피해 경로에 연결한다. 치명타는 순정 사망/드롭을 막고 논리 사망·개인 퀘스트 저장·생존자 관전으로 처리한다. 퀘스트 사망 저장 실패도 전투 HOLD로 연결한다. 기존 인던 콘텐츠의 조건·개인/공동 부활 예산·HP/효과·복귀 보호와 종료 위치를 사용하며 새 레벨 수치를 정하지 않는다. 일반 피해나 다른 플레이어 공격은 계속 제한한다.

필드 도전은 관리 구역 전부를 처리하면 승리로 닫지만 보스/던전 승리 목표를 지급하지 않는다. 관리 몹 체력 합계를 기존 전투 HUD에 연결한다. 전멸 대기의 명시적 복귀는 실패 종료 후 기존 저장/종료 원장·복귀 이동을 따른다. 보스 재도전으로 보스를 잘못 소환하거나 필드를 자동 재소환하지 않는다. 저장/복귀가 끝난 중단 구역의 관리 몹만 정리하고 완료/다른 진행 기록은 보존한다. 다시 여는 것은 기존 명시적 필드 리셋 경계다.

기존 확정 종료/복귀 원장을 재사용한다. 활성 도전/불명 이동의 프로세스 재시작과 기존 필드 표식은 HOLD하며 원본을 지우지 않는다. 새 DDL·복원 형식이나 고비용 자동 복구는 추가하지 않았다.

## 최종 코드 검사

- 관련 전투 **187개 PASS**, 신규 10개·실패/오류/skip 0. 고정 명단/권한·늦은 참가 거부, 인던 정책 재사용, 사망/관전·동일 요청 부활과 횟수, 새 세션/세대, 저장 실패 복귀·명시적 리셋/정리 실패를 함께 확인했다. JAR/통합 fixture 컴파일도 통과했다. 한 번의 단위 묶음만 실행했다.
- 같은 최종 JAR의 **Paper 1회·격리 PG 1개, 100개 assertion·38.858초 PASS**. 기존 보스/재도전·사망 퀘스트·저장 장벽을 포함해 실제 필드 몹의 진행/세대 판별, 전멸 관전 제어 시 자기 몹 AI만 정지, 조건부 부활의 적용/횟수 확정 뒤 AI 재개를 확인했다.
- 실제 PG CAS 실패는 인벤토리·관리 몹·복귀 원본/dirty를 보존하고 이동/정리를 하지 않았다. 정상 저장 뒤 제어 포트 복귀와 실제 관리 몹 정리를 확인했으며 다른 진행의 엔티티는 그대로였다. 소유 프로세스/포트 닫힘·정리 오류 0이다.
- 기존 저장 계약을 재사용하므로 두 번째 JVM·변경 없는 AI/스마트폰 검사를 반복하지 않았다. 실제 Player를 만들거나 인증을 흉내 내지 않았다. Paper 객체/제어 포트의 성공은 실제 이동·피해/카메라·부활 조작 성공이 아니다.

실제 인증 개인/코옵의 필드 진입·공격·관전·부활/복귀, 전체 플레이와 운영 적용은 미검증이다. 선택형 개발 모드이며 전체 S4 완료·일반 서버 자동 활성화/운영 배포로 보지 않는다.
