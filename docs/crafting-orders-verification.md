# 현장 작업대의 개인 제작 의뢰·공동 준비 연결

> 후속 변경: 실패·보상 대기 기록과 확인/결과·원래 화면 복귀의 현재 동작은 [실패·보상·결과·복귀 통합](quest-followup-batch-verification.md)을 따른다. 아래 검증은 명시한 기준 커밋의 기록이다.

확인일: 2026-11-09. 기준 `f4d61a2` 이후 코드. 기존 일괄 제작·준비 순서·개인 의뢰 저장을 재사용해 **작업대에서 본인의 현재 목표 확인→제작법/공동 재료 준비→기존 제작 확정→다음 목표·보고 안내**를 연결했다. [검증 JSON](../verification/crafting-orders-result.json)이 상세 수치·원시 로그·명령의 정본이다. 일반 서버 활성화나 운영 배포는 수행하지 않았다.

## 플레이 흐름

- 등록 작업대의 **내 제작 의뢰**에서 관련된 진행 중/보고 대기 개인 의뢰를 6개씩 확인한다. 보고 대기를 우선하며 기존 추적/목록 정렬을 재사용한다. 미수락·완료·실패·스킵·접근 차단된 의뢰를 제외한다.
- 현재 목표가 이 작업대의 제작이면 해당 제작법으로 이동한다. 이전 방문 목표·제작 후 다음 목표·보고 대기는 현재 안내와 담당 NPC를 표시하고, 선택한 의뢰의 기존 상세/관리 화면으로 연결한다. 미래 제작 목표를 현재 제작으로 표시하지 않는다. NPC 보고의 기존 거리·권한 경계도 유지한다.
- 같은 쪽의 현재 제작 목표들을 함께 준비한다. 동일 제작 이벤트로 여러 의뢰가 진행될 수 있어 같은 제작법은 한 번만 계산한다. 기존 순정 레시피와 보유 재료/중간 결과/잔여물 계산으로 제작 순서·보유분·추가 원재료·남는 재료를 표시한다. 후속 목표까지 미리 제작하거나 자동 연쇄 제작하지 않는다.
- 준비 단계의 제작법을 선택하면 지원되는 1·4·8회 횟수를 유지한다. 그 밖의 횟수는 기존 안내대로 1회씩 나누어 제작한다. 제작법·수량 선택·재료 상세·전체 준비·제작 완료 후에도 **내 제작 의뢰로** 돌아가 현재 상태를 다시 조회할 수 있다.
- 쪽 이동·목표/중간 제작법 선택 시 비동기로 의뢰를 재조회하고 표시했던 목록/revision과 비교한다. 변경된 목표·공개 상태를 이전 선택으로 실행하지 않는다. 새로고침/복귀는 현재 쪽 범위를 다시 잡는다. 조회 실패·늦은 응답·세션/시설 무효화는 빈 성공 화면으로 바꾸지 않는다.
- 작업대의 거리·생존·커서·WorldGuard·월드 세대·현재 화면 검사는 기존 경로를 사용한다. 안내 자체는 아이템·수락·목표·보상·DB 저장을 적용하지 않으며 실제 제작은 기존 일회용 확인과 source 저장 뒤 목표 저장 경계를 따른다. 새 스키마·제작법·플러그인·운영 정책은 없다.

## 미검증과 후속 경계

실제 인증 클라이언트의 작업대 열기·의뢰/중간 제작법 선택·수량/쪽 이동·왕복·NPC 보고 클릭과 가독성은 별도 요청 전 보류다. 제어 세션·실제 Inventory 객체는 Player 클릭 성공을 뜻하지 않는다. 저장/복원 계약이 불변이므로 두 번째 JVM/DB 재시작을 추가하지 않았다. 장기 성능·운영 활성화/배포도 미실행이다. 다음 공개 시설 보완은 같은 개인 목표 안내와 기존 접근/저장 경계를 재사용한다.
