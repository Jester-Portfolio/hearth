# 복수 길목·체크포인트·최종 보스 연결

확인일: 2026-11-08. 기준 `fd6607b`. [ADR-0007](decisions/0007-dungeon-and-boss-operations.md)·[후속 참가 경계](decisions/0013-vote-boss-and-gathering-state-boundaries.md) 및 기존 [복수 체크포인트](multiple-checkpoints-verification.md)를 재사용한다. [검사 JSON](../verification/combat-route-result.json)에 상세 증거를 기록한다. S4는 진행 중이다.

## 구현

- 외부 `path.route.sections`에 순서 있는 구간 ID·제목·집결 범위·다음 입장 위치·선택적 체크포인트 연결을 정의한다. `restart-section`은 명시된 구간 또는 최종 `boss_gate`다. 자동으로 최신 체크포인트를 추측하지 않는다. 중복/없는 구간·없는 체크포인트·지원하지 않는 회복 설정은 거부한다. 최대 8개는 개발 입력 상한이며 게임 밸런스 값이 아니다.
- 기존 단일 `path`와 체크포인트 정의는 그대로 동작한다. 새 합성 파일 `combat-route-demo.yml`만 추가하며 기존 콘텐츠 파일/월드/저장 기록을 덮어쓰지 않는다. 일반 서버 비활성·기존 격리 게이트를 유지한다.
- `/hearthcombat gather`는 현재 길목 구간의 체크포인트 조건과 온라인 생존자 집결을 확인한 후 기존 진행별 저장 → 이동 → 구간 완료로 연결한다. 마지막 구간 이후에 기존 보스 집결을 실행한다. `/hearthcombat status`와 이동 결과에 현재 구간·최종 보스 대기를 안내한다.
- 구간 이동은 **같은 길목 도전**을 유지한다. 관리 몹·참가 명단·사망/오프라인 기록·사용한 개인/공동 부활 횟수를 새로 만들지 않는다. 이동 자체로 체력을 회복하거나 사망자를 부활시키지 않는다. 온라인 사망자는 관전 상태를 유지하며 기존 참가자의 재접속 경계를 바꾸지 않는다.
- 체크포인트 회복은 기존 `CombatCheckpoint`가 담당한다. 같은 던전·해당 개인 퀘스트의 온라인 대상 중 생존자 전원이 모이면 사망자 무료 부활과 생존자 포함 최대 체력 회복을 적용하고 기존 부활 사용 횟수를 보존한다. 이번 합성 두 구간은 각각 기존 체크포인트 하나를 명시적으로 연결했다. 다른 콘텐츠의 체크포인트 순서를 일괄 강제하지 않는다.
- 마지막 보스 입장은 기존 `CombatGathering`을 재사용한다. 온라인 생존자 집결·온라인 사망자 자동 복귀 → 보스 시작 명단/난이도 고정·보스 전용 횟수 초기화 규칙을 유지한다. 보스 시작 시 오프라인인 길목 참가자는 해당 보스 도전에 중도 참가하지 않는다.
- 기존 길목/보스 재도전의 저장·지정 체크포인트 복귀·관리 구역 초기화·새 도전 생성 이후 콘텐츠에 명시한 재시작 구간을 사용한다. 이전 구간 전체를 임의로 반복하거나 최신 지점을 자동 선택하지 않는다.

## 안전·저장

`CombatRoute`는 `IDLE → SAVING → MOVING → DONE`을 사용하며 현재 구간은 성공한 경우에만 전진한다. 구간별 요청 ID의 중복/과거 요청을 재실행하지 않는다. 저장 중 이탈, 세션/온라인 명단·월드 세대·사망 상태 변경, 이동 실패, 종료와 늦은 콜백은 적용을 거부한다. 실패는 HOLD이며 원본 DB 인벤토리·dirty·현재 구간을 성공으로 덮지 않는다. 이미 일부 플레이어가 이동한 뒤 실패하면 자동 되돌리기를 약속하지 않고 해당 진행을 보류한다.

입장/체크포인트/재시작과 구간 이동의 중복 진행을 막고 기존 저장 장벽·조작 제한·안전한 메인 스레드 이동을 사용한다. DB를 메인 스레드에서 기다리지 않고 이동은 기존 `combatMove` 경로다. 구간 작업은 개발용 30초 한도를 둔다. 다른 진행의 정상 동작과 개인 인벤토리는 유지한다.

V001~V009·기존 저장 계약·30초 dirty 정책을 변경하지 않았다. 구간 인덱스는 기존 전투 도전과 함께 같은 JVM에서 관리한다. 전체 전투의 프로세스 재시작 복구는 미구현이며 기존 `combat-trials.started` 검토 표식을 우회하거나 초기화하지 않는다. 체크포인트 기록/인벤토리의 기존 영속 저장과 전투 도전 복구는 구분한다.

최종 `/tmp/hearth-s4-11.fxbcniel`에서 42.136초. Paper 준비 13.937초, 최대 표본 RSS 1133300KiB, CPU 관측 77.86초, 종료 3.672초. 최소 호스트 가용 RAM 12287260KiB, PG 최대 표본 RSS 221548KiB이며 기존 CPU2/nice+10·Xmx1536MiB·RAM/디스크/시간 한도를 유지했다. TPS/MSPT·장기 누수는 측정하지 않았다.

첫 `/tmp/hearth-s4-11.8kj4ulu7`은 FAIL이며 원시 기록을 보존했다. 실제 저장 실패가 보존됐는데도 검사에서 정상 증가하는 `combatMillis`까지 전체 Snapshot 동일 조건으로 비교했다. 시간만 제외하고 소유권·revision·참가 상태·횟수 등은 계속 비교하도록 수정했다. 해당 실패의 정리 JSON에는 DB 풀 종료 확인 누락/정리 불완전 판정이 남아 있다. 이후 소유 PID 전부 소멸과 `ss`의 게임/해당 PG 포트 리슨 없음을 따로 확인했다. 성공으로 원본을 수정하지 않았다.

원인 수정 후 새 경로에서 한 번 재시험해 총 두 묶음이다. 통과한 변경 없는 단위/과거 전체 통합은 반복하지 않았다. 저장 복원 계약이 그대로여서 두 번째 JVM/DB 재시작 시험도 반복하지 않았다. 운영 서비스·기존 월드·이전 증거는 변경하지 않았다.

## 다음 범위

실제 인증 클라이언트 시험은 사용자 요청 전 보류한다. 콘솔 fixture 시작은 정식 던전 입장/권한 UI가 아니다. 공개 던전·퀘스트·스마트폰 안내와 정식 참가 경계의 통합, 운영용 전투 콘텐츠, 전체 전투/구간의 새 JVM 복원은 후속이다. 체크포인트 회복·길목 재도전과 채집 인던 초기화를 같은 정책으로 합치지 않는다.
