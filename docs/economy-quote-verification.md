## 변경

- 상점 상품에서 ±1/8/64개 조절과 최대 구매/판매 가능 수량을 제공한다. 기존 기술 한도 1~4096을 유지하며 운영 거래 한도를 새로 정하지 않는다.
- `EconomyQuote`는 기존 `EconomyEngine.quote`로 수량별 총액·예상 잔액·재고와 거래 가능 여부를 계산한다. 일반 보관 36슬롯의 공간/기본 아이템만 계산하고 방어구·보조 손·이름 등 메타데이터가 있는 아이템은 판매 대상으로 세지 않는다.
- 수량 변경은 DB 쓰기 없이 같은 견적을 재사용한다. 최대 가능 수량은 단조 가격/재고/공간/잔액 조건으로 이분 탐색하며 기존 4096 한도에서 최대 13회 가격 평가다. 이는 계산량 분석이며 FPS/TPS 성능 측정 결과가 아니다.
- 구매/판매 선택 → 총액·예상 잔액 확인 → 고유 요청 ID의 확정 버튼 → 기존 최신 인벤토리 저장/거래 CAS → 실제 영수증의 총액·잔액·revision 표시로 이어진다. 시세 변경은 재확인을 요구하며 변경된 가격으로 자동 거래하지 않는다.
- 수량/확인 화면은 클릭 이벤트 이후 다음 틱에 화면·세션·상인 선택·거리·세대를 재검사한다. 중복 클릭은 기존 busy/세션 거래 경계에서 거부한다. 조회·견적만으로 인벤토리나 DB revision을 바꾸지 않는다.
- 정상 거부는 재고/잔액/아이템/공간/시세 원인을 표시하고, 미확인 실패는 성공 대신 HOLD 안내와 요청 ID를 제공한다. 일반 서버 비활성·30초 dirty 저장·경제/스토리 격리·관리자 수동 복구를 유지한다. 신규 스키마/외부 의존성/게임 밸런스 변경은 없다.

## 미검증과 다음 작업

실제 인증 플레이어의 NPC 클릭·수량/확정 버튼·클라이언트 인벤토리 조작은 보류다. 이번 자동 실행은 네이티브 Inventory 객체와 서버 내부 세션/실DB 경계 검증이며 실제 플레이어 성공이 아니다. 실제 commit 결과 불명 주입은 이번에 반복하지 않았고 기존 [상점/관리 증거](economy-desk-verification.md)를 보존하며 안내 분기만 확인했다. TPS/MSPT·장기 부하·운영 배포는 미실행이다.

다음 경제 배치는 기존 생산/소비/운송의 콘텐츠 조절·관측과 게임 내 공개 정보 연결을 묶는 방향을 추천한다. 실제 수동 시험은 별도 요청 이후 진행한다. S4와 운영 E1~E3는 완료 처리하지 않는다.
