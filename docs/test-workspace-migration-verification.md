# 시험 임시 경로의 사용자 홈 이전

확인일: 2026-11-11. 사용자가 시험 임시 경로를 `/home/server` 아래로 옮기도록 승인했다. 새 기준은 **`/home/server/hearth-tmp`**이며 `/tmp`와 다른 `/home` 파일시스템을 사용한다. 검증 종료 시 여유는 약 **373GiB**였다. [원시 증거·명령 입력·최종 JAR](../verification/test-workspace-migration-result.json)을 따른다.

## 변경

- 기준 디렉터리는 실제 실행 사용자 소유·0700·정본 경로·전용 표식으로 확인한다. `python3 scripts/isolated_paths.py`로 준비하고 `--prefix hearth-s4-11.` 등으로 새 하위 경로를 만든다. 각 시험의 기존 표식·fresh 데이터·접두사·소유권 검사를 유지한다.
- Python의 S4-1/2/4/5·인벤토리·월드/세션·실제 팩 제공기·AI·공간 정리와 Java 플러그인/DB fixture·Gradle stage/통합 task를 같은 기준으로 맞췄다. 기존 `/tmp`는 검증된 아티팩트의 읽기 전용 복사 원본으로만 허용한다. 다른 경로/별칭 symlink·잘못된 기준 권한/표식은 거부한다.
- Gradle 배포본/의존성 캐시를 같은 기준 아래에 복사해 검증했다. 단위 JVM, 실제 Paper/DB 보조 JVM의 `java.io.tmpdir`, AI 모델·프로필·runner 임시 경로를 새 파일시스템에 둔다. 명령에 기존 Java 임시 경로가 있으면 해당 시험 안인지 검사한다. 자동 공간 정리도 새 파일시스템의 여유를 확인한다.
- 이전 `/tmp`의 증거·DB/월드·모델·도구는 이동/삭제/덮어쓰지 않는다. 시스템 `/tmp` 마운트·LVM·운영 서비스/패키지/SSH는 변경하지 않는다. 기존 EULA·CPU/RAM/GPU·디스크·시간·포트 한도를 유지한다. [현행 절차](DEVELOPMENT_WORKFLOW.md#시험-임시-경로)와 [AI 예산](decisions/0018-local-ai-runtime-and-trial-budget.md)에 반영했다.

## 실행한 검증

- Python **28개 고유 검사 PASS**: 새 기준/접두사·정본 경로·소유권/권한·표식·symlink·Java 임시 경로 경계, 기존 AI/공간 정리와 팩 제공기의 HTTP fixture다. 최초 공간 검사 모듈의 import 오타를 고쳐 영향받은 5개만 다시 검사했으며 초기 로그도 보존했다.
- Java 경로 단위 **3개 PASS**, 최종 main/JAR/integration fixture 컴파일·Gradle stage PASS. 6종 S4 접두사와 잘못된 경로/별칭·표식/권한을 검사했다. Gradle 캐시/배포본에 기존 `/tmp`를 가리키는 symlink가 없음을 확인했다.
- 실제 CLI에서 과거 `/tmp`의 Paper·AI 경로를 실행 대상으로 지정하면 프로세스 시작 전에 거부한다. 거부 전후 기존 결과의 SHA-256이 같다. 새 모델 복사 원본은 과거 `/tmp`에서 읽으며 크기/수정 시각/inode/소유자도 보존했다.
- **Paper 2 JVM·PG 1개, 79회 assertion PASS·62.619초**. 새 파일시스템에서 진행별 월드 로드/언로드·세션/인벤토리/퀘스트·공유 진행 저장/복원과 관련 실패/원본 보존을 확인했다. 최초 DB 보조 JVM은 공통 경로 클래스가 classpath에 없어 DB/Paper 시작 전에 실패했다. 해당 클래스만 stage에 추가하고 새 경로로 재시험했으며 실패 경로/로그를 보존했다. 실행/설치 JAR과 fixture 경로 클래스의 바이트가 최종 JAR과 같다.
- **실제 Ollama/Qwen3 자료/캐시 probe PASS·100.333초**. 이전 고정 해시 파일 4,043,062,302바이트를 검증 복사했고 다운로드는 0바이트다. 새 경로의 준비 응답은 76.854초로 기존 90초 한도 이내였다. 자료 번호·진행/세션 분리·반복 캐시 4회 적중·stale 거부·입력 한도 `CONTEXT_LIMIT`·종료 정리를 확인했다. 최대 표본 RSS 3,412,556KiB/GPU 3132MiB로 기존 상한 이내다.
- Paper/PG와 AI는 순차 실행했다. 소유 프로세스·포트/GPU 정리 오류가 없고 부모 환경/운영 서비스는 유지했다. 실제 Minecraft 클라이언트는 사용하지 않았다.

개별 S4-1/2/4/5/6의 전체 과거 시나리오는 반복하지 않았다. 공통 경로 검사·컴파일과 대표 두 JVM/실제 PG·실제 AI로 변경 영향을 확인했다. 실제 화면/입력·코옵, 운영 배포·기존 데이터 이전, 일반 모델 정답률/과학 지식·목표 사용량/장기 성능은 이번 검증 범위가 아니다.
