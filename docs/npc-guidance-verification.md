# 공개 인물 안내·NPC 정보 공개 경계 통합

확인일: 2026-11-09. 기준 `6b185e7` 이후 코드. [공개 코스](public-course-integration-verification.md)의 현재 동선과 기존 개인 의뢰/기록·NPC 대화를 재사용했다. 상세 실행·해시·원시 증거는 [검증 JSON](../verification/npc-guidance-result.json)에 기록한다.

## 구현한 플레이 흐름

- 다음 플레이 안내·현재 코스 동선과 스마트폰 기록에서 **인물 안내**를 연다. 본인의 수락 의뢰 담당자, 활성 의뢰의 **현재** NPC 대화 목표, 본인이 기록했고 현재 질문 조건도 충족한 인물, 현재 공개 코스의 담당자/공동 조사 안내자를 표시한다. 미수락 미래 의뢰와 다음 목표의 인물을 미리 나열하지 않는다. 새 개인 발견/대화 저장 규칙은 추가하지 않는다.
- 목록·상세·쪽 이동·갱신과 원래 동선/안내/기록 복귀를 제공한다. 상세는 인물 이름, 본인의 연결 이유, 현재 허용된 질문 제목만 읽는다. 좌표·원본 대화·질문 답변을 포함하지 않는다. 같은 이름도 내부 NPC ID로 구분하며 해당 키를 화면 본문이나 AI에 전달하지 않는다.
- **가까운 NPC와 대화**를 선택하면 최신 안내의 개인 목표/revision·기록 버전·공유 revision·보상 epoch를 다시 확인한다. 책은 세션/일회용 화면 표식/원래 접근 조건을, Dialog는 기존 화면 nonce를 유지한다. 이후 기존 실제 NPC 엔티티·같은 월드·거리·지역 상호작용 권한을 검사해 원래 대화/개인 상호작용 목표 처리로 이어진다.
- 서버 내부 조회 스냅샷에 NPC 위치의 비공개 상태를 포함했다. 기록의 관련 NPC 버튼과 스마트폰 연결, 인물 안내, 실제 NPC 표시/대화, 기록 없는 질문/중요 답변의 저장 진입은 같은 `QuestJournal.npcAllowed` 기준을 사용한다. 공유 상태가 불명/HOLD이면 열지 않는다. 조회 중 권한이 달라지거나 비공개 목록을 누락한 이전 스냅샷을 재사용하면 거부한다. 질문의 선행 퀘스트 조건도 계속 적용한다.
- 새 격리 공개 코스에는 기존 CONTENT 제한 구역의 공개 합성 연구원과 개인 시설 기록에 연결된 질문을 추가했다. 같은 개인 기록이 있어도 공유 개방 전에는 인물 연결이 숨겨진다. 개방 뒤에도 P1의 기록이 P2의 인물 연결을 만들지 않는다. 기본 코스/게이트·기존 파일·DB/인벤토리 계약을 유지하며, 이전 코스 파일에 선택 `npcs` 항목이 없어도 로드할 수 있다.

## 실행한 검사

- 관련 퀘스트·스마트폰·제작·채집·던전·인벤토리/세션의 고유 **494개 단위·회귀 PASS**. 최초 493개 뒤 현재 NPC 목표 안내 1개를 보강해 해당 모델 9개만 재실행했다. 새 모델 9개와 권한 gateway 5개는 개인/공유 기록 구분, 미수락 미래·다음 목표 제외, 현재 목표 안내, 위치 비공개와 기록/스마트폰 버튼 필터, 같은 이름/쪽 이동·읽기 불변, 이전 revision·가짜 선택 거부, 질문 본문/좌표 비노출, 저장 없는 거부·공유 HOLD·조회 중 접근 변경을 확인했다.
- main/test 컴파일·최종 JAR을 생성했다. runtime stage는 기존 경로의 덮어쓰기 방어가 한 번 작동해 신규 `/tmp/hearth-s4-11.*`에서 다시 준비했다. 성공한 단위 검사는 반복하지 않았다.
- 신규 `/tmp/hearth-s4-11.aJkDfrCG`의 PostgreSQL 1개·Paper 1 JVM에서 전체 공개 코스와 신규 인물 경계 **249회 세션 assertion PASS**(고유 표식 152개), **86.82초**. 개방 전/후 위치 권한·책 기록/스마트폰 인물 연결, 기본 숨김·비영구·중복 없는 NPC, 실제 Book/Dialog·이전 선택 거부·조회 무변경·P2 개인 격리를 확인했다. 기존 채집/두 도구 제작·공유 투표·던전 보고/DB 반영 거부 보존·최종 월드 재연결/도구·개인 기록 보존도 통과했다. 최종 JAR/설치 해시 일치, Paper 최대 표본 RSS 약 1348MiB, 종료·DB 풀·프로세스/포트 정리도 PASS다.

통합은 기존 `--sessions --quests --story-batch --public-course`의 자원·시간·localhost·한 JVM/DB 한도를 유지한다. 개인 시설 질문은 서버 제어 경계에서 호출했고, 실제 Book/Dialog/Inventory·기본 숨김 NPC 엔티티 속성과 PG 상태/저장·기존 CAS 실패 보존을 확인한다. 실제 클라이언트 클릭이나 인증을 합성하지 않는다.

## 실패 이력·남은 범위

첫 Paper 실행은 공유 개방 전 이름/기록/스마트폰 비노출을 통과한 뒤 새 NPC 엔티티 속성 조회에서 `NoSuchElementException`으로 중단됐다. 무인 시험의 해당 청크 로드/엔티티 복원을 보장하지 않은 fixture였다. 해당 속성을 검사하는 동안만 기존 비동기 청크 준비·플러그인 티켓과 NPC ensure를 사용하고 검사 뒤 티켓을 반납하도록 보완했다. 원래 실패 결과·로그는 보존한다.

실제 인증 클라이언트의 NPC 패킷 노출/표식·페이지/복귀/거리 변화·질문/개인 목표 클릭과 코옵 플레이는 사용자 요청 전 보류다. 공개 DTO/Mock 이외의 실제 AI 실행과 S5, 운영 배포도 수행하지 않았다. NPC 표시 검사는 기본 숨김/비영구·중복 없음의 서버 속성 범위다. 저장/복원 계약을 바꾸지 않아 두 번째 JVM 복원은 반복하지 않았으며, 같은 JVM의 최종 월드 언로드/재로드·인벤토리/개인 기록 보존과 구분한다.
