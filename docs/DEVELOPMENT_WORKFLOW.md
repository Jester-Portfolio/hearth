# Hearth: 작업·검증·토큰 최적화

대원칙: **근거 있는 검사만 실행한다. 같은 결과를 얻기 위한 확인·읽기·재실행·문서화를 반복하지 않는다.** 보안·데이터·권한·운영 안전 규칙은 축소하지 않는다.

## 개발 목표와 배치 규모
- **토큰 절약을 이유로 기능 구현을 축소하거나, 완료 가능한 개발 작업을 불필요하게 여러 배치로 분할하지 않는다.** 절약 대상은 무관한 탐색·중복 실행·중복 문서다.
- 배치는 기술 요소 하나나 시험 항목 수가 아니라 연관 기능의 구현·통합과 실제 플레이 흐름을 기준으로 구성한다. ChatGPT가 설계·범위를 정하고 Codex는 승인 범위를 끝까지 구현·검증한다.
- 관련 기능을 중형~대형 배치로 묶고 작은 버그·기술 개선도 함께 처리한다. 긴급 차단 결함·필수 선행 조건은 우선 해결하되, 시험 확장이나 작은 기술 과제만 다음 목표로 계속 선정하지 않는다.
- 승인 범위의 조사→구현→오류 수정→관련 검증→문서→커밋/푸시는 연속 수행한다. 단계마다 새 Issue나 재승인을 요구하지 않는다. 미정 게임 정책·운영 변경은 별도 결정 경계를 유지한다.
- 기능 구현 완료, 내부 자동 검증, 실제 인증 클라이언트 검증, 운영 배포를 구분한다. 저장·격리·권한·실패의 필수 검사는 비용 때문에 생략하지 않는다.

## 탐색 및 작업 묶기
- 시작 시 `git status --short --branch`, 원격 기준과 기존 변경을 한 번 확인한다. 무관한 파일을 읽거나 변경하지 않는다.
- `rg -n`으로 해당 코드 위치를 찾고 필요한 줄만 읽는다. 장문 Markdown·로그·증거 JSON 전체 읽기 금지. 컨텍스트가 이미 가진 정보는 파일 변경 시에만 다시 확인한다.
- 현재 구현이 필요한 경우 PROJECT_STATUS의 짧은 요약, 설계가 필요한 경우 해당 ADR, 시험 실행이 필요한 경우 관련 검증 기록/스크립트만 본다. ROADMAP/CHANGELOG를 모든 작업에 재조회하지 않는다.
- 승인된 기능은 연관 배치로 구현하고 성공·실패 검사를 묶는다. 큰 배치 완료 시 짧은 Git 기반 인계만 남기고 무관한 이전 채팅은 새 작업에 재주입하지 않는다.

## 변경 범위별 최소 시험

| 변경 종류 | 기본 시험 | 필요한 경우에만 추가 |
| --- | --- | --- |
| Markdown·설명·주석 | 변경 파일 diff/링크/형식 | 코드 변경 없으면 Java·DB·JVM 금지 |
| Java 계산·DTO·GUI 표시 | 컴파일+해당 단위/회귀 | 세션·정보 노출 경계도 바꾸면 관련 격리 |
| 기존 퀘스트·NPC·탐험 | 관련 단위/회귀 | DB/권한·월드 변경 시 해당 통합 |
| PostgreSQL 스키마·CAS·투표·분기·인벤토리 | 관련 단위/실DB·경합·실패·보존 | 저장 후 복원 계약 변경 시 새 JVM/PG |
| 월드/권한/WorldGuard/세션 이벤트 | 관련 단위+격리 Paper 통합 | 복원 계약 변경 시 두 JVM |
| 릴리스·운영 배포 | 영향받는 전체 회귀/보안·운영 점검 | 배포 전 별도 사용자 승인 |

- `gradle build test check`처럼 의존 작업을 중복 나열하지 않는다. 이미 실행하는 task 그래프를 확인해 필요한 명령 한 번만 실행하고, 개발 중엔 테스트 클래스/패키지를 좁힌다.
- **동일 소스·실행 조건·기존 성공 증거**가 있는 검사만 재실행을 생략한다. 의존성·공개 인터페이스·데이터 규약이 바뀌면 영향 받는 회귀 범위를 넓힌다. 위험 기능의 필수 실패/경합/보존 검사를 비용 때문에 생략하지 않는다.
- 실패하면 첫 실패 로그/관련 테스트만 확인→수정→영향 테스트 재실행. 전체 검사는 변경 범위가 확대될 때에만 수행. 반복/비결정성 문제는 필요한 재현 횟수의 근거를 먼저 밝힌다.
- 서버·DB 시험의 기존 EULA/자원 예산/localhost/사용자 소유 신규 임시 경로/원시 증거 보존은 그대로 적용한다. 실제 클라이언트는 사용자 지시 전 보류.

## 출력·검증 증거·문서
- 성공 시 짧은 PASS/FAIL·실행 범위·개수·소요 시간. 실패 시 핵심 오류 일부만 읽는다. 원본 로그와 JSON은 기존 경로에 보존하되 채팅에 통째로 붙이지 않는다.
- 파일 전체 해시/전량 링크 검사/과거 검증 기록 재확인은 모든 작업의 기본 단계로 강제하지 않는다. 배포 아티팩트 정합성·원본 보존 등 필요한 변경에서만 수행한다.
- 코드 컴파일/내부 명령/DB 통합/인증 클라이언트/운영 배포를 구별한다. 부분 통과를 전체 통과라고 기록하지 않는다.
- 현황은 현재 결과, 로드맵은 다음 단계만. 중요 변경은 CHANGELOG에 간결히 한 번, 상세 증거는 해당 검증 기록에만 작성한다.
- 기존 Git Gitleaks 훅을 매 작업 별도 수동 재검사로 중복하지 않는다. GitHub API 쓰기는 훅을 거치지 않으므로 수행되지 않았다고 알린다.
- 추가 CLI·MCP 도구(RTK·CodeGraph 포함)는 지금 설치하지 않는다. 기존 개선 전후에서 도구 출력/긴 탐색의 병목이 측정되면 한 종류씩 별도로 검토한다.
