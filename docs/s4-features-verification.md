# S4 개인 장면·지도·시설·전투 복귀 통합 검증

확인일: 2026-11-09. 기준 `d65ccac` 이후 코드. 이번 요청에서 승인한 [ADR-0016](decisions/0016-s4-personal-features-and-recovery.md)의 정책을 기존 공개 코스·세션·개인/공유 퀘스트·탐험·스마트폰에 연결했다. 기능 구현·자동 검사와 실제 인증 플레이 수용은 구분하며 S4는 수용 완료 전이다. 상세 명령·해시·실패·자원·원시 증거 경로는 [검증 JSON](../verification/s4-features-result.json)에 기록한다.

## 구현

- 개인 장면은 콘텐츠 fingerprint와 시작/프레임/최초 완료/향후 스킵을 PG CAS로 저장한다. 시작 확정 뒤 해당 개인만 이동/시선을 잠그고 책의 다음 프레임을 연다. 중단은 완료가 아니며 첫 완료 전 수락은 거부한다. 시청 재도전/명시적 스킵과 별도 읽기 전용 재시청을 제공한다. 오래된 응답·CAS 실패는 원본/HOLD를 보존한다. 재개 후 NPC를 다시 열 때 대화 목표를 중복 반영하지 않는다.
- 개인 엔더 보관함은 진행/개인별 27칸이다. 실제 시설·현재 세션·거리·WorldGuard 접근을 확인하고 별도 화면을 열며, 일반 인벤토리 41칸과 같은 dirty 저장의 한 트랜잭션으로 확정한다. 순정 전역 엔더 데이터는 읽거나 수정하지 않는다. 가공/자동화의 화로·용광로·훈연기·호퍼·드로퍼·디스펜서·양조대와 설치된 셜커는 기존 현재 블록/화면/권한 경계에 포함하고 월드 저장 책임을 유지한다. 상자 엔티티·거래/마법/모루 같은 별도 인터페이스까지 일괄 허용하지 않는다.
- 스마트폰은 개인/진행 PDC와 전용 모델을 사용한다. 최초 정상 접속은 빈 칸과 최신 41칸을 확인해 발급 표시/아이템을 함께 저장한 뒤 적용한다. 공간 부족은 보류, 발급 이력 뒤 부재는 명시적 재발급만 허용한다. 기존 메타데이터·아이템을 덮어쓰지 않고 버리기·보관함/제작 투입·타인 사용을 제한한다. 복구 상태를 확인하기 전에는 조작을 잠근다.
- 지도는 현재 접근 가능한 공개/개인 발견 장소의 지형과 위치 공개 정책을 사용한다. 로드된 청크만 최대 1024열/2초 주기로 샘플링하고 무단 청크 생성/전체 월드 순회는 하지 않는다. 지도는 잠금·개인 렌더러와 캔버스별 캐시를 사용하며 퀘스트/알려진 NPC/장소/같은 진행의 근처 플레이어와 개인 표시 설정을 연결한다. 별도 원형 16×16 Glyph 오버레이와 소유한 quest sidebar는 다른 표시의 소유권을 보존한다. 정확한 위치는 아래 미검증 범위를 따른다.
- 무료·즉시 시설 이동은 양쪽 개인 방문/해금·현재 접근·전투 외 조건과 저장 후 이동 순서를 사용한다. 기존 시설/책/스마트폰 경로를 유지한다.
- 공개 합성 보스 콘텐츠에 고리형·둔화·밀어내기·연속 공격을 추가했다. 연속 타격은 같은 도전/세대의 전투 시간과 제한된 큐를 사용하고 정지·페이즈 변경·종료 때 중단한다. 기존 실제 피해 대상/범위/권한을 다시 검사한다.
- 전투 시작·확정 종료·복귀 대기/claim/DONE을 개인 PG에 저장한다. 재시작 후 확정 종료 대기만 저장→claim→안전 위치 이동/회복→DONE으로 이어가고, ACTIVE/RETURNING은 HOLD한다. 기존 전투 표식은 새 복구 모드에서만 보존한 채 조회를 허용한다. 기존 필드 조우 표식은 조우 모듈 HOLD로 유지해 자동 재소환/리셋하지 않는다. 몹/HP/패턴 시간이나 오프라인 보상을 임의 복원하지 않는다.

V010은 별도 개인 기능 행을 추가하며 기존 월드/인벤토리/진행을 자동 이관·초기화하지 않는다. 신규 SQL은 기존 bounded worker를 사용하고 Bukkit 메인 스레드에서 DB를 기다리지 않는다. 일반 월드 파일과 PG의 완전 원자성·고비용 자동 무손실 복구는 도입하지 않는다. 새 외부 플러그인 없이 기존 Paper·WorldGuard·WorldEdit를 사용한다. 기본 활성화 게이트는 모두 꺼져 있다.

## 실행한 검사

- 전체 단위·회귀 857개에서 856개 통과 후 고리형 범위 예고의 기존 표시 수 제한 불일치를 수정했다. 안/바깥 고리를 합쳐 기존 24개 한도를 지키도록 수정하고 관련 범위/공격·신규 HUD 15개와 세션 영향 검사를 재실행했다. 최신 testcase 결과를 합친 **861개 고유 검사, 실패 0개**다. 같은 소스의 성공 검사는 불필요하게 반복하지 않았다.
- 최종 main/test/integration fixture 컴파일·Gradle JAR/runtime stage, Python 컴파일과 잘못된 모드 조합 3개 거부, 리소스팩 JSON/PNG·16행 폰트/양방향 간격 Glyph·로컬 ZIP 빌드가 PASS다. ZIP은 게시하지 않았다.
- 최종 JAR의 `--s4-completion`은 **432회 세션 assertion PASS, 144.349초**다. 신규 `s4_` assertion 53개와 기존 공개 코스·호위·실패/재개·공유 분기·채집/두 도구 제작·던전·탐험·보상/결과 검사를 함께 실행했다. 최초 장면 중단 후 필수 유지·확정 시작/프레임·후속 선택·명시적 스킵·재시청 revision 불변, 실제 PG 동일 revision 경합의 단일 승자·41칸/27칸 롤백·stale Account HOLD, 발급 중복 거부/원본·명시적 재발급을 확인했다.
- 같은 PG/월드에서 **Paper 2 JVM**을 순차 실행했다. 두 번째 JVM에서 개인 장면/선택, 엔더 27칸/41칸 원본, 스마트폰 단일 소유 아이템, 확정 복귀 대기/ACTIVE·RETURNING HOLD, 잘못된 claim 거부와 DONE, 필드 표식 HOLD/몹 미재소환을 검사했다. 일반 화로/호퍼/셜커/양조대의 실제 블록·내용과 기존 도구도 보존됐다. PG 프로세스는 유지했으며 재시작하지 않았다.
- 실제 Paper 27칸 Inventory/ItemStack 직렬화·잠긴 MapView·Glyph Component와 실제 Villager의 둔화/속도를 확인했다. 지형 렌더 시 로드된 청크 수 불변과 비공개 위치 제외도 확인했다. 거점 이동은 실제 PG 저장과 제어 포트에서 1회 이동·기존 도구/인벤토리 보존을 검사했다. 실제 Player 이동/클릭 성공 주장은 아니다.
- 같은 최종 JAR의 기존 `--inventory-workspaces`도 **56회 assertion PASS, 48.857초**, 별도 새 PG/월드와 Paper 2 JVM에서 실행했다. 임시 2×2/3×3 제작·반환 용기·현재 이중 상자/WorldGuard·dirty/경합·SQL 실패·원본 보존·저장 복원이 회귀했다.

개발 중 첫 native 실패는 합성 SPHERE 높이/단발 간격 설정 오류였다. 다음 실패는 기존 프로세스 표식과 새 승인 복구 모드의 충돌이었고, 표식 삭제 없이 영속 복구/필드 HOLD를 연결했다. 세 번째는 새 복원 검증 명령의 dispatch 등록 누락으로 수정했다. 원래 결과/중단 정리 누락 표식은 증거에 보존했다. 최종 두 모드는 DB 풀·프로세스·포트 정리가 모두 PASS다.

모두 새 사용자 소유 `/tmp`·localhost·기존 EULA, 총 600초/작업 550초·Paper 최대 2회·힙 1536MiB/RSS 중단 2560MiB·CPU 2개/nice 10 한도를 유지했다. S4 통합 두 JVM의 최대 표본 RSS는 약 1153/960MiB였다. 운영 서비스·운영 데이터·비공개 스토리 저장소에는 접근/변경하지 않았다.

## 미검증과 수동 대응

실제 인증 클라이언트의 컷신 선택/닫기/카메라·키 입력, 스마트폰 지급·아이템 이동/재발급, 엔더/시설의 클릭·동시 이동·가공/호퍼 전달, 실제 전투·관전/부활·프로세스 장애 중 복귀는 별도 요청 전 보류다. 가짜 Player·인증 우회로 대체하지 않았다.

리소스팩 실제 로드·원형 외곽·색/문자 가독성·GUI 배율·화면 비율·보스 표시 공존은 미검증이다. 미니맵은 기본 수평 오프셋 96의 개발 Glyph BossBar이고 퀘스트 HUD는 sidebar다. **ADR-0010의 정확한 좌상단 퀘스트/우상단 미니맵 배치를 보장하거나 실제 화면 수용을 완료한 구현은 아니다.** 실제 수용 결과에 따른 배치/표시 보완이 필요하며, 기본 미니맵 설정과 데이터 저장을 변경하지 않는다.

HOLD 시 기존 개인 41칸/27칸·기능 payload/revision·월드/전투 표식을 보존하고 세션/시도/claim 및 마지막 확정 경계를 확인한다. ACTIVE/RETURNING이나 commit 불명을 새 시도로 덮거나 표식을 삭제해 자동 재시작하지 않는다. 실제 데이터 보정/운영 재시작은 별도 명시 승인 후 ADR-0003의 수동 대응으로 수행한다. 로컬 AI 실제 모델/S5·콘텐츠/성능/S6·운영/S7·경제 운영 완료를 이 결과로 대체하지 않는다.
