# HUD·관전 표시와 선택형 BetterHud 통합 검증

확인일: 2026-11-09. 기준 `e2933b1` 이후 코드. 사용자가 [선택형 BetterHud 연동](decisions/0017-optional-betterhud-presentation.md)을 선택해 기존 표시 보완과 함께 구현했다. 상세 명령·해시·수치·원시 로그 경로는 [검증 JSON](../verification/hud-display-result.json)을 따른다. 실제 Minecraft 클라이언트 시험은 수행하지 않았다.

## 변경

- 퀘스트 HUD를 한 출력기가 소유하게 해 기존 BossBar와 새 sidebar/선택형 출력의 중복을 제거했다. 정상/관전·복귀의 읽기 전용 조회를 같은 경로로 전달하며 NPC 대화/GUI/진행 복원 권한은 기존 행동 제한을 유지한다. 이전 연결·늦은 정리가 새 연결의 표시를 지우지 못하게 한다.
- HUD와 지도는 현재 준비된 세션의 검증된 조회를 사용하고 캐시에 세션 token을 결합한다. 오래된 조회/세션·HOLD/종료는 표시를 정리한다. 관전/복귀라는 이유만으로 표시를 없애지 않는다. 빈 목표는 패널을 해제하고 유니코드 문자를 중간에 자르지 않으며 동일 미니맵 프레임은 다시 전송하지 않는다.
- BetterHud를 기본 비활성의 compile-only/soft dependency로 추가했다. [고정 아티팩트](../verification/betterhud-artifact.json)의 공식 SHA-256을 빌드/격리 실행에서 확인한다. 다른 HUD·보스바/플레이 상태를 지우거나 SDK 코드를 Hearth JAR에 합치지 않는다.
- 좌상단 퀘스트와 우상단 원형 미니맵을 SDK의 화면 비율 앵커로 정의하고 6개 목표 패널/추가 추적 안내, 16×16 픽셀·설정·색/표식을 연결했다. 기본 Paper 표시를 보존하며 팩/SDK를 사용할 수 있을 때 선택형 출력으로 전환한다.
- 비동기 placeholder에는 현재 개인 연결에 발행한 불변 문자열 프레임만 전달한다. 3초 만료, actor/token 분리, 전체 프레임 원자 교체를 사용하며 Bukkit/월드/DB를 비동기로 조회하지 않는다. 팩 내용 기반 ID의 로드 성공을 확인하기 전에는 선택형 표시를 열지 않는다. 성공 응답이 준비 완료보다 먼저 와도 보존하고 다른 팩의 응답과 섞지 않는다.
- Hearth 이름의 정의/폰트/병합 폴더를 준비하고 기존 파일을 덮어쓰지 않는다. 최초 SDK 준비 뒤 비동기 재생성과 팩 변경의 ID 갱신을 연결한다. 순정 하단/핫바 제거·보스바 병합·자체 호스팅은 꺼진 설정을 사용한다. 팩 URL 게시/강제 전송은 하지 않는다. [설정/팩 안내](../integrations/betterhud/README.md)를 따른다.

## 검사 결과

- 관련 단위/회귀의 최신 결과를 합친 **68개 고유 검사 PASS**. 출력 전환/중복 억제·다른 개인/전투 채널 보존·부분 실패 정리·동일 UUID 재접속, 기존 지도/장면/보관·전투 HUD·조회 stamp, 신규 개인 프레임의 만료/동시 읽기·마크업/한글·추적 유지·팩 성공/실패/거부/교체/이전 연결을 포함한다. 변경한 범위만 재실행했다.
- 최종 JAR의 `--sessions --quests --story-batch --betterhud --betterhud-plugin … --accept-eula`는 **99회 세션 assertion PASS, 45.752초**. Paper 26.2/Java 25에서 실제 SDK 로딩·공개 API 재생성·개인 정의/placeholder 등록·콘텐츠 기반 팩 ID 내보내기·보스바 병합 해제·종료를 확인했다. 기존 실제 몹 체력/관전/부활 제어·개인 사망 실패·읽기 전용 HUD 조회·PG CAS 실패/HOLD/원본 보존도 포함한다.
- 같은 최종 JAR의 `--sessions --quests --story-batch --hud-display --accept-eula`는 **93회 세션 assertion PASS, 37.861초**. BetterHud를 설치하지 않고 S4 기본 표시 묶음을 로드했다. 선택형 API가 없어도 기존 모드의 기능/조회·종료가 동작함을 확인했다.
- 두 모드에서 실제 Scoreboard/BossBar 객체의 단일 퀘스트 출력·한글/서로게이트 쌍·읽기 전용 목표 교체·다른 개인과 전투 채널 보존·정리를 검사했다. 객체/제어 포트 검사이며 실제 Player 화면을 만든 시험은 아니다.
- 생성 통합 ZIP **17개 검사 PASS**. 내용 기반 ID와 내보낸 ID 일치, format 88, 실제 26.2 대상 shader의 화면 폭 상대 우측 앵커, 좌상단/우상단 정의·64px/12px 여백, 4px 간격의 16개 픽셀 폰트, 6개 목표의 2줄 한글 폰트, 기존 스마트폰 폰트/모델/아이템/텍스처의 바이트 보존을 확인했다. 핫바 제거·보스바 병합·자체 호스팅도 꺼져 있다.
- main/test/fixture 컴파일·Gradle JAR, API 공식 해시, Python 구문·잘못된 모드/비공식 플러그인 5개 거부를 확인했다. 최종 두 모드는 각각 PG 1개/Paper **1 JVM**을 순차 실행했고 기존 `/tmp`/localhost/EULA·600초/작업 550초·1536MiB heap/2560MiB RSS·CPU 2/nice 10 상한과 DB 풀·프로세스·포트 정리를 통과했다. 저장/복원 계약이 바뀌지 않아 두 번째 JVM은 생략했다.

초기 SDK 실행은 Paper 검사 97개를 통과했지만 후속 ZIP 검사에서 스마트폰 자산이 빠진 것을 발견했다. 병합 경로의 기준을 BetterHud 폴더가 아닌 plugins 폴더로 수정하고, 준비 완료 조건에 스마트폰 자산 확인을 넣었다. 원래 결과를 증거에 남겼으며 최종 팩에서 보존을 확인했다. 초기 Gradle DSL import/checked 예외 선언의 컴파일 오류도 수정했다.

## 미검증

실제 인증 클라이언트의 팩 수락/거부/다운로드·성공 이벤트, shader 실행·GUI 배율/해상도·글자 가독성·겹침, 실제 코옵/전투 표시·클릭은 사용자 별도 요청 전 보류다. 순정 클라이언트에서 화면 모서리가 실제로 맞았다고 주장하지 않는다. 다른 팩/다른 HUD 조합·장기 부하·운영 설치/재시작·팩 게시도 수행하지 않았다. S4 실제 수용과 S5~S7 완료는 이 결과와 별개다.
