# 길목 집결·보스 입장 통합

2026-11-05. S4 진행 중. 기존 [전투 복귀/구역 초기화](combat-return-verification.md), 전투 상태·Player 적용기·저장 장벽을 재사용했다. [결과 JSON](../verification/combat-gathering-result.json)은 단위/실DB/실제 관리 몹과 인증 플레이어 미검증을 구분한다.

## 동작과 콘텐츠

`combat-demo.yml`의 선택 `path`는 길목 전투 정의, 집결 구역, 보스 입장 위치·방향·사망자 회복값/효과를 명시한다. 길목의 전투/부활 설정은 보스 설정과 분리한다. 중첩 길목 정의·불완전한 위치/회복값을 거부한다. 기존 설정에 `path`가 없으면 기존 보스 단독 시작을 유지하며 기존 파일을 자동 덮어쓰지 않는다.

- 명시적인 격리 콘솔 시작 `hearthverify combat-player-start 프로필`에서 길목 정의가 있으면 길목 전투를 시작한다. 새 로그인/가입·파티 관리 기능은 아니다.
- `/hearthcombat gather`에서 현재 길목 참가자의 신뢰하는 온라인 세션을 확인한다. 온라인 생존자 전원이 집결 구역 안에 있어야 하며 온라인 사망 관전자는 위치 검사에서 제외한다. 오프라인 참가자는 입장 명단·난이도에서 제외한다. 생존자가 없는 전멸 상태는 보스로 넘어가지 않고 길목 실패로 확정한다.
- 집결 검사가 통과하면 길목 AI·해당 진행 조작을 제한하고 기존 활성/퇴장 인벤토리와 퀘스트·일지·공유 진행 저장 장벽을 확인한다. 저장 중 위치/접속/세션/세대 변경을 재검사한다.
- 안전성이 확인된 콘텐츠의 보스 입장점으로 이동을 적용한다. 생존자는 현재 체력 비율을 유지하고 온라인 사망자는 명시된 회복값/효과로 복귀한다. 이 경로는 길목의 부활 사용 횟수를 차감하지 않는다.
- 모든 입장 적용과 위치 확인 후에만 기존 길목 관리 몹/참조를 정리하고 새 보스를 생성한다. 보스 시작 명단·난이도와 기존 새 도전의 부활 횟수 초기화 경로를 사용한다. 보스 시작 당시 오프라인이었던 길목 참가자는 해당 도전에 들어오지 않으며, 시작한 보스 참가자의 기존 재접속 권리는 유지한다.
- 저장 실패·이동 실패·세션/세대 변경·중간 종료·보스 생성/연결 실패는 HOLD로 보존한다. 중복 요청은 같은 결과를 공유하고 이전 참가자 적용 가드를 닫는다. 집결 미충족은 저장·이동 전에 거부하여 다시 집결 요청할 수 있다.

길목 관리 몹을 먼저 처치해 승리한 경우에도 집결 후 입장할 수 있다. 기존 승리 결과는 덮어쓰지 않는다. 아직 진행 중인 길목을 인계하는 경우의 `RETIRED`는 내부 전투 객체 정리이며 공동체 퀘스트/분기 완료가 아니다. 인벤토리·소비품·개인 퀘스트/컷신 기록을 초기화하지 않는다.

## 실제 검사

- 관련 전투·세션·저장 단위/회귀 **120개 PASS**, JAR 빌드 PASS. 온라인 생존자/사망자/오프라인 구분, 집결 미충족 후 재요청, 저장 중 이탈, 실제 시작자의 재접속 권리, 중복·오래된 입력·세션/세대 변경·종료·owner 거부·저장/이동 실패를 검사했다.
- 새 사용자 소유 경로의 Paper 한 JVM·PostgreSQL 한 개 **PASS** (36.391초). 기존 `--sessions --quests --story-batch --combat-players`에 관련 회귀를 묶었으며 별도 시험 체계는 만들지 않았다.
- 실제 길목 몹과 보스의 콘텐츠별 체력, 길목 AI 중지, 기존 몹 제거 후 단일 보스 생성, backend 요청 재전달 시 중복 생성 차단을 확인했다. 내부 제어 포트로 온라인 사망자 복귀·생존자 체력 유지·같은 진행 2명 명단/난이도·기존 길목 사용 횟수 보존·새 보스 카운터 초기화를 확인했다.
- 실제 DB CAS 실패를 주입해 인벤토리 원본/dirty·길목 사용 횟수를 보존하고 입장 적용·보스 생성을 실행하지 않음을 확인했다. 다른 개인/진행 데이터와 기존 종료 복귀·구역 초기화 회귀도 같은 실행에 포함했다.
- Paper 최대 RSS 1,134,448KiB, 관측 CPU 63.83초, 준비 13.637초. 최소 관측 가용 RAM 11,485,620KiB. 기존 CPU2/nice+10·Xmx1536MiB·600초·메모리 제한을 지켰고 정상 종료·프로세스/포트 반환·최종 빌드/실행 JAR 일치를 확인했다.

## 남은 범위

실제 인증 플레이어의 집결·명령·이동·관전/회복/게임 모드 동작은 미검증이다. 제어 포트와 실제 관리 몹/DB 성공을 실제 사용자 행동 성공으로 보지 않는다. 실제 시험은 별도 요청 전 보류한다.

현재 길목은 명시적으로 시작한 하나의 관리 전투에서 보스로 넘어가는 개발 흐름이다. 여러 길목 구역과 체크포인트 도달 판정, 길목부터 재도전(`FROM_PATH`)과 기존 구역 초기화의 자동 연결, 전원 오프라인 뒤 복귀, 전투/길목의 프로세스 재시작 복구는 남아 있다. 일반 서버 자동 활성화·전체 인던 완료를 뜻하지 않는다. 기존 DB/인벤토리 저장 형식은 그대로라 두 번째 JVM은 생략했다. 공개 합성 수치와 새 도전 검사 결과를 미정 운영 밸런스의 최종 결정으로 보지 않는다.
