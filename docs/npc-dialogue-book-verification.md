# NPC 선택창·대화 책·수락/거절 통합

## 변경

격리 개발 모드의 기존 NPC 퀘스트 아이템창에 **대화 읽기·질문 선택**을 연결했다. 퀘스트가 없는 일반 NPC도 같은 경로를 사용한다. 공개 가능한 질문만 아이템으로 표시하고 답변은 책으로 연다. 중요한 답변은 기존 개인 일지 저장 성공 후 표시하며 일반 답변은 읽기 전용이다.

책은 콘텐츠 대화 페이지의 이전/다음, NPC 선택창 복귀, 대화 닫기를 제공한다. 퀘스트 제안 책에는 기존 수락과 함께 **거절**을 제공한다. 거절은 해당 제안을 수락하지 않고 선택창으로 돌아가는 동작이며, 거절 기록·실패 상태·재시작 규칙을 새로 저장하지 않는다. 기존 아이템창의 직접 수락/보고도 유지한다.

선택창 갱신·책에서 복귀·수락/보고 후 재표시는 NPC 상호작용 목표와 장소 발견을 다시 실행하지 않는다. 현재 대화 nonce·세션·진행·월드·엔티티·거리·지역/WorldGuard 권한을 유지하며, 오래된 창/책의 요청과 중복 수락/거절을 거부한다. 질문 선택 후에도 공개 조건과 비동기 결과 유효성을 재검사한다. 닫기·종료·월드 언로드 시 기존 토큰 정리를 재사용한다.

새 스키마·콘텐츠 ID·저장 체계·의존성은 추가하지 않았다. 과거 [채팅 페이지](npc-pages-verification.md), [조건부 질문](npc-topics-verification.md), [퀘스트 책](quest-inventory-book-verification.md)의 구현을 재사용하며, 현행 일반 대화/질문 선택 표시 경로를 아이템창과 책으로 통합한다. 일반 서버 자동 활성화와 운영 환경 변경은 없다.

## 수행한 검사

- 관련 단위·회귀 **고유 52개 최종 PASS**. 최초 51개 PASS·1개 FAIL은 새 시험이 기존 질문 16개 한도를 넘긴 40개 콘텐츠를 사용한 오류였다. 콘텐츠 한도를 변경하지 않고 해당 시험만 수정·재검사해 PASS했다. 초기 실패 XML과 내역을 보존했다.
- JAR 빌드·기존 통합 도구 준비 PASS. 질문 공개 조건, 일반 NPC, 메뉴/수락/거절 토큰의 소유권·중복·세션 교체·언로드, 책 분할, 개인 기록 저장 경합·stale·HOLD를 검사했다.
- **Paper 한 JVM·격리 PostgreSQL 한 개 PASS**, 자동 통합 한 묶음. 기존 `--sessions --quests --story-batch --npc-topics --npc-pages`를 결합했다. 실제 Paper의 54슬롯 GUI 객체·책/클릭 컴포넌트 생성, 질문 해금, 개인 일지/연대기 중복 방지, P2/다른 진행 비공개, 실제 DB 충돌 시 HOLD·기존 기록 보존, 대화 읽기/거절 전후 퀘스트 행·revision 및 개인 알림/추적/설정 불변을 확인했다.
- 총 **41.822초**, Paper 준비 **13.509초**, 종료 **3.666초**, 최대 관측 RSS 약 **1041MiB**, CPU 시간 **66.59초**, 최소 관측 가용 RAM 약 **11.37GiB**. 프로세스/포트 반환과 최종 빌드/설치 JAR SHA-256 일치 PASS.

[결과 JSON](../verification/npc-dialogue-book-result.json)에 실행 경로·세부 판정·자원을 기록했다. 저장/복원 계약을 변경하지 않아 두 번째 JVM과 기존 전체 게임 시험을 반복하지 않았다.

## 미검증·다음 작업

실제 인증 클라이언트의 NPC/아이템/책 클릭, 책 화면 전환·닫기·배치, 커서/드래그 등 실제 인벤토리 행동과 사용자 이동/권한 변화는 미실행이다. 서버 객체·명령 경계 검사를 실제 사용자 시험으로 보지 않는다. 실제 클라이언트 시험은 별도 요청 전 보류한다. S4는 진행 중이다.

다음 기능 배치는 기존 NPC/퀘스트/공유 진행과 스마트폰의 연결 공백을 중심으로 정하며, 실제 클라이언트가 준비되면 이번 책 흐름을 기존 수동 코스에 포함한다. 미정 게임 정책·AI 모델 설치·운영 배포는 이번에 추가하지 않았다.
