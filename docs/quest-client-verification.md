# 개인 퀘스트·책·스마트폰 실제 클라이언트 확인

2026-10-31, 인증된 시험자 한 명의 공개 합성 콘텐츠 시험이다. S4는 진행 중이며 전체 클라이언트 수용 시험을 의미하지 않는다. [결과 JSON](../verification/quest-client-result.json)에 실행별 원시 판정과 자원을 구분했다.

## 실제 관측

- 수락 전 목표 방문: `survey_marker` 미수락 유지. NPC 아이템창 수락 후 `ACTIVE/revision 0`, 재방문 후 `REPORT_READY/1`, 해당 NPC 보고 후 `COMPLETED/2`를 서버 조회와 대조했다.
- 연결 종료 후 IDLE → 저장 → 언로드 → 기존 월드 재입장으로 완료 상태가 유지됐다. 월드 세대는 1에서 3으로 바뀌었고 돌 32개와 인벤토리 revision 0이 유지됐다. 사용자가 완료 표시도 확인했다.
- 별도 새 시험에서 책의 수락 버튼 사용 후 `ACTIVE/0`을 확인했다. 사용자가 스마트폰의 선택 항목 AI 도움에서 Mock 응답을 확인한 뒤 종료했다. 실제 모델 호출은 아니다.
- 독립 퀘스트 `entry_marker` 보고를 주 퀘스트 완료와 혼동하지 않고 별도로 확인했다.

## 실행·실패 이력

| 새 격리 경로 끝부분 | 실제 확인 범위 | 실행 전체 판정 |
|---|---|---|
| `u2gz7o0f` | 미수락·수락·보고 대기 | 551.534초, 시간 상한 FAIL·DB 풀 정상 종료 표식 누락 |
| `u6n0x0ay` | 보고 완료·언로드 후 재입장 복원 | 551.098초, 시간 상한 FAIL·DB 풀 정상 종료 표식 누락 |
| `2q0605bd` | 책 수락·스마트폰 Mock 응답·정상 정리 | 215.867초, 원시 판정 `MANUAL_CLOSED_UNVERIFIED`, 정상 종료 표식 PASS·프로세스/포트 반환 확인 |

앞선 두 실패의 로그와 원시 결과는 보존했다. 종료 후 별도 프로세스·포트 조회에서 잔존하지 않음을 확인했지만, 누락된 정상 종료 확인을 PASS로 바꾸지 않는다. 마지막 원시 판정도 수동 행동을 자동 채점한 PASS로 바꾸지 않는다. 사용자 확인과 서버 상태를 위 실제 관측으로 별도 기록했다.

세 실행은 각각 새 사용자 소유 `/tmp/hearth-s4-11.*`와 독립 DB를 사용했다. 실행별 Paper 한 JVM, localhost·기존 CPU/힙/메모리·시간 한도를 유지했다. Paper 최대 RSS는 약 1.43GiB였다. 운영 환경과 이전 증거는 변경하지 않았다.

## 도구 수정·남은 범위

기존 수동 도구에 준비된 프로필의 10초 간격 읽기 전용 상태 조회를 추가했다. 선택 사항 `--manual-finish-on-logout`은 실제 접속 후 종료를 감지하면 정상 정리를 시작한다. 재접속을 이어서 시험하려는 실행에서는 이 옵션을 사용하지 않는다. 기존 TTY·인증·준비 확인과 시간 한도는 유지한다.

Java 소스와 실행 JAR은 변경하지 않았다. 실행 JAR과 현재 빌드의 SHA-256은 결과 JSON과 일치한다. 도구의 상태 조회 간격·종료 감지·비수동 옵션 거부를 제어 경계에서 검사하고 Python 구문을 확인했다. 게임 코드 변경이 없어 Gradle·기존 자동 통합을 반복하지 않았다.

이번 작업의 두 JVM 복원, 전체 NPC/퀘스트·코옵·보호 행동, GUI 드래그/전체 클릭 영역, 리소스팩 정렬, 실제 AI 서비스는 미검증이다. 기존 [수동 세션 기록](player-session-manual-test.md)과 [이전 실패 기록](npc-session-stability-verification.md)을 대체하지 않는다.
