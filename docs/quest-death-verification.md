# 전투 사망과 개인 퀘스트 실패 연결

2026-10-29 · 격리 개발 모드 · S4 진행 중.

## 변경

- [전투 Player 적용기](combat-player-verification.md)의 RPG 사망을 기존 `PersonalQuest`·`QuestStore`에 연결했다. [ADR-0006](decisions/0006-quests-dialogue-cutscenes-and-combat-revival.md)의 `DEATH` 조건이 설정된 ACTIVE 개인 퀘스트에만 적용한다. 진행 유지·제작자 체크포인트·처음부터 재시작 정책과 기존 재시작 명령/UI를 재사용한다.
- 서버가 검증한 현재 Player/세션의 연결 상태로 사망 사건을 접수하며, 일반 행동의 조작 권한은 완화하지 않는다. 사망 중 퀘스트 수락·보고·목표 진행을 허용하지 않는다. 기존 vanilla 사망 훅도 같은 저장 경로를 사용하며 전투 외 사망 정책을 새로 정의하지 않는다.
- 기존 in-flight 저장을 기다리고 최신 DB 상태/revision을 다시 읽어 같은 CAS 경로로 FAILED를 저장한다. 기존 완료/보고 대기/스킵/미수락 행은 변경하지 않는다. 아직 메모리에 열지 않은 퀘스트도 확인한다.
- 중복 사망 처리는 개인/진행별 진행 중 작업으로 합친다. 접수한 사건은 퇴장 뒤에도 저장 순서에 따라 정리하고, 그동안 새 퀘스트 세션의 변경/조회는 거부하거나 기존 갱신 장벽 뒤로 미룬다. 기존 세션에만 저장 결과를 반영하며 직접 Player 상태를 변경하지 않는다.
- 여러 퀘스트의 처리와 실패 HOLD를 월드 저장/언로드·종료 장벽에 포함한다. DB 실패/결과 불명에서 원본을 초기화하거나 성공 안내를 내지 않는다. 일부 퀘스트 저장 뒤 다음 저장이 실패할 수 있으며 여러 퀘스트 전체의 원자성은 보장하지 않는다. 해당 개인/진행의 HOLD와 확정된 DB 값을 보존한다.
- 개인 퀘스트의 실패가 보스 도전 자체를 종료시키지는 않는다. 보스 직접 필수 실패 조건은 별도 기존 경계를 유지한다. 새 저장 체계·DDL·보상·인벤토리 복구는 추가하지 않았으며 V001~V007을 보존한다. 일반 서버 자동 활성화는 없다.

실제 Paper에서는 어댑터 등록과 관리 몹, 기존 세션/DB를 사용한다. 사망 입력·관전·부활 적용은 서버 내부 제어 포트이며 가짜 Player나 합성 Player 이벤트를 실제 접속으로 취급하지 않는다. 저장 형식·복원 계약은 바꾸지 않아 두 번째 JVM 시험은 생략했다.

첫 런타임에서 새 시험 코드의 DB 응답 뒤 메인 스레드 복귀가 누락되어 `Not main thread`로 실패했다. 기존 `mainResult` 전달 경로로 수정하고 새 경로에서만 재검증했다. 실패 원시 기록은 `/tmp/hearth-s4-11.p3dj5can`에 보존한다. 이 실패에서는 풀 종료 로그 확인이 누락됐지만 두 JVM의 exit 0, 해당 PID 소멸 및 포트 반환을 별도 확인했다. 최종 통과 증거는 `/tmp/hearth-s4-11.txo9op2y`이며 총 런타임 2묶음이다. 프로세스 시작 전 소유권 표식 누락도 보완했으며 서버 데이터는 생성되지 않은 상태였다.

최종 통과 묶음 34.353초, Paper 표본 최대 RSS 1,146,876KiB·관측 CPU 59.92초, 최소 가용 RAM 12,038,088KiB. 기존 localhost·CPU2/nice+10·Xmx1536MiB·600초·메모리/디스크 한도를 유지했다.

## 미검증과 다음 범위

실제 인증 플레이어의 치명타·PlayerInventory·관전/부활·퀘스트 실패 표시·재시작 클릭은 미실행이며 사용자 별도 요청 전 보류한다. 장기 부하·강제 종료 복구·운영 배포도 미실행이다. 보스 재도전 투표·정식 전투 종료/복귀·패턴·전체 인던은 후속 기능으로 남는다.
