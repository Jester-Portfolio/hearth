# NPC·공유 진행·스마트폰 안내 통합

2026-10-28. 격리 개발 모드 전용이며 전체 S4는 진행 중이다.

## 구현한 플레이 연결

- `story-demo.yml`의 선택 항목 `guide-npcs`로 기존 NPC를 공유 진행 안내원에 연결한다. 누락 시 기존 동작을 유지하고 잘못된/중복 NPC 참조는 초기 로딩에서 거부한다. 기존 파일을 자동 덮어쓰지 않는다.
- 해당 NPC 우클릭의 기존 세션·거리·엔티티·대화 검사가 끝난 뒤 개인 퀘스트 선택과 공유 안내를 함께 표시한다. 현재 공개 공유 목표, 개인 퀘스트 목록·스마트폰 링크, 조건 확인 후 다음 진행/투표 링크를 제공한다.
- `/hearthstory guide`는 읽기 전용 안내다. 스마트폰 공동체→스토리 진행에서 채팅 안내를 열 수 있다. 투표 자체는 기존 채팅 경로이며 투표 GUI를 추가하지 않았다.
- 공유 상태 변경은 같은 run의 활성 사용자 화면을 갱신 대상으로 표시한다. 개인 퀘스트 변경도 같은 run의 진행 조건 화면 갱신을 유도하며, 개인 설정/알림 변경은 본인 갱신을 유지한다. UI가 열리지 않았다면 강제로 열지 않고 기존 주기에서 필요한 표시만 갱신한다.
- 다음 진행·투표는 기존 온라인 조건·세션·CAS·DB 확정 경로를 그대로 사용한다. 저장 대기/HOLD/결과 불명에서는 잘못된 진행 버튼을 제공하지 않는다. 미래 단계·조건 퀘스트 ID·미선택 분기를 안내에 노출하지 않는다.

## 실제 검사

- 관련 Gradle 단위·회귀 **40개 PASS**, 최종 JAR 및 실행 의존성 준비 성공. 안내 상태별 명령, 정보 비노출, NPC 참조, run별 변경 신호와 기존 퀘스트/탐험/공유 진행을 검사했다.
- 기존 도구의 `--sessions --quests --story-batch --gameplay-guide` 축소 모드를 사용해 **Paper 한 JVM/격리 PG 한 개 PASS**. 안내 NPC 연결·채팅 링크·GUI 표시·DB revision 불변, 조건/투표/탐험 개방·GUI 인벤토리 보존 및 같은 JVM의 저장/언로드/재로드를 확인했다.
- 최종 실행 37.977초, Paper 최대 표본 RSS 1,053,800KiB·관측 CPU 62.11초. 기존 자원 한도 준수, 프로세스 exit0·포트 반환·저장 장벽/풀 종료 확인. 실행 JAR과 최종 빌드 SHA-256 일치.
- 최초 실행은 새 시험 보조 콜백이 DB worker에서 메인 스레드 검사를 실행해 실패했다. 기존 `mainResult`로 전달하도록 수정했다. 실패 프로세스 exit0이지만 풀 종료 확인 누락이 있어 첫 시도는 FAIL로 보존한다. 수정 후 새 경로에서 재시험했다. 관련 변화가 없는 성공 단위 검사는 반복하지 않았다.
- [결과 요약](../verification/gameplay-guide-result.json)에 두 시도 경로·자원·해시를 기록했다. 원시 로그/JSON은 각 격리 경로에 보존한다. 기존 helper의 `new_JVM` 이름이 있는 검사 표식은 이번 실행에서 새 JVM 시험을 뜻하지 않는다.

## 남은 범위

실제 인증 플레이어의 NPC 우클릭·채팅 선택·화면 자동 갱신·GUI 클릭은 미검증이다. 내부 컨텍스트와 GUI 표시 데이터 검사를 실제 사용자 행동으로 보지 않는다. 신규 DB 스키마·저장/복원 계약 변경이 없어 두 번째 JVM은 생략했다. 기존 인벤토리/시설 안전 제한과 NPC 공통 가시성은 유지하며 보상·전투·AI·운영 배포를 구현하지 않았다.
