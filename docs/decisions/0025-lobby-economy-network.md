# ADR-0025: 로비·경제 멀티서버 네트워크 우선

- 결정일: 2026-11-18
- 사용자 결정: 스토리 모드 개발을 보류하고 **로비·경제 등을 연결하는 여러 서버 네트워크**를 먼저 구현한다.
- 구현 선택: Velocity 4.3.1 build45 + 기존 Paper 26.2/Java25, 같은 모듈형 Hearth JAR의 Paper/Velocity 진입점. 실제 운영 배치/전환 승인은 별도다.
- 관계: 스토리 B안 [ADR-0001](0001-story-world-multiworld.md)은 보존한다. 이번 네트워크는 진행별 스토리 프로세스 분리/A안 채택이 아니다. [경제 정책](0024-dedicated-economy-admission-and-currency.md)과 [저장/수동 대응](0003-inventory-performance-and-recovery.md)을 유지한다.

## 1차 구현 경계

하나의 정품 인증 프록시 → 로비 Paper → 경제 Paper의 고정 경로를 제공한다. 초기 접속은 로비에만 허용한다. 각 역할은 독립 서버 데이터 경로를 사용하며, 하나의 경제 realm에는 한 경제 백엔드만 배치한다. 경제 재고/가격/PG 잔액·개인 슬롯은 경제 백엔드가 계속 소유한다. 프록시/로비가 스토리·경제 슬롯/화폐를 복사하거나 PG에 대신 쓰지 않는다. 서버 간 인벤토리 공유·경제 샤딩/HA·운영 데이터 자동 이관은 추가하지 않는다.

로비는 검토한 기존 월드 UUID/안전 입장/WorldGuard 구역에서 탐색과 서버 선택을 제공한다. 독립 PG나 아이템 지급 없이 `/hearthserver` 메뉴를 사용한다. 기존 로비 개인 인벤토리·엔더·커서에 아이템이 있으면 원본을 비우지 않고 입장을 보류한다. 경제에서 `/lobby` 또는 같은 선택 메뉴로 복귀한다. AI·스토리 세션/퀘스트는 로비에 초기화하지 않는다.

## 인증·이동

[공식 modern forwarding 구성](https://docs.papermc.io/velocity/player-information-forwarding/)에 따라 Velocity는 online-mode 인증을 수행하고 Paper는 전달을 받는다. 백엔드 online-mode=false만으로 신뢰하지 않는다. 고정 Paper의 **실제 로드된** modern enabled/online-mode/비밀, legacy/PROXY 비활성·whitelist·localhost 바인딩을 함께 확인한다. 비밀은 독립 환경 변수로 받고 로그에 기록하지 않는다. 공개 API가 없는 부분의 고정 버전 반사 접근은 알 수 없는 구조에서 HOLD한다. 기존 직결 경제 모드는 온라인 인증을 그대로 요구한다.

현재 로비/경제의 `/hearthserver`만 저장 확인 후 이동을 요청한다. 현재 연결을 먼저 동결하고 경제의 기존 PlayerSessions 저장 장벽으로 최신 슬롯/커서/잔여 작업을 정리한 뒤 프록시로 요청한다. 진행 중 거래·채집 구역·다른 이동은 복귀 조건을 충족한 뒤 이용한다. 새로운 아이템별 DB 트랜잭션이나 통합 인벤토리 동기화는 만들지 않는다.

[Velocity 플러그인 메시지](https://docs.papermc.io/velocity/dev/plugin-messaging/)의 출처 검사를 적용한다. 앱 전용 HMAC/도메인/버전·network ID·요청 nonce·고정 출발/목적 역할과 유효 시간을 검증하고 클라이언트 발신은 전달하지 않는다. 메시지는 사용자 UUID/슬롯/잔액/주소를 받지 않으며 프록시가 실제 인증 연결을 사용한다. 서버 전환 이벤트에서 같은 연결의 단일 허가를 소비하므로 기본 `/server`, 다른 플러그인이나 메시지 경로도 소스 저장을 건너뛰지 못한다. 일반 BungeeCord 호환 채널과 무단 failover는 비활성화한다. 프록시 설정 reload/기동 당시 구성·대상 객체 교체는 접속/이동을 닫고 검토한 재시작을 요구한다. 신뢰한 설치 플러그인을 악성 운영 코드로부터 격리하는 보장은 아니다.

대상 연결 거절이 같은 요청·원래 연결에서 기한 안에 확정된 경우에만 원래 소스의 동결을 해제한다. 저장 실패/commit 불명·전송 오류·시간 초과는 HOLD/원본 보존이며 자동 재요청/재지급하지 않는다. 로그아웃·연결 교체 뒤 콜백은 새 연결을 변경하지 않는다. 재시작 중 네트워크 이동을 무손실 자동 재현하지 않으며 기존 경제 runtime 표식/저장 복구 기준을 유지한다.

## 운영·검증

기본 `network.enabled=false`를 유지한다. 생성기는 새 private 디렉터리에 설정/서로 다른 비밀/역할별 파일만 만들고 기존 월드·DB·서비스를 수정하지 않는다. 프록시/백엔드의 실제 외부 공개·포트·자원·장애 정책·컨테이너 전환은 별도 운영 승인 대상이다. [localhost와 보안 경계](https://docs.papermc.io/velocity/security/)를 따르며 현재 구현이 기존 방화벽/SSH/터널을 변경하지 않는다.

순수 프로토콜·상태/재전송·저장 경계를 단위로, 실제 Paper/Velocity 로드와 격리 PG 저장/실패/원본 보존을 함께 검사한다. 실제 정품 접속·로비 클릭·서버 이동과 끊김/재접속은 별도 사용자 요청 전 보류한다. [사용법](../../infrastructure/network/README.md)과 관련 검증 기록에서 구현/자동/실제 수용을 구분한다.
