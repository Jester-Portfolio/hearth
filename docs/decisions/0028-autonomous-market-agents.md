# ADR-0028: 시장 자동 운영과 경제 에이전트

- 작성일: 2026-11-18
- 상태: 사용자 자동 시장 요청·경제 에이전트 선택에 따른 구현 결정
- 범위: 일반 생존 경제의 생산·소비·운송 자동 틱에 연결. 스토리 개발과 운영 적용은 별도다.

## 목적과 선택

기존 경제 엔진의 생산·소비·가격·지연 운송은 자동 실행되지만 운송량은 고정이었다. 현지 재료를 고갈시키거나 이미 충분한 목적지에 계속 출하하는 일을 줄이기 위해 재고·수요를 판단하는 경제 에이전트를 추가한다. 사용자가 **경제 에이전트만 사용**을 선택했으므로 기본 운영은 외부 모델 없이 결정적 알고리즘으로 수행한다.

고정 출하량 유지, 별도 경제 플러그인, LLM의 자유로운 시장 조작도 검토했다. 기존 엔진·PG 거래/소유권 경계를 재사용하는 자체 에이전트가 추가 플러그인 없이 같은 틱의 재고·운송을 계산할 수 있다. LLM은 별도 승인한 격리 검증용 선택 연동으로 남기며 기본 실행에 필요하지 않다.

## 자동 운영

1. 기존 틱 순서인 도착 → 생산/재료 소비 → 지역 소비 → 출하 → 가격 갱신을 유지한다.
2. 운송 에이전트는 목적지 목표 재고와 소비/생산 투입량에서 현재 재고와 도착 예정량을 뺀 부족량만 요청한다. 출발지에는 목표 재고의 정책별 비율과 현지 소비/생산 재료 중 큰 수량을 남긴다.
3. 제한된 출하량을 같은 출발지 경로들의 요청 비율로 배분하고 정수 잔여량의 우선순위는 틱마다 순환한다. 여러 공급자도 목적지의 같은 남은 부족량을 공유한다. 등록 경로별 최대량·지연·차단 사건을 따른다.
4. 운영 에이전트는 공급지 부족 시 `CONSERVE`, 목적지 부족과 가동 경로가 있으면 `RESTOCK`, 나머지는 `BALANCED`를 선택한다. 기본 12개 **경제 틱**마다 평가하고 같은 후보 2회·최소 유지 24틱을 만족해야 전환한다. 서버의 Minecraft 틱 단위와 다르다.
5. 기존 생산 용량·재료 제약, 수급 기반 EMA 가격·틱별 가격 상한·매매 스프레드·대량 견적/즉시 왕복 방어를 유지한다. 에이전트가 잔액·플레이어 아이템·가격을 직접 설정하지 않는다. 사건은 기존 등록/관리 경로를 사용하며 임의 사건을 생성하지 않는다.

## 저장·장애 경계

E007은 native realm에만 연결하는 컨트롤러와 모드 전환 이력을 추가한다. 정책 해시·틱·현재 모드·유지 시작·후보/연속 횟수·revision을 재고/출하/수급/경제 시계와 **같은 PG 트랜잭션**에 기록한다. realm 잠금과 CAS로 동일 틱을 중복 적용하지 않는다. SQL 실패는 전체 롤백, commit 불명은 기존 런타임 HOLD/원본 보존 경계를 따른다.

로컬 `market-automation.properties`는 realm/정책 해시를 고정한다. 신규 컨트롤러는 별도 명시 설정이 있어야 생성한다. 기존 정책/시계 불일치·컨트롤러 누락·초기화 후 자동 운영 해제는 기동을 거부하며 자동 초기화/정책 덮어쓰기하지 않는다. 경제 realm은 단일 backend가 소유한다. 오프라인은 기존 `PAUSE`를 유지하고 재시작 때 모드/후보 횟수를 복원한다. 기존 RPG realm과 native 인벤토리/거래 저장 경계는 그대로 유지한다.

## 선택형 LLM의 한정된 경계

기본 `ai-mode: none`이며 사용자 선택에 맞는 실제 운영 경로다. 선택형 Ollama는 기존 고정 버전/모델·명시적 준비를 재사용하고 시장의 집계 숫자와 서버가 허용한 모드만 받는다. JSON Schema의 `mode` 하나를 검증하고 최신 후보·정책 해시·틱 유효기간을 PG 계산에서 다시 확인한다. [Ollama 공식 API](https://docs.ollama.com/api/generate)의 `format` 계약을 이용하되 고정 런타임의 실제 성공 여부는 별도 검증 기록으로 판단한다.

개인 식별자/위치/계정/스토리·명령 권한을 전달하지 않는다. 요청은 하나씩, 최소 12경제 틱 간격·질의 6초이며 틱은 응답을 기다리지 않는다. 준비 안 됨·거부·시간 초과·오래된 제안은 규칙으로 계속 운영한다. LLM 설정은 경제 정책 해시에 포함하지 않아 제거해도 상태를 초기화하지 않는다. 제품에서 모델 서버를 자동 시작·다운로드·준비하지 않는다.

[검증 기록](../market-automation-verification.md)과 [설정/관리](../../infrastructure/network/market-automation.md)를 따른다. 실제 플레이·장기 수급/화폐량·콘텐츠 수치/밸런스·운영 배포는 별도 수용 대상이다. 운영 적용에는 백업과 정상 drain, 기존 서비스 변경 승인·롤백 검토가 필요하며 이번 구현으로 운영 환경을 변경하지 않는다.
