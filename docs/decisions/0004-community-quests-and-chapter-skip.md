# ADR-0004: 공동체 코옵·스토리 퀘스트·장별 따라잡기와 스킵

## 배경과 선택

기존 S3의 파티 모델과 퀘스트 공통 단계 표현은 개인 따라잡기와 공동 분기의 경계를 충분히 구분하지 못했습니다. 사용자 결정에 따라 일반 파티의 탈퇴·분할·병합 모델 대신 지속되는 공동체의 공유 세계와 개인 진행을 구분합니다. 다른 운영 모델이나 추가 기능을 채택하지 않습니다.

## 확정 정책

1. 코옵은 일반 RPG 파티가 아닌 **공동체(Community)**입니다. 구성원은 같은 `story_run_id`, 월드, 세계 변화와 주요 스토리 결과를 공유합니다. 싱글의 독립 진행은 유지합니다. 게임 내 파티 탈퇴 시스템은 구현하지 않습니다. 게임 내 가입·탈퇴·초대·추방·파티장/권한 관리 기능은 없습니다. 서버 내부 player_uuid–story_run_id 연결만 구분합니다.
2. 개인 인벤토리·개인 퀘스트 완료·개인 보상 기록은 플레이어별로 구분합니다. 개인 퀘스트 진행은 공동체 ID와 플레이어 UUID로 구분하며 일반 길목·서브 퀘스트는 독립 진행할 수 있습니다. A의 완료로 B를 자동 완료하지 않습니다.
3. 중요 메인 퀘스트·스토리 분기점은 공동체 진행입니다. **당시 접속 중인 공동체 구성원 전원**이 진행 조건을 충족해야 합니다. 한 명이라도 미충족이면 진행할 수 없고, 비접속 구성원은 검사에서 제외합니다. 모든 구성원의 동시 접속을 요구하지 않습니다. 추가 접속 시 현재 전투·컷신·퀘스트 단계를 강제로 중단하지 않습니다. 다음 중요 진행 단계 진입 시 현재 접속 구성원 전원의 조건을 다시 확인하고, 미충족자가 있으면 다음 단계만 차단합니다. 기존 완료 단계는 되돌리지 않습니다. 세부 단계 경계와 접속·종료 경합 처리는 추후 구현 설계 대상입니다.
4. 한번 확정한 분기는 공동체의 고정 결과입니다. 이후 같은 진행을 경험하는 개인의 따라잡기는 이미 선택한 분기 라인만 진행합니다. 완료자는 다른 구성원의 과거 퀘스트를 지원할 수 있습니다. 재진행·지원·스킵은 분기·NPC 상태·세계 변화를 되돌리거나 다시 적용하거나 덮어쓰지 않습니다.
5. 공동체가 이미 진행한 장을 놓친 개인은 **장마다 직접 플레이 또는 스킵**을 독립적으로 선택합니다. 장 스킵은 해당 장의 메인 퀘스트와 그 장 진행에 필요한 길목 퀘스트를 함께 스킵하고, 다음 장의 개인 선행 조건을 충족한 것으로 처리합니다. 일반 서브 퀘스트는 필수 길목과 구분하며 일괄 스킵 대상으로 확정하지 않습니다. 따라잡기·스킵은 개인 상태만 변경하며 공동체 분기·월드 상태를 변경하지 않습니다.

## 중요 분기 투표 — 추가 확정 (2026-10-23)

- 중요 퀘스트 진행 조건을 충족한 상황에서 현재 접속 중인 공동체 구성원들이 과반수 투표로 중요 분기를 선택합니다.
- 과반수는 **전체 대상 인원의 50% 초과**입니다. 유효 투표 수만으로 분모를 임의로 줄이지 않습니다. 과반수 선택지가 없거나 동률이면 확정하지 않고 재투표합니다.
- 한 명만 접속 중이고 조건을 충족했다면 그 구성원이 선택할 수 있습니다.
- 한번 확정한 분기는 변경할 수 없고 뒤늦게 합류한 구성원도 따릅니다.
- 기권/미투표는 찬성이 아니고, 초기 30초 채팅 투표·중복 차단·미확정 대상 변경 시 취소/새 대상 재투표를 적용합니다. 이미 확정한 결과는 보존합니다(ADR-0011).

보상 지급 로직과 설정 데이터를 분리하는 설계 원칙은 [S3 보상 설계](../story-world-detailed-design.md#보상-로직과-설정-분리--확정-원칙)를 따릅니다. 스킵·재참여 보상 밸런싱은 보류하며 ADR-0003의 중복 방지·지급 상태 즉시 저장을 유지합니다.

## 미정 정책

- 스킵 시 보상 지급·감소 여부 및 비율.
- 이미 완료한 사람의 재참여 보상.
- 게임 내 가입/탈퇴/추방/파티장과 관리자 관리 UI는 요구하지 않음. 내부 식별 연결 형식만 구현 후보.
- 중요 진행의 세부 단계 경계 및 접속·종료 경합 처리.
- 투표 입력 구문·마감/commit 경합 구현은 후속 설계. 시간/기권/대상 변경 정책은 ADR-0011로 확정.
- 과거 퀘스트를 다시 플레이할 때 필요한 인스턴스·연출·NPC 처리 방법.

## 기존 설계와의 관계 및 영향

기존 `party_id`, `party_member`, 파티장·탈퇴·분할·병합 후보는 현행 공동체 설계의 확정 스키마나 구현 요구사항이 아닙니다. 게임 내 파티 탈퇴 후보는 철회하며, 파티장 권한·분할·병합도 구현 범위로 승계하지 않습니다. 공동체 ID와 `story_run_id`의 물리 키 관계·내부 식별 연결의 물리 키는 미정으로 두고 대체 DDL을 채택하지 않습니다. 과거 비교·구현 가능성 문서의 파티 표현은 당시 검토 이력이며 이 ADR이 현재 정책을 우선합니다.

공동체 주요 진행, 개인 완료, 장 스킵·선행 조건 충족, 개인 보상을 구별해야 합니다. 스킵을 실제 플레이 완료나 보상 지급으로 자동 해석하지 않습니다. 공동체 중요 퀘스트의 조건 충족은 모든 개인 퀘스트의 자동 완료를 뜻하지 않습니다. 공유 세계의 과거 장면 재현 방법은 미정이므로 문서 승인만으로 플레이 구현 가능성을 검증했다고 보지 않습니다.

## 후속 검증과 운영 범위

[S3 상세 설계](../story-world-detailed-design.md)의 공동체 모델과 C1~C13 시나리오를 구현 이전 시험 명세로 사용합니다. 모두 미실행이며 단계 경계·접속/종료 경합·투표 상세·보상·과거 재현 방법은 확정 후 시험 기대값을 보완합니다. S3는 진행 중으로 유지합니다. 실제 게임 코드·서버·DB·컨테이너 실행이나 기존 운영 설정 변경은 범위 밖입니다.
