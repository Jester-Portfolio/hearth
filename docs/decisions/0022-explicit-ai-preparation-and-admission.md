# ADR-0022: 명시적 AI 준비와 사용자 요청 진입

- 결정일: 2026-11-17
- 상태: 승인된 S5 연결 보완의 구현·내부 검사 및 사용자가 별도 승인한 새 1회 콜드 시험 통과. 첫 시간 초과 원본은 보존한다. 운영 배포/상시 실행 예산 승인이 아니다.
- 관계: [ADR-0018](0018-local-ai-runtime-and-trial-budget.md)의 고정 모델·첫 준비/질의 분리·한도, [ADR-0021](0021-science-reading-and-reference-questions.md)의 공개 노트·자료 표시를 유지한다.

## 결정

일반 질의의 6초(화면 작업 8초) 한도를 초기 모델 로딩 때문에 연장하지 않는다. 고정 버전/모델 manifest를 확인한 뒤 `/api/ps`의 적재 모델/컨텍스트를 검사한다. 같은 어댑터에서 초기 연산까지 준비를 완료한 표식이 없거나 모델이 내려갔으면 질문을 보내지 않고 `NOT_READY`로 초안을 유지한다. 적재 모델이 여러 개/다른 모델·digest/컨텍스트이면 상태 불일치로 거부하고 강제 해제/재구성하지 않는다.

`hearthai prepare`는 정확한 서버 콘솔 요청에서만 실행한다. 기존 `hearthai status`는 계속 집계 조회만 하며 준비/로딩을 시작하지 않는다. `mock`/text/plain에는 준비를 자동 적용하지 않는다. 준비가 시작되면 다른 준비/일반 질의/캐시 확인을 섞지 않고, 기존 사용자 작업이 있으면 준비를 거부한다. 단일 준비의 전체 기한과 준비 POST는 최대 90초, 메타 조회/일반 질의 HTTP는 기존 한도를 유지한다. 같은 HTTP 클라이언트의 4개 상한·2스레드/큐·본문 8192바이트·origin/redirect/종료 경계를 재사용한다.

빈 프롬프트로 가중치를 적재하는 것만으로는 첫 질의의 초기 연산이 끝나지 않음을 실제로 관측했다. 최종 준비는 개인/게임 정보가 없는 고정 지렛대 과학 노트/질문으로 기존 4096/128토큰·2스레드·60초 keep-alive의 정상 연산을 수행한다. 정상 완료/자료 표시 검증 뒤 적재/버전/manifest를 다시 확인해 해당 준비 작업의 성공 Future를 표식으로 사용한다. 실패/취소된 준비는 적재 목록에 모델이 보이더라도 준비 완료로 인정하지 않는다. 준비 답변은 사용자 대화/캐시/개인 저장에 넣지 않는다.

적재 해제 관측 시 표식을 잊으며, 같은 어댑터의 준비가 확인된 상태에서는 명시적 재확인 때 추가 예열을 반복하지 않는다. keep-alive 자동 연장·자동 준비/질의 재시도·모델 설치/교체·새 서버/서비스 실행·도구 실행 권한을 추가하지 않는다. 캐시 확인은 기존 현재 버전/manifest와 게임/세션 권한을 확인하며, 새 추론이 필요 없는 유한 캐시는 모델이 내려가 있어도 사용할 수 있다.

준비는 `PREPARATION` 집계로 사용자 생성/캐시 확인과 분리한다. 질문/답변/주소·예외 원문을 콘솔에 기록하지 않는다. 기본 Mock/비활성·운영 미적용을 유지한다. [구현·첫 실패·재시험 경계](../s5-ai-preparation-verification.md)를 따른다.
