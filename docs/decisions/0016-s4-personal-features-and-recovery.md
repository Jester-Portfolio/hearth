# ADR-0016: S4 개인 장면·시설·스마트폰·전투 복귀 정책

- 작성일: 2026-11-09
- 상태: 승인 — 이번 작업에서 사용자가 제안 정책 및 전투 복구 기준을 직접 선택했다.
- 관계: ADR-0003·0006·0008·0009·0010·0012의 미정 세부 정책을 아래 범위에서 확정한다. 기존 격리·성능 우선·수동 장애 대응 경계는 유지한다.

## 결정

1. 컷신은 개인 최초 시청을 끝까지 완료해야 한다. 중단·종료는 완료가 아니며 다음에도 필수다. 재도전 횟수는 서버가 시작 저장을 확정한 때만 증가한다. 최초 완료 뒤 계속 시청하면 다음에도 선택할 수 있고, 명시적으로 건너뛰면 이후 재도전에도 적용한다. 과거 장면 재시청은 별도 읽기 전용 경로이며 개인 퀘스트·장·공유 진행·보상을 다시 적용하지 않는다. 이번 공개 콘텐츠는 책의 프레임과 이동/시선 잠금으로 표현하며 다른 플레이어는 정지시키지 않는다.
2. 거점 이동은 양쪽 모두 본인이 직접 방문해 해금한 거점의 시설에서만 무료·즉시 허용한다. 전투 중 금지한다. 접근 권한·세션·월드 세대와 최신 인벤토리 저장을 먼저 확인한다.
3. 개인 엔더 보관함은 진행/개인별 PG 27칸이다. 일반 인벤토리 41칸과 같은 dirty 저장 순서에서 원자적으로 저장한다. 순정 전역 엔더 데이터는 읽거나 가져오거나 지우지 않는다. 일반 가공·자동화·설치된 셜커 보관함은 Minecraft 월드 저장 책임과 WorldGuard 보호를 따른다. 월드 파일과 개인 PG 전체의 원자성은 요구하지 않는다.
4. 최초 정상 접속에 빈 보관 슬롯이 있으면 개인/진행에 묶인 스마트폰 하나를 발급 표시와 함께 저장한 뒤 적용한다. 공간이 없으면 보류한다. 버리기·보관함 이동·제작 투입·타인 사용은 차단한다. 발급 이력이 있으면 자동 재지급하지 않는다. 명시적 재발급 요청에서도 본인 최신 저장 인벤토리의 부재와 빈 공간을 확인한다. 기존 아이템은 덮어쓰지 않는다.
5. 전투 프로세스 재시작에서는 확정된 종료/복귀 대기를 영속 보존해 이어간다. 진행 중인 전투와 이동 결과가 불명인 기록은 HOLD로 보존한다. 활성 전투의 몹·HP·패턴 시간이나 불명 이동을 자동 재생성/재실행하지 않는다. 복귀는 저장→단일 claim→안전 위치 이동/회복→DONE이며 어느 단계의 불명 결과도 새 claim으로 재시도하지 않는다. 오프라인 승리/보상의 자동 재지급을 이 기록에서 유추하지 않는다. 영속 상태가 없는 기존 필드 조우 표식은 재시작 뒤 그대로 유지하고 조우 모듈만 HOLD해 자동 재소환/리셋을 막는다.

## 근거와 대안

전역 엔더 저장을 재사용하면 진행 격리를 깨고, 매 클릭마다 전체 저장소를 동기화하면 ADR-0003의 성능 경계를 벗어난다. 개인 27칸을 기존 비동기 저장에 함께 묶는다. 전투의 완전 무손실 재현 대신 시작/종료/복귀 경계만 저장해 수동 확인에 필요한 상태를 남긴다. 지급 표시와 아이템은 하나의 트랜잭션으로 확정해 중복 발급을 막는다.

## 구현·검증·운영 경계

V010의 `personal_feature`는 서버 발급 문맥의 소유권/FK와 revision CAS를 사용한다. 기존 행·월드·순정 엔더 데이터의 자동 변환은 없다. 확정 실패·commit 불명·stale 상태는 원본/HOLD를 유지하며 메인 스레드에서 DB를 기다리지 않는다.

같은 JVM에서 정상 IDLE 언로드한 필드 조우는 프로세스 재시작과 구분한다. 같은 물리 월드의 새 세대에 재연결하되 완료 기록은 유지하고, 정상 정리한 미완료 구간도 자동 재소환하지 않는다. 기존 콘텐츠의 명시적 구간 리셋과 최신 저장 장벽이 성공해야 해당 구간만 다시 시작할 수 있다. 정리 실패·세대 불일치·종료된 모듈과 재시작 표식은 HOLD/종료를 유지한다. [실제 시험 제외 보완 검증](../s4-offline-completion-verification.md)에 구현 경계를 기록한다.

상세 증거와 실제 행동 미검증은 [S4 개인 기능 통합 검증](../s4-features-verification.md)에 기록한다. 지도는 공개/발견/접근 필터와 로드된 청크를 사용하고, 미니맵 Glyph 오버레이와 퀘스트 sidebar는 개발 표시다. ADR-0010의 정확한 상단 좌우 배치·GUI 배율·가독성·채널 공존은 실제 클라이언트 검증이 필요하다. 이 결정은 운영 배포·재시작·데이터 조정 승인이나 S5~S7 완료를 뜻하지 않는다.
