# ADR-0032: 자체 설정형 인챈트와 native 거래 경계

- 날짜: 2026-11-20
- 상태: 사용자 자체 이식 요청에 따른 구현 결정. 자동 검증 완료, 실제 클라이언트·부하·운영 수용 별도.
- 근거: [구현/검증](../enchant-system-verification.md), [105종 대응표](../enchant-port-map.md), [운영 가이드](../../infrastructure/network/enchants.md).

## 문제·대안

CrazyEnchantments 전체 효과를 Hearth의 WG·입장·전투·사망·보상과 통합하고 같은 YAML/GUI에서 관리해야 한다. 외부 CE 실행 의존은 사용자 요구와 맞지 않고, 원본을 통째로 포크하면 메뉴/획득처·Factions·저장 등 불필요한 결합과 정책 충돌이 남는다.

## 결정

1. MIT 고정 소스 105종을 안정 `hearth:ce_*` ID와 설정 규칙으로 대응하고 32개 자체 Java 효과 모듈로 실행한다. 원본 저작권/라이선스와 개별 대응·적응 근거를 보존한다. 부위·레벨·확률은 예제이며 향후 밸런싱한다.
2. YAML을 불변 카탈로그로 컴파일하고 장착 ID/해당 트리거만 조회한다. 조건/확률/쿨다운/지속/효과 인자는 제한된 수식을 사용한다. 신규 효과는 공개 Java 확장 등록을 사용하며 임의 스크립트/명령 실행은 제공하지 않는다.
3. 안정 PDC ID/버전은 아이템 자체가, 비용/고정 난수/영수증/그림자 CAS와 복원 쿨다운은 기존 PostgreSQL이 소유한다. 적용·합성·회수·감정·관리 지급은 기존 NativeTransactions 저널/세션/HOLD 경계에 결합한다. 별도 escrow/아이템별 상시 PG 트랜잭션을 만들지 않는다.
4. GUI는 동일 YAML을 편집하고 후보를 검증한 뒤 원자 공개한다. 비활성/최대 레벨 변경/불명 ID로 기존 아이템을 삭제하거나 자동 재지급하지 않는다. 전체 리로드 실패는 이전 세대를 유지한다.
5. Aura는 기존 공식 API·저장 구성을 유지한다. 자체 스탯 modifier와 포션/비행 소유권을 분리하고 WorldGuard·거주·PvP·공통 접근/전투/RewardCoordinator·사망 정책을 먼저 따른다. 충돌 효과는 삭제 대신 비활성/정책 재구성한다. 미래 자동 판매는 최종 수집 알림/action ID 경계를 사용한다.

## 결과·수용 경계

자체 이식은 원본 신규 버전에 자동 추종하지 않는다. 고정 checkout에서 importer로 새 후보를 만든 뒤 대응/효과·정책 변화만 검토한다. 105종 구현 대응률과 실제 플레이 검증률을 분리한다. 기존 성능 우선·수동 장애 복구 정책을 유지하며 unclean 상황의 무손실 자동 복구를 보장하지 않는다.

기본 비활성·운영 변경 없음. 실제 클라이언트·다인/부하·밸런스·획득처·운영 승인은 후속이다. 배포 전 일관 백업·정상 drain·격리 복구·이전 JAR/설정으로의 롤백 준비가 필요하다.
