# ADR-0038: 실제 물품 거래와 사망·거주 비동기 파일 경계

- 날짜: 2026-11-25
- 상태: 승인된 보완 범위의 구현 선택. 운영 미적용.
- 관련: [ADR-0003](0003-inventory-performance-and-recovery.md), [검증](../economy-followup-verification.md).

native `/거래`는 기존 상품/화폐에 더해 실제 가방 슬롯·수량·고정 원본 바이트 SHA를 제안한다. 원본은 escrow로 이동하지 않고 화면에는 복사본만 표시한다. NBT의 직렬화 표기 차이를 물품 변경으로 오판하지 않도록 고정 바이트의 SHA는 제안/영수증에, Paper의 정규화된 ItemStack 내용 동등성은 현재 물품 검증에 사용한다. 두 계정의 기존 PG 거래·revision CAS·동시 확인과 native 저널을 재사용하며 책·강화·외부 메타데이터를 재구성하지 않는다. legacy 상품-only API를 metadata 교환으로 자동 해석하지 않는다.

사망에서는 커서/작업대 입력까지 native 슬롯에 보관 가능한 원본을 먼저 저장하고, worker가 원본·pending을 영속화한 후 owner 스레드에서 최신 생명 세대/월드·인벤토리·Aura 상태를 확인한다. 결과 native 저장 이후에만 예정 드랍/XP를 공개한다. 작업 도중 이동·인벤토리·재접속과 리스폰 후 경제 admission은 같은 완료 경계를 따른다. 원본 보관 공간이 부족하면 전체 작업대/커서 원본을 worker에 보존하고 개인 HOLD·퇴장으로 전환한다. 취소된 사망이 반복 가능한 무적 상태가 되지 않게 하며 자동 재지급하지 않는다. Bukkit 인벤토리/월드 및 native save는 메인 스레드 계약을 유지한다.

사망 정리는 완료 의도 `.done`을 먼저 공개한 뒤 pending/preimage를 제거한다. 중단된 완료 정리는 다음 실행에서 효과 재실행 없이 마무리한다. 독립 preimage·서로 다른 pending/done·불명 결과는 원본을 유지하고 개인 HOLD로 분류한다. 자동 재지급/확률 재판정·고비용 자동 무손실 복구는 추가하지 않는다.

거주 메타파일은 순서 보장 worker, 월드/청크·WG 적용은 owner 스레드를 사용한다. idle 언로드 실패는 해당 월드만 제한적으로 재시도하고 세 번 실패 후 명시적 재시도를 요구한다. 전역 작업 중지나 영속 파일 삭제로 실패를 숨기지 않는다.

종료는 사망 원본/결과 확정→거주 퇴장/언로드 순서로 진행하며, 종료 준비/전역 RPG HOLD에서는 새 native 작업을 시작하지 않는다.
