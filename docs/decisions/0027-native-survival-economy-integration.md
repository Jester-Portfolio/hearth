# ADR-0027: 기존 경제 엔진의 일반 생존 연결

- 날짜: 2026-11-18
- 사용자 결정: 일반 생존 멀티서버에 기존 RPG 프로젝트에서 개발하던 경제 시스템도 넣는다.
- 관계: [3월드 생존](0026-vanilla-survival-world-selection.md)·[로비 네트워크](0025-lobby-economy-network.md)를 유지하며, [기존 경제 엔진](0015-economy-engine-and-transaction-boundaries.md)·[PG 화폐/잔액 0/PAUSE](0024-dedicated-economy-admission-and-currency.md)를 재사용한다. 스토리 추가 개발은 재개하지 않는다.

후속 사용자 결정인 [ADR-0029](0029-single-spawn-shops.md)가 일반 생존의 상점 진입/단일 스폰 정책을 대체한다. 아래 근거리/지역별 진입은 당시 구현 이력이며 PG/native 거래 안전성은 유지한다.

## 연결 범위

같은 경제 Paper의 거주·야생·지옥은 하나의 경제 realm/PG 잔액을 쓴다. `survival-economy.enabled`로 명시한 새 연결에서 지역별 생산·소비·투입 재료 제련·지연 운송·재고·수급/EMA 가격·등록 사건을 기존 EconomyEngine/EconomyStore로 처리한다. `/경제`, `/돈`, 근거리 NPC 상점/`/상점 <ID>`, `/거래`의 양쪽 제안/최종 확인을 연결한다. 시장·시설·운송·사건·상품 공급망/안내와 본인 거래 기록도 기존 공개 DTO/조회 규칙을 재사용한다. 일반 상자 상점/Vault/QuickShop·외부 화폐 플러그인은 추가하지 않는다.

상인은 콘텐츠의 월드 역할/좌표/상품을 사용하며 기본 역할은 거주다. 준비된 청크·안전 지점에서만 비영속 Villager를 생성한다. 실제 NPC 객체·같은 접속/화면·거리·취급 상품·시세 revision을 확인한 뒤 거래한다. 상인 교체/청크 언로드와 늦은 조회는 이전 화면을 무효화한다. 개인 거래는 같은 월드에서 6블록 이내의 두 활성 계정, 같은 최종 제안 revision에 대한 양쪽 확인을 요구한다. 기존 3분 만료·제안 수정 시 양쪽 동의 취소·등록 일반 상품/PG 화폐 규칙을 유지한다.

## native 인벤토리와 PG 거래

일반 생존의 아이템·엔더·경험치·체력·사망/드롭 정본은 계속 native Minecraft다. 입장 때 잔액 0의 PG 계정을 확보하지만 **PG payload를 플레이어에게 적용하지 않는다.** 기존 RPG PG realm/개인 인벤토리·스토리 데이터는 자동 이전하지 않는다. E006은 native realm을 생존 group/세 월드 식별자 해시에 묶으며, 기존 RPG realm/다른 묶음·일반 economy 런타임과의 혼용을 거부한다. 로컬 연결 기록이 있으면 PG realm이 없어도 새로 만들지 않는다.

거래는 현재 접속/생명 상태를 잠시 보호하고 빈 커서·최신 41슬롯을 확인한다. 작은 보류 표식과 native 저장 확인 뒤 최신 슬롯을 PG account.payload 그림자에 CAS로 저장하고, 기존 PG 트랜잭션에서 상품/재고·잔액·거래 기록을 한 번에 반영한다. 양쪽 개인 거래도 기존 단일 PG 거래를 사용한다. 모든 결과 payload 검증을 마친 뒤 같은 접속/원본 슬롯일 때만 메모리에 적용하고 native 저장 확인 후 표식을 정리한다. 평상시 클릭/채집마다 PG에 저장하지 않는다.

그림자 payload는 거래 검증/수동 진단용이다. 재접속/사망/재시작 때 이를 자동 복원하거나 영수증을 아이템 재지급 근거로 쓰지 않는다. 별도 재고 escrow·아이템 전체 원장·파일/DB 일체형 체크포인트를 추가하지 않는다. [성능 우선/수동 장애 대응](0003-inventory-performance-and-recovery.md)의 완전 자동 무손실 복구 제외 원칙을 유지한다. native 파일/PG/메모리는 하나의 원자적 저장소가 아니다.

확정된 잔액/재고/시세/용량 거부는 같은 원본을 확인한 뒤 해제한다. 거래 시작 전 커서/준비 실패는 금융 작업 없이 확정 거부한다. SQL 실패·CAS 충돌·commit 불명·사망/접속 종료·늦은 결과·적용/저장 실패·시간 초과는 HOLD/원본·영수증·작은 요청 표식을 보존한다. 자동 재제출/복원/재지급하지 않는다. 재시작 후 보류 계정은 입장을 차단하며 다른 정상 계정은 준비된 경제를 사용할 수 있다.

## 기동·종료·운영 경계

기본 연결/새 realm 생성은 비활성이다. 검토한 새 realm에만 명시적으로 연결하고 기존 콘텐츠 해시·월드/DB 연결 기록을 보존한다. 비정상 종료의 active 표식은 자동 삭제하지 않는다. 정상 종료는 거래 worker 정산을 확인하고 스케줄러를 닫은 뒤 native 플레이어 종료·PG 종료·active 표식 정리 순서로 drain한다. 결과가 확정된 HOLD 요청 표식은 정상 drain 뒤에도 남겨 재시작 시 자동 지급을 막는다. 오프라인은 PAUSE이며 경과 시간 생산 보정은 하지 않는다.

하나의 realm에는 한 경제 backend만 둔다. 프록시/로비로 인벤토리·잔액을 복사하지 않는다. 거래/계정 준비/개인 거래 제안 중에는 월드/로비 이동을 시작하지 않고, 완료 뒤 기존 native 저장 확인/서명 전환을 이용한다. 실제 정품 계정과 부하 수용, 콘텐츠 수치/상인 배치·거주지 소유/보호·야생 리셋·운영 배포는 별도 범위다. [검증 기록](../native-economy-verification.md)과 [설정/사용법](../../infrastructure/network/native-economy.md)을 따른다.
