# ADR-0024: 경제 전용 실행·PG 잔액·정상 계정 진입

- 결정일: 2026-11-17
- 상태: 승인 — 사용자가 경제 전용 실행 모드·PG 잔액 화폐·새 계정 잔액 0·오프라인 PAUSE 제안을 선택함
- 관계: [ADR-0015](0015-economy-engine-and-transaction-boundaries.md)의 엔진/거래/격리는 유지하고 정상 계정·화폐/오프라인 미정 항목을 구체화함. [ADR-0003](0003-inventory-performance-and-recovery.md)의 비동기 저장·수동 장애 대응 유지

## 결정

같은 내부 모듈형 JAR에 기본 비활성 `runtime-mode: economy`를 제공한다. 스토리 세션/시험 모듈과 함께 플레이어 이벤트를 처리하지 않는다. 경제 모드는 로컬 AI/스마트폰 없이 동작한다. 실제 배포 프로세스/컨테이너·볼륨·자원 배정과 운영 적용은 별도 결정/승인한다.

화폐 정본은 `hearth_economy.account`의 정수 PG 잔액이다. 화폐 아이템을 새로 발급하지 않는다. 새 정상 계정은 잔액 0·빈 41슬롯으로 저장한 뒤 입장한다. 최초 접속/재접속 경합은 한 행만 만들고 기존 잔액·인벤토리/revision과 거래 기록을 덮어쓰지 않는다. 기존 데이터의 자동 이전/초기화·개발 fixture 자산 지급은 하지 않는다.

경제 전용 식별자가 기존 인벤토리 소유권과 맞아야 한다. 소유자가 확인되지 않은 비어 있지 않은 인벤토리나 다른 realm 표식은 보류한다. 소유 표식이 있지만 DB 계정이 없고 아이템이 남은 경우 빈 계정을 만들어 덮지 않는다. PG 준비 실패/commit 불명·늦은 콜백은 정상 입장으로 표시하지 않는다. 본인/진행/경제 저장 분리는 유지한다.

경제 오프라인 진행은 PAUSE로 정한다. 재기동 때 경과 시간만큼 생산/소비·운송/가격 Tick을 보정하지 않는다. 엔진의 별도 개발 `CATCH_UP_CAPPED` 검증 기능을 운영 기본으로 활성화하지 않는다. 기존 realm 내용 해시가 맞지 않으면 데이터를 초기화하거나 새 설정으로 조용히 바꾸지 않는다.

정상 실행은 명시한 기존 경제 차원·UUID·소유권과 WorldGuard 보호 규칙을 확인한 뒤 사용한다. 새 빈 월드/바닥/보호 구역을 자동 생성하지 않는다. 자원 채집/블록 조작은 같은 경제 월드의 준비 세션과 기존 WorldGuard 허가에 묶는다. 콘텐츠 좌표·시설·재고·가격/수요·생산/운송·Tick 주기/밸런스는 제작 설정으로 남긴다.

관리자는 명시적인 비동기 drain으로 거래/인벤토리·월드/보호 저장과 PG 종료를 확인한 뒤 서버를 중단한다. 완료 전 실행 표식은 유지하고, 비정상 종료/변경된 표식은 다음 기동에서 접속 HOLD로 보존한다. 원본/영수증을 읽고 수동 검토하며 자동 지급/차감/재확정이나 HOLD 일괄 해제를 하지 않는다. 운영 중지·복원·설정 변경은 별도 명시 승인 경계를 유지한다.

## 검증과 한계

관련 단위와 격리 PG의 정상 계정·경합/실패·기존 데이터 보존, 두 JVM의 기존 차원/계정 복원·일반 모드 기동/종료를 확인한다. 제어 포트는 실제 로그인/이동·상인 클릭을 대체하지 않는다. 운영 배포·자원/부하 수용·스토리↔경제 전환·관리자 데이터 보정이나 전체 E1~E3 완료를 이 결정으로 승인하지 않는다.
