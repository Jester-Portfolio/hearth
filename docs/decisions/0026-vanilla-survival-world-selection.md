# ADR-0026: 일반 생존 기반 경제 서버와 거주·야생·지옥 선택

- 날짜: 2026-11-18
- 사용자 결정: 스토리 개발을 보류하고 경제 기반 멀티서버를 일반 Minecraft 기준으로 시작한다. 거주·야생·지옥 월드를 나누고 명령어로 인벤토리 선택창을 연다.
- 구현 선택: [ADR-0025](0025-lobby-economy-network.md)의 별도 로비 + 경제 Paper 구성을 유지하고, 경제 Paper 내부에 3개 Bukkit 월드를 둔다. 세 월드를 각각 별도 Paper로 나누는 선택 질문에는 아직 답변이 없으며, 추가 백엔드/서버 간 슬롯 동기화를 승인된 것으로 간주하지 않는다.

## 실행과 플레이

`runtime-mode: survival`을 명시한 새 경제 backend에서 `/월드` 또는 `/world`로 27칸 가상 인벤토리를 연다. 거주(11)·야생(13)·지옥(15)을 왼쪽 클릭하면 해당 월드의 고정 안전 입장점으로 이동한다. 현재 월드는 표시하고 다시 이동하지 않는다. 하단 슬롯·드래그·Shift/숫자키·이전 화면·이전 연결의 선택으로 이동하거나 메뉴 아이템을 가져갈 수 없다.

기존 RPG 경제 모드와 구분하여 일반 채집·제작·전투·사망·드롭·경험치·포탈·명령어를 Minecraft/Paper에 맡긴다. RPG 세션/전투/스마트폰/퀘스트 모듈은 등록하지 않는다. 같은 Player의 월드만 바꾸며 인벤토리·엔더·경험치·체력을 별도로 캡처/복사/복원하지 않는다. 기본 End는 바닐라 차원으로 유지하며 세 선택 버튼에 추가하지 않는다.

입장점의 기존 청크를 유지하고 이동 직전 안전성을 다시 확인한다. 최초 준비에서는 각 월드의 스폰 청크 안에서만 자연 지형의 안전 지점을 찾으며 블록을 고치지 않는다. 지옥 지붕 위·용암/물·막힌 공간은 제외한다. 안전 지점이 없으면 준비/이동을 보류한다. 사용자 승인이 없는 야생 초기화·땅 소유/보호·PvP/몬스터/keepInventory 정책은 추가하지 않는다. 일반 보호 정본은 WorldGuard다.

이동은 같은 접속/생명 상태에 한 번만 허용한다. 이동 중 탑승/추가 전환·소지품 조작을 제한하며, 확정 거부는 원래 위치일 때만 해제한다. 실패 불명·시간 초과·이동 중 사망은 HOLD로 보존한다. 원래 비동기 teleport가 끝나기 전까지 해당 실제 작업을 추적해, 재접속/새 생명의 이동 허가로 늦은 작업을 승인하지 않는다. HOLD의 정상 자동 인벤토리 복구는 만들지 않는다.

## 데이터 경계

일반 생존의 개인 데이터 정본은 Paper의 native playerdata다. [성능/수동 장애 대응 원칙](0003-inventory-performance-and-recovery.md)에 따라 아이템별 PG 거래나 고비용 체크포인트를 추가하지 않는다. 네트워크 복귀는 같은 인증 연결을 동결한 뒤 `Player.saveData()` 호출과 새 개인 파일 확인을 통과해야 기존 서명된 프록시 경로를 요청한다. Paper API가 저장 오류를 로그로 처리하는 경우도 있어 파일 교체/변경 확인을 추가했다. 이 영수증은 장애 시 완전 자동 무손실 복구 보장이 아니다.

기존 `economy` 모드·PG 잔액/거래/생산·스토리 데이터는 보존한다. `survival`이 기존 PG 인벤토리를 읽어 덮어쓰거나 이전하지 않는다. 최초 3월드 배치에서는 PG 화폐/상점/생산 연결을 제외했으며, 사용자 후속 요청으로 [ADR-0027](0027-native-survival-economy-integration.md)에서 기존 엔진을 연결한다. native 정본/기존 PG 자동 이전 금지는 유지한다. 기존 RPG 경제 realm 표식/다른 생존 묶음의 개인 데이터는 입장을 보류한다.

새 묶음의 `allow-create` 기본값은 false다. 검토한 새 게임 데이터에서만 true로 초기 준비하고, 준비 결과에 group ID·세 key/UUID/seed·안전 입장점을 고정한다. 기존 PG 경제 매핑·기존 native 개인 파일·미등록 custom 월드는 자동 채택하지 않는다. 준비 중 실패 표식은 자동 삭제하지 않는다. 준비 완료 이후 custom 월드 메타데이터 누락·UUID/seed/설정 변경은 재생성 대신 HOLD다. 기존 기본 차원은 Paper가 플러그인 전에 로드하므로 그 식별자 변경도 준비 단계에서 입장을 닫는다.

## 도구 선택과 검증

기존 적합성 검토의 Multiverse-Core는 미채택 상태다. 현재 요구는 고정 3월드/메뉴이므로 [Paper WorldCreator](https://jd.papermc.io/paper/26.2/org/bukkit/WorldCreator.html)와 [비동기 teleport](https://jd.papermc.io/paper/26.2/org/bukkit/entity/Entity.html)를 사용한다. 외부 월드 관리/인벤토리 동기화 플러그인을 추가하지 않는다. WorldGuard/WorldEdit은 기존 고정 버전을 유지한다.

[구현/검증 기록](../survival-world-verification.md)과 [설정 안내](../../infrastructure/network/survival.md)를 따른다. 콘솔·GUI 객체·두 JVM 복원을 실제 플레이 성공으로 대체하지 않는다. 운영 서비스·DB·월드·SSH/방화벽·터널은 변경하지 않으며 운영 적용/실제 클라이언트 수용은 별도 경계다.
