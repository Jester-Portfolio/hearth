# ADR-0001: 스토리 월드 B안 채택

> 2026-10-25 후속 통합: [ADR-0010](0010-coop-information-and-hud.md)의 가입 없는 코옵/정보 UI, [ADR-0011](0011-votes-boss-return-and-gathering-reset.md)의 투표/보스 복귀/채집, [ADR-0012](0012-progress-storage-world-lifecycle-and-content.md)의 저장/월드/버전 정책을 우선합니다. 이전 검토 이력과 원래 결정일은 보존합니다.

> 후속 확정: [ADR-0004](0004-community-quests-and-chapter-skip.md)의 공동체·개인 퀘스트·고정 분기·장별 스킵 정책을 함께 적용합니다. 아래 파티 표현은 공동체 공유 진행으로 해석하며 탈퇴·분할·병합 후보는 현행 요구로 승계하지 않습니다. 가입·탈퇴·관리자 구성원 관리 UI는 현행 요구가 아닙니다(ADR-0010). 본 ADR의 B안·기술·저장 정책은 유지합니다.

- 작성일·결정일: 2026-10-22
- 상태: **승인** — 사용자가 스토리 월드 운영 구조 B안을 확정함
- 범위: 논리 아키텍처 결정. 구현 검증 완료나 운영 적용 승인이 아님

## 배경과 요구사항

Hearth 스토리 월드는 현대인이 마법 없는 현실적인 중세 세계에서 현대 과학·기술 지식을 활용하는 싱글·소규모 코옵 환경입니다. 서로 다른 플레이어·파티의 퀘스트, NPC와 실제 월드 변화가 간섭하지 않아야 합니다. 필수 로컬 AI 스마트폰 어시스턴트도 진행별 정보를 구분해야 합니다.

기존 검토에 기록된 Rocky Linux 호스트는 6코어·12스레드 CPU와 약 15.1GiB RAM을 사용합니다. Minecraft 외 기존 서비스와 로컬 AI의 자원도 고려해야 하므로 실행 기본 비용을 공유하면서 실제 월드를 분리하는 방향을 선택합니다. 현재 동시 접속자·활성 월드 수용량과 자원 절감량은 **미검증**입니다.

## 검토한 대안과 채택 근거

| 대안 | 장점 | 제약과 판단 |
| --- | --- | --- |
| A. 진행별 서버·컨테이너 분리 | 프로세스 격리와 진행 단위 호스트 분산에 유리 | 실행 기본 비용과 운영 대상 증가. 향후 확장 선택지로 유지 |
| B. 단일 서버의 진행별 독립 월드 | 서버 기본 비용을 공유하면서 실제 지형·엔티티 변화 분리 가능 | 공유 프로세스 장애·자원 경쟁 및 외부 상태 격리 구현 필요. 현재 운영 구조로 채택 |
| C. 공통 월드의 논리 진행 분리 | 공통 지형 재사용 가능 | 서로 다른 실제 블록·NPC 상태까지 분리하기 어려워 현재 요구의 기본 구조로 채택하지 않음 |

이 판단은 설계상의 선택이며 후보 구현체나 플러그인 조합의 동작·성능을 검증했다는 뜻이 아닙니다. [구조 비교](../story-world-architecture.md)와 [구현 가능성 검토](../story-world-feasibility.md)의 근거·제약·출처는 보존합니다.

## 결정

1. **하나의 Minecraft 서버 프로세스**에서 플레이어·파티별 독립 월드를 운영합니다(B안). 이 결정은 스토리 월드 범위이며 경제 월드의 프로세스 배치는 별도입니다.
2. **싱글 플레이어는 자신만의 독립 스토리 진행과 월드**를 가집니다.
3. **코옵 파티는 하나의 스토리 진행과 월드**를 공유합니다. 여러 차원이 필요한 경우 진행별 월드 묶음의 구성은 후속 설계에서 정합니다.
4. **퀘스트·NPC·월드 변화·플레이어 상태를 진행별로 격리**합니다. 같은 파티에서도 인벤토리 등 개인 상태는 진행 범위 안에서 플레이어별로 구분합니다. 월드 분리만으로 모든 상태가 자동 격리된다고 가정하지 않습니다.
5. **유휴 월드는 저장 후 언로드**하는 방향으로 설계합니다. 저장·재접속 일관성과 언로드 성공 확인이 필요하며 언로드는 데이터 삭제를 의미하지 않습니다.
6. 필수 **로컬 AI 스마트폰 어시스턴트는 공통 AI 서비스**를 사용합니다. 정보 조회·검색·대화·캐시의 접근 범위를 진행별로 격리합니다. 세부 권한·연동·동시 처리 방식은 미정입니다.
7. **논리 진행 ID(`story_run_id`)와 물리 서버·월드 배치를 분리**하여 필요 시 A안으로 확장할 가능성을 유지합니다. 실제 이전 도구·이식성·무중단 이전은 검증하거나 보장하지 않습니다.

스토리와 경제 월드의 진행·경제 데이터 분리 원칙은 유지합니다. 공통 기능 재사용이 진행 데이터 공유를 의미하지는 않습니다.

## 영향과 수용한 제약

- 진행 생성·복제·로드·저장·언로드·재접속 수명주기를 관리해야 합니다. 유휴 조건·대기 시간·비활성 기간의 게임 시간 처리는 미정입니다.
- 인벤토리·퀘스트 저장소·NPC 레지스트리·전역 이벤트 등 모든 상태 경계가 진행 ID를 존중해야 합니다. 코옵은 가입/탈퇴 기능이 없으며 보상 세부는 의도적 보류입니다(ADR-0010). 게임 내 파티 탈퇴는 구현하지 않습니다.
- 여러 진행은 프로세스·메모리·틱 처리 자원을 공유합니다. 프로세스 장애나 메모리 부족이 전체 스토리 진행에 영향을 줄 수 있습니다.
- 유휴 언로드와 공통 AI는 자원 절약 방향이며 실제 절감량·메모리 회수·동시 처리량은 미검증입니다. 동시 활성 진행 수 제한은 측정 후 정합니다.
- 월드 파일과 외부 퀘스트·NPC·개인 상태의 저장·복구 시점을 조정해야 합니다. 백업·복구와 향후 A안 이전에는 모든 관련 데이터가 포함되어야 합니다.

## 미결정 사항과 후속 검증

이 ADR 작성 당시 서버 구현체·버전·Java·확장 방식·데이터 저장 기술은 미정이었습니다. 해당 기술 선택과 템플릿·보호·채집 정책은 후속 [ADR-0002](0002-stack-and-world-policies.md)로 갱신합니다. B안과 진행 격리·공통 AI 경계는 유지합니다. AI 구체 기술과 DB 스키마 등 세부 설계는 여전히 미정입니다.

다음은 **미검증**이며 구현 전에 검증 계획과 수용 기준을 구체화합니다.

- 후보 기술 조합의 동적 다중 월드·NPC·퀘스트·개인 상태 격리 지원.
- 두 진행의 상반된 NPC·퀘스트·블록 상태와 명령·포털·부활·재접속 경계.
- 동시 공동체 이벤트, 개인 진행·분기 고정·장별 스킵, 보상 중복 방지 및 저장 도중 장애 복구. 가입·관리자 변경 시험은 정책 확정 후 구체화.
- 유휴 언로드·재로드 반복, 참조·작업·청크 티켓 누수, 입장과 언로드 경합.
- AI 정보 접근·캐시·지연 응답의 진행 간 누출 방지.
- 기존 서비스·필수 AI와 공존할 때 CPU·RAM·I/O·틱 지연·응답 시간 및 활성 월드 한도.
- 진행별 복원과 A안 이전 가능성. 후속 [ADR-0003](0003-inventory-performance-and-recovery.md)에 따라 고비용 체크포인트·자동 무손실 복구는 필수 요구가 아니며, 아이템 장애 대응에는 로그·백업 기반 관리자 수동 조정을 허용합니다.

상세 시험 항목은 [구현 가능성 검토](../story-world-feasibility.md)에 남깁니다. 검증 결과 구조 변경이 필요하면 후속 ADR로 이 결정을 대체하고 상호 링크합니다.

## 운영 승인 범위와 롤백

이번 승인은 문서에 기록한 아키텍처 채택과 관련 문서 커밋에 한정합니다. 서버 설치·실행, 컨테이너 생성, 서비스 재시작 및 기존 Docker·Zabbix·Cloudflare 운영 변경은 수행하지 않습니다.

이번 작업은 실행 구성과 영속 데이터를 바꾸지 않으므로 운영 롤백 대상은 없습니다. 향후 구현·배포 변경에는 기존 설정·월드 및 외부 상태의 백업, 일관된 복구 지점, 복원 절차·결과 확인과 필요한 운영 승인을 별도로 준비합니다. A안 전환 시에도 원본 보존과 단일 쓰기 소유권을 포함하는 롤백 계획이 필요합니다.
