# ADR-0034: 공통 영속 작업과 예약 자원 교체

- 날짜: 2026-11-20
- 상태: 사용자 후속 플랫폼 개발 요청에 따른 구현 결정. 콘텐츠/운영 주기·실제 플레이/운영 수용 별도.
- 근거: [구현·검증](../platform-jobs-verification.md), [운영 가이드](../../infrastructure/network/platform-jobs.md).

## 문제와 결정

자원 세대 엔진은 준비/교체/복구를 제공하지만 예약 실행과 관리자가 확인할 작업 이력이 분리돼 있었다. 서버 정지 중 wall-clock 예약을 따라잡거나 실패한 세계 작업을 자동 재시도하면 미정 주기·중복 효과·원본 보존 경계를 침범한다.

기존 경제 논리 시계/offline PAUSE를 재사용하고 기본 비활성·주기0의 설정을 제공한다. E013에 실행 전 의도와 고정 입력, 예약 revision·다음 tick, 상태/이력을 저장한다. realm당 미확정 작업 하나로 직렬화하고 완료/취소한 현재 tick부터 다음 주기를 계산한다. 백로그 연속 실행은 하지 않는다.

실제 자원 효과는 기존 엔진을 재사용하며 job UUID와 같은 요청 ID/고정 시드를 전달한다. 재시작 RUNNING은 HOLD로 보존하고 자동 재실행하지 않는다. 관리자 확인/취소는 기록된 효과와 로컬 제어 상태만 조회하며 전역/native HOLD·보상/세계 효과를 재실행/해제하지 않는다. 주거 세계는 대상에서 제외한다.

공통 관리자 GUI/콘솔과 신뢰하는 Java JobHandler/JobExtension을 제공한다. 별도 Quartz/cron daemon·임의 명령/스크립트·LLM 실행기는 추가하지 않는다. 운영 서비스/패키지를 변경하지 않고 동일 JAR/PG/수명주기를 사용한다. 일반 게임 상호작용과 관리자 작업 조회의 busy 조건을 분리하되 세션/권한을 유지한다.

## 결과와 후속

주기/보존/아카이브와 실제 운영 활성화는 미선정이다. 기술 상한은 handler32·자동 대상4·미확정1·최근128/전체4096 이력이다. 실제 클라이언트·장기 부하/디스크·정전 장애 수용과 운영 배포는 별도이며 기존 전체 일관 백업/정상 drain/롤백 경계를 유지한다.
