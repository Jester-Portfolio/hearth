# ADR-0002: 기술 스택과 월드 운영 정책

> 후속 확정: [ADR-0004](0004-community-quests-and-chapter-skip.md)의 공동체·개인 퀘스트·고정 분기·장별 스킵 정책을 함께 적용합니다. 아래 파티 표현은 공동체 공유 진행으로 해석하며 탈퇴·분할·병합 후보는 현행 요구로 승계하지 않습니다. 가입·관리자 구성원 변경은 미정입니다. 본 ADR의 B안·기술·저장 정책은 유지합니다.

- 작성일·결정일: 2026-10-23
- 상태: **승인** — 사용자가 기술 스택과 월드 운영 정책을 확정함
- 관계: [ADR-0001](0001-story-world-multiworld.md)의 B안을 유지·구체화하며 당시 미정이던 기술 선택을 갱신함
- 범위: 설계 결정과 문서 반영. 호환성·구현·실행 검증이나 운영 적용 승인이 아님

## 배경과 결정 근거

기존 B안의 진행별 독립 월드와 데이터 격리를 유지하면서 구현 기준과 콘텐츠 운영 경계를 명확히 합니다. 사용자가 아래 기술과 정책을 확정했으며, 이번 작업은 후보 재평가나 설치 시험을 수행하지 않습니다. 기존 [구조 비교](../story-world-architecture.md)와 [구현 가능성 검토](../story-world-feasibility.md)는 당시 대안과 검증 과제의 기록으로 보존합니다. 그 문서의 API 버전을 채택 버전의 검증 근거로 간주하지 않습니다.

## 확정 기술 스택

| 영역 | 결정 |
| --- | --- |
| Minecraft 서버 | Paper 26.2 |
| 플러그인 언어·빌드 | Java 25, Gradle |
| 플러그인 구조 | 단일 JAR 배포, 내부 기능별 모듈화 |
| 데이터베이스 | PostgreSQL |
| 배포 | Docker Compose |
| 모니터링 | 기존 Zabbix 활용 |
| 클라이언트 | 순정 Minecraft Java Edition, 별도 모드 설치 최소화 |
| 리소스팩 | 필요시 서버에서 제공 |
| AI 서비스 | 구체 기술 스택 미정 |

내부 모듈화는 기능별 책임 분리를 뜻하며 Gradle 멀티프로젝트 구성이나 모듈 간 API를 확정하지 않습니다. Paper 26.2·Java 25는 사용자 지정 기준이며 배포물 가용성, 호환성 및 지원 API를 이번에 검증하지 않았습니다. Gradle·PostgreSQL 등의 세부 버전도 미정입니다.

## 스토리 월드와 데이터 수명주기

- 하나의 Paper 서버 프로세스에서 플레이어·파티별 독립 월드를 운영합니다. 싱글은 개인 진행, 코옵은 파티 공유 진행을 유지합니다.
- 미리 제작한 월드 템플릿을 복제하여 생성합니다. 템플릿은 버전별로 관리하며 지속적으로 추가합니다.
- 기존 플레이어의 월드와 진행 데이터는 유지합니다. 새 템플릿 버전이 기존 월드를 자동 교체한다는 정책은 아닙니다.
- 비활성 월드는 저장 후 언로드하며 재접속 시 저장된 월드와 진행을 복원합니다. 비활성 기준, 저장 순서와 경합·실패 처리는 후속 설계 대상입니다.
- 퀘스트, NPC 관계, 스토리 분기와 플레이어별 진행 상태는 PostgreSQL에 저장하고 월드별로 논리적으로 분리합니다. 기존 논리 진행 ID와 월드 배치 분리를 유지하며 구체 키·스키마·DB 인스턴스 경계는 미정입니다.
- 스토리와 경제 멀티 월드의 인벤토리 및 진행 상태를 분리합니다. 코옵 내 개인 상태 구분과 공통 AI의 진행별 정보 접근 격리도 유지합니다.

## 템플릿·콘텐츠·진행 상태의 분리

| 데이터 | 관리 원칙 |
| --- | --- |
| 월드 템플릿 | 지형·건축물 등 공간 데이터, 버전별 관리와 지속 추가 |
| 콘텐츠 정의 | NPC 배치·대화·퀘스트 정의를 템플릿과 별도 콘텐츠 데이터로 관리 |
| 진행 상태 | 플레이어별 진행과 월드별 퀘스트·NPC 관계·분기 상태를 PostgreSQL에 저장 |

콘텐츠 정의의 저장 형식·배포 방식과 템플릿 버전 연결 방식은 미정입니다. 기존 스토리 월드에 신규 지형·건축물을 적용하는 방식도 추후 결정합니다.

## 보호와 자원 채집

| 영역 | 건축·지형 변경 | 주요 자원 수급 |
| --- | --- | --- |
| 싱글·코옵 스토리 | 전체 보호가 기본, 지정 구역에서만 허용 | 별도 인던형 채집 구역 중심 |
| 경제 멀티 | 주요 도시·공용 시설 등 지정 구역만 보호, 일반 지역 자유도 확대 | 스토리와 동일하게 전용 채집 인던 중심 |

건축을 위한 지형 변경과 자원 채집은 별개 정책으로 관리합니다. 보호 이벤트 범위와 우회 방지, 자원 수급 규칙은 상세 설계·검증이 필요합니다. 자원 인던의 생성·초기화·재생성 방식과 두 모드 사이의 물리적 공유 여부는 확정하지 않습니다.

## 미정 사항과 후속 검증

- 경제 멀티 월드의 서버 프로세스 분리 여부.
- 자원 인던의 생성·초기화·재생성 방식.
- AI 서비스의 구체 기술, 정보 제공·연동과 장애 처리.
- 기존 스토리 월드에 신규 지형·건축물을 적용하는 방식.
- 세부 콘텐츠·게임 시스템, 공동체 가입·관리자 변경·보상 세부·유휴 시간 정책. 공동체·퀘스트 정책은 ADR-0004의 확정/미정 구분을 따름.
- DB 스키마, 저장·복구 일관성, 인벤토리 전환, 콘텐츠 버전 연결과 배포 세부 구성.

후속 검증에는 선정 버전의 API·빌드 호환성, 두 진행 간 상태 격리, 템플릿 복제와 기존 데이터 보존, 저장·언로드·재접속 경합, 보호·채집 경계, AI 정보 누출 방지와 호스트 자원 수용량을 포함합니다. 이번 문서 검사는 이러한 실행 검증을 대체하지 않습니다.

인벤토리 저장 책임과 성능 우선·수동 장애 대응의 후속 확정 정책은 [ADR-0003](0003-inventory-performance-and-recovery.md)을 따릅니다. 이 정책은 B안·데이터 격리·기술 스택을 변경하지 않습니다.

## 운영 승인과 롤백

문서 수정·검사·commit·push만 승인된 범위입니다. 서버·컨테이너·DB·플러그인 설치나 실행 및 기존 Docker·Zabbix·Cloudflare 설정 변경은 수행하지 않습니다. 향후 운영 변경에는 기존 구성 확인, 승인, 백업·복구 검증과 롤백 계획이 필요합니다. 기존 월드 및 PostgreSQL 상태를 함께 보존·복원할 절차는 구현 전에 설계합니다.
