# ADR-0030: 공용 거주·구매형 개인 거주·자원 월드

- 작성일: 2026-11-18
- 상태: **사용자 요구 확정·시스템 구현/격리 검증, 세부 설정·실제 수용/운영은 보류**. 아래 추천 크기/금액 배율·세부 기본값은 예제이며 운영 실행값으로 확정하지 않았다.
- 사용자 요구: 제한된 건축/수정이 가능한 기본 거주 월드, 구매 후 유지되는 크기별 개인 거주 월드와 원하는 사람의 공동 거주, 자원 채집용 오버월드/지옥 분리.
- 관계: [ADR-0026](0026-vanilla-survival-world-selection.md)의 3월드 기반을 확장하고 [ADR-0029](0029-single-spawn-shops.md)의 공용 스폰 한곳·종류별 NPC·공통 상점을 유지한다. 스토리 개발은 보류한다.

## 월드 구성

| 선택창의 구분 | 용도 | 건축·수정 | 보존/접근 |
| --- | --- | --- | --- |
| 기본 거주 | 공용 스폰·종류별 상점 NPC·작은 기본 거처 | 스폰/시설/도로는 보호, 배정된 소규모 건축 구획 안에서만 허용 | 구매 없이 이용, 생활 거점으로 보존 |
| 개인 거주 | 구매자의 독립된 집·공동 생활·농장/창고 | 구매한 경계 안에서 소유자와 허가한 거주자가 변경 | 구매 후 지속 보존, 소유자/초대된 사람만 입장 |
| 자원 오버월드 | 일반 자원·광물·농작물/생물 자원 채집 | 공용 입장점 등 보호 구역 밖은 기본 생존 규칙 | 모두 이용, 영구 거처의 보존 대상과 분리 |
| 자원 지옥 | 네더 광물·블록·생물 자원 채집 | 공용 안전 입장점 등 보호 구역 밖은 기본 네더 생존 규칙 | 모두 이용, 개인 소유/점유 월드로 만들지 않음 |

기본 거주/자원 두 월드는 공통 월드, 개인 거주는 소유자별 별도 Overworld다. 개인 거주 월드마다 별도 서버 프로세스를 띄우지 않는다. 로비/경제의 기존 네트워크 배치와 같은 경제 Paper 안에 공통 3월드 + 구매한 개인 월드들을 둔다. 여러 마을이나 스토리 지역은 만들지 않는다. 개인 월드에 상점 NPC를 복제하지 않으며 `/상점`은 어디서든 같은 공통 시장을 연다.

## 기본 거주 월드의 제한

공용 스폰과 상점·안내/이동 시설, 도로/공용 땅은 일반 플레이어가 파괴·설치·수정할 수 없게 한다. NPC/상점 사용 허가를 건축 권한과 분리한다. 건축은 배정된 작은 구획에서만 허용하고, 구획 밖으로 나무·피스톤·유체·폭발 등 간접 변경이 넘어가지 않게 한다.

추천 기본안은 계정당 무료 구획 하나, 가로/세로 16블록·높이 32블록이며 실제 면적/고도·배치 수는 콘텐츠/운영 설정으로 정한다. 구획의 정해진 높이 바깥 지하 채굴은 허용하지 않는다. 무료 구획은 구매형 개인 월드의 소유권/구매 크기와 별개다. 다른 사람의 구획/공용 보관함에 자동 접근 권한을 주지 않는다. 구획을 없애거나 회수하는 별도 자동 정책은 두지 않는다.

일반 보호는 기존 WorldGuard를 사용한다. Hearth는 구획/개인 월드의 소유권·역할·구매/초대 상태와 WG 반영을 연결한다. 새 범용 블록 보호 엔진이나 스토리 퀘스트 권한을 만들지 않는다.

## 개인 거주 월드 구매·확장

추천 기본 정책은 **서버 내 PG 화폐로 1회 구매·유지비 없음·미접속 기간으로 삭제/회수하지 않음**이다. 계정당 소유 월드 하나로 시작하되 다른 소유자의 월드에는 거주자로 참여할 수 있다. 소유자 접속 여부와 관계없이 허가한 거주자는 이용한다. 방문/건축 권한을 월드 구매와 별도로 판매하지 않는다.

| 추천 등급 | 가로 × 세로 | 사용 면적 | 누적 가격 | 직전 등급에서 확장 비용 |
| --- | --- | --- | --- | --- |
| 기본 | 64 × 64 | 4,096블록 | P | 최초 구매 P |
| 중형 | 128 × 128 | 16,384블록 | 4P | 3P |
| 대형 | 256 × 256 | 65,536블록 | 16P | 12P |
| 특대형 | 512 × 512 | 262,144블록 | 64P | 48P |

P는 설정 가능한 기본 가격이며 현재 숫자/잔액에 적용하지 않는다. 면적에 비례한 가격을 기본으로 하고 첫 구매 때 가격표 버전을 고정한다. 같은 가격표의 새 등급 총액에서 현재 등급 총액을 뺀 차액을 낸다. 중간 등급을 건너뛰어도 차액만 낸다. 신규 구매 가격표 변경이 기존 소유자의 확장 계약을 조용히 바꾸지 않도록 버전/견적에 표시한다.

크기는 건축/사용 가능한 수평 정사각형의 폭이다. 높이는 해당 월드의 정상 건축 높이를 사용한다. 동일한 중심·seed·월드 UUID를 유지하면서 경계를 바깥으로 확장한다. 집/상자/농장·설치 블록·월드 엔티티를 초기화하거나 다른 월드에 복사하지 않는다. 축소/재추첨/소유권 판매·환불/양도·삭제 버튼은 초기 기능에서 제외한다. 장기 보존은 정상 저장/백업을 전제로 하며 단순 언로드가 데이터 삭제를 뜻하지 않는다.

개인 거주는 전용 거주 템플릿/지형으로 준비한다. 구매할 때마다 외부 자원 월드/공용 창고·다른 사람의 집을 복제하지 않는다. 실제 지형/스타일은 레벨 디자인에서 정하며, 채집 목적의 오버월드/네더는 별도로 유지한다. 구매 가능 경계 밖으로 이동/블록 조작·포탈·간접 변경을 할 수 없게 경계와 보호를 함께 적용한다.

## 원하는 사람과 공동 거주

| 역할 | 할 수 있는 일 |
| --- | --- |
| 소유자 | 자신의 월드 입장/건축, 확장, 초대·초대 취소·거주 권한 변경/해제, 안전한 집 입장점 설정 |
| 거주자 | 초대 수락 후 해당 월드 입장·건축/수정·공용 상자/시설 사용. 확장 결제·소유권/다른 거주자 관리는 불가 |
| 방문자 | 소유자가 방문 권한으로 초대하고 상대가 수락했을 때만 입장. 건축/파괴·보관함/제작/동물 등 변경은 불가 |

등록된 정품 계정의 UUID로 초대하며 일방적으로 다른 사람을 거주자로 등록하지 않는다. 초대 목록에서 수락/거절한다. 새 구매자에게 다른 월드의 초대/상자 권한을 자동 승계하지 않는다. 초대 정원은 UI에 표시하는 설정값으로 두며 미정 운영 인원/예산을 무제한 허용으로 해석하지 않는다.

거주자는 소유자가 오프라인이어도 입장할 수 있고 본인이 탈퇴할 수 있다. 소유자는 거주자/방문자를 해제할 수 있다. 권한을 해제하면 열린 관련 화면과 뒤늦은 요청을 무효화하고, 월드 안에 있던 사람은 공용 스폰의 안전 입장점으로 돌려보낸다. 개인 인벤토리/잔액을 압수·삭제하거나 공용 상자의 내용을 자동 분배하지 않는다. 공동 상자는 거주자끼리 공유하므로 거주자 해제에 따른 자동 재산 정산은 만들지 않는다.

## 명령어·인벤토리 UI

대표 진입은 기존 **`/월드` 하나**로 유지한다. 화면에는 기본 거주·개인 거주·자원 오버월드·자원 지옥 네 종류를 둔다. 개인 월드가 여러 개면 개인 거주 안에서 나의 집/함께 사는 집을 목록으로 선택한다. 월드를 소유하지 않아도 초대받은 집에는 들어갈 수 있다.

- 기본 거주: 공용 스폰 이동, 배정된 기본 구획 보기/이동.
- 개인 거주: 내 집 이동, 미소유 시 크기/누적 가격·잔액·보존 규칙 확인 후 구매, 소유 시 현재 크기/확장 차액/초대·거주자·받은 초대/함께 사는 집 관리.
- 자원 오버월드/지옥: 보호된 안전 입장점 이동. 초기화 정책이 정해지면 같은 버튼에 세대·예정 시각/주의를 표시한다.

구매/확장은 대상 크기·최종 금액·현재/예상 잔액을 한 화면에서 확인하고 최종 확인한다. 중복 클릭·닫힌 화면/재접속의 오래된 요청을 같은 구매로 재실행하지 않는다. 월드 로드 중은 진행 상태를 표시하고 반복 요청으로 같은 월드를 여러 번 생성하지 않는다. 거래/이동/HOLD 중에는 기존 작업을 보존하고 완료 후 다시 이용하도록 안내한다.

집 안에서는 경계 내 안전한 집 입장점을 정할 수 있고, 막힌 경우 기존 안전 지점 또는 공용 스폰으로 돌아간다. 여러 거주자가 동시에 이용해도 월드/가방을 복사하지 않는다. 인벤토리·엔더·경험치·체력과 PG 잔액/상점은 기존 경제 서버의 공통 데이터를 사용한다.

## 자원 월드와 포탈

기존 야생 월드는 자원 오버월드, 기존 지옥은 자원 지옥의 역할로 이어받는다. 기존 데이터를 새 이름으로 자동 재생성/삭제하지 않는다. 각 자원 월드의 입장점/시설은 보호하고 그 밖에서는 일반 자원 채집과 기본 생존을 허용한다. 야생에 임시 건축은 가능하지만 개인 거주 소유권을 주지 않는다.

자원 월드는 추후 세대 교체/초기화가 가능하도록 경계를 설계하되 **주기·실행 시각·자동 초기화는 이번에 확정/적용하지 않는다**. 초기화 구현 시 공지 → 신규 진입 닫기 → 전원 안전 복귀/저장 확인 → 새 세대 검증 → 진입 전환을 적용하고, 결과가 불명하면 기존 세대/원본을 보존한다. 공용 거주/개인 거주를 자원 세대 교체 대상으로 포함하지 않는다. 실제 영속 데이터 삭제는 별도 명시 승인 경계를 유지한다.

구현 시 기본 포탈/침대·리스폰/로그인 위치/다른 이동 명령도 목적지 역할·개인 월드 접근권한을 재확인해야 한다. 개인 네더를 추가 생성하지 않고 네더행 이동은 공통 자원 지옥으로 연결한다. 공통 자원 오버월드/지옥의 포탈 대응은 거주 월드에 자원용 포탈 출구를 임의 생성하지 않게 정한다. End는 이번 구성에 포함하지 않으며, 새 구성에서는 별도 결정 전 진입을 열지 않는 안을 기본으로 한다. 이는 현재 바닐라 포탈 동작을 이미 수정했다는 뜻이 아니다.

## 구현·저장 경계

기존 WorldGuard/WorldEdit과 Hearth의 월드 생성/등록 경계를 재사용한다. [기존 도구 검토](../plugin-suitability-review.md)의 Multiverse-Core는 미채택 상태를 유지하며 이번 설계 때문에 플러그인을 설치하지 않는다. 구현 시 API 호출/간접 보호의 실제 경계는 관련 격리 Paper 검사로 검증한다.

- 소유권은 `생존 group + owner UUID`, 개인 월드 ID는 별도 UUID로 저장한다. 월드 UUID/key/seed·경계/등급·가격표 버전·요청/영수증·초대/역할 revision을 PG에 보존한다. 한 계정의 동시 구매에는 고유 소유권/단일 진행 작업을 적용한다.
- 기존 E006의 공통 3월드 묶음/해시를 개인 월드 구매마다 바꾸지 않는다. 별도 개인 월드 registry를 같은 group/경제 realm에 연결하고 현재 3월드 고정 접근 판정을 등록된 개인 월드/회원 권한까지 확장해야 한다. 기존 RPG/미등록/다른 소유권 월드를 자동 채택하지 않는다.
- 구매는 견적/요청 예약 → 접근 닫힌 전용 월드 준비/보호·저장 검증 → PG의 잔액 차감/영수증·소유권 활성화를 같은 거래로 확정 → 권한/진입 개방 순서다. 생성 실패는 결제하지 않으며, 결과가 불명한 결제는 재차감/임의 환불하지 않고 HOLD/영수증·원본을 보존한다. 준비된 미확정 월드를 자동 삭제하지 않는다.
- 확장은 기존 경계/원본을 보존한 채 단일 요청으로 준비·차액/목표 크기를 확정하고 경계를 반영한다. PG와 월드 파일/WG는 하나의 원자 저장소가 아니므로 반영 실패/commit 불명은 진입/수정을 보류하고 진단한다. 오래된 승인으로 바깥을 열거나 건축물을 지우는 자동 롤백을 만들지 않는다.
- 소유권/권한과 보호 데이터가 누락/불일치하면 닫힌 상태로 보류한다. WG manager/보호 로드 실패를 무보호 입장으로 처리하지 않는다. 가입/탈퇴와 늦은 이동은 권한 revision·현재 접속/생명 상태를 함께 확인한다. DB/WG 저장의 동기 대기를 Bukkit 메인 스레드에 추가하지 않는다.
- 개인 월드는 필요할 때 로드하고 마지막 이용자/진행 작업이 없으면 저장 후 언로드한다. 소유자가 접속하지 않았다는 이유로 데이터/소유권을 지우지 않는다. 전체 크기의 청크를 구매 시 전량 생성하지 않으며, 생성/로드 동시 작업과 활성 월드 수는 운영 예산으로 제한한다. 백업은 소유권/가격표/초대와 실제 월드·WG 데이터를 함께 다룬다.

## 현재 구현과 다음 배치

2026-11-20 사용자 지시에 따라 시스템을 먼저 구현했다. 공용 구획/WG 보호·개인 월드 구매/차액 확장/초대 공동 거주·기존 `/월드`/거래/이동/포탈·저장 종료를 연결했고, 초기 개인 지형은 전용 FLAT 생성기를 사용한다. 구체적인 지형/시설과 가격·크기·정원·한도는 예제 설정에 분리했다. 시스템/구매는 기본 비활성이며 운영 설정/세계/DB/서비스에는 적용하지 않았다.

[구현/검증](../housing-system-verification.md)·[사용법/설정](../../infrastructure/network/housing.md)을 따른다. Java37개·실제 PG21개·두 JVM 기능 경로와 최종 한 JVM 복원을 확인했다. 실제 클라이언트·장기 부하/밸런스·자원 월드 세대 교체/자동 초기화는 완료하지 않았다. 기본 가격 P·실제 스폰 배치/구획 수·초대/활성 월드 자원 한도·자원 초기화 주기는 운영값으로 미확정이다.
