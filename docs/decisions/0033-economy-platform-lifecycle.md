# ADR-0033: 경제 공통 플랫폼과 명시적 수명주기

- 날짜: 2026-11-20
- 상태: 사용자 플랫폼 우선·8개 작업 일괄 구현 요청에 따른 구현 결정. 실제 플레이/부하·운영 수용 별도.
- 근거: [구현·검증](../economy-platform-verification.md), [운영 가이드](../../infrastructure/network/platform.md).

## 문제·대안

콘텐츠/밸런스 전에 강화·최종 수집/판매·능력치·정책 변경·자원 세대·관리/복구를 함께 사용할 기반이 필요하다. 별도 장비 DB/화폐·인챈트·권한 엔진을 중복 개발하거나 전체 서버를 새로운 게임 엔진으로 재작성하면 기존 원본 보존/거래 경계를 분리하게 된다.

## 결정

1. 선택형 `hearth-platform`이 기존 RPG/NativeTransactions·시장·Aura·WG·공통 admission/전투·RewardCoordinator를 조합한다. 기능별 스위치와 수치/재료/필터를 설정으로 두고 운영값/획득처를 확정하지 않는다.
2. 강화는 아이템 PDC 안정 ID/버전과 기존 E011·native 단일 actor 저널을 재사용한다. 자동 판매는 최종 실제 소지품을 기존 상점 거래로 소비한다. 판매용 드랍/화폐 원장을 새로 만들어 보상을 재지급하지 않는다.
3. 장비/패시브/인챈트의 출처는 유한 StatLedger로 교체·합산한다. Aura에는 Hearth 소유 최종 nonpersistent modifier를 반영하고 외부 modifier를 보존한다. ADD/MAX_ABSOLUTE와 cap은 설정한다.
4. E012는 개인 판매 설정 CAS·세대 상태·설정 변경 영수증을 저장한다. 라이브/재시작·정지 이전을 구분하고 원본/후보/해시/저널을 보존한다. 변경/롤백으로 최신 잔액·아이템을 과거 데이터로 되돌리지 않는다. 세계 ID/재질/토폴로지 변환은 자동 추론하지 않는다.
5. 자원은 원본을 삭제하지 않고 새 세계를 준비해 논리 역할을 교체한다. 후보 청크 소유·WG·대피·언로드·PG 활성화·정상/중단 복원을 함께 관리한다. 불명 commit/timeout은 HOLD·명시적 재개이며 PREPARING 후보를 임의 재생성하지 않는다. 거주 세계는 제외한다.
6. 관리/지표·전체 Paper+PG 백업/복원은 기존 도구에 연결한다. 모델/기동 검증과 실제 플레이·지속 부하/운영 승인을 구분한다. 실제 클라이언트는 사용자 재개 요청 전 보류한다.

## 결과·후속

원본 세대를 보존하므로 저장 공간이 증가한다. 기존 최초 바인딩 원본도 신원 검증에 필요하며 임의 삭제할 수 없다. 실제 초기화 주기·보존/정리 정책, 콘텐츠 수치/획득처·밸런스·레벨 디자인은 후속이다. 정책 도구의 표식과 전체 일관 백업을 유지하며 무손실 자동 정전 복구를 약속하지 않는다.

운영 변경은 없었다. 향후 운영 적용은 별도 승인 후 정상 drain·전체 백업·격리 복구·이전 JAR/설정 보존 및 같은 계획의 롤백으로 수행한다.
