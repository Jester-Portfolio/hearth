# ADR-0006: 퀘스트·NPC 대화·개인 컷신·전투 사망과 조건부 부활

- 결정일: 2026-10-24
- 상태: **승인** — 사용자 확정 정책. 구현·실행 검증 완료는 아님.
- 기준 커밋: `4a1c54acaa09b711a07746b60db85feef20f04d5`.
- 관계: [ADR-0001](0001-story-world-multiworld.md)·[ADR-0002](0002-stack-and-world-policies.md)의 진행 격리·기술·콘텐츠 분리, [ADR-0003](0003-inventory-performance-and-recovery.md)의 저장·성능, [ADR-0004](0004-community-quests-and-chapter-skip.md)의 공동체·고정 분기·투표·장 스킵, [ADR-0005](0005-dungeon-spawning-and-difficulty.md)의 소환 시점 난이도를 유지합니다.

## 배경과 결정 범위

퀘스트 운영·대화·컷신과 전투 실패/부활을 데이터 기반으로 설정하고 개인 경험과 공동체 결과를 구분합니다. 공개 문서에는 일반 시스템 정책만 기록합니다. 비공개 스토리 저장소를 읽거나 실제 서사·비밀·반전·결말·원고를 옮기지 않습니다. 구체 UI·카메라 기술·플러그인·물리 DB 스키마는 채택하지 않습니다.

## 확정 정책

### 퀘스트

- 메인 스토리·필수 길목 퀘스트는 조건에 따른 자동 시작 또는 NPC 대화로 시작할 수 있습니다. 서브 퀘스트는 NPC·게시판 등을 통해 직접 수락합니다.
- 스마트폰에서 전체 퀘스트 목록·진행 상황을 확인하고, 게임 화면에는 현재 추적 중인 퀘스트 목표만 간략히 표시합니다. AI 질의 기능과 목록 UI의 구체 연동 기술은 미정입니다.
- 퀘스트마다 자동 완료 또는 NPC 보고 후 완료를 설정합니다. 보고형은 목표 달성 후 **보고 대기** 상태를 지원합니다.
- 실패 조건은 사망·호위 실패·시간 초과 등을 퀘스트별로 설정합니다. 실패 시 진행도 유지·체크포인트 재시작·처음부터 재시작 중 하나를 설정하며 체크포인트는 제작자가 직접 지정합니다.
- 이 체크포인트는 게임 진행 재시작 지점입니다. ADR-0003에서 필수 제외한 고비용 DB/월드 일체형 저장·자동 복구 체크포인트를 요구하지 않습니다. 퀘스트 재시작이 공동체 확정 분기·세계 변화 rollback이나 소비 아이템 복원을 의미하지 않습니다.

### NPC 대화

- 일반 NPC는 간단한 대화 UI를 사용하고 상점·퀘스트 NPC는 대화에서 해당 기능으로 연결합니다. 주요 스토리 NPC는 카메라 연출·컷신을 사용할 수 있습니다.
- 일반 대화는 단순 진행하며 정보 수집·질문·퀘스트 수락·중요 선택에서만 선택지를 제공합니다. 중요 공동체 분기는 기존 ADR-0004의 조건 검사와 과반수 투표를 유지합니다.
- 대사·선택지·퀘스트 정의는 게임 코드와 분리된 데이터입니다. 순정 Minecraft 클라이언트를 기준으로 구체 UI 구현은 후속 기술 검증합니다.

### 컷신과 재시청

- 일반 NPC 대화에서는 자유로운 이동·시점 조작을 유지합니다. 중요 컷신에서만 플레이어 이동·카메라를 제어합니다.
- 코옵 컷신은 발동한 플레이어만 시청하며 다른 공동체 구성원의 플레이를 강제로 중단하지 않습니다. 개인 시청이 공동체 분기 선택 권한을 대신하지 않습니다.
- 첫 시청은 끝까지 봐야 하며 스킵할 수 없습니다. 첫 시청 중 접속 종료는 완료로 기록하지 않고 재접속 후 처음부터 재생합니다.
- 두 번째 도전에서는 스킵 여부를 묻습니다. 스킵을 선택하면 이후 재도전은 선택 화면 없이 퀘스트로 바로 진행합니다. 이후 지정 입력으로 다시 볼 수 있게 하되 입력 키·구현 방법은 미정입니다.
- 두 번째 도전에서 스킵하지 않은 경우의 이후 동작은 미정입니다. 재시도와 시청 완료 기록은 플레이어별로 구분합니다. 접속 종료 횟수만으로 첫 시청 완료를 간주하거나 첫 시청 필수 정책을 우회하지 않습니다. 도전/재시도 횟수의 정확한 집계 경계는 후속 설계 대상입니다.
- 컷신 재생·스킵으로 중복 보상이나 공동체 분기·NPC·세계 상태의 재적용이 발생하지 않도록 합니다. 컷신 스킵과 ADR-0004의 장 단위 스킵은 다른 기능입니다.

### 코옵 전투 사망·실패

- 일반 보스전은 **해당 전투 참가자 전원 사망** 시 실패합니다. 전체 공동체 접속자와 전투 참가자를 동일시하지 않습니다. 특수 전투는 별도 실패 조건을 설정할 수 있습니다.
- 사망자는 관전자 모드로 전환하고 생존 동료의 시점을 관전하며 대상을 전환할 수 있도록 설계합니다. 관전자는 전투에 개입할 수 없습니다.
- 기본적으로 전투 종료 전 복귀할 수 없으며 전투에 설정된 특정 부활 조건을 만족할 때만 재참여할 수 있습니다.
- 사망·부활로 이미 소환된 몬스터 난이도를 재계산하지 않습니다. ADR-0005의 다음 스폰 구역 재산정 정책은 유지합니다.

### 조건부 부활과 인벤토리

아래 부활 항목은 모두 **전투별 설정 데이터**로 관리합니다.

| 항목 | 확정된 설정 가능 범위 |
| --- | --- |
| 조건 | 아이템 사용·동료 행동·특정 목표 달성 등; 부활 불가 전투 지원 |
| 횟수 | 전투별 횟수 설정, 개인별 제한 또는 전투 참가자 전체 공동 횟수 공유 |
| 복귀 상태 | 체력 회복 비율과 상태 효과 |
| 위치 | 사망 위치·전투 시작 위치·제작자 지정 위치; 위치 안전성 확인 |

전투 중 사망해도 인벤토리·착용 장비를 유지하고 아이템을 떨어뜨리지 않습니다. 사망 전에 소비한 아이템은 자동 복구하지 않습니다. 조건부 부활에서도 기존 보유 아이템·장비를 유지합니다. 이는 전투 중 사망 정책이며 전투 외 사망까지 확대 확정하지 않습니다. PostgreSQL 중심 인벤토리·30초 dirty 비동기 저장·거래/지급 상태 즉시 저장은 ADR-0003 그대로입니다. 사망 직전 과거 snapshot으로 되돌리는 자동 복구를 요구하지 않습니다.

## 미정 사항과 검증 경계

- UI·카메라·관전 대상 전환·재시청 입력의 구체 구현과 순정 클라이언트 호환성.
- 두 번째 도전에서 스킵하지 않은 뒤의 동작, 도전/재시도 집계 경계·기록의 구체 저장/전이 방식.
- 퀘스트별 실제 조건·체크포인트와 실패/보고/보상 경합 처리, 개인 재시작과 공유 상태의 연결 상세.
- 전투 참가자 확정·중도 접속/종료·전투 종료 후 복귀 위치/상태, 생존 관전 대상 부재 처리.
- 전원 사망 판정과 처리 중인 부활 요청의 경합·우선순위. 이것을 자동 부활 또는 전투 실패 취소로 임의 결정하지 않습니다.
- 부활 아이템 사용 주체·소비/실패 처리, 공유 횟수 동시 요청, 안전 위치 판정·위치 불가 시 대안.
- 구체 부활 횟수·체력 비율·효과·보상 등 밸런싱은 보류. 설정 저장 형식·상세 API·물리 스키마는 미정.
- 기존 ADR의 공동체 가입·투표 상세·인던 초기화/재입장 등 미정 사항은 이번 결정 범위 밖에서 유지합니다.

후속 검증은 [S3 상세 설계](../story-world-detailed-design.md)의 Q1~Q4·N1~N2·V1~V5·B1~B5 명세를 따르며 **모두 미실행**입니다. S2 완료·S3 진행 중·S4 미착수입니다. 게임 코드·서버·DB·컨테이너 실행이나 기존 운영 설정 변경은 승인 범위 밖입니다.
