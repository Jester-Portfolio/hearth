# ADR-0012: 내부 진행 식별·저장·월드 생명주기·콘텐츠 보존

- 결정일: 2026-10-25
- 상태: **승인된 정책 / 구현·실행 검증 미완료**. 추천 모델·추천값은 별도로 표시합니다.
- 기준 커밋: `19e91531758d588441cfd401c265250f19ee1479`.
- 관계: ADR-0001~0003의 B안/기술/성능과 [ADR-0010](0010-coop-information-and-hud.md)의 가입 없는 코옵, [ADR-0011](0011-votes-boss-return-and-gathering-reset.md)의 채집 세대/보스 상태를 구체화합니다. 이전의 기존 월드 신규 지형 적용 전체 미정 표현은 보존 우선 조건을 확정하고 적용 도구는 미정으로 구분합니다.

## 사용자 확정 — 데이터 경계

| 구분 | 소유 데이터 |
| --- | --- |
| 공유 | story_run·world_instance·중요 퀘스트·고정 분기·NPC/세계 상태·주요 일지 사건 |
| 개인 | player_progress·개인 퀘스트/따라잡기/스킵·NPC 관계·장소/거점·일지/알림/HUD 설정·인벤토리/지급 이력 |
| 전투/인던 | 도전 식별/참가 상태·필요 복귀 좌표/상태·채집 템플릿/generation/다음 초기화 시각 |

스토리는 story_run_id 중심, 개인은 story_run_id+player_uuid 범위이며 스토리/경제 인벤토리는 분리합니다. 클라이언트 진행 ID를 신뢰하지 않고 다른 진행 참조를 막는 복합 키/제약 후보를 설계합니다. 가입/탈퇴/길드 테이블을 요구하지 않습니다. 실시간 투표·보스 HP·카메라는 기본 서버 메모리, 확정 분기/보상/개인 진행 등 필요한 상태만 영속화합니다. 프로세스 종료 뒤 도전 자동 재개/무손실 보장은 하지 않습니다.

## 사용자 확정 — 월드 작업

단일 Paper에서 원본 템플릿을 복제하고 기존 스토리 월드를 새 템플릿으로 자동 교체하지 않습니다. 같은 진행의 생성/로드는 단일 작업이며 동시 입장은 작업을 공유합니다. 월드 준비·개인 복원 전 조작 불가, 마지막 퇴장 후 IDLE, 유휴 대기 내 재접속은 언로드 취소, 대기 만료 뒤 저장 정리·언로드입니다. 저장 중 재접속은 작업 완료 후 처리합니다. 저장/언로드 실패를 OFFLINE 성공으로 기록하거나 손상 월드를 빈 월드로 대체하지 않습니다. 무관한 진행까지 불필요하게 중단하지 않습니다.

**IDLE 초기 5분은 ChatGPT 추천값**으로 운영 확정값이 아닙니다. 그 대기 범위 내 재접속이 취소한다는 규칙은 확정이지만 정확한 시간/경계는 S4 측정/구현 대상으로 구분합니다. 채집 초기화와 별개 수명주기입니다.

## 사용자 확정 — 저장·실패

일반 dirty 인벤토리 초기 30초 비동기 배치·변경분만 저장, 메모리 버전/DB revision 분리·오래된 결과 덮어쓰기 금지·개인별 보상/거래/일반 저장 순서 조정, NPC 상점/경제 거래 즉시 DB·보상 중복 방지/상태 즉시 저장을 유지합니다. **공동체 중요 분기는 영속화 성공 후 결과 확정**합니다. 언로드는 필요한 DB/월드 저장 확인 뒤이며 일반 상자/건축/지형은 월드 파일입니다. 매 이동 DB transaction/동기 flush는 요구하지 않습니다.

DB 실패는 성공 오기록 금지·dirty 보존, commit 불명은 새 거래 무조건 재실행 금지, 해당 기능/데이터 범위 격리·최소 로그/백업/수동 조정입니다. 전체 정지/손상 데이터 빈 초기화·강제 종료 무손실 자동 복구를 보장하지 않습니다. 이 원칙이 파일/DB 원자성을 만들지 않습니다.

## 사용자 확정 — 버전 보존

템플릿/콘텐츠 버전 분리·승인 버전에서 신규 진행·적용 버전 추적·기존 월드/건축/진행 보존입니다. NPC/퀘스트 추가는 호환성 검사 후, 정의 ID 변경/삭제로 진행 초기화/중복 보상 방지입니다. 신규 지역/건축물은 기존 변경 영역과 충돌 검사 후 적용하고 충돌 시 기존 월드 보존·업데이트 보류, 실패 시 정상 상태 유지·영향 범위/되돌리기 절차를 문서화합니다. 통째 덮어쓰기는 금지합니다.

## 추천 후보·S4 이관

**설계 추천:** PostgreSQL/월드/콘텐츠 버전을 묶는 백업 manifest 후보. 승인된 유지보수 경계에서 관련 쓰기 정리→DB/월드 상태/버전 식별 기록→별도 보관→복원 대조/rollback 시험 순서를 검토합니다. 매 아이템 이동의 고비용 checkpoint가 아니며 일상 가용 백업의 동시 원자성 보장은 아닙니다. 주기/보관/매체는 용량 측정 뒤 결정합니다.

기존 Zabbix로 서버/DB 연결·저장 실패·메모리·틱 지연을 관측하는 방향이며 항목/트리거를 생성하지 않습니다. DDL·PostgreSQL 버전·드라이버/풀 크기·manifest/배포/마이그레이션·캐시/조정자 구현은 S4 상세화/검증 대상으로 남깁니다. 숫자 추천은 사용자 검토/측정 전 확정하지 않습니다.
