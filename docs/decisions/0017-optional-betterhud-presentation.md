# ADR-0017: 선택형 BetterHud 표시 연동

- 작성일: 2026-11-09
- 상태: 승인 — 사용자가 “선택형 BetterHud 연동까지 구현”을 선택했다.
- 관계: ADR-0010의 좌상단 퀘스트/우상단 미니맵 목표와 ADR-0016의 개인 상태 정책을 유지한다. 이 결정은 개발 연동과 격리 검증 범위이며 운영 설치·팩 게시·실제 클라이언트 시험 승인이 아니다.

## 결정과 비교

순정 Paper의 기존 sidebar/Glyph BossBar는 기본 출력으로 보존한다. 정확한 상대 앵커는 BetterHud 공개 API와 생성 리소스팩을 선택형으로 연결한다. 자체 core shader를 별도로 유지하는 대안보다, 기성 엔진의 좌표/폰트 생성을 재사용하고 Hearth의 개인 정보·세션 경계만 담당한다.

고정 대상은 BetterHud `2.1.0-SNAPSHOT-448`이다. [공식 Hangar](https://hangar.papermc.io/toxicity188/BetterHud/versions/2.1.0-SNAPSHOT-448)는 Paper 1.21–26.2 지원을 표시한다. [MIT 라이선스](https://github.com/toxicity188/BetterHud/blob/master/LICENSE)와 공개 HUD/placeholder API를 확인했다. 실제 조합 검사와 아티팩트 고정은 [검증 기록](../hud-display-verification.md)을 따른다. 최신 버전 자동 상향이나 운영 채택을 의미하지 않는다.

## 경계

- 기본 `betterhud-enabled: false`, soft dependency와 compile-only API다. BetterHud 코드/라이브러리를 Hearth JAR에 합치지 않는다. 활성 모드에서는 고정 버전·보스바 병합 해제 등 전제 조건을 확인한다.
- 기존/새 퀘스트 표시를 한 출력기가 담당한다. 정상·관전/복귀의 읽기 전용 조회가 같은 출력 경로를 사용하며 NPC/진행 조작은 기존 행동 권한을 따른다. 다른 플레이어·다른 플러그인의 HUD/전투 채널을 지우지 않는다.
- 메인 스레드에서 현재 문맥/세션/조회 권한을 확인하고 문자열 프레임만 발행한다. 비동기 placeholder는 개인 actor 식별·현재 프레임·3초 만료만 확인한다. 월드·DB·게임 진행을 조회/변경하지 않는다. 이전 연결/늦은 정리가 새 연결의 화면을 변경하지 못한다.
- 퀘스트는 좌상단 `(0%,0%)+(12px,12px)`, 원형 미니맵은 우상단 `(100%,0%)+(-76px,12px)`다. 미니맵 64px와 여백 12px, 6개 목표 패널/추가 추적 안내는 표시 한도이며 저장된 추적을 해제하지 않는다. 실제 가독성과 최대 적정 수는 클라이언트 수용 전이다.
- 생성 팩의 모든 파일 내용에서 팩 ID를 도출한다. 해당 ID의 성공적인 로드 응답을 받은 연결에만 선택형 표시를 허용한다. 대기·거부·실패·다른 팩·이전 연결은 이를 허용하지 않는다. 팩 내용 변경 뒤에는 새 ID를 확인한다. Hearth는 팩을 자동 호스팅/강제 전송하지 않는다.
- Hearth 이름의 새 정의와 병합 폴더만 준비하고 기존 파일은 덮어쓰지 않는다. 스마트폰 자산을 병합한 생성 결과를 검사한다. [BetterHud FAQ](https://github.com/toxicity188/BetterHud/wiki/General-FAQ)가 다루는 셰이더/다른 팩 충돌도 실제 수용 대상이다. 순정 하단 HUD·핫바를 제거하지 않고 보스바 병합/자체 호스팅을 끈다.

## 운영·롤백

현재는 기존 S4 개발 게이트 안의 선택형 연동이다. [설정과 통합 팩 안내](../../integrations/betterhud/README.md)는 운영 실행 승인을 대신하지 않는다. 실제 적용 전에 대상 팩의 URL·해시·ID 및 기존 BetterHud 설정/자산 백업을 별도로 검토한다. 문제가 있으면 선택형 출력을 비활성화해 기본 표시로 복귀하고, 원래 설정/팩으로 되돌린다. 기존 월드·개인 DB·커스텀 파일을 삭제하거나 자동 초기화하지 않는다.
