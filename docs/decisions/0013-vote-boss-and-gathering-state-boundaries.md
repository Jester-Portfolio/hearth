# ADR-0013: 투표 마감·보스 상태·채집 초기화 경계

- 결정일: 2026-10-25
- 상태: **사용자 승인 정책 / 구현·실행 검증 미완료**. 상태명·키·처리 자료구조는 설계 후보로 구분합니다.
- 기준 커밋: `346ffc446d12155aa01abdef758f1fc294a243fc`.
- 관계: [ADR-0011](0011-votes-boss-return-and-gathering-reset.md)·[ADR-0012](0012-progress-storage-world-lifecycle-and-content.md)의 G1~G3 미결정 경계를 구체화합니다. [ADR-0006](0006-quests-dialogue-cutscenes-and-combat-revival.md)·[ADR-0007](0007-dungeon-and-boss-operations.md)의 개인 시청/정확 복귀·사망 관전·부활·보스 명단 고정은 유지합니다. 보호 엔진은 [ADR-0014](0014-worldguard-protection-engine.md)를 따릅니다.

## 1. G1 사용자 승인 — 투표 마감과 영속화

스토리 분기/보스 재도전의 채팅·전체 대상 50% 초과·초기30초·기권/미투표 비찬성·중복 차단 정책을 유지합니다. **투표 진행 중** 명단이 바뀌면 취소하고 새 명단으로 재투표합니다. 과반수 달성 시 입력을 마감하며 그 뒤 접속 변화로 결과를 재계산하지 않습니다. 스토리 분기는 DB 성공 확인 후 최종 확정/세계 적용, 실패는 미확정, commit 불명은 기존 요청 ID로 확인하고 확인 전 새 분기를 확정하지 않습니다. 마감/종료/시간 만료는 서버 순서화 경로로 판정합니다. 보스 재도전은 중복 처리로 새 도전이 두 개 생성되지 않게 하며 찬성표 전체 DB 저장은 필수가 아닙니다.

### 상태 전이 후보

| 상태/입력 | 다음 상태와 처리 |
| --- | --- |
| OPEN / 명단 변경 | CANCELLED → 새 vote_ref의 OPEN, 기존 지연 입력 무시 |
| OPEN / 과반수 달성 | INPUT_CLOSED, 선택·명단·요청 ID 고정. 이후 표/접속변경/타임아웃이 결과를 뒤집지 못함 |
| OPEN / 시간 만료·동률·미달 | UNDECIDED, 확정 없음·재투표 가능. 자동 분기 선택 없음 |
| INPUT_CLOSED / 스토리 저장 요청 | PERSISTING, run/분기 정의·예상revision·고유 요청ID로 비동기 저장 |
| PERSISTING / 성공 확인 | CONFIRMED → APPLYING → APPLIED, 고정 분기/효과 중복 검사. 공개 확정 안내는 성공 확인 뒤 |
| PERSISTING / 확실한 실패 | SAVE_FAILED, 결과 미확정·기존 상태 보존. 제한 재시도/재투표 구체 UI는 후보 |
| PERSISTING / 결과 불명 | RESULT_UNKNOWN, 동일 요청 조회·신규 경쟁 확정 차단. 단순 행 미조회만으로 실패 단정 금지 |
| INPUT_CLOSED / 보스 재도전 | RETRY_REQUESTED → 해당 기존 도전 CLOSED → 다음 준비, (attempt_ref,retry_request_ref)의 단일 처리 후보 |
| 이미 CONFIRMED/APPLIED/CLOSED / 중복 이벤트 | 기존 결과 유지, 분기/효과/새 도전 재생성 없음 |

**설계 후보:** run/attempt 단위 직렬 조정 경로·vote/attempt/session 세대 검사·DB 고유 요청키와 revision 비교. 월드 객체 접근은 서버 스레드, DB는 비동기이며 메인 스레드 대기/전체 서버 잠금은 없습니다. 저장 후 효과 적용 실패는 DB 분기를 취소하거나 재보상하지 않고 해당 효과 적용 오류/수동 조치로 구분합니다. 실제 SQL/스케줄러/재시도 한도는 S4 대상입니다.

## 2. G2 사용자 승인 — 보스 상태와 실패 연동

| 도전 상태 조건 | 처리 |
| --- | --- |
| 확정 종료 상태 | 결과 보존·후속 사망/부활/복귀 callback 거부·카메라/도전 작업 정리 |
| 참가자 전원 오프라인 | CLOSED. 이전 도전 재진입 금지 |
| 직접 필수 보스 실패 조건 확정 | FAILED/CLOSED, 해당 도전 종료 |
| 정상 전투 가능한 생존자 ≥1 | ACTIVE |
| 생존자는 있으나 전부 오프라인/복귀 보호 중, 온라인 참가자 존재 | PAUSED (해당 보스 AI/공격/스킬/전용 타이머 중지, 복귀 보호시간은 경과) |
| 참가자 전원 사망, 온라인 참가자 존재 | WIPE_WAIT, 자동 실패/재시작 없음 |

일시정지는 해당 도전에만 적용하고 다른 run/월드의 틱·게임을 멈추지 않습니다. 정상 생존자 복귀 및 보호 종료로 자동 재개합니다. 개인/무관 퀘스트 실패는 보스를 자동 종료시키지 않고 보스에 직접 연결된 필수 실패 조건 확정만 종료 원인으로 사용합니다. 정확한 종료 좌표·방향 복귀/위험 좌표 보정 금지·사망자 관전/사용량 보존·관전 카메라 정책은 ADR-0011 유지입니다. 정상 조건 분류와 결과 원인(승리/필수실패/전원종료/투표)은 별도 축으로 관리합니다.

**설계 후보:** 모든 관련 이벤트에 서버 처리 순서·attempt_ref/상태revision을 부여하고 처리 직전 도전의 최신 상태를 재검사합니다. 승리/직접실패/종료 중 먼저 유효하게 확정된 결과가 terminal이며 후속 중복 결과는 적용하지 않습니다. 사망/부활/접속 이벤트는 그 순서의 상태만 바꾸며 다음 이벤트가 이전 snapshot으로 복귀시키지 않습니다. 임의 ‘승리 우선/실패 우선’ 동시 우선순위를 추가하지 않고 직렬 순서를 시험합니다. 타이머는 보스 전용 clock과 복귀 보호 clock을 분리하는 후보이며 방어적으로 새로운 공격을 허용하지 않는 정책 이상의 게임 규칙은 추가하지 않습니다.

### 집결 규칙의 대체와 남은 충돌 C1

집결 판정은 **온라인 생존자** 기준이며 오프라인은 대기 조건에서 제외하는 승인 설계안을 반영합니다. 이는 집결 대기 집합에만 적용하며 보스 시작 명단 고정/중간 신규 참가 금지와 기존 참가자 재접속을 변경하지 않습니다. 기존 길목 사망자 보스방 진입 자동 부활·시작 인원 포함·길목 횟수 미소비도 유지합니다.

**미결정 C1:** 길목 참가자가 시작 직전 오프라인일 때 시작 명단/난이도에 예약 포함할지, 길목에서 사망한 오프라인 참가자 자동 부활을 언제/어떻게 반영할지 직접 지시되지 않았습니다. 예: A 온라인 생존·B 오프라인 생존·C 온라인 사망·D 오프라인 사망. A 집결 기준은 충족 가능하고 C 자동 부활은 기존 원칙이지만 B/D의 시작 명단·인원·복귀 상태는 임의 결정하지 않습니다. B/D를 무조건 신규 참가로 거부하거나 명단에서 삭제하지 않습니다. C1 해소 전 해당 조합의 시작 전이 기대값은 미충족으로 감사합니다.

## 3. G3 사용자 승인 — 진행 범위별 채집 초기화

같은 story_run_id 코옵은 같은 진행 범위 채집 인던을 사용하고 다른 run의 자원/초기화 상태는 분리합니다. 이는 ADR-0001의 격리 구체화이며 새 선택지가 아닙니다. 경제의 구체 소유 범위는 E1입니다.

정기 시각이면 잔류자가 있어도 사전 안내/입구 이동 뒤 초기화하며 전원 퇴장 뒤 다음 입장도 리셋 계기입니다. 획득 개인 아이템 보존, 초기화 중 신규 입장/채집 차단, 필요한 개인 저장·이동·월드 작업 정리 확인, 이동/저장/템플릿 준비 실패 시 파괴적 초기화 보류·해당 범위 ERROR_HOLD·원본 보존입니다. 동시 요청은 단일 작업으로 합치고 완료 전 generation 증가/성공 표시 금지입니다. 정기로 이미 갱신한 세대에 다음 입장 중복 리셋 금지, 초기화 중 종료/복귀는 이전 세대의 위험 좌표로 강제 진입시키지 않습니다.

### 리셋 전이와 중복 억제 후보

| 전이 | 사전 조건·성공/실패 |
| --- | --- |
| OPEN → RESET_PENDING | (run,instance,current_generation,reset_request_ref) 단일 작업; 계기 병합·새 입장/채집 보호 |
| RESET_PENDING → PREPARING/EVACUATING | 사전 안내, 새 템플릿 준비·필요 dirty 저장·입구 이동·월드 작업 정리. 어느 하나 실패하면 ERROR_HOLD/원본 보존, 파괴적 단계 금지 |
| 준비 확인 → RESETTING | 이전 세대 입장/쓰기 권한 차단 후 새 템플릿으로 리셋·보호 구역 연결 준비. 개인 아이템/보상 기록을 되돌리지 않음 |
| RESETTING → OPEN | 리셋·월드/보호 초기화·필요 저장 완료 뒤에만 generation+1, 다음 정기 시각·리셋 필요 표식 갱신·대기 입장 허용 |
| 임의 단계 실패 | ERROR_HOLD·새 성공/세대 표시 없음, 보존된 원본/작업단계 기록·제한 재시도/관리자 수동 판단 후보. 전 run 정지 금지 |

빈 인던의 퇴장 주기(empty_cycle_ref)와 그 주기를 충족한 reset_generation 표식은 **추천 후보**입니다. 정기 리셋이 빈 주기를 이미 처리했다면 다음 입장은 새 리셋을 만들지 않고, 새 방문/전원퇴장 주기가 생겨야 다음 재입장 리셋을 요구합니다. 정기 리셋을 위한 강제 입구 이동은 새 플레이 방문/퇴장 주기로 보지 않고, 그 리셋이 만든 빈 상태는 완료 표식으로 충족시켜 바로 다음 입장에 다시 리셋하지 않는 후보입니다. 동시 정기/재입장도 같은 요청 처리로 수렴합니다. 실제 표식 영속 방식·DB/월드의 비원자성·부분 리셋 오류 복구는 S4 검증이며 자동 무손실/전체 DB·월드 checkpoint를 도입하지 않습니다.

복귀 요청은 현재 generation·session을 확인하고 구세대 위치 대신 준비된 현 세대 입구 진입 또는 작업 완료 대기로 처리하는 후보입니다. 이는 보스 정확 좌표 복귀와 다른 채집 경계입니다. 일반 인벤토리 초기30초 비동기 저장은 유지하며 리셋 경계 저장 확인이 매 획득 DB 쓰기/동기 flush를 뜻하지 않습니다. 빈 인던 언로드·지연 초기화는 성능 최적화 후보이지 승인 리셋 계기를 바꾸는 기본 정책이 아닙니다.

## 4. 실행 검증 경계

정책은 승인, 상태명/요청키/조정자/표식은 구현 추천, 실제 SQL·Paper 순서/일시정지 범위·WG 연동·실패 주입/자원 측정은 S4입니다. [S3 상세 설계](../story-world-detailed-design.md) §13과 [감사](../s3-completion-audit.md)의 C1을 따릅니다. 문서 작성만 수행하며 코드/서버/DB/서비스 실행·비공개 서사 접근은 없습니다.
