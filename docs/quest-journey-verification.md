# 개인 진행 안내·NPC 책·스마트폰 행동 연결

## 구현

기존 콘텐츠 기반 `/hearthjourney` 안내를 채팅 나열 대신 **책**으로 표시하고, 코스가 등록된 격리 개발 모드의 NPC 선택창에 다음 플레이 안내를 추가했다. NPC에서 연 안내는 기존 거리·월드·엔티티·대화 유효성 및 선택창 복귀를 유지한다. 스마트폰의 다음 플레이 안내도 같은 공개 표시 모델을 사용한다.

현재 상태에 따라 다음 행동을 연결했다.

- 미수락 NPC 시작형: 가까운 담당 NPC와 기존 대화 경로. 안내만으로 직접 수락하지 않는다.
- 진행 중/보고 대기: 현재 목표 상세, 추적/추적 해제, 보고 가능한 담당 NPC 대화.
- 실패: 기존 실패 정책에 따른 재시작. 스마트폰에서는 기존 확인 화면을 사용한다.
- 완료: 다음 코스 안내를 계속하며, 본인에게 공개된 지급 대기 보상이 있으면 기존 보상 목록으로 이동한다. 지급받지 않았다고 다음 안내를 막거나 조회로 보상을 지급하지 않는다.
- 공유 단계·탐험: 기존 공동 조사 안내와 지도·일지·개인 알림으로 연결한다. 미발견 장소의 이름/좌표나 잠긴 퀘스트 제목·목표는 추가 공개하지 않는다.

`QuestJourneyView`는 기존 `Playthrough`·퀘스트/추적/공유 스냅샷에서 표시 데이터와 허용된 행동만 계산한다. 클릭 시 비동기로 최신 상태를 조회해 목표·revision·추적/공유 상태·지급 경계가 달라졌으면 실행을 거부한다. 세션/화면 교체·HOLD·조회 실패는 빈 안내나 성공으로 처리하지 않는다. DB 응답을 메인 스레드에서 기다리지 않으며 기존 저장·재시작·NPC·GUI 경로를 재사용한다.

책의 행동 버튼은 페이지마다 최대 3개로 나누고 전체 페이지 한도를 넘으면 잘라내지 않고 거부한다. 신규 스키마·콘텐츠 ID·보상 규칙·자동 추적/자동 재시작 정책·운영 활성화는 추가하지 않았다. [기존 코스](public-playthrough-verification.md), [NPC 책](npc-dialogue-book-verification.md), [공동 조사 안내](shared-progress-ui-verification.md)를 보존한다.

## 검증

- 관련 단위·회귀 **52개 PASS**. 상태별 행동·추적 변경·이전 revision·HOLD/불명 상태·잠긴 정보 비노출·개인별 상태 구분·조회/쓰기 경합과 기존 NPC/책/완료 흐름을 검사했다. 최초에는 새 시험의 저장 타입 패키지명이 잘못돼 시험 컴파일이 실패했으며, 이를 고친 뒤 실제 시험을 실행했다.
- **Paper 한 JVM·격리 PostgreSQL 한 개 PASS**, 자동 통합 한 묶음. 실제 DB의 보고 대기/revision·추적 상태에서 다음 행동을 계산하고 실제 책/54슬롯 NPC GUI/Dialog 객체를 생성했다. 책의 모든 버튼 보존·버튼 페이지 분할/총량 거부·HOLD의 오래된 행동 거부·조회 후 41슬롯 스냅샷 불변을 확인했다. 기존 보고 완료와 추적 정리, P2/다른 진행의 미수락 보존도 확인했다.
- 최종 JAR 실행/설치 해시 일치와 정상 종료·소유 프로세스/포트 반환 PASS. 저장/복원 계약이 유지되어 두 번째 JVM은 반복하지 않았다. 실행 경로·시간·실측 자원은 [결과 JSON](../verification/quest-journey-result.json)에 기록했다.

## 미검증·다음

실제 인증 클라이언트의 NPC/책/스마트폰 클릭·버튼 배치·페이지 가독성·실제 재시작/보고/추적 조작과 코스 이동은 미실행이다. 제어 경계·표시 객체·DB 검증을 실제 사용자 행동 성공으로 보지 않는다. 실제 시험은 별도 요청 전 보류하며 전체 S4는 진행 중이다. 다음 배치에서도 기존 공개 코스의 남은 연결을 묶어서 진행하고, 미정 게임 정책이나 운영 배포를 임의로 추가하지 않는다.
