# 정상 스토리 공동체 명단 복원

2026-11-18. [ADR-0010의 전체 구성원/온라인·오프라인 표시](decisions/0010-coop-information-and-hud.md)를 정상 실행에 연결했다. 기존 구현은 이번 JVM에서 등록된 연결만 조회해 재시작 뒤 접속하지 않은 기존 구성원이 빠질 수 있었다.

## 변경

기동 시 설정한 진행의 불변 PG 연결을 확인하고 두 개의 제한 SELECT/일관된 스냅샷에서 실제 저장된 전체 구성원을 복원한다. 현재 접속 허용 설정에서 빠진 과거 구성원도 같은 진행의 오프라인 명단에 포함한다. 반대로 설정에만 있고 아직 저장된 적 없는 계정은 만들거나 표시하지 않는다. 한도 초과/연결 불일치/SQL 실패는 빈 명단으로 성공 처리하지 않는다.

정상 admission의 알려진 PG 저장 성공만 명단 캐시에 반영한다. 접속이 교체된 뒤 저장 성공이 확인되어도 저장 사실은 남기되 오래된 접속에 인벤토리를 전달하지 않는다. commit 불명/실패는 성공 이벤트를 발행하지 않는다. 공동체 가입/탈퇴/권한이나 보상·개인 진척·공유 분기를 추가/변경하지 않는다.

`PaperSessionAdapter`는 저장 명단과 실제 현재 연결을 결합한다. 저장 명단 자체는 온라인/투표 대상이 아니며 다른 진행과 미등록 연결을 제외한다. 실제 접속 여부의 기존 정책은 유지하면서 교체된 Player 객체/연결의 접속 표시를 차단한다. 이름은 서버 whitelist의 캐시된 프로필과 현재 인증 접속명만 이용한다. 고정 Paper 배포의 프로필 getter가 메모리 정보를 복사하는 경로임을 확인했으며 네트워크 프로필 업데이트나 개인 저장 파일 조회를 추가하지 않았다. 캐시에서 이름을 모르는 구성원은 기존 `이름 미확인` 표시를 사용한다.

콘솔 `hearthstoryadmin members <run UUID> [page]`는 선언한 진행의 최근 확정 명단 캐시를 페이지당 6명으로 조회한다. 실제 온라인 상태/개인 정보 상세를 이 콘솔 목록으로 단정하지 않는다. 기존 `hearthrecovery`의 개인 조회 권한 범위는 유지한다.
