# 전투 종료 복귀·길목 관리 구역 초기화

2026-11-05. S4 진행 중. 기존 [보스 재도전](combat-restart-verification.md), 세션·41슬롯 저장·월드 수명주기를 재사용했다. [결과 JSON](../verification/combat-return-result.json)에 최종 실행과 자원을 기록한다.

## 구현한 범위

- 콘텐츠의 선택 설정 `exit`에 복귀 위치·방향·체력 비율·효과를 명시한다. 미등록 콘텐츠는 기존 상태를 유지하고 임의 복귀값을 만들지 않는다. 새 공개 합성 설정만 추가했으며 기존 파일 자동 덮어쓰기는 없다.
- `/hearthcombat leave`는 본인이 참가한 전투가 승리 또는 필수 실패로 확정된 뒤 사용한다. 전멸 대기·HOLD·진행 중·재도전 투표 결과를 일반 종료 복귀로 우회하지 않는다. 기존 콘솔 release 경로도 같은 저장·복귀 경계를 사용한다.
- 활성/퇴장 저장과 퀘스트·일지·공유 진행 저장 장벽을 확인한 뒤 안전한 설정 위치로 이동한다. 이동·위치·현재 세션·월드 세대를 재확인하고 카메라·게임 모드/참가 참조를 정리한 뒤 완료를 알린다. 인벤토리나 소비품은 복구하지 않는다.
- 마지막 연결된 전투 참가자의 복귀 정리 후 해당 종료 도전의 관리 보스·참조를 제거한다. 같은 JVM에서 기존 명시적 개발 시작 경로로 다음 도전을 시작할 수 있다. 온라인 명단·난이도는 새 시작 시 다시 확정한다. 다른 도전·퇴역 월드를 재생성하지 않는다.
- 저장·이동·세션·세대·정리 실패는 HOLD로 남기고 자동 반복하지 않는다. 중복 복귀는 기존 작업을 공유하며 늦은 적용 가드를 닫는다. 복귀 중 종료/새 세션은 성공으로 처리하지 않는다.

## 길목 초기화 경계

외부 `field-demo.yml`의 선택 `reset` 설정은 구역 순서와 `ALL`, `PRESERVE`, `AFTER_CHECKPOINT`를 지원한다. 체크포인트는 제작자가 등록한 구역 ID이며 존재하지 않거나 중복된 ID는 로딩 때 거부한다.

`PRESERVE`는 기존 처치·생존 몹 상태를 유지한다. `AFTER_CHECKPOINT`는 지정 구역까지 보존하고 이후 구역의 관리 몹·조우 상태만 지운다. `ALL`은 명시한 길목 구역 전체를 대상으로 한다. 다음 정상 진입 때 기존 스폰 경계로 인원을 다시 계산한다.

`PaperFieldEncounters.reset`은 서버 내부의 명시적인 저장·이동 조정 호출자를 위한 경계다. 전달한 저장 장벽 성공과 현재 진행/월드 세대 확인 후 실행한다. 요청 ID가 같으면 이후 재소환된 몹을 다시 삭제하지 않는다. 부분 제거 실패는 남은 참조와 HOLD를 보존하며 다른 진행을 초기화하지 않는다. 블록·상자·지형·월드 템플릿이나 보상 데이터를 되돌리지 않는다.

**아직 전체 길목 재도전 기능은 아니다.** 길목 진입·체크포인트 도달 판정·집결·온라인 사망자 자동 부활·보스 입장 및 `FROM_PATH` 투표 결과와의 전체 연결은 남아 있다. 현재 보스 재도전 자동 경로는 기존 `BOSS_ONLY`를 유지한다. 이 경계를 일반 필드 전체의 자동 리셋 정책으로 확대하지 않는다.

## 실제 검사

- 관련 전투·세션·저장 단위/회귀 **111개 PASS**, JAR 빌드 PASS. 종료 조건·중복·저장/이동 실패·잘못된 소유권·세션/세대 변경·종료·owner 거부, 초기화 모드·잘못된 참조·중복 요청·부분 제거 실패·다른 진행 보존을 검사했다.
- 기존 `--sessions --quests --story-batch --combat-players` 한 묶음에 검사들을 통합했다. 새 격리 경로, Paper 한 JVM·PostgreSQL 한 개 **PASS** (44.117초). 최종 JAR 일치·정상 종료·프로세스/포트 반환 확인.
- 실제 DB의 최신 dirty 저장 후 복귀 제어·인벤토리 revision 4, 실제 관리 보스 제거와 다음 시작, 실제 구역 몹의 체크포인트 이후 제거/재진입 소환·요청 재전달 시 보존을 확인했다. 실제 CAS 실패 주입 시 복귀 이동과 초기화를 실행하지 않고 DB 원본/dirty를 유지했다.
- Paper 최대 RSS 1,169,588KiB, 관측 CPU 76.75초, 준비 16.135초. 최소 관측 가용 RAM 11,554,096KiB. 기존 CPU2/nice+10·Xmx1536MiB·600초·메모리 한도 유지.

## 미검증·남은 작업

복귀 이동·회복·카메라는 서버 내부 제어 포트로 검사했다. 인증 클라이언트의 명령/이동/모드/회복 성공으로 기록하지 않는다. 실제 시험은 보류한다. 기존 전투 중 재접속의 정확한 위치·방향 복귀는 변경하지 않았다.

전원 오프라인으로 끝난 도전의 재접속 복귀, 전투/길목 상태의 프로세스 재시작 복구, 길목 전체 수명주기와 보스 패턴은 남아 있다. 이 구현의 종료 복귀는 현재 연결된 참가자 범위다. 기존 저장 형식/DB 복원 계약은 그대로라 두 번째 JVM은 생략했다. 전체 S4·정식 인던·운영 배포 완료가 아니다.
