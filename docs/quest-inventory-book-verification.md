# 퀘스트 아이템창과 책 상세 화면

2026-10-30 · 격리 개발 모드 · S4 진행 중.

## 변경된 흐름

- NPC 우클릭 시 연결된 퀘스트를 아이템창으로 표시한다. 퀘스트 아이템 이름은 `[진행 상태] 퀘스트 제목`이며, 설명 아이템을 누르면 NPC 이름·현재 상태·현재 단계/대사를 책 화면으로 읽는다. 긴 설명은 여러 페이지로 나눈다.
- 같은 NPC 창의 별도 수락·보고 아이템으로 진행한다. 현재 대화의 선택 nonce를 먼저 검증한 뒤 새 동작 nonce와 최신 revision·세션·월드·NPC·거리·권한을 재확인해 기존 저장 경로를 호출한다. 자동 시작형에는 NPC 수락 버튼이 없다. 저장 성공 후 NPC 창을 다시 갱신한다.
- `/hearthquest list`는 본인의 수락 목록 아이템창을, `/hearthquest info <quest_id>`와 목록 아이템 클릭은 책 상세를 연다. 스마트폰 퀘스트/알림에서 상세로 이동할 때도 책을 사용한다. 책의 진행 관리 링크에서는 추적·보고 대화·기존 보상/재시작 등 관리 아이템창으로 돌아간다.
- 책의 수락·보고 링크도 기존 검증 경로를 사용한다. 책을 열기만 해서는 수락·완료·보상이 발생하지 않는다. 미수락 퀘스트는 개인 목록/상세에서 공개하지 않고, NPC가 제공하는 현재 허용 선택지에서만 안내한다.
- 기존 54슬롯 GUI의 클릭 취소·다음 틱 처리·세션 확인과 41슬롯 인벤토리 보호를 재사용한다. 읽기·책 생성으로 DB 행이나 revision을 바꾸지 않는다. 실패/HOLD·이전 세션 응답을 정상 화면으로 처리하지 않는다.
- [Paper 공식 책 API](https://docs.papermc.io/adventure/book/)의 Adventure Book과 `openBook`을 사용한다. 실제 책 아이템을 플레이어에게 지급하거나 기본 인벤토리/E키를 교체하지 않는다. 새 플러그인·DB 스키마·스마트폰 아이템 정책은 추가하지 않는다.

## 검증

관련 단위·회귀 43개 PASS. 상태별 제목/현재 단계, 미수락·잠긴/잘못된 ID 비노출, 개인 표시 데이터, 긴 설명/문자 보존, NPC 수락/보고와 자동 시작 구분, 현재 대화·중복 nonce·기존 저장/조회 회귀를 확인했다.

최종 Paper 한 JVM/새 PostgreSQL 한 개 자동 검증 PASS: 내부 확인 21건, 35.197초. 실제 서버에서 GUI 아이템 이름·아이콘/holder와 Adventure 책 제목/페이지, 보고 대기→완료 DB revision·개인/진행 격리·기존 인벤토리 불변을 확인했다. 정상 종료·프로세스/포트 반환과 실행 JAR/최종 빌드 해시 일치도 통과했다. 저장 형식이 불변이므로 두 번째 JVM을 반복하지 않았다.

최종 Paper/DB 자동 결과와 JAR 해시는 [결과 JSON](../verification/quest-inventory-book-result.json)에 기록한다. GUI 객체·책 데이터 검사는 실제 사용자 클릭 성공을 뜻하지 않는다.

## 미검증

실제 NPC 우클릭→아이템 선택/수락→목표 달성→보고, 책 렌더링·페이지/버튼 클릭·화면 전환·클라이언트별 가독성은 사용자 별도 요청 전 보류한다. 일반 서버 활성화와 운영 배포는 수행하지 않았다.
