# AuraSkills 1차 정식 통합 — 숙련도 기반과 공통 월드 접근

후속 현재 사실은 [공통 전투·TPA 구현](combat-travel-verification.md)을 함께 따른다. 아래는 입장 제어 배치 당시의 범위다.

날짜: 2026-11-20. 사용자 “다음 작업 진행해”에 따라 [기술 검증 다음 순서](auraskills-technical-verification.md)의 첫 배치를 구현했다. 운영 설치/정식 바이너리 릴리스·실제 클라이언트 시험은 수행하지 않았다.

## 변경과 플레이 흐름

- 공개 `auraskills-api-bukkit:2.4.0` compileOnly adapter와 optional softdepend를 추가했다. 꺼졌을 때 Aura 클래스가 없어도 기본 생존/거주 경로가 시작된다. 활성 상태의 미설치/버전 불일치·콘텐츠 로드 실패·disable은 접근을 열지 않는다.
- 불변 정책은 여섯 역할, 특정/평균/합산/복수 AND/커스텀 숙련도, 미로드 거부와 고정 평균 분모를 지원한다. 거주는 레벨 조건에서 제외하고 기존 개인 ACL을 유지한다. 오타/누락/미사용 규칙과 알 수 없거나 비활성인 숙련도는 거부한다.
- 기존 `/월드` 메뉴의 조건 표시·선택, 비동기 이동 준비/이동 직전/teleport 이벤트, 포탈·리스폰·초기 로그인 위치를 공통 admission으로 연결했다. 이전 HousingAccess의 이동 리스너를 옮겨 서로 다른 권한 판정을 유지하지 않는다. 건축/상호작용은 기존 Housing/WG 경계를 사용한다.
- permit은 사용자 UUID·도착 월드·거주 권한 세대에 묶이고 최종 이동 때 최신 레벨/ACL을 재평가한다. 기존 접속 token·원위치·정확한 도착 좌표·이동 tombstone도 유지한다. 메인 스레드에서 PG를 기다리지 않는다.
- 활성 모드의 재접속은 데이터 로드 전 공용 스폰으로 시작한다. 제한된 리스폰은 같은 안전 위치를 사용한다. 입장 후 권한/레벨 변화는 행동 판정과 1초 주기 검사에서 확인하고 공용 복귀 또는 재접속 안내로 처리한다. 거부된 플레이어의 채취/상호작용/피해 등은 Aura 보너스 생산보다 앞선 LOWEST에서 취소한다. 이를 모든 외부 보상 경로의 최종 1회 페널티 구현으로 주장하지 않는다.

설정은 [운영 검토 예제](../infrastructure/network/skills.md)와 [정책 템플릿](../src/main/resources/skills-access.properties)을 따른다. 기능 기본값은 비활성이고 요구 레벨은 모두 명시적 `none`이다. 시험 전용 20/3 조건은 새 격리 복사본에만 썼으며 밸런스로 채택하지 않았다.

## 월드·데이터 보존 경계

실제 바인딩은 기존 기본 거주/자원 오버월드/지옥과 동적 개인 거주다. **초보 자원·엔드는 논리 역할/조건 표현만 준비했으며 물리 월드는 추가하지 않았다.** 기존 월드 묶음의 UUID가 native 경제 PG와 묶여 있어 새 월드를 조용히 추가/채택하지 않는다. 기존 엔드는 미등록 월드로 접근을 거부한다. 해당 두 자원 월드의 생성·UUID/PG 바인딩 확장은 안전한 이전 절차를 포함한 후속 범위다.

Aura YAML만 숙련도 정본이며 Hearth PG에 레벨을 이중 저장하지 않는다. 기존 schema/화폐/인벤토리/월드 registry 저장 형식은 바꾸지 않았다. 이번 두 Paper는 off/on 경로 구분 시험이며, 새 저장 형식의 두 JVM 복원을 증명하는 것으로 표기하지 않는다. 기존 Aura YAML 복원 증거는 [기술 검증](auraskills-technical-verification.md)을 따른다.

## 실행한 검사

상세 경로·해시·소유 프로세스/포트 종료는 [구조화 결과](../verification/skills-admission-result.json)에 보존했다.

- 관련 Java 단위/회귀 **25개 PASS**: 정책 9, WorldTravel 10, 기존 월드 선택 3, 거주 상태 3. Java 25 컴파일·정식 JAR·통합 fixture 빌드 성공.
- 새 소유 복사 PG에서 거주 경합/실패/원본 보존 **23개 PASS**. 권한 획득/철회의 실제 snapshot을 정식 정책에 넣어 accepted visitor/외부인/탈퇴자 판정도 확인했다. 다른 경제/스토리 행 보존 비교와 정상 PG 종료를 통과했다.
- Paper 26.2/Java 25 **off 6개 / on 12개 PASS**. off는 Aura 미설치의 선택 경로·명시 활성화 요청 거부, on은 공개 API 레벨/커스텀 조건·미로드 거부·준비 뒤 레벨 감소·다른 사용자/월드 permit 거부·실제 PG refresh의 세대 변경·개인 월드 실제 로드/ACL/좌표 경계를 확인했다.
- API 입력은 합성 오프라인 UUID 레코드와 실제 Location/ItemStack 객체다. Player/인증/클릭/사망/이동 이벤트를 합성하지 않았다. 테스트용 데이터는 새 소유 복사본에만 썼다.
- CPU 2개/nice 10, localhost, Paper heap 1536MiB/RSS 2560MiB, 합산 RSS 6144MiB, 호스트 가용 최소 6144MiB, 총 600초/작업 550초·Paper 2회 한도 안에서 종료했다. 기존 원본 control/config/registry 해시와 복사본 PG 행 보존을 확인했다.

## 미검증·제한

실제 정품 Player의 로그인/메뉴/포탈/리스폰·외부 Home/TPA 플러그인·레벨 변경 중 실제 이동, 코옵·동접·장기 부하·운영 백업/배포는 보류했다. 리스너 코드/API 판정 성공은 이러한 플레이 성공이 아니다. 표준 이벤트를 무시하는 NMS/악성 플러그인까지 우회를 막는다고 보장하지 않으며 설치 플러그인을 통제해야 한다.

새 TPA/Home 명령·30초 전투 태그·월드 PvP 소유자 설정·사망/부적·최종 보상 coordinator·정식 커스텀 콘텐츠/HUD는 이번 구현 범위가 아니다. 이후 이동 기능은 같은 최종 gate를 재사용한다. 라이선스/배포 정책은 기존 ADR-0031의 외부 배포 전 검토 경계를 유지했다.

## 다음 배치

공통 전투 상태·30초 이동 제한과 TPA 수락/최종 이동 검사를 통합하고, 사망/PvP 정책에서 확정된 부분을 함께 연결한다. XP 종류/차감 산식·기본 거주 사망 정책·부적 범위는 미정이므로 임의 확정하지 않는다. 초보 자원·엔드의 실제 월드 확장은 기존 바인딩 이전 설계와 함께 진행한다.
