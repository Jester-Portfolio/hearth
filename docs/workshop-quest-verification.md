# 공개 탐험·작업대 제작·개인 퀘스트 연결

확인일: 2026-11-08. 기준 `1821f44`. [작업대 제작](crafting-verification.md)·기존 개인 다단계/선행 조건·탐험/일지·세션/저장 경계를 재사용한다. 수치·JAR 식별·첫 실패는 [JSON](../verification/workshop-quest-result.json)에 보존한다. S4는 진행 중이며 일반 서버에서는 비활성이다.

## 구현한 플레이 흐름

1. 공개 작업대 주변을 방문하면 본인의 장소 발견·지도·일지·최초 발견 알림에 반영된다. 발견만으로 퀘스트를 수락하거나 거점을 해금하지 않는다.
2. 기존 안내원에게 `workshop_route`를 수락하고 작업대 주변 방문 → 등록 작업대의 나무 곡괭이 제작 → 공개 조사 지점 방문 → 안내원 보고를 진행한다. 단순 목표 좌표 방문이나 이미 가진 도구는 제작 목표를 충족하지 않는다.
3. 보고 완료 후 작업대 주변에 다시 진입하면 개인 선행 조건을 검사해 `workshop_followup`을 자동 시작한다. 이 의뢰는 막대기 제작 성공으로 자동 완료된다. 보상·아이템 제출·공유 진행 변경은 추가하지 않았다.
4. 기존 목록·책·스마트폰·추적·다음 플레이 안내가 현재 단계와 공개된 시설 위치를 표시한다. 보고 완료 일지를 기록하고 완료된 추적을 정리한다. 일지 자체는 추가 알림을 만들지 않는다.

새 콘텐츠는 [별도 파일](../src/main/resources/crafting-quest-demo.yml)의 퀘스트·장소·중요 일지·안내 단계로 정의한다. 기존 콘텐츠/ID/저장 기록을 덮어쓰지 않는다. `interaction: craft:<facility_id>:<recipe_id>`의 형식과 실제 시설·레시피 연결·목표 구역을 활성화 전에 검사한다. 외부 플러그인은 기존 순정 레시피/GUI/저장 기반으로 충분해 추가하지 않았다.

## 저장·권한 경계

- 제작 확인 전에 해당 개인의 수락 상태·현재 목표/revision·권한을 비동기로 읽어 고정한다. 실제 제작에 성공한 동일 진행/플레이어/시설/레시피의 일회용 요청만 목표 반영에 사용한다. 중복 요청과 이전 요청의 재사용으로 다음 목표를 건너뛰지 못한다.
- 제작 직전에 세션·월드 세대·시설·거리·권한·재료/공간과 목표 상태를 다시 확인한다. 준비 중 종료·세션 교체·목표 변경은 적용 전에 거부한다.
- **현재 제작 목표와 일치할 때만** 기존 인벤토리 저장 장벽을 기다린 뒤 퀘스트 CAS를 요청한다. 이 정리 중 조작을 제한하고, 저장 성공 뒤 목표 안내를 보낸다. 일반 제작과 미수락 제작은 기존 dirty/30초 정책을 유지하며 제작마다 별도 거래나 원장을 만들지 않는다.
- 실제 제작 후 GUI만 닫으면 현재 세션의 저장 정리는 계속한다. 종료·다른 세션에는 늦은 안내를 보내지 않고 화면을 강제로 다시 열지 않는다. 부분 적용/저장 실패는 기존 인벤토리와 퀘스트 상태를 보존하며 HOLD·관리자 확인 경계를 따른다.
- 새 작업도 진행별 저장/언로드·정상 종료 장벽에 포함한다. 소유권은 `story_run_id + player_uuid`이며 물리 월드 UUID를 DB 소유권으로 사용하지 않는다.
- V001~V009와 41슬롯 payload는 그대로다. 제작 인벤토리 저장과 퀘스트 저장은 서로 다른 DB 작업이므로 완전 원자성·강제 종료 자동 복구를 보장하지 않는다. source 저장 후 목표 저장 전 장애는 수동 확인 대상이며 아이템 삭제·빈 상태 초기화·무조건 재제작으로 자동 처리하지 않는다.

첫 실행은 기존 플레이 코스의 JVM 게이트 전달 누락으로 준비 단계에서 실패했다. 실행 도구만 수정하고 Java 검사/JAR을 불필요하게 반복하지 않았다. 첫 자동 정리 판정의 DB 풀 종료 확인 누락도 보존했으며 재시험 전에 해당 PID·포트의 반환을 별도로 확인했다. 두 번째 새 경로 실행은 정상 종료까지 PASS다.

최종 실행은 51.78초, Paper 최대 표본 RSS 1259.8MiB·CPU 81.23초였다. 기존 600초·힙 1536MiB·RSS 2.5GiB·가용 RAM 6GiB·CPU 2/nice +10 제한 안에서 실행했다. TPS/MSPT·장기 부하는 측정하지 않았다.

## 실행 및 미검증

기존 stageLifecycleRuntime으로 새 사용자 소유 `/tmp/hearth-s4-11.*` 경로를 준비하고, `verify-lifecycle.py`의 필수 인자와 `--sessions --quests --story-batch --crafting-quests --accept-eula`를 사용한다. 별도 시험 도구를 만들지 않았다. 일반 설정의 `crafting-quest-verification-enabled`·제작 게이트는 기본 꺼짐이며 운영에 자동 연결하지 않는다.

실제 인증 클라이언트의 NPC/작업대 클릭·책/GUI 조작·PlayerInventory·이동/조작 제한은 미검증이다. Bukkit 객체·제어 세션을 실제 사용자 행동 성공으로 보지 않는다. 저장 형식/복원 계약을 바꾸지 않아 두 번째 JVM·DB 프로세스 재시작은 생략했다. 실제 스마트폰 아이템·경제/보상·재료 채집 목표·운영 배포는 추가하지 않았다.
