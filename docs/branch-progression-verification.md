# 확정 분기·장 따라잡기·보상 화면 통합

2026-10-29 · 격리 개발 모드 · S4 진행 중.

## 변경

- 확정된 공동체 분기에 맞는 개인 퀘스트만 시작한다. 공개 필터와 실제 DB INSERT 모두 같은 진행의 저장된 분기를 검사한다. 미확정·다른 분기는 거부하며 정상적인 접근 거부를 저장 장애 HOLD로 취급하지 않는다.
- 장의 공통 필수 퀘스트와 분기별 필수 퀘스트를 구분한다. 공동체가 이미 완료한 장만 제공하고 해당 진행의 확정 경로만 개인 스킵 대상으로 저장한다. 다른 경로·공동체 결과·개인 발견은 변경하지 않는다.
- 스마트폰 퀘스트 화면에 보상 대기 목록·지급 상태와 장 목록·상세·직접 플레이 안내·스킵 확인을 연결했다. `/hearthphone rewards`, `/hearthphone chapters`도 본인 활성 세션만 조회한다.
- 보상은 지급 대기·지급 완료·스킵 정책 미정·설정 불일치·과거 지급 기록 없음을 구분한다. 현재 정의와 지급 기록이 일치하는 PENDING만 기존 지급 경로로 연결하며 소급 지급하지 않는다.
- 미수락 퀘스트 이름과 다른 분기 내용을 장 DTO에 넣지 않는다. 장 스킵은 확인 화면을 거치며 이미 스킵한 장의 과거 장면 재현을 구현했다고 표시하지 않는다.
- 지급·장 스킵 전후 조회 세대를 무효화한다. 기존 세션·쓰기 장벽·HOLD 검사와 함께 늦은 화면 결과를 거부한다. 조회 오류를 빈 지급 목록이나 성공으로 표시하지 않는다.

V001~V007과 기존 퀘스트 ID·저장 형식은 유지한다. 기존 평면 장의 지문 계산도 유지해 기존 스킵 기록을 호환한다. 실제 사용자 조작과 운영 활성화는 수행하지 않는다.

## 콘텐츠

기존 규칙 파일에 선택적으로 다음을 지정한다.

```yaml
quests:
  - id: branch_one_review
    requires-branch: {stage: trial_vote, choice: route_one}
chapters:
  - id: public_branch_review
    title: 공개 확정 경로 따라잡기
    shared-stage: trial_vote
    required-quests: []
    branch-stage: trial_vote
    branch-quests:
      route_one: [branch_one_review]
      route_two: [branch_two_review]
```

분기 장 목록은 해당 단계의 모든 선택지를 명시해야 하며 잘못된 ID·중복 배정·상충하는 분기 조건을 활성화 전에 거부한다. 분기 목록은 해당 퀘스트의 시작 조건도 연결한다. 새 합성 퀘스트에는 퀘스트 정의의 `requires-rules: true`를 지정해 규칙 모듈이 비활성인 환경에서 시작되지 않도록 했다. 기존 콘텐츠 자동 덮어쓰기·hot reload는 추가하지 않았다. 합성 아이템 수량은 시험값이며 실콘텐츠 밸런스 결정이 아니다.

## 검사

최종 결과는 [검증 JSON](../verification/branch-progression-result.json)에 기록한다.

- 관련 퀘스트 단위·회귀 153개: 실패 0, 오류 0. 분기 정의·호환 지문·비노출·보상 상태·확인 화면·비동기 오류/세대·규칙 비활성 방어를 포함한다.
- 첫 통합 실행은 분기 거부가 정상 발생했으나 시험에서 예외 메시지와 오류 코드를 혼동해 실패했다. 기존 오류 코드 비교 도구로 교체했으며 이력은 새 결과와 별도로 보존한다. 실패 실행의 정상 종료 단계는 완료되지 않았고 후속 점검에서 사용 포트 반환을 확인했다.
- 두 번째 실행은 투표 단계를 일반 단계 전진으로 호출한 시험 코드 때문에 `VOTE_REQUIRED`로 중단됐다. 기존 `openVote` 경로로 수정했고 도메인 코드를 우회하지 않았다. 두 실패 실행의 기록과 포트 반환 확인을 보존했다.
- 수정 후 새 격리 경로에서 순차 두 Paper JVM과 한 PostgreSQL로 재검증해 PASS했다. DB 분기 차단·선택 경로 스킵·지급 대기/정책 미정 복원·단일 지급과 중복 지급 차단·개인/진행 격리·표시 데이터·정상 종료를 대상으로 한다.

최종 실행 56.566초, 내부 세션 검사 32개 PASS. Paper 표본 최대 RSS 1,041,088KiB, 최소 가용 RAM 11,907,804KiB, Paper 관측 CPU 시간 64.07초/34.49초. 두 JVM 정상 종료와 전체 소유 프로세스·포트 반환을 확인했다. 최종 JAR과 설치 JAR SHA-256은 `41e505f53dd2912557fed1152490a552cb795fd24de43484197fa268a874c9a0`로 일치한다.

실제 NPC 클릭·채팅·GUI 버튼·PlayerInventory 적용은 미실행이다. 과거 장면/인스턴스, 스킵·재참여 보상 수치, 실제 서사·보상 정의는 확정하지 않았다. S4 전체 완료를 뜻하지 않는다.
