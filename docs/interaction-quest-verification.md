# NPC·블록 상호작용 목표와 연속 퀘스트

2026-10-29 · 격리 개발 모드 · S4 진행 중.

## 구현

기존 순서형 목표에 선택 항목 `interaction`을 추가했다. 없으면 기존 방문 목표이며, `npc:<npc_id>`는 지정 NPC 대화, `block:<x>:<y>:<z>:<MATERIAL>`은 지정 좌표·종류의 블록 우클릭이다. NPC/블록 위치는 목표 범위 안이어야 하며 잘못된 참조·좌표·재료는 활성화 전에 거부한다. 기존 퀘스트 ID·V001~V006·저장 단계는 변경하지 않는다.

이동만으로 상호작용 목표를 완료할 수 없다. 현재 목표와 일치하는 서버 측 NPC/블록 참조만 기존 CAS 저장으로 전진한다. NPC는 기존 엔티티·거리·세션·지역·WorldGuard 대화 경계를, 블록은 주 손 우클릭·실제 좌표/종류·월드·거리·WorldGuard 상호작용 경계를 사용한다. 비동기 조회 뒤 권한과 현재 세션을 다시 확인하며 DB 성공 뒤에만 안내한다. 중복 저장·HOLD·저장 장벽은 기존 조정자를 재사용한다. 아이템 소모·보상은 추가하지 않는다.

공개 합성 `contact_route`는 기존 `survey_marker` 완료 후 수락 → `survey_guide`와 다시 대화 → `(7,64,7)` 레버 우클릭 → 지정 구역 방문 → NPC 보고로 이어진다. 기존 `/hearthjourney`에도 이 흐름을 연결했다. 일반 서버에서는 계속 비활성이다.

새 격리 코스만 바닥 위에 시험 레버를 배치하고 코스 메타데이터 버전 2를 기록한다. 기존 버전 1은 그대로 읽고 보존하며 레버를 자동 추가하지 않는다. 기존 콘텐츠 파일도 덮어쓰지 않는다. 이전 코스/콘텐츠에 새 흐름을 자동 이관하는 기능은 없다.

## 최종 검사

- 관련 단위·회귀 **34개 PASS**, JAR 빌드·시험 도구 준비 PASS. 순서·방문과 상호작용 구분·잘못된 대상·중복 저장·실패 시 기존 값/HOLD·기존 콘텐츠 호환을 검사했다.
- `--sessions --quests --story-batch --quest-interactions`의 새 격리 **Paper 두 JVM·PostgreSQL 한 개 PASS**. 첫 JVM에서 수락과 NPC 목표를 저장해 `ACTIVE/revision 1`로 종료하고, 새 JVM에서 목표 인덱스와 레버 상태를 복원했다. 블록·방문·보고 후 `COMPLETED/revision 4`, A/P2·B/P1의 미수락 상태를 확인했다.
- 시험의 레버 상태 변경과 NPC/블록 목표 처리는 서버 내부 호출이다. 실제 클릭 이벤트를 합성해 사용자 성공으로 판정하지 않았다. 실제 월드·WorldGuard 구역·공유 상태 복원 및 정상 저장/언로드는 기존 도구를 재사용했다.
- 총 **48.34초**, Paper 최대 관측 RSS 약 **1004MiB**, 두 JVM 관측 CPU 시간 각각 **59.6초/30.6초**, 최소 가용 RAM 약 **11.4GiB**. 정상 종료·소유 프로세스/포트 반환 PASS. 자원 상세와 실행/설치 JAR 해시는 [결과 JSON](../verification/interaction-quest-result.json)에 기록했다. 최종 빌드 JAR과 실행 JAR이 일치하며 같은 성공 시험을 반복하지 않았다.

## 미검증·다음 작업

실제 인증 플레이어의 NPC/레버 클릭·보호 거부·거리/권한 변경·채팅/화면·연속 코스 플레이는 미검증이다. 블록 클릭은 상호작용을 목표로 하며 레버의 특정 전원 상태를 완료 조건으로 보장하지 않는다. 실제 클라이언트 시험은 별도 요청 전 보류하고, 다음 기능 배치에서도 기존 세션·개인/진행 격리·인벤토리 제한을 유지한다.
