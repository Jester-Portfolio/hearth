# 보스 참가·관전·조건부 부활 제어 기반

2026-10-29 · 격리 개발 모드 · S4 진행 중. 전체 보스전이나 실제 플레이어 전투 완성 판정이 아니다.

## 함께 연결한 기능

| 영역 | 구현·보존 경계 |
| --- | --- |
| 시작 명단 | 서버가 넘긴 검증된 온라인 참가 컨텍스트만 받아 진행/월드·중복 UUID를 검사한다. 도전 명단과 난이도 인원은 고정하며 중도 신규 참가를 거부한다 |
| 상태·시간 | ACTIVE/PAUSED/WIPE_WAIT/HOLD/CLOSED, 종료 원인 별도 관리. 정상 생존자 없음·생존자 오프라인/복귀 보호·전원 사망·전원 오프라인을 구분한다. 전투 시간과 복귀 보호 시간을 분리한다 |
| 종료 경합 | owner 경로에서 먼저 확정한 승리/필수 실패/전원 종료 결과를 보존한다. 무관한 개인 퀘스트 실패는 종료시키지 않는다. 기술 정리 RETIRED는 전원 오프라인과 구분한다 |
| 관전 | 정상 생존자만 대상으로 선택/전환한다. 대상 종료·사망·보호 중이면 다른 정상 생존자를 찾고 없으면 명시적으로 연결 해제·대기한다. 카메라 오류로 생존/사망 상태를 바꾸지 않는다 |
| 기존 참가자 복귀 | 기존 참가자만 새 세션 토큰으로 복귀한다. 정확한 마지막 위치·방향을 그대로 반환하며 위험 위치 보정을 하지 않는다. 위치 적용 확인 전에는 개입 불가, 적용 후 보호 시간이 끝나야 정상 생존자로 돌아온다. 사망/부활 사용량은 유지한다 |
| 조건부 부활 | 전투별 사용 가능 여부·서버 확인 조건 ID·개인/공동 횟수·회복 비율·상태 효과·사망/시작/지정 위치를 설정한다. 부활 위치 안전성은 적용 포트에서 검사한다. 이는 정확 좌표 재접속과 다른 정책이다 |
| 부활 경합 | 요청 ID 중복은 같은 작업으로 합친다. 대기 중 횟수를 예약해 동시 초과를 막고 적용 성공을 확인한 뒤 사용 횟수를 확정한다. 오류·결과 불명·오래된 세션/세대는 사망/예약을 HOLD로 보존한다. 종료된 도전에 늦은 결과를 적용하지 않는다 |
| 상태 표시 데이터 | 본인 진행/세션을 검사한 한국어 상태·개인/공동 부활 잔여 횟수·관전 대기 DTO를 제공한다. 타인의 개인 퀘스트/인벤토리를 넣지 않는다. 실제 HUD/스마트폰 화면 연결은 후속이다 |

## 실제 Paper 연결과 미완료 경계

`combat-demo.yml`은 중립적인 합성 정의다. 시작 인원에 비례한 체력과 설정 공격력의 실제 Zombie를 생성하고, 해당 도전만 AI를 정지/재개한다. 몹 사망 이벤트는 승리 경계에 연결하며 개발 몹의 드롭·경험치·NPC 타격·블록 변경은 차단한다. 스킬/보스 패턴 엔진은 추가하지 않았다.

이 모듈은 `combat-state-verification-enabled` 설정과 `hearth.verification.combatState` JVM 속성을 모두 요구한다. 새 격리 실행에서만 켜며 일반 서버 자동 활성화는 없다. 진행별 한 시험 도전을 유지하고 재시작 표식이 있으면 자동 재생성을 거부한다. 명단/HP/카메라 등 일시적 전투 상태를 정식 PostgreSQL 모델로 확대하지 않는다. V001~V007과 기존 월드/개인 진행/인벤토리 저장 계약은 보존한다.

**인증 플레이어 적용 포트는 아직 연결하지 않았다.** 사망/접속·복귀·부활 입력과 카메라·회복 적용 확인은 이번 자동 시험에서 제어 포트를 사용한다. 실제 Player 게임 모드/카메라·teleportAsync·체력/효과 적용, 사망 이벤트·인벤토리 드롭 방지는 실행 성공으로 기록하지 않는다. 기존 플레이어 피해 제한은 유지하므로 일반 사용자가 지금 이 모듈로 전투를 시작할 수 있다는 뜻이 아니다. 생존/사망 상태를 이유로 인벤토리를 과거 스냅샷으로 되돌리는 기능도 없다.

길목 집결/사망자 자동 부활·보스 재도전 투표·보스 패턴·아이템 소비 조건·전투 종료 후 실제 복귀 위치/세션 연동·전체 인던 수명주기는 후속 범위다. 스토리 분기 투표와 혼합하지 않는다. 3초 보호·부활 2회·절반 회복은 합성 설정값이며 운영 밸런스가 아니다. 전투 상태의 새 JVM 복원을 구현했다고 표시하지 않는다.

## 검사

최종 근거는 [검증 JSON](../verification/combat-state-result.json)에 보존한다.

- 단위·회귀 52개 PASS. 이후 이전 세션 토큰의 재사용 차단을 보강하고 영향받는 전투 조정자 15개만 재검증했다. 중복 합산하지 않는다. 최초 컴파일의 Paper/콘텐츠 동명 타입 충돌은 명시적 타입 import로 수정했다.
- fixed roster·진행 격리·혼합 상태/보호 시간·전멸 대기·관전 순환/오류·개인/공동 예약·실패/늦은 적용·종료 결과·owner 전달 거부를 포함한다. worker 완료 경로에서 직접 Bukkit/전투 상태를 바꾸지 않고 owner 경로에서 보류한다.
- `--sessions --quests --story-batch --combat-state` 한 묶음/한 Paper JVM과 신규 격리 PostgreSQL로 실제 몹 체력/AI 정지·재개·사망 이벤트·다른 진행 독립성·기존 인벤토리 보존·정상 종료를 검사해 PASS했다. 시간·세션·관전·회복 입력/출력은 내부 제어 경계이며 실제 플레이어 시험이 아니다.

실제 클라이언트·코옵 행동, 운영 배포, 장기 부하/TPS/MSPT는 미실행이다. 저장 복원 계약을 바꾸지 않아 두 번째 JVM은 실행하지 않는다.

최초 Paper 실행은 중첩 YAML의 ConfigurationSection/Map 차이로 세션 초기화에서 실패했다. Paper 로딩 경계에서 부활/고정 위치 정의를 일반 데이터로 변환하도록 수정했고 새 경로에서 재검증했다. 최초 실패의 정상 종료 검사 누락과 후속 사용 포트 반환 확인은 최종 성공으로 덮어쓰지 않는다.

두 번째 Paper 실행은 실제 플레이어가 없어 시작 청크가 로드되지 않은 시험 준비 문제로 `COMBAT_SPAWN_NOT_READY`가 발생했다. 기존 조우 시험과 같이 대상 청크를 비동기로 준비하고 소유 티켓을 시험 뒤 반환하도록 수정했다. 새 경로의 마지막 통합 실행으로 판정하며 소환 전 준비 검사는 유지한다.
