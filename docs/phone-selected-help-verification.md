# 선택한 퀘스트·장소·일지의 AI 도움

## 구현

스마트폰의 퀘스트·장소·현재 일지 상세에서 **이 항목 AI 도움**을 연다. 전체 범위 키워드 검색과 별도로 사용자가 선택한 **공개 항목 한 개**만 전송 미리보기에 넣는다. 질문을 작성하고 자료 확인 화면에서 전송해야 요청이 시작된다. 과거 연대기는 직접 현재 기록처럼 전송하지 않으며 기존 현재 일지 연결을 사용한다.

- 선택 자료의 제목을 표시하고 원래 정보로 돌아가기·항목 선택 해제를 제공한다. 비어 있는 초안에는 기본 질문을 넣고 기존 질문은 덮어쓰지 않는다. AI 화면에서 다른 메뉴로 이동할 때 입력창이 있는 화면의 초안을 저장하며 응답 대기 화면에서는 없는 입력 필드를 읽지 않는다.
- `PhoneHelp`는 기존 승인된 `GameInformation`에서 선택한 한 항목만 사용한다. 내부 기록 키·진행/플레이어 UUID·다른 항목·원본 콘텐츠는 요청에 넣지 않는다. 정렬 순서가 바뀌면 내부 키로 다시 찾고, 내용 변경·삭제·공개 범위 변경 시 전송을 거부한다.
- 전송 직전 최신 DB 조회로 항목을 재검사한다. 응답 뒤에도 비동기로 현재 항목을 다시 확인한 후 대화 기록에 반영한다. 재검사 중에는 중복 요청을 막으며 실패·시간 초과·취소·종료·세션 교체 시 응답을 표시하거나 성공 기록으로 남기지 않는다. 질문 초안은 유지한다.
- 조회 완료와 응답 적용 사이에는 기존 개인 저장 경계의 메모리 정보 세대로 추가 변경을 검사한다. 읽기는 이 세대를 변경하지 않으며 성공한 개인 UI/기록 저장만 갱신한다. 새 DB 스키마·저장 경로·아이템별 DB 쓰기·지속형 AI 대화 저장을 만들지 않았다.

기존 범위 검색·참고자료·대화 기록 제한·Mock/선택형 로컬 HTTP 인터페이스를 유지한다. LLM 모델·AI 서버를 설치하거나 실행하지 않았고 AI에 퀘스트 완료·보상·세계 상태 변경 권한을 주지 않았다. 일반 서버 자동 활성화도 없다.

## 검증

- 관련 단위·회귀 **62개 PASS**, JAR 빌드 PASS. 한 항목/정보 범위 제한, 위치 비공개 보존, 개인/공유 동일 ID 분리, 정렬 변경 후 올바른 대상, 전체 본문 변경/삭제·잠긴 퀘스트 거부, 긴 Unicode 제한과 기존 검색·대화 흐름을 검사했다.
- 응답 후 비동기 확인 대기·중복 요청·조회 실패/미승인·시간 초과·취소·늦은 세션 응답·초안 보존과 메모리 정보 세대의 읽기 불변/성공 저장 갱신·대기/HOLD/종료 거부를 검사했다. 실패/경합의 제어 시험과 실제 DB 시험을 구분한다.
- **Paper 한 JVM·격리 PostgreSQL 한 개 PASS**, 한 묶음. 기존 `--sessions --quests --story-batch --npc-topics --npc-pages --phone-dialog`에 실제 개인 기록 선택·Mock 요청·응답 후 DB 재확인을 연결했다. 확인 전 대화 기록이 비어 있고 확인 성공 뒤에만 Mock 응답이 반영되며, 프롬프트에 내부 키·소유권 UUID·다른 발견 기록이 포함되지 않는 것을 확인했다.
- 같은 묶음에서 기존 개인/진행 격리·기록 충돌/HOLD·원본 보존 및 조회 전후 탐험 기록·알림/추적/표시 설정·인벤토리 불변을 확인했다. 최종 빌드/설치 JAR 일치, 정상 종료와 소유 프로세스/포트 반환 PASS. [결과 JSON](../verification/phone-selected-help-result.json)에 실행 시간·실측 자원·원시 증거 경로를 기록했다.

## 미검증·다음

실제 인증 클라이언트의 버튼·입력 초안·Dialog 이동·화면 배치는 미실행이다. 실제 AI 모델/HTTP 서버의 응답 품질·지연·성능·정보 은폐도 검증하지 않았다. 실제 모델 통합과 자원 예산 결정은 별도 S5 작업이다. S4는 진행 중이며 실제 클라이언트 시험은 별도 요청 전 보류한다.
