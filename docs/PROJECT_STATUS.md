## 프로젝트와 현재 단계

Hearth는 현대인이 마법 없는 현실적인 중세 세계에서 과학·기술 지식을 활용하는 Minecraft RPG 및 서버 엔지니어링 프로젝트입니다. 싱글·소규모 코옵 스토리 월드와 생산·수급·가격·거래·무역 중심 경제 멀티플레이 월드를 구분합니다.

**현재 단계는 기술 스택·월드 정책 확정 후 호환성 부분 확인 단계입니다. 상세 설계·실제 빌드 검증은 미완료입니다.** 초기 기획·구조 비교·기술 검토와 운영 구조 ADR은 작성됐습니다. 세부 설계·구현·실행 검증·운영 배포는 미완료입니다. 단계와 완료 조건은 [ROADMAP](ROADMAP.md), 주요 이력은 [CHANGELOG](CHANGELOG.md)에서 관리합니다.

## 확정 기술·월드 정책

2026-10-23 사용자 확정 사항을 [ADR-0002](decisions/0002-stack-and-world-policies.md)에 기록했습니다. Paper 26.2·Java 25·Gradle·PostgreSQL, 단일 JAR 내부 기능별 모듈화, Docker Compose와 기존 Zabbix 활용을 채택했습니다. 순정 Java Edition과 별도 모드 최소화, 필요시 서버 리소스팩 제공을 기준으로 합니다. 2026-10-23 부분 확인에서 공식 Stable API `26.2.build.134-stable`의 POM·module·JAR 다운로드와 파일 일관성을 확인했습니다. Java·javac·Gradle을 찾지 못해 compileJava·jar 및 전이 의존성 해결은 미실행입니다. 공식 문서 호환성은 실제 컴파일 성공과 구분하며, 도구 설치는 수행하지 않았습니다. [빌드 검증 기록](stack-build-verification.md)에 오류·버전·SHA-256·재개 조건을 남깁니다.

버전별 공간 템플릿 복제와 기존 월드·진행 보존, 별도 NPC·대화·퀘스트 콘텐츠 정의, PostgreSQL 월드별 진행 격리, 비활성 저장·언로드·재접속 복원, 스토리·경제 인벤토리·진행 분리를 확정했습니다. 스토리 전체 보호·지정 구역 변경 허용, 경제 지정 구역 보호·일반 지역 자유도 확대와 양쪽 전용 채집 인던 중심 정책도 확정했습니다. 세부 내용과 미정 항목은 ADR을 따릅니다.

이번 부분 확인은 호스트 도구 조사, 공식 Maven 파일 다운로드·파싱·해시 대조와 문서·Git 보안 검사를 대상으로 합니다. /tmp 최소 프로젝트는 준비했지만 빌드 도구 부재로 Gradle 작업·결과 JAR 검사는 미실행이며 게임 구현·런타임 테스트 완료를 뜻하지 않습니다.

## 확정된 아키텍처

결정 원문은 [ADR-0001](decisions/0001-story-world-multiworld.md), 시스템 경계는 [architecture.md](architecture.md)를 따릅니다.

- B안: 하나의 Paper 서버 프로세스에서 진행별 독립 월드를 운영합니다.
- 싱글은 자신만의 진행·월드를 가지며 코옵 파티는 하나의 진행·월드를 공유합니다.
- 퀘스트·NPC·월드 변화·플레이어 상태를 진행별로 격리하고 개인 상태는 그 안에서 플레이어별로 구분합니다.
- 비활성 월드는 저장 후 언로드하고 재접속 시 복원합니다.
- 필수 로컬 AI 스마트폰 어시스턴트는 공통 서비스를 쓰되 진행별 정보 접근을 격리합니다.
- 논리 진행 ID와 물리 서버·월드 배치를 분리해 향후 A안 확장 가능성을 유지합니다.

스토리·경제 데이터 분리도 유지합니다. B안은 스토리 운영 구조 결정이며 경제 월드의 프로세스 배치를 확정하지 않습니다. 위 항목은 구현 결과가 아닌 설계 결정입니다.
