# Hearth 프로젝트 현황

마지막 확인: **2026-10-29**. 구현 확인 기준은 현재 main의 코드와 아래 기능별 검증 기록이다. 문서 정리와 게임 시험은 각 기록의 실행 범위로 구분한다. [과거 현황](PROJECT_STATUS-archive-2026-10-27.md)은 이력으로 보존하며 현재 상태는 이 문서를 우선한다.

## 프로젝트 목표·현재 단계

Hearth는 현대 과학·기술 지식을 마법 없는 중세 세계에서 활용하는 Minecraft RPG 게임 서버다. 싱글·소규모 코옵 스토리 월드와 생산·수급·가격·거래·무역 중심의 별도 경제 월드를 개발한다. **스토리 월드의 로컬 AI 스마트폰 어시스턴트는 필수**이며 경제 월드 AI는 제거 가능한 선택 기능이다. 시험 도구와 기술 검증은 게임 구현을 지원하는 수단이다.

- **S0~S2 완료, S3 설계 완료, S4 핵심 시스템 구현·통합 진행 중.** S5 필수 로컬 AI·S6 플레이 범위/성능·S7 운영 준비 및 경제 E1~E3는 미완료다.
- 확정 기반: Paper 26.2·Java 25·Gradle·PostgreSQL·단일 모듈형 JAR, 한 Paper의 진행별 독립 월드(B안), WorldGuard 보호. 논리 소유권은 `story_run_id` 및 `story_run_id + player_uuid`이며 스토리/경제 데이터는 분리한다. AI 기술과 경제 프로세스 배치는 미정이다.
- 현재 기능은 격리 개발 모드의 프로토타입이다. 전체 게임 완성·일반 서버 자동 활성화·운영 배포를 뜻하지 않는다. 정책 정본은 [ADR](decisions/README.md), 단계별 완료 조건은 [ROADMAP](ROADMAP.md)이다.

## 남은 구현·결정·검증

- **미구현**: 실제 콘텐츠용 보상 정의·호위 실패 이벤트·과거 장면 재현, 컷신·길목/체크포인트 초기화·보스 정식 종료 복귀·패턴·전체 인던 등 승인 설계의 남은 게임 기능, 실제 빠른 이동·지도 렌더러/미니맵, 필수 로컬 AI, 경제 게임 기능 및 운영 배포. 각각의 범위와 선행 정책을 정한 기능 배치로 진행한다.
- **미정**: AI 기술/자원 예산, 경제 배치·규칙, 미승인 스마트폰 아이템 운영 세부·컷신 일부 후속 동작, 실제 콘텐츠/보상 수치·밸런스·수용량. 이미 승인된 ADR 정책을 다시 미정으로 돌리지 않는다.
- **미검증**: 기존 부분 시험 밖 실제 클라이언트 상호작용, 실사용 코옵 경합·전체 플레이 흐름, 전체 부하/TPS/MSPT·장기 누수·운영 복구/배포. 자동 성공을 이 범위의 성공으로 기록하지 않는다.
- 성능 우선 저장·진행 격리·오류 HOLD·원본 보존·로그/백업 기반 관리자 수동 대응은 유지한다. 완전 자동 무손실 복구는 보장하지 않는다.

## 다음 배치에서 해소할 연결 공백

- `PaperSessionAdapter`는 활성 세션에서 커서 없는 숫자키/Shift/보조 손/슬롯 버리기와 비컨테이너 시설을 허용한다. 커서 클릭·드래그·제작·컨테이너·피해/공격은 격리 안전을 위해 제한한다. 저장 기반 구현을 일반 플레이의 인벤토리/제작/전투 완성으로 해석하지 않는다. 다음 배치에서는 필요한 상호작용만 기존 41슬롯·저장 경계 안에서 선정하며 제한을 일괄 해제하지 않는다.
- `PaperQuestAdapter`는 NPC 기본 숨김과 유효한 세션/지역 권한에 따른 노출, 개인 퀘스트 표식을 구현했다. [검증](npc-views-verification.md): 관련31개·한 JVM/PG 서버 속성/표시 데이터 PASS. 실제 플레이어별 화면·표식·클릭은 미검증이며 비밀 콘텐츠 배포 전 실제 정보 공개 경계를 확인해야 한다.
- 공유 진행은 등록된 NPC의 아이템창/책과 스마트폰 Dialog의 공동 조사 안내에서 조건 확인·공유 단계 진행/채팅 투표 시작으로 연결된다. 실제 분기 선택·집계는 채팅에서만 진행하며, 개인 퀘스트는 기존 NPC/이동 경계를 사용한다. 전체 실제 게임플레이 완성 및 운영 승인은 별도로 판단한다.

공동 조사 책·스마트폰 Dialog에 공개 목표/온라인 조건 확인과 revision·단계가 고정된 실행 요청을 통합했다. 오래된 화면·세션 교체·중복 요청·HOLD를 거부하며 기존 CAS/채팅 투표를 재사용한다. [최신 통합 기록](shared-progress-ui-verification.md): 관련42개·정상 및 SQL 실패/불명 결과 전용 Paper/PG 경로 최종 PASS, 실제 사용자 행동 미검증. S4는 진행 중이다.

슬롯 조작·비컨테이너 시설·조작 도움말을 기존 세션/저장에 연결했다. [검증](player-interactions-verification.md): 관련25개·한 JVM/PG 내부 슬롯 저장/재접속 PASS. 실제 키 입력·시설 이벤트는 미검증.

본인 공개 게임 정보 조회(`/hearthinfo`)와 외부 모듈용 비동기 조회 경계를 연결했다. [검증](game-information-verification.md): 관련24개·한 JVM/PG 조회/DB 불변 PASS. 스마트폰의 선택형 공개 정보/대화 전달·Mock 응답·취소와 상태 변경 후 응답 거부까지 [연결](phone-ai-context-verification.md)했다. 실제 모델 및 정식 S5 검색·캐시·응답 품질은 미검증/미구현이다.

퀘스트 목록 필터·상세/추적/알림 연결과 가까운 NPC 보고 대화 열기를 통합했다. [검증](quest-navigation-verification.md): 관련25개·한 JVM/PG 수락→보고→완료/추적 정리 PASS. 실제 GUI/NPC·WorldGuard 사용자 권한 동작은 미검증이다.

콘텐츠 기반 `/hearthjourney`와 새 격리용 도보 코스를 준비하고 개인 조사→공유 조건/투표→탐험 개방→다단계/후속 퀘스트→발견/일지/알림을 연결했다. [검증](public-playthrough-verification.md): 관련29개·두 JVM/PG 연속 흐름·기록/수정 바닥 복원 PASS. 실제 코스 플레이·새 수동 경로는 미검증이다.

개인 목표에 단계별 정형 위치 공개(정확/탐색 구역/비공개)를 연결했다. [검증](quest-locations-verification.md): 관련22개·한 JVM/PG 표시/진행 경계 PASS. 기존 저장 계약은 유지하며 실제 화면·목표 마커는 미검증이다.

NPC의 여러 페이지 대화·조건부 질문·퀘스트를 같은 아이템 선택창과 책으로 연결했다. 책에서 수락/거절·대화 이동·선택창 복귀를 제공하며 메뉴 복귀는 상호작용 목표를 다시 처리하지 않는다. [최신 검증](npc-dialogue-book-verification.md): 관련52개·한 JVM/PG PASS, 실제 책/아이템 클릭·화면·거리/권한 변화는 미검증이다.

NPC·블록 상호작용 목표와 방문 목표를 한 퀘스트에 연결하고 새 공개 코스에 레버를 추가했다. [검증](interaction-quest-verification.md): 관련34개·두 JVM/PG 단계/레버 복원·개인/진행 격리 PASS. 기존 코스 자동 이관과 실제 NPC/블록 클릭은 미실행이다.

확정 분기별 개인 시작·장 스킵과 보상/장 스마트폰 화면을 연결했다. 실제 클라이언트 조작과 미정 스킵 보상·과거 장면 정책은 유지하며 [범위와 검사 결과](branch-progression-verification.md)를 따른다.

## 다음 개발 목표

1. **우선 추천**: 기존 NPC·개인 퀘스트·공유 단계/분기·탐험·스마트폰을 연결하는 공개 테스트 게임플레이 통합 배치. 실제 연결 공백을 특정해 기능적 시작~완료 흐름과 필요한 플레이어 상호작용을 함께 완성한다. 다음 구현 범위의 승인을 대신하지 않는다.
2. 미구현 핵심 게임 기능 보완과 S5에 필요한 권한 있는 실제 게임 정보 조회 경계를 관련 배치로 묶는다. 시험 확장만 반복하거나 완료 가능한 기능을 소기능별로 잘게 나누지 않는다.
3. 클라이언트 보류 중에도 독립적인 구현·자동 검증은 계속한다. S5·S6·경제는 별도 완료 조건을 유지한다. Issue #1·#2 완료는 보존하고, Issue #3은 확인 당시 이미 `not_planned` 종료 상태여서 수정하지 않았다.

## 최근 실제 시험과 안정성 보완

인증된 한 명의 접속·초기 인벤토리 복원, 수락 전 목표 방문의 미수락 유지, 별도 지역 자동 시작과 목록 조회를 부분 관측했다. NPC 오류 안내와 시간 상한 종료 중 표시 정리 예외가 확인됐다. 대화 조회 경합·중복 클릭과 종료 정리 누락을 보완했으며 [관측·검증 기록](npc-session-stability-verification.md)에 원래 실패와 실제 행동 미검증 범위를 보존한다. 실제 클라이언트 시험은 다시 보류하며 S4는 진행 중이다.

퀘스트 선택·수락/보고를 NPC 아이템창에 연결하고 제목/상태 아이템의 상세를 책 화면으로 표시한다. 목록·스마트폰 상세도 같은 책 경로를 사용한다. [구현·검증](quest-inventory-book-verification.md)의 자동 검증과 실제 클라이언트 미검증을 구분한다. 기존 DB/진행·인벤토리 정책은 유지한다.

스마트폰 Dialog 홈·개인 AI 입력/응답·Glyph/아이템 리소스팩 프로토타입을 추가했다. 기존 공개 정보의 목록·상세·페이지 이동과 표시 설정 6개를 연결하며 Mock/선택형 로컬 HTTP 어댑터와 도움 범위별 공개 정보 검색·전송 미리보기·참고자료 상세·대화 전달·취소/최신 정보 재시도·질문 초안을 연결했다. AI 실패 질문 재시도·대화 정리, 퀘스트 상태별 목록/추적/가까운 NPC 보고, 개인 알림, 일지 4분류/연대기·공동체 정보 3종·공개 지역/확정 분기 읽기에 더해 실패 퀘스트 재시작·지급 대기 보상·장 따라잡기/스킵 확인·등록된 다음 플레이 안내를 연결했다. [결과·제약](phone-dialog-verification.md): 실제 클라이언트와 실제 모델은 미검증이며 기존 스마트폰 GUI를 보존한다. S4는 진행 중, 정식 S5 AI 통합은 완료하지 않았다.
