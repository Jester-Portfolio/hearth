## 프로젝트와 현재 단계

Hearth는 현대인이 마법 없는 현실적인 중세 세계에서 과학·기술 지식을 활용하는 Minecraft RPG 및 서버 엔지니어링 프로젝트입니다. 싱글·소규모 코옵 스토리 월드와 생산·수급·가격·거래·무역 중심 경제 멀티플레이 월드를 구분합니다.

**현재 단계는 S2 완료(빌드·API 경로 검토·후속 성공 기준 정리), S3 상세 설계 초안 작성·검토 진행 중입니다. 런타임 검증은 미실행입니다.** 초기 기획·구조 비교·기술 검토와 운영 구조 ADR은 작성됐습니다. 세부 설계·구현·실행 검증·운영 배포는 미완료입니다. 단계와 완료 조건은 [ROADMAP](ROADMAP.md), 주요 이력은 [CHANGELOG](CHANGELOG.md)에서 관리합니다.

## 확정 기술·월드 정책

2026-10-23 사용자 확정 사항을 [ADR-0002](decisions/0002-stack-and-world-policies.md)에 기록했습니다. Paper 26.2·Java 25·Gradle·PostgreSQL, 단일 JAR 내부 기능별 모듈화, Docker Compose와 기존 Zabbix 활용을 채택했습니다. 순정 Java Edition과 별도 모드 최소화, 필요시 서버 리소스팩 제공을 기준으로 합니다. 2026-10-23 부분 확인에서 공식 Stable API `26.2.build.134-stable`의 POM·module·JAR 다운로드와 파일 일관성을 확인했습니다. 이후 사용자 승인으로 공식 체크섬 검증된 Temurin JDK 25.0.5+8-LTS를 사용자 전용 경로에, Gradle 9.1.0을 /tmp에 준비했습니다. 기존 최소 프로젝트의 전이 의존성 해결·compileJava·jar가 성공했고 메인 클래스(major 69)·plugin.yml 포함 및 API 미포함을 확인했습니다. [빌드 검증 기록](stack-build-verification.md)에 버전·명령·체크섬·산출물 근거를 보존합니다. 공식 문서 확인, 실제 최소 빌드 성공, 미실행 런타임 검증을 구분합니다.

버전별 공간 템플릿 복제와 기존 월드·진행 보존, 별도 NPC·대화·퀘스트 콘텐츠 정의, PostgreSQL 월드별 진행 격리, 비활성 저장·언로드·재접속 복원, 스토리·경제 인벤토리·진행 분리를 확정했습니다. 스토리 전체 보호·지정 구역 변경 허용, 경제 지정 구역 보호·일반 지역 자유도 확대와 양쪽 전용 채집 인던 중심 정책도 확정했습니다. 세부 내용과 미정 항목은 ADR을 따릅니다.

S2 추가 검사에서는 월드 생성·식별·이동·저장·언로드, 대표 보호 이벤트와 인벤토리 API 참조 코드를 같은 고정 API로 컴파일했습니다. 후속 런타임 시험 성공 기준과 위험을 기록해 S2의 기술 경로·기준 정리 범위를 완료했습니다. [S3 상세 설계 초안](story-world-detailed-design.md)은 상태 전이·PostgreSQL 키/제약·버전 연결·보호/채집·복구 후보를 제안합니다. SQL·게임 구현은 없으며 DB·AI·멀티월드·NPC·퀘스트 실제 동작·성능과 서버 로딩은 미검증입니다.

## 인벤토리·아이템 운영 정책

사용자 확정 사항을 [ADR-0003](decisions/0003-inventory-performance-and-recovery.md)에 기록했습니다. 성능과 원활한 플레이를 복잡한 자동 복구보다 우선하며 일반 상자·창고는 월드 파일, 플레이어 인벤토리는 PostgreSQL 중심으로 관리합니다. 정상 동작의 기본 동시성·저장 순서·진행 격리는 유지하고 일반 클릭별 DB 트랜잭션/동기 flush는 요구하지 않습니다. 일반 인벤토리는 변경된 데이터만 초기 30초 간격으로 비동기 배치 저장하며 성능 측정 후 조정할 수 있습니다. NPC 구매·판매/플레이어 경제 거래는 거래마다 즉시 DB 반영하고, 퀘스트 보상은 중복 방지·지급 상태 즉시 저장 방향입니다. 스토리·경제 전환은 이전 인벤토리 저장 완료를 확인합니다.

고비용 체크포인트·거래 보관 시스템·완전 자동 복구는 필수 범위에서 제외했습니다. 추가 안전장치는 단순·저비용일 때만 검토하고 부하·지연이 크면 제외합니다. 예상치 못한 장애의 일부 유실·복사는 최소 오류 로그·백업을 근거로 관리자가 수동 조정할 수 있습니다. 자동 무손실·모든 상황의 복사 방지를 보장하지 않습니다. 이번에는 설계 정합성만 검사하며 게임·복구·성능 테스트는 수행하지 않았습니다. S2 완료/S3 진행 중 상태는 유지합니다. 최신 미저장 메모리를 포함하는 거래 후보, 자동 저장의 stale 덮어쓰기 방지, DB 실패/commit 불명·메모리 적용 실패 처리를 S3에 추가했습니다. 메모리·DB·월드 파일 간 원자성이나 모든 장애의 무손실은 보장하지 않습니다.

## 확정된 아키텍처

결정 원문은 [ADR-0001](decisions/0001-story-world-multiworld.md), 시스템 경계는 [architecture.md](architecture.md)를 따릅니다.

- B안: 하나의 Paper 서버 프로세스에서 진행별 독립 월드를 운영합니다.
- 싱글은 자신만의 진행·월드를 가지며 코옵 공동체는 하나의 진행·월드를 공유합니다.
- 퀘스트·NPC·월드 변화·플레이어 상태를 진행별로 격리하고 개인 상태는 그 안에서 플레이어별로 구분합니다.
- 비활성 월드는 저장 후 언로드하고 재접속 시 복원합니다.
- 필수 로컬 AI 스마트폰 어시스턴트는 공통 서비스를 쓰되 진행별 정보 접근을 격리합니다.
- 논리 진행 ID와 물리 서버·월드 배치를 분리해 향후 A안 확장 가능성을 유지합니다.

스토리·경제 데이터 분리도 유지합니다. B안은 스토리 운영 구조 결정이며 경제 월드의 프로세스 배치를 확정하지 않습니다. 위 항목은 구현 결과가 아닌 설계 결정입니다.

## 미결정 사항과 미검증 항목

미결정 사항은 [S3 재감사](s3-completion-audit.md)의 C1을 우선합니다. 오프라인 길목 참가자의 보스 시작 명단/난이도·자동부활/기존 참가자 복귀 권리 연결이 남습니다. G1 입력마감/DB결과 경계·보호자만 남는 일시정지·story_run 채집 범위/오류·WorldGuard 보호 책임/시험 행렬은 후속 명세로 구체화했습니다. SQL/UI 기술·수치는 S4 이관 또는 의도적 보류이고 가입 기능은 없습니다. 채집 리셋 계기/지도 공개/채팅 투표 정책은 확정입니다. 경제 E1/AI 기술은 별도 범위입니다.

미검증 항목: 진행별 전체 상태 격리, 템플릿 복제, 저장·언로드·재접속 경합, 중복 보상·장애 복구, AI 정보 누출 방지, 기존 서비스와 AI를 포함한 CPU·RAM·I/O·지연, A안 이전 가능성입니다. 상세 시험 계획은 [구현 가능성 검토](story-world-feasibility.md)에 보존합니다.

협업·갱신 규칙은 [AGENTS.md](../AGENTS.md)에 둡니다. 이 문서는 현재 사실을 요약하고 상세 설계·검증 절차·변경 이력은 링크로 참조합니다.

공동체·개인 퀘스트, 고정 분기와 장별 따라잡기/스킵의 확정 정책은 [ADR-0004](decisions/0004-community-quests-and-chapter-skip.md)를 따릅니다. 중요 퀘스트는 당시 접속한 공동체 구성원 전원의 조건 충족이 필요하며 비접속자는 제외합니다. 개인 완료·보상은 구분하고, 따라잡기·스킵은 공유 분기·NPC·월드 상태를 변경하지 않습니다. 신규 접속 시 현재 단계는 중단하지 않고 다음 중요 단계에서 전원 조건을 재검사하며, 분기는 전체 대상의 50% 초과 투표로 선택합니다. 가입은 제외, 보상/과거 재현은 보류·단계/commit 경합은 감사 미결정이며 채팅 투표 정책은 확정입니다.

이전 `b3117e6`에서 S3 모델의 기존 파티 탈퇴·분할·병합 후보를 현행 요구에서 제외하고 공동체/개인 상태·고정 분기·장별 스킵 후보와 C1~C9 후속 시험 명세를 정리했습니다. 문서 검사만 수행하며 게임 시험은 모두 미실행입니다. S2 완료·S3 진행 중을 유지합니다.

이전 공동체 정책 갱신의 문서 검사는 `b3117e6`에 기록했습니다. 이번 검사 범위는 변경 문서의 상대 링크·정책 정합성·diff 및 Gitleaks이며 실제 결과는 작업 보고와 Git 이력에 남깁니다. 게임 기능 검증 결과는 아닙니다.

## 이전 작업 기록 (2026-10-23~25, 당시 미정은 ADR-0010~0012로 갱신)

### 추가 확정과 남은 S3 범위 (2026-10-23)

[ADR-0004](decisions/0004-community-quests-and-chapter-skip.md)에 신규 접속 후 다음 중요 단계 재검사와 과반수 분기 투표를 반영했습니다. [ADR-0005](decisions/0005-dungeon-spawning-and-difficulty.md)에 내부 진입 스폰·더 넓은 경계의 소환 시점 인원 산정·난이도 고정·다음 구역 재산정·중복 억제를 기록했습니다. 채집 인던 정책은 별개로 유지합니다. 보상 로직/설정 분리 원칙은 S3에 기록했고 수치·배율·스킵·재참여 밸런싱은 보류했습니다. 설정 저장 형식은 미정입니다.

S3에는 단계 경계/경합·투표 상세, 스키마·저장/실패 처리·보상 설정 적용 방식, 전투 인던 미정 항목 및 테스트 입력 구체화가 남습니다. C1~C13·D1~D5·R1~R2는 계획이며 모두 미실행입니다. **S2 완료·S3 진행 중·S4 미착수**를 유지합니다. 실제 스토리·비밀·반전·결말·원고를 추가하지 않았으며 비공개 스토리 저장소에 접근하지 않았습니다.

## 퀘스트·연출・전투 사망/부활 추가 확정 (2026-10-24)

[ADR-0006](decisions/0006-quests-dialogue-cutscenes-and-combat-revival.md)과 [S3 초안](story-world-detailed-design.md)에 퀘스트 시작/보고 대기/실패 설정, 대화 데이터/UI 원칙, 개인 컷신 시청/재시도 기록, 당시 전원 사망 실패·관전·조건부 부활·전투 인벤토리 유지를 반영했습니다. 보스 전원 사망 실패는 후속 ADR-0007의 전멸 대기로 대체합니다. 진행용 체크포인트와 고비용 저장 체크포인트, 개인 컷신 스킵과 장 스킵을 구분했습니다. ADR-0003 저장 정책·ADR-0004 공동체 결과/투표·ADR-0005 난이도 고정은 유지합니다.

새 Q1~Q4·N1~N2·V1~V5·B1~B5 시험 계획은 모두 미실행입니다. UI/카메라/관전 입력 검증, 스킵 거절 후 동작·시도 집계, 전투 참가자·종료 복귀·부활/전원 사망 경합, 횟수/소비/위치 안전성 실패 처리가 남으며 수치·밸런싱은 보류입니다. **S2 완료·S3 진행 중·S4 미착수**입니다. 변경 문서 링크·정합성·diff·Gitleaks 검사를 수행하고 실제 결과는 작업 보고와 Git 이력에 남깁니다. 게임 기능·서비스를 구현/실행하지 않았고 비공개 스토리 저장소에 접근하거나 서사를 추가하지 않았습니다.

## 인던 유형·보스 운영 추가 확정 (2026-10-24)

[ADR-0007](decisions/0007-dungeon-and-boss-operations.md)에 필드 구역별/보스 시작 명단별 난이도, 생존 집결·길목 사망자 자동 부활, 길목/보스 부활 횟수 분리, 길목 초기화 3종·보스 재도전 범위, 중도 신규 합류 금지·기존 참가자 복귀, 전멸 대기·전원 접속 종료·재도전 운영 투표를 기록했습니다. ADR-0005의 적용 범위와 ADR-0006의 보스 전원 사망 실패를 후속 결정으로 갱신했습니다. 개인 컷신 기록은 도전 재시작으로 초기화하지 않습니다.

복귀 대기/관전/오프라인 혼합·접속/투표/집결 경합, 안전 보정·정확한 시간/수치, 초기화 실행/저장/보상 억제 상세는 미정입니다. F1~F2·O1~O12는 모두 미실행 시험 계획입니다. **S2 완료·S3 진행 중·S4 미착수**를 유지하며 게임 구현/실행·운영 변경·비공개 서사 접근은 없습니다. 문서 검사 결과와 결과 커밋은 작업 보고/Git 이력에서 확인합니다.

## 탐험·스마트폰 추가 확정 (2026-10-25)

[ADR-0008](decisions/0008-story-exploration-regions-and-fast-travel.md)에 메인 기반 공동체 자유 탐험 개방·지역 접근 3종·개인 직접 방문 거점/시설 이동, [ADR-0009](decisions/0009-smartphone-item-gui-and-information.md)에 순정 인벤토리 보존·전용 아이템/슬롯 GUI·기본 6메뉴·알림·기본 채팅 AI·월드 지도/상시 미니맵 구분을 기록했습니다. 자유 탐험 개방은 개인 퀘스트를 완료시키지 않고 지도는 빠른 이동 수단이 아닙니다. 기존 ADR-0001~0007·필수 로컬 AI·비공개 정보 격리는 유지합니다.

구체 챕터/지역/조건, 이동 수단/비용/시간, 스마트폰 발급/고정/양도/복구·식별/입력 충돌, GUI 표현·지도 공개/렌더링/미니맵 구현/성능은 미정·미검증입니다. S3에 논리 데이터·접근 검사 후보와 E1~E6/H1~H4/P1~P7/M1~M3 미실행 계획을 추가했습니다. **S2 완료·S3 진행 중·S4 미착수**입니다. 문서/보안 검사만 수행하고 게임/서버/DB/운영 변경·비공개 서사 접근은 하지 않았습니다. 결과 커밋과 검사 근거는 Git 이력/작업 보고에서 확인합니다.

## 통합 정책과 완료 감사 (2026-10-25 현재)

ADR-0010~0012와 S3 §11~12에 확정/추천/구현 미정/S4 검증을 구분했습니다. 가입·관리자 구성원 변경 기능, 보스 위험 위치 보정, 공동체 알림은 현행 요구에서 제외합니다. 지도/일지/3개 공동체 하위 기능·개인 알림/설정·다중 목표/HUD, 채팅 투표 초기30초·대상변경 재투표, 정확 위치/방향 복귀·관전 자동 전환/해제·혼합 일시정지, 채집 정기/빈인던 재입장 리셋을 반영했습니다. 추천3초/5분·작업ID/generation·캐시·백업 후보를 승인값으로 기록하지 않았습니다.

**이전 통합 감사는 S3 진행 중**이었습니다. 당시 G1~G4 공백의 후속 판정은 아래 최신 재감사를 따릅니다. [항목별 감사 표](s3-completion-audit.md)를 사용자 검토에 제시하며 실제 기능·SQL·부하는 미실행입니다. S2 완료·S4 미착수, 운영 환경/비공개 서사는 접근/변경하지 않았습니다.

## G1~G4 재감사 — 최신 (2026-10-25)

[ADR-0013](decisions/0013-vote-boss-and-gathering-state-boundaries.md)은 과반수 입력마감/DB확정·순서화 경합, 정상생존/보호자 일시정지·필수 실패/개인 실패 구분, 동일 story_run 채집 범위/리셋 준비 실패·단일 세대 경계를 확정합니다. [ADR-0014](decisions/0014-worldguard-protection-engine.md)로 스토리·경제 기본 보호 WorldGuard, WorldEdit 제작/관리+선택 dependency 검증, Hearth 콘텐츠/run/리셋 전용 책임을 채택했습니다. 버전 호환/플래그/런타임·부하는 S4 미검증입니다.

감사: **G1 충족, G2 부분 충족(C1 미충족), G3 충족, G4 명세 충족·실행 S4 이관**. C1은 집결 대기에서 오프라인을 빼는 것과 기존 사망자 자동부활·보스 시작 명단/난이도를 연결하는 정책입니다. 오프라인 길목 참가자를 삭제/신규참가 거부로 임의 처리하지 않았습니다. S3 진행 중·사용자 검토 대기, S2 완료·S4 미착수입니다. 문서/공식 문서 열람/보안 검사만 수행하며 플러그인 다운로드·코드/SQL/서버/DB 실행·운영 변경·비공개 서사 접근은 없습니다.
