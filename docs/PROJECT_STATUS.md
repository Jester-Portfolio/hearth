## 프로젝트와 현재 단계

Hearth는 현대인이 마법 없는 현실적인 중세 세계에서 과학·기술 지식을 활용하는 Minecraft RPG 및 서버 엔지니어링 프로젝트입니다. 싱글·소규모 코옵 스토리 월드와 생산·수급·가격·거래·무역 중심 경제 멀티플레이 월드를 구분합니다.

**현재 단계는 S2 완료(빌드·API 경로 검토·후속 성공 기준 정리), S3 설계 완료, S4-4 최소 PostgreSQL 저장 기반·실DB 격리 검증 통과 상태이며 S4 전체는 진행 중입니다. S4-3 접속 행동 검증은 미실행입니다. 최소 Paper 로딩·A/B 블록/식별자 보존·WorldGuard 구역 API smoke는 통과했고 전체 기능/런타임 시험은 남습니다.** C1 사용자 최종 승인과 [12영역 감사](s3-completion-audit.md)를 근거로 설계 기준선을 완료했습니다. 명시적 보류 정책·구현 후보를 모두 확정했다는 뜻은 아니며 기능 구현·실행 검증·운영 배포는 미완료입니다. 단계와 완료 조건은 [ROADMAP](ROADMAP.md), 주요 이력은 [CHANGELOG](CHANGELOG.md)에서 관리합니다.

## 확정 기술·월드 정책

2026-10-23 사용자 확정 사항을 [ADR-0002](decisions/0002-stack-and-world-policies.md)에 기록했습니다. Paper 26.2·Java 25·Gradle·PostgreSQL, 단일 JAR 내부 기능별 모듈화, Docker Compose와 기존 Zabbix 활용을 채택했습니다. 순정 Java Edition과 별도 모드 최소화, 필요시 서버 리소스팩 제공을 기준으로 합니다. 2026-10-23 부분 확인에서 공식 Stable API `26.2.build.134-stable`의 POM·module·JAR 다운로드와 파일 일관성을 확인했습니다. 이후 사용자 승인으로 공식 체크섬 검증된 Temurin JDK 25.0.5+8-LTS를 사용자 전용 경로에, Gradle 9.1.0을 /tmp에 준비했습니다. 기존 최소 프로젝트의 전이 의존성 해결·compileJava·jar가 성공했고 메인 클래스(major 69)·plugin.yml 포함 및 API 미포함을 확인했습니다. [빌드 검증 기록](stack-build-verification.md)에 버전·명령·체크섬·산출물 근거를 보존합니다. 공식 문서 확인·최소 빌드·이번 S4-1 smoke와 아직 실행하지 않은 기능 시험을 구분합니다.

버전별 공간 템플릿 복제와 기존 월드·진행 보존, 별도 NPC·대화·퀘스트 콘텐츠 정의, PostgreSQL 월드별 진행 격리, 비활성 저장·언로드·재접속 복원, 스토리·경제 인벤토리·진행 분리를 확정했습니다. 스토리 전체 보호·지정 구역 변경 허용, 경제 지정 구역 보호·일반 지역 자유도 확대와 양쪽 전용 채집 인던 중심 정책도 확정했습니다. 세부 내용과 미정 항목은 ADR을 따릅니다.

S2 추가 검사에서는 월드 생성·식별·이동·저장·언로드, 대표 보호 이벤트와 인벤토리 API 참조 코드를 같은 고정 API로 컴파일했습니다. 후속 런타임 시험 성공 기준과 위험을 기록해 S2의 기술 경로·기준 정리 범위를 완료했습니다. [S3 상세 설계](story-world-detailed-design.md)는 승인 정책과 상태 전이·PostgreSQL 키/제약·버전 연결·보호/채집·복구 후보를 구분한 완료 기준선입니다. S4-1 월드 및 S4-4 최소 SQL 저장 구현은 있으나 NPC·퀘스트·AI·경제·전체 인벤토리는 없으며 합성 A/B 월드의 최소 동작/보존과 서버 로딩은 확인했으나 실제 플레이어·전체 데이터 격리·성능 검증은 남습니다.

## 인벤토리·아이템 운영 정책

사용자 확정 사항을 [ADR-0003](decisions/0003-inventory-performance-and-recovery.md)에 기록했습니다. 성능과 원활한 플레이를 복잡한 자동 복구보다 우선하며 일반 상자·창고는 월드 파일, 플레이어 인벤토리는 PostgreSQL 중심으로 관리합니다. 정상 동작의 기본 동시성·저장 순서·진행 격리는 유지하고 일반 클릭별 DB 트랜잭션/동기 flush는 요구하지 않습니다. 일반 인벤토리는 변경된 데이터만 초기 30초 간격으로 비동기 배치 저장하며 성능 측정 후 조정할 수 있습니다. NPC 구매·판매/플레이어 경제 거래는 거래마다 즉시 DB 반영하고, 퀘스트 보상은 중복 방지·지급 상태 즉시 저장 방향입니다. 스토리·경제 전환은 이전 인벤토리 저장 완료를 확인합니다.

고비용 체크포인트·거래 보관 시스템·완전 자동 복구는 필수 범위에서 제외했습니다. 추가 안전장치는 단순·저비용일 때만 검토하고 부하·지연이 크면 제외합니다. 예상치 못한 장애의 일부 유실·복사는 최소 오류 로그·백업을 근거로 관리자가 수동 조정할 수 있습니다. 자동 무손실·모든 상황의 복사 방지를 보장하지 않습니다. 이 인벤토리·거래·복구 정책의 구현/실행·성능 시험은 수행하지 않았습니다. S2 완료·S3 설계 완료·S4-2 재시작·보호 경로 검증 진행 중입니다. 최신 미저장 메모리를 포함하는 거래 후보, 자동 저장의 stale 덮어쓰기 방지, DB 실패/commit 불명·메모리 적용 실패 처리는 S3에 기록했습니다. 메모리·DB·월드 파일 간 원자성이나 모든 장애의 무손실은 보장하지 않습니다.

## 확정된 아키텍처

결정 원문은 [ADR-0001](decisions/0001-story-world-multiworld.md), 시스템 경계는 [architecture.md](architecture.md)를 따릅니다.

- B안: 하나의 Paper 서버 프로세스에서 진행별 독립 월드를 운영합니다.
- 싱글은 자신만의 진행·월드를 가지며 코옵 공동체는 하나의 진행·월드를 공유합니다.
- 퀘스트·NPC·월드 변화·플레이어 상태를 진행별로 격리하고 개인 상태는 그 안에서 플레이어별로 구분합니다.
- 비활성 월드는 저장 후 언로드하고 재접속 시 복원합니다.
- 필수 로컬 AI 스마트폰 어시스턴트는 공통 서비스를 쓰되 진행별 정보 접근을 격리합니다.
- 논리 진행 ID와 물리 서버·월드 배치를 분리해 향후 A안 확장 가능성을 유지합니다.

스토리·경제 데이터 분리도 유지합니다. B안은 스토리 운영 구조 결정이며 경제 월드의 프로세스 배치를 확정하지 않습니다. 위 항목은 구현 결과가 아닌 설계 결정입니다.

## 미결정 사항과 미검증 항목

C1은 ADR-0013 후속 승인으로 해소했습니다. 보스 시작 시 온라인 참가자만 명단/난이도에 반영하며 온라인 사망자는 진입 자동 부활, 시작 당시 오프라인 길목 참가자는 다음 도전부터 참여합니다. 이미 참가한 뒤 접속 종료한 사람은 기존 복귀 권리를 유지합니다. [최종 감사](s3-completion-audit.md)의 보류/이관 표에 컷신 거절 이후·폰 발급/양도/복구·보상 상세 등 미정 정책과 물리 SQL/UI·이벤트/생명주기/성능 시험을 분리했습니다. 관련 기능 구현 전에 필요한 후속 결정을 받으며 가입 기능은 없습니다. 경제 E1/AI 기술은 별도 범위입니다.

미검증 항목: 진행별 전체 상태 격리, 엔티티/일반 콘텐츠 템플릿 복제, 저장·언로드·재접속 경합, 중복 보상·장애 복구, AI 정보 누출 방지, 기존 서비스와 AI를 포함한 CPU·RAM·I/O·지연, A안 이전 가능성입니다. 상세 시험 계획은 [구현 가능성 검토](story-world-feasibility.md)에 보존합니다.

## 통합 정책과 완료 감사 (2026-10-25 현재)

ADR-0010~0012와 S3 §11~12에 확정/추천/구현 미정/S4 검증을 구분했습니다. 가입·관리자 구성원 변경 기능, 보스 위험 위치 보정, 공동체 알림은 현행 요구에서 제외합니다. 지도/일지/3개 공동체 하위 기능·개인 알림/설정·다중 목표/HUD, 채팅 투표 초기30초·대상변경 재투표, 정확 위치/방향 복귀·관전 자동 전환/해제·혼합 일시정지, 채집 정기/빈인던 재입장 리셋을 반영했습니다. 추천3초/5분·작업ID/generation·캐시·백업 후보를 승인값으로 기록하지 않았습니다.

**이전 통합 감사는 S3 진행 중**이었습니다. 당시 G1~G4 공백의 후속 판정은 아래 이전 재감사에 보존합니다. C1 승인 후 현재 판정은 상단과 [최종 감사 표](s3-completion-audit.md)를 따르며 실제 기능·SQL·부하는 미실행입니다. S2 완료·S4 미착수, 운영 환경/비공개 서사는 접근/변경하지 않았습니다.

## G1~G4 이전 재감사 (2026-10-25, C1 승인 전)

[ADR-0013](decisions/0013-vote-boss-and-gathering-state-boundaries.md)은 과반수 입력마감/DB확정·순서화 경합, 정상생존/보호자 일시정지·필수 실패/개인 실패 구분, 동일 story_run 채집 범위/리셋 준비 실패·단일 세대 경계를 확정합니다. [ADR-0014](decisions/0014-worldguard-protection-engine.md)로 스토리·경제 기본 보호 WorldGuard, WorldEdit 제작/관리+선택 dependency 검증, Hearth 콘텐츠/run/리셋 전용 책임을 채택했습니다. 버전 호환/플래그/런타임·부하는 S4 미검증입니다.

감사: **G1 충족, G2 부분 충족(C1 미충족), G3 충족, G4 명세 충족·실행 S4 이관**. C1은 집결 대기에서 오프라인을 빼는 것과 기존 사망자 자동부활·보스 시작 명단/난이도를 연결하는 정책입니다. 오프라인 길목 참가자를 삭제/신규참가 거부로 임의 처리하지 않았습니다. S3 진행 중·사용자 검토 대기, S2 완료·S4 미착수입니다. 문서/공식 문서 열람/보안 검사만 수행하며 플러그인 다운로드·코드/SQL/서버/DB 실행·운영 변경·비공개 서사 접근은 없습니다.
