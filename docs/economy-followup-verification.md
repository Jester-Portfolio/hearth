# 경제 거래·사망·거주 후속 보완

2026-11-25. 승인된 다섯 항목과 수정 중 발견된 같은 경로의 결함을 한 배치로 보완했다. [ADR-0038](decisions/0038-metadata-peer-and-async-native-lifecycle.md), [구조화 증거](../verification/economy-followup-result.json)를 따른다. 운영 서비스·실제 클라이언트·밸런스/획득처는 변경하지 않았다.

## 변경

1. **실제 물품 거래:** native `/거래`에서 가방 클릭 또는 `slot <1~36> <수량>`으로 책·강화 장비·임의 정상 메타데이터 물품을 제안한다. 좌클릭+1/우클릭-1, Shift 좌클릭은 해당 스택 전체다. 원본은 가방에 유지하고 양쪽 화면에 복사본을 표시한다. 제안 변경은 양쪽 확인을 해제한다. 선택 슬롯·원본 바이트 SHA·수량을 영수증에 연결하고 최신 물품의 Paper 내용 동등성을 검사한다. NBT 표현 순서 차이는 SHA를 다시 비교해 오판하지 않는다. 물품별64KiB/선택 합계1MiB와 기존41슬롯 봉투 한도를 유지한다. 양쪽 출고 후 빈 공간에 입고하고, 메타데이터를 재구성하지 않는다. 상품/화폐와 같은 PG 원자 거래·native CAS/저널·stale/불명 HOLD를 사용하며 새 DDL/아이템별 DB 트랜잭션은 추가하지 않는다.
2. **사망 기록 정리:** `.done` 완료 의도를 먼저 보존한 뒤 pending/preimage를 제거한다. 시작 시 같은 파일의 중간 정리를 효과 재실행 없이 재개하고 독립 `.before`는 개인 HOLD로 분류한다. 상충하는 완료/진행 증거는 보존한다. `/hearthsurvivaladmin death-status`는 보호/보류 중인 원본 UUID를 콘솔에서 조회한다.
3. **거주 언로드:** 실패 결과를 수집하고 해당 월드에5초/10초 대기·세 번 실패 후 보류를 적용한다. 월드/청크 티켓을 유지하고 예외가 주기 작업을 종료하지 않게 한다. 등록된 World와 내부 참조가 다르면 재사용을 거부한다. `housing unload-status`, `housing retry-unload <집 UUID>`로 확인/재시도한다. 운영 세계를 자동 삭제하거나 강제로 내보내지 않는다.
4. **자동 판매:** 플레이어별 마지막 시도 상품 다음부터 순환한다. 계속 공급되거나 거절되는 첫 상품이 다른 상품을 영구적으로 가로막지 않는다. 퇴장 시 커서를 정리한다. 기존 가격/재고/보상 정책과 거래 수명주기를 유지한다.
5. **사망·거주 파일 작업:** 사망 원본/표식과 거주 메타데이터 read/write/force를 별도 순서 보장 worker로 옮겼다. 시작 시 작은 경로/설정 확인과 Bukkit save/world API는 기존 메인 스레드 계약을 유지한다. 사망에서는 원본 native 저장→audit 영속화→owner에서 결과 저장→예정 드랍 공개→완료 정리를 따르며, 각 비동기 경계에 세션/소유권·원본 검사를 둔다. 생명 세대 변경 후의 토큰을 사용하고, 리스폰 admission은 완료 전 열지 않는다. 커서/입력을 모두 원본 native 슬롯에 담을 수 없으면 전체 원본을 worker에 보존하고 개인 HOLD·퇴장으로 전환해, 사망 취소를 무적으로 악용하지 못하게 한다.

추가 점검에서 **사망 인챈트가 일반적인 dead 검사에 막히는 경로**, 정상적인 입장점 지정 거절의 거주 전체 HOLD, 직렬화 표현 차이로 인한 정상 거래/사망 원본 비교 실패를 함께 수정했다. 생명 세대가 바뀐 뒤 이전 callback이 새 세션에 효과를 적용하지 않도록 보호했다. 입력 한도 초과는 원본 보존 후 개인 HOLD·퇴장으로 연결하고 취소된 사망의 인챈트 발동 차단을 유지했다. 전역 RPG HOLD와 종료 준비 단계도 공통 진입에서 반영해, 사망만 취소된 채 계속 플레이하거나 예약된 GUI 작업이 새 거래를 시작하는 경로를 닫았다. 종료 시에는 사망 원본/결과 확정을 먼저 기다린 뒤 거주 퇴장/언로드를 시작한다. 마지막 UI 점검에서는 변경된 물품 견적의 정상 거절을 거래 HOLD로 오표시하던 분류도 수정했다. commit 불명·CAS/세대 변경의 HOLD는 그대로 유지한다. 이 순수 GUI 분류 변경 뒤에는 컴파일과 NativeMenuRules3개만 확인했으며 같은 Paper/DB 행렬을 반복하지 않았다. 실제 플레이 성공을 주장하는 변경은 아니다.

이전 인챈트 문서의 “기존 native 거래로 책 교환 완료” 설명은 실제 상품-only 코드와 일치하지 않았다. 이번에 실행 경로를 추가했고 운영 가이드를 바로잡았다. 105종 구현 대응률과 실제 플레이 전수 검증률의 구분은 유지한다.

원본 증거 경로와 코드/JAR 해시는 구조화 기록을 따른다. 최종 복원본은 `/home/server/hearth-tmp/hearth-native-economy-run.11dix2q8`, 통합 두 JVM은 `hearth-native-economy-run.480ogzg_`다. 각 실행은 CPU2/nice10·600초/작업550초·최대Paper2/PG1·Paper heap1536MiB/RSS2560MiB·합산RSS6GiB·localhost/EULA/소유 경계를 유지했다. 관측 합산 peak는 최종 복원 약1586.80MiB이며 동접/상시 예산 판단이 아니다. 프로세스 종료·포트 정리·원본 config/월드 매핑/PG control 해시 보존과 기존 스토리/다른 realm 비교를 확인했다.

초기 준비 오류(새 계정의 nonempty 초기화 거부)는 `hearth-native-economy-run.yl33hd5o`, 직렬화 바이트 차이의 실제 거부는 `hearth-native-economy-run.3pe_3fam`에 FAIL로 보존했다. 첫 실패의 PG8개는 독립 단계로 통과했고, 후속에는 fixture·PeerTrade/EconomyStore/InventoryPayload/DDL 해시가 같음을 검사해 재사용했다. 성공 결과로 실패 원본을 덮어쓰지 않았다. 정규화·입력 HOLD·종료 순서 보완 뒤에는 영향받은 한 JVM 복원과 순서 단위 검사만 확인하고 같은 DB/두 JVM 행렬을 반복하지 않았다.

한 빌드 명령의 캐시 경로 오기는 즉시 해당 작업의 Gradle만 종료해 바로잡았다. 같은 명령 시작 시각에 생성된 캐시 디렉터리5개만 소유권/생성시각 확인 후 hearth-tmp로 옮겨 보존했고 JDK 실행 파일·기존 캐시·운영 프로세스는 변경하지 않았다.

## 미검증·보존 경계

Player/행동 이벤트를 합성하지 않았다. 실제 가방 클릭·다인 교환·사망/리스폰·아이템 엔티티/XP 획득의 전체 흐름과 장기 부하는 미실행이다. ItemStack/API/DB/실제 월드 수명주기 검사가 이를 대신하지 않는다. vanilla 세계 저장과 파일/PG의 완전한 분산 원자성·정전 무손실 복구를 보장하지 않는다. 불명 결과는 증거를 보존하며 자동 재지급·과거 사망 효과 재실행은 하지 않는다. 운영 배포와 기존 서비스 변경도 하지 않았다.
