# S4 실제 시험 제외 보완 배치

확인일: 2026-11-10. 기준 `9ee8ff9` 이후 코드. 사용자 요청에 따라 실제 Minecraft 클라이언트 시험을 제외하고, 현재 승인된 S4 범위의 독립 보완을 함께 구현·검증했다. 상세 결과·명령·해시·원시 증거는 [검증 JSON](../verification/s4-offline-completion-result.json)에 모은다. 이전 [실제 부분 수용](s4-client-acceptance.md)은 당시 관측으로 보존한다.

## 구현

- **정상 언로드 후 필드 조우 재연결**: 정상 IDLE 언로드를 모듈의 영구 종료와 분리한다. 같은 JVM·같은 물리 월드의 새 세대에만 재연결하며 CLEARED 기록을 보존한다. 미완료 조우는 관리 몹을 정리한 뒤 RETIRED로 유지하고 자동 재소환하지 않는다. 기존 콘텐츠의 명시적 구간 리셋과 최신 저장 장벽이 성공해야 선택 구간만 다시 시작할 수 있다. 다른 진행·완료 구간·인벤토리는 보존한다. 정리 실패/진행 중 리셋/오래된 세대는 HOLD하고, 프로세스 재시작 표식은 기존 재시작 HOLD를 유지한다. 관리자 읽기 전용 진단에 현재 suspended/hold 상태도 표시한다.
- **컷신 조회·현재 장면 복귀**: 같은 접속의 중복 비동기 조회를 한 조회/세션으로 합치고 다른 접속의 덮어쓰기를 막는다. 저장 세션의 유효성은 접속 수명으로 판단하고, 메뉴 응답은 별도의 화면 수명으로 제한한다. 종료 시 안전한 캐시만 해제하며 저장 중/불명 HOLD는 보존한다. 채팅의 `[현재 장면 다시 열기]`는 만료되는 callback 대신 `/hearthscene resume`으로 현재 프레임을 연다. 책의 재열기도 최신 프레임을 사용한다. 현재 본인의 장면·세션·접근·이동 잠금을 확인하며, 재열기로 새 시도/완료/보상을 저장하지 않는다. 읽기 전용 재시청은 해당 재시청 위치를 사용한다.
- **시험 환경 난이도 복원**: 최초 난이도를 진행/물리 월드 ID와 함께 격리 월드의 불변 메타데이터에 저장한다. 다음 JVM에서 시험용 PEACEFUL을 원래 난이도로 잘못 기억하지 않는다. 다른 ID·손상 파일·심볼릭 링크는 덮어쓰거나 기본값으로 대체하지 않는다. 게임 DB 스키마·기존 영속 데이터의 자동 변환은 없다.

## 검사 범위

전체 단위/회귀와 시험 스크립트 검사, 최종 JAR 컴파일을 수행하고 다음 기존 격리 모드를 최종 코드로 실행한다. 각 결과의 실제 횟수와 판정은 아래 및 검증 JSON을 따른다.

| 모드 | 확인할 경계 |
| --- | --- |
| `--sessions --quests --story-batch --s4-completion` | 실제 PG 동시 컷신 조회의 단일 세션, 중단 프레임/시도/원본 revision 보존, 기존 개인 장면/엔더/스마트폰·CAS/롤백·전투 복귀, 두 Paper JVM의 난이도 원본 복원·활성 전투/필드 HOLD |
| `--sessions --quests --story-batch --field-encounters` | 실제 관리 몹·사망 이벤트, 정상 월드 언로드/재로드, 완료 구간 유지·미완료 자동 재소환 금지, 실제 PG 저장 실패의 원본 보존과 성공 후 선택 리셋, 다른 진행 보존·종료 정리 |
| `--sessions --quests --story-batch --betterhud` | 고정 해시 BetterHud 선택 연동, 생성 팩·SDK·정상/관전 단일 표시 경계 회귀. 화면 표시 판정은 제외 |

결과는 전체 단위·회귀 **912개 PASS**와 Python **6개 PASS**다. 책 재열기를 최신 프레임으로 통일한 마지막 변경 뒤 관련 **17개**와 JAR 빌드를 통과했다. 기존 전체 결과와 중복되므로 929개로 합산하지 않는다. 격리 통합은 S4 기능/복원 **439개·145.820초·2 JVM**, 필드 조우 **28개·38.335초·1 JVM**, BetterHud **99개·46.979초·1 JVM**, 합계 **566회 assertion PASS**다. 생성 팩의 앵커·폰트·자산 **17개**도 PASS다. 최종 세 실행의 소유 프로세스·포트·DB 풀 종료 검사는 모두 통과했다.

첫 필드 재시험에서는 비동기 저장 중 시험 청크가 유지되지 않아 `FIELD_CHUNK_NOT_READY`로 실패했다. 실패 원본과 종료 확인 누락 판정을 보존했다. 실제 소유 프로세스는 exit 0이며 로그에 DB 풀 종료 완료가 남았다. 시험 메서드의 플러그인 청크 티켓 유지/정리를 보완하고 새 격리 경로에서 해당 모드를 통과했다. 이 마지막 변경은 시험 fixture에만 해당하므로 이미 성공한 S4 기능/복원 경로를 반복하지 않았다. 각 실행 JAR 해시와 최종 아티팩트의 차이는 검증 JSON에 명시한다.

자원 경계는 새 사용자 소유 `/tmp`·localhost·기존 승인 EULA, 실행별 총 600초/작업 550초·Paper 최대 2회·힙 1536MiB/RSS 중단 2560MiB·CPU 2개/nice 10이다. 과거 실제 시험의 시간 제한 예외를 자동 검사에 적용하지 않는다. 기존 증거를 덮어쓰지 않고 운영 서비스·운영 월드/DB·SSH/방화벽/터널·비공개 스토리 저장소는 변경하지 않는다.

## 남는 경계

실제 인증 클라이언트는 실행하지 않았다. 컷신 완료/선택/장시간 닫기와 키 입력, NPC 표식 높이·추적 HUD·배율, 전체 스마트폰/엔더/자동화/거점 이동, 실제 전투·관전/부활·저장/재접속·장애 및 두 계정 코옵은 [잔여 수용 작업](s4-remaining-work.md)을 따른다. 제어 포트·GUI 객체·Paper 이벤트와 PG 검사는 실제 사용자 행동 PASS가 아니다.

이번 배치에서 확인한 승인 범위의 독립 보완은 처리했다. S4 실제 수용 완료·운영 배포를 의미하지 않는다. 필수 로컬 AI의 모델/자원 예산과 S5 품질, 실제 스토리·밸런스·수용량/S6, 운영/S7·경제 규칙/배치는 별도 미정 범위로 남는다. 자동 검사 반복이나 임의 모델/인프라 선택으로 이 결정을 대신하지 않는다.
