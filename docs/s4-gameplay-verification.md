# S4 개인 호위·실패 재개·코스 결과 통합

확인일: 2026-11-09. 기준 `44cf16a` 이후 코드. 사용자 요청에 따라 같은 NPC·개인 의뢰·실패/보상·공개 코스·스마트폰 영역을 한 배치로 연결했다. 원시 실행 결과는 [검증 JSON](../verification/s4-gameplay-result.json), 남은 범위는 [S4 잔여 기능 배치](s4-remaining-work.md)를 따른다.

## 구현 범위

- 등록된 개인 호위 목표의 출발 지점에서 명시적으로 시작한다. 순정 Villager와 Paper Pathfinder가 경로를 이동하며 본인과 함께 도착해야 기존 개인 목표 CAS 저장을 실행한다. 이동 중인 대상과 진행/개인/접속/월드 세대·현재 목표를 결합하고 중복 시작/사망 이벤트를 소비한다. 다른 구성원이나 다른 진행의 목표를 대신 완료하지 않는다.
- 대상 사망/지정 구역 이탈을 기존 `OBJECTIVE` 실패로 기록한다. 멀어진 소유자는 기다리고, 기존 실패 확인→체크포인트 재시작→현재 구간 호위→NPC 보고→1회 보상으로 이어진다. 접속 종료/월드 변경은 대상만 정리하며 저장된 목표를 초기화하지 않는다. 오래된 세션/세대는 대상을 정리하고 원본을 보존하며 DB 실패/불명·정리 실패는 HOLD한다. 늦은 commit을 임의 재시작/중복 지급하지 않는다.
- 대상은 기본 숨김·비영속·비충돌·아이템 수집 불가이고 현재 소유자에게만 보이도록 설정한다. 기본 AI goal을 제거해 등록 경로만 이동한다. 실제 사망의 드롭/경험치는 지급하지 않는다. 등록 경로/속도/추적 거리/청크 수와 동시 호위 수를 제한한다. 기존 기능이 이미 보유한 청크 티켓은 호위 정리 때 반납하지 않는다. 선택형 개발 콘텐츠·설정은 기본 비활성이며 기존 월드를 자동 이관하지 않는다.
- `/hearthresult` 책과 스마트폰 홈·이어 하기·현재 코스에서 **코스 결과·기록**을 연다. 개인 직접 완료/장 스킵/진행/보고/실패, 중복을 제거한 공유 단계 도달/완료, 본인 발견/방문과 지급 대기/지급 완료/정의 확인 보상을 구분한다. 원래 의뢰의 상세/재시작/수령 및 장소/일지/현재 공동체 기록을 읽고 결과 쪽으로 돌아온다. 화면/세션·개인 revision·공유 상태·보상 epoch/항목·쪽을 재검사한다. 결과 조회는 게임 완료·장면 재현·상태 재적용·보상 확정이 아니다.

기존 [플러그인 적합성 검토](plugin-suitability-review.md)와 [실패/재시작 정책](decisions/0006-quests-dialogue-cutscenes-and-combat-revival.md)을 재사용한다. 제한된 개인 경로 이동은 기존 Paper의 MobGoals/Pathfinder와 Hearth의 소유권·CAS 경계로 구현했으며 추가 NPC 플러그인을 도입하지 않았다. DB 스키마·개인 퀘스트 저장/복원 계약은 불변이다.

## 실행 결과

- 관련 퀘스트·스마트폰·제작·채집·던전·인벤토리/세션 **고유 542개 검사**를 실행했다. 최초 541개 PASS/1개 실패는 HOLD 문구의 책 자동 줄바꿈을 문자열 검사가 고려하지 못한 문제였다. 문구 검사를 수정한 뒤 영향받는 결과 테스트 6개를 재실행해 전부 PASS했다. 신규는 호위 10개·결과 6개다. 전체 542개를 두 번 실행했다고 기록하지 않는다. 초기 컴파일의 package-private 페이지 구성 호출도 기존 공개 페이지 구성으로 고쳤고 최종 main/test 컴파일·Gradle JAR·격리 runtime stage는 PASS다.
- 최종 묶음 **375회 세션 assertion PASS**, **118.955초**. 실제 순정 NPC가 이동한 뒤에만 목표를 PG에 기록했고 사망→FAILED→체크포인트 재시작→제어 재접속→보고→1회 지급을 연결했다. A의 두 개인/B 진행·이전 대상/세션·현재 목표와 독립 개인 행의 실제 경쟁 commit/CAS 거부·HOLD/인벤토리 원본 보존을 확인했다. 호위 표식 27회와 결과 표식 18회는 고유 시나리오 수가 아니다.
- 같은 코스에서 기존 채집/제작 도구·공유 투표·인물 공개 경계·AI Mock 자료·던전/최종 월드 재연결을 통과했다. 최종 결과는 직접 완료 5건·개인 방문 3곳·서로 다른 공유 단계 도달/완료 2개이며 장 스킵·지급 대기·지급 완료를 별도 집계한다. Book/Dialog 2쪽과 기존 의뢰 상세/기록 읽기·갱신/복귀 모델·P2 분리·조회 후 일지/인벤토리 불변도 PASS다.
- 기존 재시작/보상 회귀 `--completion-navigation`도 **35회 assertion PASS**, **37.235초**다. 실제 실패 기록→체크포인트 재시작→PENDING→source 저장/1회 지급·확인 취소/중복 불변·실제 DB 지급 거부의 원본/PENDING/HOLD 보존을 확인했다. 이 경로도 같은 최종 JAR이며 별도 새 PG/Paper 1 JVM을 순차 실행했고 해시/프로세스·포트 정리를 통과했다. Paper 최대 표본 RSS는 약 1049MiB였다.
- 신규 모드의 의존 옵션 누락·기존 공개 모드/완료 모드 혼합 거부 3개를 임시 경로 생성 전 확인했고 Python AST·변경 Markdown 링크/인코딩·diff 형식을 검사했다.

개발 중 통합 두 차례는 시험 구성 때문에 실패했다. 첫 경합 주입이 뒤의 정상 던전이 읽는 행을 직접 바꿔 `QUEST_LIST_CHANGED`를 유발해 독립 개인 행으로 옮겼다. 두 번째 최종 다른 개인 비교는 이미 종료된 제어 세션으로 읽어 `STALE_JOURNAL`을 유발해 기존 오프라인 제어 조회처럼 별도 조회 토큰을 사용했다. 기존 상태/세션 검사는 완화하지 않았다. 원래 로그·실패 결과와 정상 최종 결과를 별도 경로에 보존했다.

최종 묶음은 새 사용자 소유 `/tmp`·localhost·기존 EULA에서 PG 1개/Paper 1 JVM으로 실행했다. 총 600초/작업 550초·힙 1536MiB/RSS 중단 2560MiB·CPU 2개/nice 10 경계를 유지했고 Paper 최대 표본 RSS는 약 1134MiB였다. 최종/설치 JAR 해시·소유 프로세스/포트/DB 풀 정리 PASS다.

## 남은 경계

실제 인증 클라이언트의 표시·책/Dialog 클릭·경로 동행/공격·코옵·네트워크 재접속은 사용자 별도 요청 전 보류다. 순정 NPC 이동/사망 이벤트와 제어 세션·책/Dialog 객체·실제 PG 결과는 실제 플레이어 행동 성공이 아니다. 가짜 Player는 사용하지 않는다.

호위 대상은 프로세스 재시작 후 자동 재생성하지 않는다. 기존 개인 목표를 읽고 현재 출발 지점에서 명시적으로 다시 시작하며, 전투/인던/컷신의 영속 복원을 추가하지 않았다. 저장/복원 계약 불변으로 같은 DB를 두 번째 JVM에 복원하는 검사는 반복하지 않았다. 실제 스토리/보상 밸런스·S5 로컬 AI·S6 전체 게임·운영 배포는 완료하지 않았다.
