# 전투 Player 적용기·세션 연결

2026-10-29 · 격리 개발 모드 · S4 진행 중.

## 구현 범위

- 기존 `CombatAttempt`·세션/인벤토리/월드 조정자 사이에 작은 `CombatPlayers` 연결부와 실제 `PaperCombatPlayers` 적용기를 추가했다. 전투 진행·생존 상태의 정본은 기존 전투 조정자이며 인벤토리 저장 체계를 새로 만들지 않았다.
- 정상 참가자의 관리 보스 근접 공격만 허용한다. 보스 역시 같은 진행·실제 월드의 정상 참가자만 대상으로 한다. 기존 WorldGuard 취소를 되돌리지 않고 NPC·다른 진행·비참가자·일반 엔티티/PvP 경계를 유지한다. 전투 외 피해 제한도 유지한다.
- 치명타를 취소하고 RPG 전투 사망 상태로 전환한 뒤 관전자 모드·대상을 적용한다. 이 경로는 실제 vanilla 사망/리스폰을 발생시키는 방식이 아니다. 인벤토리/장비를 과거 스냅샷으로 덮어쓰거나 소비한 아이템을 돌려주지 않는다. 예외적인 vanilla 사망은 드롭/경험치 유출을 막고 HOLD로 기록하며 자동 복귀하지 않는다.
- 사망/복귀/부활 처리 중에는 기존 아이템·퀘스트/GUI 조작과 전투 개입을 제한한다. 관전 대기에는 같은 월드의 허용된 범위에서 자유 시점을 유지한다. `/hearthcombat status`, `/hearthcombat watch`는 본인의 준비된 세션만 받으며 타인/run 인자를 받지 않는다.
- 관전 카메라와 부활 이동도 기존 순간이동 허가 경로를 사용한다. 요청 시점뿐 아니라 실제 TeleportEvent 시점에 세션·작업 유효성을 검사한다. 메인 스레드에서 Future를 기다리지 않는다. 이동 작업은 기술적 200틱 한도와 종료 시 작업 정리를 갖는다.
- 부활은 현재 세션·도전·월드 세대, 위치 안전성, 이동 성공·정확 위치, 게임 모드·체력·효과 적용을 확인한 뒤 기존 조정자에 성공을 반환한다. 불명확한 결과는 예약 횟수/사망 상태를 HOLD로 보존한다. 인벤토리 슬롯을 쓰는 적용 코드는 없다.
- 위치 안전성은 로드된 청크·월드 높이/경계·발 공간/머리 공간·바닥·대표 위험 블록을 보수적으로 검사한다. 조건부 부활의 안전성 검사와 재접속의 정확 좌표/방향 복귀를 구분한다. 재접속 좌표를 안전 위치로 바꾸지 않는다.
- 종료 전 현재 좌표/방향을 확보하고 카메라/모드 연결을 정리한다. 기존 세션이 최신 dirty 인벤토리 저장을 마친 뒤 새 세션이 복원한다. 재접속의 첫 이동 목적지에 기존 참가자의 좌표를 연결하고 실제 적용 위치 확인 후 복귀 상태를 확정한다. 사망/사용 횟수와 시작 명단은 유지한다.
- 이전 세션·세대의 늦은 적용, 중복 정리, 실패한 이동, 퇴장/종료 중 작업, owner 전달 실패를 거부한다. 저장/언로드 장벽은 적용 작업뿐 아니라 전투 조정자의 부활 확정까지 기다린다. 정리 실패도 정상 OFFLINE 성공으로 바꾸지 않는다.

부활/복귀의 좌표 비교는 yaw의 360도 동치만 인정하며 좌표 보정은 하지 않는다. 회복값이 실제 서버의 float 체력에서 0으로 내려가는 값도 거부한다. [기존 보스 제어](combat-state-verification.md)·[ADR-0006](decisions/0006-quests-dialogue-cutscenes-and-combat-revival.md)·[ADR-0011](decisions/0011-votes-boss-return-and-gathering-reset.md)을 유지한다.

## 활성화와 운영 경계

기존 격리 세션/전투 모드에 `combat-player-verification-enabled: true`와 `hearth.verification.combatPlayers=true`가 모두 있어야 한다. 일반 서버는 비활성이다. 기존 [플러그인 검토](plugin-suitability-review.md)의 Paper 연동을 재사용하며 새 플랫폼·DDL·운영 배포는 추가하지 않았다. V001~V007을 보존한다.

개발용 시작은 콘솔이 지정한 준비 완료 프로필의 동일 진행 온라인 세션만 고정 명단으로 받는다. 시작 시 커서/열린 GUI가 안전하지 않으면 거부한다. 이것은 정식 인던 입장/집결 규칙이나 가입 시스템이 아니다. 새 참가자를 도중 추가하거나 종료된 도전을 재생성하는 기능은 없다.

후속 사용자 요청으로 인증 시험을 할 때 사용할 콘솔 경로만 준비했다. 지금 클라이언트·TTY 준비를 요구하거나 수동 서버를 실행하지 않았다.

```text
hearthverify combat-player-start J_Ester
hearthverify combat-player-revive J_Ester public_rescue
hearthverify combat-player-release J_Ester
```

`public_rescue`는 명시적 콘솔 시험 조건 입력이다. 실제 목표 달성/아이템 소비 조건을 검증했다고 보지 않는다. release는 정상 종료된 개발 시험의 모드/관전 정리이며 정식 전투 종료 후 복귀 위치/자동 부활 정책을 확정하지 않는다. 종료된 전투의 생존자는 일반 조작으로 돌아가고 사망자는 명시적 시험 정리 전까지 관전을 유지한다. HOLD는 release로 해제하지 않는다.

## 검증과 남은 범위

[검증 JSON](../verification/combat-player-result.json)에 최종 근거를 기록한다.

- 관련 단위·회귀 66개 PASS 후 적용 결과 누락/퇴장 정리 오류 방어를 보강해 영향받는 연결부 16개만 재검증했다. 유효 검사 68개 PASS이며 반복 실행을 중복 합산하지 않았다. 소유권·조작 차단·관전/적용 단계·정확 복귀·세대/세션 교체·실패/정리/HOLD·저장 장벽·위험 위치·체력값 방어를 포함한다.
- `--sessions --quests --story-batch --combat-players` 한 JVM/신규 PostgreSQL로 실제 Player 적용기 등록·라이브러리 로딩, 기존 세션 저장/빠른 재접속·인벤토리 revision, 제어 포트의 복귀/부활·대표 실패·다른 진행 보존·정상 종료를 검사해 PASS했다. 보스 시작 청크는 기존 비동기 준비 도구를 재사용한다.
- 자동 시험의 플레이어 위치/카메라/회복은 내부 제어 포트다. 실제 Player 객체나 합성 Player 이벤트를 만들지 않는다. 실제 인증 접속·치명타·PlayerInventory·관전 카메라·체력/효과 적용·teleportAsync는 실행 미검증이다. 저장 형식/복원 계약이 같으므로 두 번째 JVM은 실행하지 않는다.
- 전투 사망의 개인 퀘스트 DEATH 실패 연결은 기존 행동 권한과 세션 유효성의 분리가 더 필요해 후속으로 남긴다. 기본 vanilla 사망 훅을 이 수동 사망 전환의 성공 근거로 사용하지 않는다. 보스 재도전 투표·패턴·길목·정식 종료/복귀·전체 인던 수명주기도 후속이다.

구현 API 근거: [Paper 비동기 이동](https://docs.papermc.io/paper/dev/entity-teleport/), [Player 관전 API](https://jd.papermc.io/paper/26.2/org/bukkit/entity/Player.html), [효과 Registry](https://jd.papermc.io/paper/26.2/org/bukkit/Registry.html). 실제 클라이언트·장기 부하/TPS/MSPT·운영 배포는 미실행이다.
