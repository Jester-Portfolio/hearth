# 공통 전투 상태·30초 이동 제한·TPA 통합

날짜: 2026-11-20. [숙련도/공통 접근](auraskills-admission-verification.md)의 다음 기능 배치를 구현했다. 운영 서비스·기존 데이터와 실제 클라이언트 보류는 유지했다.

## 변경

- `CombatTags`는 UUID별 마지막 공격의 30초 만료시각을 관리한다. MONITOR/ignoreCancelled/최종 피해 양수 조건의 Paper 리스너로 플레이어·투사체·TNT·펫 귀속을 연결했다. PvE 포함 여부는 활성화 시 명시해야 하며 운영값은 미선정이다.
- 기존 월드/개인 거주/포탈·표준 teleport·로비 전환이 하나의 전투 상태를 사용한다. 리스폰/권한 회수 안전 복귀만 내부 목적에 따라 예외 처리하고 태그를 지우지 않는다. 로그인은 남은 태그가 끝날 때까지 거부해 공용 스폰 재접속을 이용한 즉시 이동을 막는다. async 경로는 concurrent map·volatile 상태만 읽으며 DB/Bukkit 상태 동기 대기를 하지 않는다.
- `/tpa`·`/tpaccept`·`/tpdeny`·`/tpcancel`, 채팅 버튼, 요청 만료/정원/접속 세대·참가자별 단일 요청을 연결했다. 버튼은 request ID에 묶어 만료된 버튼이 새 요청을 수락/거절하지 못한다. 수락 뒤 한 번만 MOVING으로 소비하며 결과 불명은 HOLD로 보존한다.
- 수락 및 실제 이동에 양쪽 전투·세대·목적지 레벨/ACL·안전 셀·상대 위치/다른 이동을 검사한다. 상대는 수락 위치 2블록 안에 있어야 한다. 기존 WorldTravel·정확 좌표/원위치 확인·native future tombstone을 재사용한다.
- E009 `combat_tag`는 realm/UUID별 만료시각과 활성 검색 인덱스를 추가한다. 기존 E001~E008 원문·체크섬은 바꾸지 않았다. PG realm 잠금과 발급 context를 재사용하며 1초 단위 묶음/quit/drain 저장, max upsert, 새 JVM 복원을 연결했다. 새 스키마가 존재해도 다른 경제/스토리/인벤토리를 재확정하지 않는다.
- 재시작 후 미저장 마지막 공격의 우회를 막는 30초 시작 보호 대기가 있다. 활성 태그가 남은 realm에서 기능을 꺼서 시작하지 못한다. 기존 비정상 종료 HOLD와 수동 복구 경계를 유지한다. 로그아웃 처벌이나 자동 무손실 복구를 새로 만들지 않았다.

[검토용 설정/사용법](../infrastructure/network/combat-travel.md)을 따른다. 기본 비활성이고 운영 설치·수치/콘텐츠 설정은 적용하지 않았다. 요청 기본 60초/15~300초 범위는 변경 가능한 편의 설정이고, 전투 30초는 사용자 요구를 따른다.

## 검사와 증거

[구조화 결과](../verification/combat-travel-result.json)에 각 JAR/로그/검사 XML과 결과 경로를 보존했다. 모든 실행은 새 소유 `/home/server/hearth-tmp`·localhost·CPU 2개/nice 10, Paper heap 1536MiB/RSS 2560MiB·합산 RSS 6144MiB·호스트 가용 최소 6144MiB, 시험당 600초/작업 550초·Paper 최대 2회 안에서 진행했다.

- 단위/회귀: **31개**. 태그 갱신/만료·미저장 변경 ack·새 인스턴스 복원·시작 보호, 수락/세대/참가자 경합·만료·HOLD·오래된 버튼, 기존 WorldTravel/입장 정책을 검사했다.
- 실제 격리 PG: **8개**. E009 반복 migration/기존 checksum, 경합/역순 flush의 최대값, foreign issuer/realm 거부, SQL trigger 실패의 묶음 rollback·원본 태그 보존, 만료 경계·realm 분리, E009 checksum 불일치 거부를 확인했다. 기존 다른 경제/스토리 행 보존과 소유 PG 정상 종료도 통과했다.
- 첫 Paper **prepare 10개 / resume 9개**. 실제 Paper에 명령·MONITOR 리스너 등록, 공통 게이트의 양측 제한, 메모리 묶음/PG ack, 실제 30초 값 저장과 새 Paper JVM/새 pool의 동일 PG 값 복원을 확인했다. 리스폰/안전 복귀의 접근 조건이 태그 삭제 없이 유지되는 데이터 계약도 확인했다.
- 그 뒤 요청 ID에 묶인 채팅 입력과 기본 비활성 경로의 PG 완료→Bukkit 초기화 스레드 경계를 보완했다. 영향받은 단위 검사·중간 JAR prepare 10개 후, 최종 JAR의 **기본 off 6개 / on prepare 10개**를 확인했다. 초기화는 명시적으로 메인 스레드에 배치하고 guard를 추가했다. PG 행렬/이미 통과한 저장 복원 행렬은 반복하지 않았으며 각 JAR 해시와 범위를 구분해 보존한다.
- 두 JVM 복원의 만료 경쟁을 피하기 위해 별도 합성 UUID의 `현재+120초` 값을 fixture에서만 직접 PG에 저장했다. 실제 게임 태그는 계속 30초이며, fixture 값을 운영 설정으로 채택하지 않았다.

## 미검증·남은 범위

실제 공격/투사체/펫·피해 취소·클라이언트 명령/버튼·수락 중 이동/전투·리스폰/로그인/로비 전환, 외부 Home 플러그인, 동접·장기 부하·장애 전원 차단은 미검증이다. 합성 오프라인 UUID·접속 token 객체·PG 행과 명령/리스너 등록을 실제 Player 행동 성공으로 기록하지 않는다. 가짜 Player나 인증 우회는 사용하지 않았다.

기능은 같은 경제 Paper의 플레이어끼리 동작한다. 표준 이벤트를 무시하는 NMS/악성 플러그인의 이동까지 보장하지 않는다. 다른 backend 간 분산 태그/TPA는 단일 writer·공유 이동 계약 확장 전까지 미구현이다. 전투 중 로그아웃의 자동 처벌은 추가하지 않았으며, 남은 시간의 재접속/이동 제한을 유지한다.

다음 배치는 월드별 PvP·개인 소유자 설정·확정 가능한 사망 처리다. 기본 거주 사망 정책·XP 종류/산식·부적 범위는 미정으로 남긴다. 초보 자원/엔드의 물리 확장·최종 보상 coordinator·장비/HUD와 실제 플레이/운영 수용도 별도 잔여다.
