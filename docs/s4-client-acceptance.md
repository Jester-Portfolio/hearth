# S4 실제 클라이언트 부분 수용·NPC 표시 보완

2026-11-09. 기준 `70175a2` 이후 코드. 사용자가 실제 플레이 시험과 이번 수동 시험의 600초 제한 해제를 요청했다. 기존 정품 계정·접속 환경과 팩 터널을 확인해 한 명으로 시험했고, 사용자가 **실제 시험 종료와 NPC 표식 높이 수정을 요청해 종료했다.** 전체 S4 수용 PASS가 아니다. 해시·실행별 원시 판정·검사 수치·증거 경로는 [검증 JSON](../verification/s4-client-acceptance-result.json)에 기록한다.

## 이번 변경

- 기존 도구에 실제 인증용 `--s4-client`를 추가해 공개 코스·개인 장면/스마트폰/지도·보관/가공·채집/제작·거점 이동·호위/던전을 같은 새 격리 환경에 준비했다. 사용자 준비·TTY·허용 목록·일반 권한·`online-mode=true`를 유지한다. 가짜 Player나 인증 우회를 사용하지 않는다.
- `--manual-no-time-limit`는 명시적으로 요청한 수동 S4 모드에서만 허용한다. 전체 경과 시간만 해제하고 CPU 2/nice 10·heap 1536MiB/RSS 중단 2560MiB·호스트 가용 RAM 6GiB·개별 기동/작업/정리 대기는 유지한다. 자동 모드의 작업 550초/전체 600초 한도는 그대로다. 실제 실행 한 번은 1688.725초까지 이어졌고 정상 정리했다.
- 확대된 퀘스트 상태 조회의 작업 큐 초과를 순차 조회·중복 조회 억제·변화 시 출력으로 수정했다. 최초 입장 `MOVING`을 채집장 필터가 거부하던 `MOVE_FAILED`도 수정했다. 자기 물리 월드의 채집장 밖 입장 이동을 허용하고, 내부는 활성 세션/현재 참가·예약 검사를 유지한다.
- 요청받은 새 시험 환경은 실제 월드 UUID의 Bukkit API로 낮6000·맑음·평화로움·자연 스폰/몹 블록 파괴 끄기를 설정하고 다시 읽어 검사한다. 실습 시설 10종과 동선 시설 5곳을 검사하고, 실습 구역의 폭발은 WorldGuard로 차단한다. 자연 스폰 이벤트만 제한하고 Hearth의 CUSTOM 스폰은 보존한다. `hearthverify client-environment combat`은 현재 시험 JVM에서 기억한 원래 난이도로 전환하며 자연 스폰 억제는 유지한다. 활성 전투가 추적 중이면 `ui` 전환을 거부한다.
- 팩 제공기는 `127.0.0.1:25587/hearth-s4.zip`만 제공한다. 사용자 PC는 팩용 로컬 전달 25588을 사용한다. 디렉터리/DB/다른 파일을 공개하지 않는다. `hearthverify client-pack PROFILE`은 준비된 실제 세션에 생성 팩 ID·SHA-1을 포함한 선택형 요청을 보낸다. 선택형 팩을 로드하기 전에는 해독할 수 없는 Glyph 미니맵을 내보내지 않는다.
- **NPC `?`·`!`는 기존 발밑 기준 +2.2에서 몸체 높이 +1.0으로 올렸다.** 성인 주민 기준 약 +2.95이며 X/Z와 NPC 위치는 유지한다. 컷신 이동 잠금을 일반 상호작용 불가 상태로 처리해 NPC까지 숨기던 경로도 보완했다. 검증된 같은 세션/월드와 최신 공개 권한을 가진 읽기 전용 표시는 유지하고, 대화·수락 등 실행은 기존 `current` 권한을 계속 요구한다. 준비/저장/복귀 HOLD·전투 중 비활성 상태의 권한을 넓히지 않는다.

## 실제로 확인한 범위

| 항목 | 관측·판정 |
| --- | --- |
| 정상 인증·입장 | 수정 후 실제 Player의 이동 성공, `ACTIVE/playable=true`, 돌32·저장 revision1 확인 |
| 스마트폰 지급/재접속 | 최초 지급·재접속 후 1개 유지 사용자 확인, 저장 상태 대조 |
| 팩 거부 | `DECLINED` 뒤 접속·이동 유지 확인. 미적용 전 Glyph가 네모로 보였던 문제는 후속 표시 게이트로 보완 |
| 팩 다운로드/로드 | 초기 SSH 대체 문구 오류·PC 연결 거부를 실제 접속 명령으로 해결. 생성 팩 ID의 `ACCEPTED → DOWNLOADED → SUCCESSFULLY_LOADED` 확인 |
| 화면·스마트폰 | 네모 사라짐, 우상단 미니맵과 카메라 반응, 스마트폰 한글·아이콘·메뉴 동작 사용자 확인. 목표 추적/정확한 앵커·배율은 미확인 |
| 필수 장면 | 첫 시청 시작 저장, 미완료 기록과 현재 장면/채팅 재열기 사용자 확인. 의뢰 수락 확정·장면 완료·재접속 복원은 미확인 |
| 환경 초기화 | 자연 크리퍼로 시설이 파손됐다. 콘솔의 변경 성공 응답만으로 실제 시험 월드 적용을 확정했던 판단을 정정했다. 사용자 요청으로 기존 월드/DB/증거를 보존하고 새 환경을 만들었고, UUID별 실제 상태·시설 검사와 사용자 ‘복구 환경’ 확인을 받음 |
| 종료 | 두 부분 실제 실행 모두 `MANUAL_CLOSED_UNVERIFIED`, 정상 저장/종료·DB 풀 종료 표식·소유 프로세스/포트 정리 확인. 이 원시 판정은 행동 자동 심사 PASS가 아님 |

실제 시험 JAR은 최종 NPC 표시 수정 전 버전이다. 사용자 종료 후 높이·컷신 표시 수정은 내부 검사로 확인했으며 실제 화면 재확인으로 기록하지 않는다. 계정 이름/UUID·IP·채팅 원문은 공개 요약에 복제하지 않는다.

## 수정 후 내부 검사

관련 Java 단위/회귀 **204개**, 팩 제공 범위·수동 명령·시간 예외/자원 방어 Python **6개**, 잘못된 CLI 조합 거부 **4개**를 확인했다. 당시 생성 팩은 **17개** 자산/앵커 검사도 통과했다. 신규 NPC 표시의 최종 Paper/격리 DB 검사 수치와 원본 해시는 검증 JSON을 따른다.

최종 격리 Paper **1 JVM/PG 검사 76회, 47.123초 PASS**이며 소유 프로세스/포트를 정상 정리했다. 게임 저장/복원 계약은 바꾸지 않아 추가 두 번째 JVM은 실행하지 않았다.

NPC 객체 검사는 실제 주민의 몸체 높이보다 1블록 높은 TextDisplay, 같은 X/Z·NPC 위치 불변, 두 표식의 개인 기본 숨김/비영속/정리·권한 필터·인벤토리 보존을 검사한다. 공유 진행의 CAS·저장 장벽·월드 재연결과 개인 상태 보존도 같은 실행에 포함한다. 첫 확장 검사에서 표시용 NPC 생성 준비가 누락돼 실패했고 `ensure`를 추가한 뒤 해당 통합만 재실행했다. 초기 컴파일 오류·조회/입장 실패·환경 적용 불일치와 원시 종료 확인 누락 기록은 덮어쓰지 않았다.

## 남은 실제 수용

사용자가 시험을 종료했으므로 추가 실제 플레이는 재개 요청 전 보류한다. 수정 후 표식 간격/컷신 NPC 표시, 목표 HUD 추적·전체 화면/배율, 장면 완료/중단 후 재접속, 퀘스트/공유 투표/보상, 인벤토리·시설/엔더·제작/채집·거점 이동·호위/전투·복귀의 전체 흐름, 실제 두 JVM 복원은 완료하지 않았다. 동시 코옵은 두 번째 인증 계정이 없어 미실행이다. 강제 종료/실제 파일시스템 장애·장기 부하·운영 복구/배포도 수행하지 않았다. [S4 남은 수용 작업](s4-remaining-work.md)을 유지한다.
