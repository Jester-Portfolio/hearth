# 경제 엔진·Minecraft 연결 검증

확인일: 2026-11-07. [설계 선택](decisions/0015-economy-engine-and-transaction-boundaries.md), [실행 결과 JSON](../verification/economy-result.json), [경제 실행 안내](../minecraft/economy/README.md).

## 구현과 경계

Java 내부의 순수 계산·경제 SQL·Paper 적용을 분리했다. 생산/실제 소비·재료 소모 제련·지연 운송·공급/수요/경로 사건·EMA와 수량별 총액, 경제 전용 계정/41슬롯/잔액/요청 기록을 구현했다. 기존 저장 worker·CAS·세션·월드 수명주기를 재사용한다. 별도 Python/AI 서비스·Citizens·새 UI 프레임워크를 설치하지 않았다.

수도 상인의 우클릭 → 54슬롯 견적 → 수량/매수·매도 선택 → 현재 소유권/월드/화면/거리 확인 → 최신 dirty 저장 → DB 확정 → 메인 스레드 적용 경로가 있다. 기존 스토리 인벤토리를 경제 계정으로 가져오지 않는다. 일반 서버 기본 비활성이고 경제 전용 격리 gate가 필요하다. 실제 NPC 클릭·PlayerInventory·GUI 행동은 이번에 실행하지 않았다.

E001은 별도 `hearth_economy` 스키마를 생성하고 checksum·필수 열을 확인한다. 기존 V001~V008과 기존 증거는 수정하지 않았다. 경제 스키마는 realm/market/account/shipment/event/trade를 분리하고 realm 및 계정 외래키, 수량/잔액 제약과 요청 키를 둔다. 계정은 명시적 fixture 생성만 지원한다. 운영 계정/화폐·스토리↔경제 이전 정책은 미정이다.

## 측정과 최적화

단일 측정이며 통계적 성능 보증이 아니다. 모의 시간은 시험에서 **1 Tick=1시간**으로 해석한 2,160 Tick(90일)이며 운영 Tick/시간 정책이 아니다.

| 측정 | 관측값 | 한계 |
| --- | --- | --- |
| 4 시장 셀·90일 | 약 106ms | 공개 철광석/제련/운송 콘텐츠의 순수 계산 |
| 512 시장 셀·90일 | 약 5.759초 | 32지역×16상품, 시설/경로 없는 셀 확장 시험. 대형 생산망 성능을 뜻하지 않음 |
| 4,096개 총액 200회 | 구간 적분 약 0.718ms / 단위 반복 기준 약 2,228ms | 같은 적분·반올림 결과. 단순 재고 비율 공식이나 Python과의 성능 비교가 아님 |
| 전체 계산 시험 스레드 CPU | 약 8.0초 | 시뮬레이션·기준 반복·재현 검사 합계 |
| 계산 시험 종료 시 사용 heap | 약 34.8MiB | 최고치/누수 측정 아님 |
| 4 내부 세션 구매 완료 | 약 447ms | DB 대기·견적 재시도·owner 전달 포함. 실제 클라이언트 지연 아님 |
| Tick+판매 요청 완료 | 약 150ms | 단일 표본. 개별 SQL 비용은 측정하지 않음 |

구간 적분은 수량당 반복을 최대 세 구간 계산으로 바꾼다. 캐시된 콘텐츠 hash, 계정/시장 복합 키, 미완료 운송/사건 조회 인덱스, 변경 시장만 batch 갱신, 단일 in-flight Tick·제한 worker/큐를 사용한다. 메모리는 현재 시장·진행 중 운송/사건 중심이며 거래 이력 전체를 RAM에 적재하지 않는다. DB 이력 보관/정리 주기는 미확정이다. 현재 공급 평가의 시설/경로 탐색은 시장 셀 수와 함께 비용이 늘므로 대형 생산망 도입 시 인덱싱·프로파일링이 필요하다.

## 미검증·후속

- 실제 인증 플레이어의 NPC 우클릭·GUI 클릭/드래그·shift/숫자키·거리/월드 이탈·거래 후 화면/인벤토리·4인 행동. 내부 세션/ItemStack 시험을 실제 접속으로 표시하지 않는다.
- 실제 네트워크 단절/commit 응답 유실은 미실행. SQL 오류와 commit 후 불명 결과는 명시적 제어 주입이다. PostgreSQL 프로세스 재시작, 강제 종료 무손실 복구·TPS/MSPT·장기 누수/부하도 미실행이다.
- 자동 수요 적응형 목표 재고, 운송비/세금·무역 UI·실물 운송, 다중 재료 출력/복잡한 제조망, 사건의 퀘스트 조건 실행, 운영 이력/백업·관리자 복구 도구는 후속이다. 현재 사건 신호 조회 경계만 제공한다.
- E1 운영 화폐/자산·서버 배치·최초 계정·오프라인 정책과 밸런스를 확정하고, 실제 상점 플레이 및 운영 규모 비용을 검증해야 한다. E1/E2·전체 S4 완료나 운영 적용 승인으로 기록하지 않는다.
