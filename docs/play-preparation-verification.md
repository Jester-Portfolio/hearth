# 공개 코스의 시설·재료·던전 준비 안내

확인일: 2026-11-09. 기준 `cfdbda7`. [재료 공급 실습](material-supply-verification.md)과 [던전 의뢰](dungeon-play-verification.md)의 기존 경계를 재사용했다. [검증 JSON](../verification/play-preparation-result.json)에 실행 수치·표식·JAR 해시를 기록한다. S4는 진행 중이며 일반 서버에서는 비활성이다.

## 연결한 기능

- `/hearthprepare`와 기존 NPC의 다음 플레이 안내 책, 스마트폰의 퀘스트/다음 플레이 안내 화면에서 같은 준비 목록·상세·새로고침을 제공한다. 스마트폰 최상위 6메뉴는 유지한다.
- 채집: 공개 장소 위치와 기존 채집 상태를 표시한다. 미준비·초기화·HOLD 상태를 이용 가능으로 바꾸지 않는다.
- 작업대: 등록 레시피별 필요·보유·부족 수량을 한국어 재료명으로 표시한다. 기존 제작 계획기로 본인 보관 슬롯의 실제 사용 가능한 재료만 집계한다. 방어구·보조 손·다른 메타데이터의 재료를 새로 허용하지 않는다.
- 던전: 본인의 수락/진행/보고/완료, 입구 범위, 기존 도전 상태와 저장 대기/처리 상태를 구분한다. 미수락 의뢰의 제목·NPC·목표는 숨기며 접근 제한·선행 조건으로 잠긴 의뢰는 목록에서 제외한다.
- 책과 스마트폰은 같은 `PreparationGuide` 표시 모델을 사용한다. 공개 필터를 통과한 장소 DTO만 사용하고 원본 위치를 표시 데이터에 복사하지 않는다. 재료·위치·진행·저장 상태가 달라진 이전 선택은 거부하고 다시 조회하도록 안내한다. 세션 교체 후 결과도 표시하지 않는다.

[콘텐츠](../src/main/resources/play-preparation-demo.yml)에서 안내 제목·재료명·연결을 관리한다. 중복 ID·잘못된 시설/레시피/장소/던전 연결·재료명 누락은 활성화 전에 거부한다. 새 플러그인이나 UI 프레임워크는 추가하지 않았다.

이 화면은 **조회 전용**이다. 원격 제작·이동·던전 진입, 퀘스트 수락/보고·저장 작업을 실행하지 않는다. 제작 실습 완료나 장비 소지를 던전의 새 필수 조건으로 추가하지 않는다. 최종 권한·집결·명단·저장은 기존 NPC 진입 요청에서 다시 판정한다. V001~V009·41슬롯 형식·일반 30초 dirty 저장·기존 입장 정책은 변경하지 않았다.

실제 DB 장애를 새로 주입하지 않았다. 기존 저장 구현을 바꾸지 않았으며 관련 단위 회귀에서 쓰기 실패/HOLD·조회 중 상태와 표시 권한의 거부를 확인했다. 채집 상태의 현장 수치는 기존 조회 경로를 재사용하고, 이번 자동 시험에서는 미준비 안내와 표시 모델을 검사했다. 채집/전투 자체를 다시 실행한 결과가 아니다.

## 실행·미검증 범위

새 사용자 소유 `/tmp/hearth-s4-11.*`를 기존 `stageLifecycleRuntime`으로 준비한 뒤 `verify-lifecycle.py` 필수 인자와 `--sessions --quests --story-batch --combat-players --dungeon-play --play-preparation --accept-eula`를 사용한다. 기존 자원 한도 안에서 한 JVM만 실행한다. 설정 `play-preparation-verification-enabled`와 JVM `hearth.verification.preparation`을 함께 명시해야 활성화된다. 기존 콘텐츠는 덮어쓰지 않는다.

**실제 인증 클라이언트의 NPC/책/스마트폰 클릭·화면·PlayerInventory·이동은 미검증**이며 사용자 요청 전 보류한다. 서버 내부 제어 인벤토리와 세션 시험을 실제 행동 성공으로 보지 않는다. 저장/복원 계약 불변이므로 두 번째 JVM·DB 재시작과 기존 전체 회귀는 반복하지 않았다. TPS/MSPT·장기 부하/누수·운영 배포도 미실행이다. 운영 서비스/DB/월드·이전 증거·비공개 스토리는 변경하지 않았다.
